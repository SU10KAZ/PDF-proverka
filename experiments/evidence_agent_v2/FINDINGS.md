# EV2 — сводка находок и сравнение с алгоритмом Cursor

Дата: 2026-06-27. Автор: EV2 (независимая ветка агента-верификатора).
Контекст: над `backend/.../evidence_verifier/` параллельно работает Cursor; EV2 —
изолированная альтернатива в `experiments/evidence_agent_v2/`. Цель — сравнить два
подхода. Тесты на локальных vision-моделях (ngrok/LM Studio) не пересекаются по времени.

---

## 1. Главное в двух абзацах

Идея Андрея Ивановича верна: golden-set из подтверждённых/отклонённых «графических»
замечаний — рабочая основа для выбора и настройки vision-модели. Но **сырой golden-set
нельзя использовать как есть** — в нём ~15% битых меток (осыпавшийся F-ID), и бенчмарк
по нему меряет шум. EV2 добавляет фильтр консистентности и сбалансированную выборку.

**Ни одну из двух реализаций нельзя брать в прод как есть.** Код Cursor сейчас не
запускается (3 аварийных бага в графическом пути). EV2 запускается и даёт честные
метрики, но его слабое место — `false_reject=0.4` (на 40% реальных замечаний модель
ошибочно говорит «чертёж опровергает»), корень — подача первого попавшегося блока.
Правильный путь — **гибрид**: каркас Cursor + ядро принятия решений и гигиена данных EV2.

## 4. EV2 — результаты и слабые места

Baseline qwen3.6-35b (verdict, 10+10 чистых): `false_reject=0.4 true_reject=0.2 abstain=0.4`.

Что вскрыли метрики (честно):
1. **Голосование при temp=0 вырождено** — 0/20 расхождений голосов; идентичные ре-раны
   не добавляют робастности, только латентность. Нужны **возмущения** (масштаб картинки/
   разные модели), а не K одинаковых прогонов.
2. **false_reject=0.4** — корень не в политике, а в **восприятии**: подаётся ПЕРВЫЙ блок
   (`primary_png`), в нём часто нет предмета замечания → модель говорит «противоречит»
   вместо «не вижу».
3. Слабый recall (2/10 misread) — консерватизм режет чувствительность.

Применённые не-ngrok улучшения (готовы к замеру после освобождения ngrok):
- **Промпт вариант C** (`EV2_PROMPT=c`, дефолт): presence-gate (сначала «виден ли предмет»)
  + quote-gate («yes» только с дословной цитатой) + анти-флип («не вижу» ≠ «опровергнуто»).
- **Детерминированный guard** в `extract.py`: «yes» без непустой `evidence_quote` →
  принудительно `cannot_tell` (машинно-проверяемое правило, не зависит от послушания модели).
- Схлопывание `.pdf`-дублей проектов в сэмплере.

Ожидаемый эффект: ↓false_contradict, ↑abstain (безопасно — abstain=needs_human, замечание
не теряется). **Цифры будут после A/B baseline-vs-C на ngrok.**

## 5. Сравнение архитектур и вердикт

| | EV2 (моя версия) | Cursor |
|--|--|--|
| Решение | восприятие⊥суждение + явная Python-политика | один vision-shot → вердикт в промпте |
| Графика | **работает** | **не запускается** (баги 1-3) |
| Текст/mixed | заглушка needs_human | **реализованы** (Claude CLI + mixed-стратегия) |
| KB-gate, batch | нет (прототип) | **есть**, встроено в pipeline |
| Гигиена данных | consistency_gate + баланс | сырой join (≈15% шума) |
| Защита реальных замечаний | явный консерв. порог голосов | `REJECT_CONFIDENCE_THRESHOLD=0.75` |

**Вердикт — гибрид:**
1. Починить 3 аварийных бага Cursor (референс — `extract.py`/`context.py` EV2).
2. Заменить single-shot вердикт Cursor на схему EV2 «восприятие⊥суждение» + явную политику.
3. Голосование — только по **возмущениям**, не идентичными temp=0 ре-ранами (до этого K=1).
4. Решить корень false_reject: подавать **правильный блок** (где предмет замечания), не первый.
5. Перенести `consistency_gate` и сбалансированный сэмплер EV2 в `golden_set.py` Cursor.
6. Text/mixed — брать рабочий путь Cursor.

Кратко: **каркас от Cursor, мозг и метрику — от EV2.**

## 6. Результаты бенчмарка (ngrok, 2026-06-27, выборка 10+10 чистых)

### 6.1. Выбор модели — победитель qwen3.6-35b

| Модель | latency/кейс | JSON-дисциплина | примечание |
|--------|-------------|-----------------|------------|
| **qwen/qwen3.6-35b-a3b** | **~3.0с** | **чистая** | прод; единственная пригодная |
| qwen/qwen3.6-27b | ~45с | плохая (CoT) | непригодна: игнорит «только JSON», спасается salvage'ем |
| google/gemma-4-26b-a4b | ~22с | плохая (CoT) | abstain=0.7; в 7 раз медленнее qwen35 |

**Вывод: qwen3.6-35b — единственная пригодная модель** для структурного восприятия.
Решают prompt-независимые факторы: скорость (3с против 22-45с) и дисциплина вывода
JSON. 27b и gemma уходят в chain-of-thought, медленны и почти всё отправляют в abstain.

**Находка о фолбэке:** `describe_image_local` при `invalid_json` делает фолбэк на
`qwen3.6-35b-a3b-mtp` (env `..._FALLBACK_MODEL`) → per-model бенчмарк контаминируется
чужой моделью. Для чистого сравнения нужен `allow_fallback=False`.

### 6.2. A/B промптов на qwen35 (verdict, K=2, 10+10) — precision/recall фронтир

| Конфигурация | false_reject ↓ | true_reject ↑ | abstain |
|--------------|---------------|---------------|---------|
| baseline-промпт | 0.4 | 0.2 | 0.4 |
| baseline + guard + переранжирование | 0.4 | 0.2 | 0.4 |
| **промпт C** + guard + переранжирование | **0.0** | 0.0 | 0.55 |

**Главный вывод: промпт — доминирующий рычаг.** Промпт C (presence-gate) **обнулил
false_reject** (главная опасность — удаление реальных замечаний — устранена), но и
recall упал до 0 (под C модель НИ РАЗУ не сказала «yes» — только accept/needs_human).
guard и переранжирование на этой выборке нейтральны (findings одно-блочные, «yes»
приходил с цитатами). Нужен **средний режим** (промпт B) для полезного recall при
низком false_reject. Выборка мала (n=20) → ставки шумные, нужна 50+50 для стабильности.

### 6.3. Корень нулевого recall — пустой контекст блока (ФИКС НАЙДЕН)

Диагностика (read-only, после переноса схемы EV2 в Cursor): на misread-замечаниях
модель отвечает «no» (подтверждает проблему), а не ловит ошибку. Причина — **верификатор
кормит модель ПУСТЫМ OCR**: per-block gemma JSON в v2-раскладке пуст (0/40 блоков).
Модель смотрит картинку «на глаз» и повторяет ту же ошибку чтения.

**Текст блока есть — но в другом месте:** `02_blocks_analysis.json`, поле `label`
заполнено у **40/40** блоков (описание чертежа от обогащения), `key_values_read`/`summary`
— реже. Фикс в EV2 `context.py` (`_blocks_analysis_text`): после него **40/40** блоков
имеют непустой контекст, у 14/40 он пересекается с текстом замечания.

**Это касается и порта Cursor** — его `_build_prompt` подаёт `{{GEMMA_TEXT}}` из того же
пустого источника. Cursor нужно тем же образом брать `label`(+`key_values_read`,`summary`)
из `02_blocks_analysis.json`. Замер прироста recall — на ngrok-окне.

### 6.4. Что осталось (требует ngrok-окна без Cursor)

- Промпт B (средняя точка) + больший сбалансированный набор (50+50) → стабильные ставки.
- Голосование по **возмущениям** (масштаб/несколько блоков), а не temp=0 ре-раны.
- Подача ПРАВИЛЬНОГО блока (где предмет) + high-res для много-блочных findings.
- Перенести фиксы/гигиену в гибрид (каркас Cursor + мозг EV2), см. §5.

## 7. Многоисточниковый верификатор (Фазы 0-6, 2026-06-27)

Построен поверх EV2: **норма + кросс-блок + зрение → детерминированное слияние**.

| Источник | Модуль | Офлайн | Закрывает |
|----------|--------|--------|-----------|
| Норм-база | `norm_check.py` | да | нормативные ~7/24 |
| Кросс-блок | `cross_block.py` + `table_extract.py` | да | инфо-в-другом-месте ~5/24 |
| Слияние | `fusion.py` (F1-F9) | да | инвариант: норма не reject'ит |
| Зрение | `verify.py:verify_finding_multi` + `_montage` | ngrok | визуальные |

**Главный инвариант доказан property-тестом:** при `visual=accept` любой норм-сигнал → результат ≠ reject. `reject` только из сильного визуала (с цитатой) или `xref_refutes`+согласный визуал.

**Офлайн-валидация (без нейросети):**
- Норм-путь: 23/40 норм = `not_in_index` (индекс из 565 неполон → soft_human), 1 replaced → accept-с-пометкой. **0 reject-хинтов.**
- Кросс-блок: на 30 absence-кейсах **14 `xref_refutes`** (нашёл «отсутствующее» в другом блоке) + 3 context_only.
- Multi offline (50 findings): `false_reject=0.0`, 48 needs_human + 2 accept (norm_flag), vision_saved=50/50.
- Тесты: **41/41** офлайн.

**Роутинг экономит vision:** норма заменена/отменена → accept-с-пометкой БЕЗ зрения; кросс-блок подтвердил → accept без зрения; зрение только для спорных графических.

**Осталось (ngrok-окно без Cursor):** полный multi-бенчмарк с визуалом (Фаза 4-5) — замерить recall по источникам и реальный false_reject. Порт в production — `PORT_SPEC_MULTISOURCE.md`.

**Честный потолок:** инженерные суждения (~6/24) не автоматизируются → needs_human. Норм-индекс неполон (~58% цитируемых норм отсутствуют) → норм-путь часто откладывает (безопасно).

### 7.1. Полный multi-бенчмарк с визуалом (ngrok, K=1, 30 кейсов)

`false_reject=0.0` ✅ (0 реальных замечаний удалено — инвариант на живом прогоне)
`abstain=0.633` · `accept=11` (9 визуал + 2 норм-флаг офлайн) · `conflict=1` · `vision_saved=2/30`
