# ГОСТ Р 21.101-2020 — СПДС, основные требования

**Полное название:** ГОСТ Р 21.101-2020 «Система проектной документации
для строительства. Основные требования к проектной и рабочей документации».

**Статус:** действующий национальный стандарт. Введён 2021-07-01. Заменил
**ГОСТ Р 21.1101-2013** (другой номер!).

## Зона ответственности

ГОСТ Р 21.101-2020 — общие требования к составу и оформлению как ПД,
так и РД. В отличие от ПП РФ 87, он применим **и к РД тоже**.

## Структура комплектов рабочей документации

ГОСТ Р 21.101-2020, раздел 4 — состав РД. **Ключевые подходы для нашего
completeness-валидатора:**

1. РД делится на **марки** (АР, КР/КЖ/КМ, ОВ, ВК, ЭОМ, СС и т.д.) — это
   первичная единица, которая может попасть в один PDF.
2. Каждая марка имеет свой состав по соответствующему ГОСТ СПДС:
   - АР → ГОСТ 21.501-2018
   - КЖ/КМ → ГОСТ 21.502-2016 (КМ), ГОСТ 21.501-2018 / СП 63.13330 (КЖ)
   - ЭОМ → ГОСТ 21.613-2014
   - ОВ → ГОСТ 21.602-2016
   - ВК → ГОСТ 21.601-2011
   - СС → ГОСТ 21.602-2016 (общие) + СП 484.1311500.2020
3. **«Состав комплекта»** ≠ «состав каждого тома». Один PDF может содержать
   ОДНУ марку или ОДИН том внутри марки.

## Применимость для разных document_type

| document_type | Что completeness-валидатор может требовать на основе ГОСТ Р 21.101-2020 |
|---|---|
| `full_rd` | **Состав конкретной марки.** Например, для марки ЭОМ — общие данные + поэтажные планы + однолинейные + кабельный журнал + спецификация (если это полный том ЭОМ, а не его часть). НО НЕ полный комплект ВСЕХ марок проекта. |
| `audit_comparison` | **Только формальные атрибуты документа.** Штамп, шифр, стадия, дата изменений, лист изменений. Состав марки требовать НЕЛЬЗЯ — аудит сравнения это другой жанр документа. |
| `tz_vs_rd` | Только соответствие пунктов РД пунктам ТЗ. Состав марки требовать ВЫБОРОЧНО — только если ТЗ упоминает конкретные документы. |
| `specification_only` | **Только спецификация.** Не требовать ПЗ, общих данных, схем, расчётов. |

## Раздел 5 ГОСТ Р 21.101-2020 — обозначения и штамп

| Атрибут | Требование |
|---|---|
| Основная надпись | По форме 3 / 4 / 6 (раздел 5) — содержит шифр, наименование, стадию, дату, подписи. |
| Стадия | П (ПД), Р (РД), Эс (эскизная), И (исходные данные). На РД ставится «Р». |
| Шифр документа | Структурированный (объект-стадия-марка-…), пример: `13АВ-РД-ЭМ-К3`. |

**Что completeness-валидатор может требовать:** наличие штампа со
стадией. Это reliable signal — отсутствие штампа в РД-PDF почти всегда
ошибка комплектности.

## Раздел 4 — отметки об изменениях

ГОСТ Р 21.101-2020, п. 4.7 — лист изменений. Обязателен при ревизии РД.

Применимость: для `audit_comparison` (исходный аудит должен ссылаться
на конкретный лист изменений) — это **единственный** mandatory item,
который валиден для audit_comparison.

## Что completeness-валидатор НЕ может требовать на основе только этого ГОСТа

1. **Конкретные расчёты** (это уровень дисциплинарных СП — СП 256, СП 60 и т.д.).
2. **Конкретные параметры на схемах** (то же).
3. **Сводный перечень всех марок проекта** — это атрибут комплекта в целом,
   а не одного PDF-тома, который мы видим в `projects/<...>/document.pdf`.
