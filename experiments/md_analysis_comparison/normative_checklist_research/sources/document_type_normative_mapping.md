# Document_type ↔ нормативная база — mapping для completeness lens

**Дата:** 2026-05-21
**Контекст:** в нашей системе `document_type_detector.py` различает 4
типа: `full_rd`, `audit_comparison`, `tz_vs_rd`, `specification_only`.
Каждый тип имеет свой набор применимых норм.

## Сводная таблица

| document_type | ПП РФ 87 | ГОСТ Р 21.101-2020 | Дисциплинарные СП | Дисциплинарные ГОСТ СПДС | СанПиН | ФЗ-123 + СП 1-12.13130 |
|---|---|---|---|---|---|---|
| `full_rd` (как РД-том) | НЕТ напрямую¹ | ДА | ДА | ДА | ДА | ДА |
| `full_rd` (как ПД-том) | ДА | ДА | ДА | НЕТ² | ДА | ДА |
| `audit_comparison` | НЕТ | Частично³ | НЕТ | НЕТ | НЕТ | НЕТ |
| `tz_vs_rd` | Условно⁴ | Частично | НЕТ | НЕТ | НЕТ | НЕТ |
| `specification_only` | НЕТ | Частично⁵ | НЕТ | Условно⁶ | НЕТ | НЕТ |

¹ ПП РФ 87 регулирует ПД. РД регулируется СПДС.
² СПДС применим к РД, не к ПД.
³ Только формальные атрибуты — штамп, шифр, стадия, лист изменений.
⁴ Только если ТЗ ссылается на ПП РФ 87.
⁵ Только в части оформления спецификации (раздел 5 ГОСТ Р 21.101-2020).
⁶ ГОСТ 21.110-2013 (спецификация) — да; чертёжные ГОСТы — нет.

## Что completeness-lens ИМЕЕТ ПРАВО считать missing finding'ом

### `full_rd`

Применимый чек: соответствующая марка СПДС-ГОСТ + дисциплинарный СП.
Например, для марки ЭМ (РД):

✅ Можно требовать (mandatory):

- Общие данные марки (ГОСТ 21.613-2014, п. 4)
- Однолинейная схема ВРУ/ГРЩ (ГОСТ 21.613-2014, п. 5.4)
- Кабельный журнал (ГОСТ 21.613-2014, п. 5.5)
- Спецификация (ГОСТ 21.110-2013)
- Расчётные параметры на кабелях/автоматах (СП 256, ГОСТ 31996)

✅ Можно требовать (conditionally_mandatory):

- АВР для I категории — **только если** упомянуто, что есть I категория
- Молниезащита — **только если** объект попадает под СО-153
- Расчёт КЗ — да, СП 256.1325800.2016 требует

❌ Нельзя автоматически требовать:

- Полный электробаланс — может быть в томе ПД, а не в этой марке
- Сводный перечень всех марок проекта — атрибут комплекта, не марки
- Программа испытаний — это часто отдельный документ (исполнительная)

### `audit_comparison`

Это документ-сравнение, обычно письмо «По разделу ЭОМ выявлены
расхождения: …». Это **НЕ** РД и **НЕ** ПД.

✅ Можно требовать:

- Указание шифра/наименования сравниваемого документа
- Указание стадии сравниваемого документа
- Дату сравнения
- Подпись/автора сравнения

❌ Категорически нельзя требовать:

- Принципиальных схем, расчётов, спецификаций — это другой жанр
- Coordination с другими разделами — out-of-scope сравнения
- Полного состава марки

### `tz_vs_rd`

Документ-соответствие требований ТЗ решениям в РД.

✅ Можно требовать:

- На каждое требование ТЗ — ссылка на соответствующий пункт РД
- Явная фиксация отклонений
- Согласование отклонений

❌ Нельзя требовать:

- Самих расчётов и схем — они в исходной РД, не в этом документе
- Полного состава марки

### `specification_only`

Документ-спецификация (часто Excel-выгрузка в виде PDF, или единый раздел
«Спецификация» из тома РД).

✅ Можно требовать:

- Структурированное содержимое (позиция, наименование, тип, кол-во, единицы)
- Соответствие ГОСТ 21.110-2013 по оформлению
- Указание ключевых параметров на каждой позиции (для ЭОМ — сечение
  кабеля; для ОВ — мощность вентустановки; и т.д.)

❌ Нельзя требовать:

- Пояснительной записки
- Расчётов
- Схем расположения / принципиальных
- Координации с другими разделами
- Программ испытаний

## Anti-pattern catalog (нормативно обоснованный)

| Pattern | Почему ошибка |
|---|---|
| Флаг «отсутствует пояснительная записка» в РД-марке | ПЗ — атрибут раздела ПД (ПП РФ 87 раздел 5), не дублируется в каждой марке РД |
| Флаг «отсутствует расчёт нагрузок» в марке ЭМ-К3 | Электробаланс — атрибут раздела ПД, в РД может быть только ссылка на ПД |
| Флаг «отсутствует ОДИ» в АР-марке | ОДИ — самостоятельный раздел ПД |
| Флаг «отсутствует ПБ-раздел» в инженерном томе | ПБ — самостоятельный раздел ПД |
| Флаг любой mandatory section в `audit_comparison` | Документ-сравнение out-of-scope для составной комплектности |
| Флаг расчётов в `specification_only` | Спецификация по определению не содержит расчётов |
| Флаг отсутствия раздела «N» без указания, что значит «отсутствует» | Может быть просто в другом томе/марке |

## Confidence levels для completeness findings — рекомендация

| Сценарий | Confidence |
|---|---|
| MD явно говорит «не разрабатывается» или «вне объёма» | drop, не finding |
| MD содержит явное противоречие норме («раздел отсутствует, хотя обязателен») | high → КРИТИЧЕСКОЕ |
| MD молчит об обязательном пункте, стадия известна | medium → ПРОВЕРИТЬ_ПО_СМЕЖНЫМ |
| MD молчит, стадия НЕ известна | low → drop или ПРОВЕРИТЬ_ПО_СМЕЖНЫМ с пояснением «стадия не определена» |
| Пункт рекомендованный, MD молчит | low → РЕКОМЕНДАТЕЛЬНОЕ или drop |
