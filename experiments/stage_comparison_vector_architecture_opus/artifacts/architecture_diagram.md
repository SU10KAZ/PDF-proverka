# Предлагаемая архитектура: где что живёт

## Текущая архитектура (Track A, v0.1)

```
PDF page
   │
   ├─ page.get_drawings()            ← в НЕповёрнутой системе координат
   └─ page.get_text(clip=block_rect) ← block_rect построен из page.rect (ПОВЁРНУТАЯ система)  ✗ O13
   │
   ▼
L0/L1  примитивы: raw + normalized сегменты, style, длина, угол
   │      нормировка АНИЗОТРОПНАЯ: x/w, y/h  ✗ O10
   │      кап 20 000 примитивов «самые длинные»  ✗ O11
   ▼
L2   topology (9 счётчиков)  ✗ движутся в 1.2–283 раза от одного допуска
     anchors (ближайший отрезок)  ✗ 20–186 равных кандидатов там, где confidence=high
     repeated_elements (хеш формы path)  ✗ 169 ложных «count changed» на 7 «тихих» парах
     dimensions/labels (regex по тексту)  ✗ теряют 36 % span'ов
   ▼
L3   compact payload → 73.9 % текста + 17.4 % хешей
   ▼
comparator: покрытие сегментов при tolerance, подобранном под расхождение кропов
   ▼
статус + список строк «Число примитивов: 11 → 7», «Текст/значение Согласовано → этажного»
```

Проблема не в отдельных полях. Проблема в том, что **между геометрией и выводом нет ни одного
уровня, на котором существует объект**. Поэтому единственная форма, в которой система умеет
говорить, — это счётчики анонимных примитивов.

## Что где решается — граница ответственности

| Решение | Кто | Почему |
|---|---|---|
| какой отрезок какому соответствует | **только детерминированно** | пространство назначений 10^9.85 на ss_plan_dense (84 439 × 84 298 сегментов) — это вопрос масштаба, а не политики |
| выравнивание двух блоков | **только детерминированно** | 4 параметра, замкнутая форма по якорям |
| точная геометрия, координаты, длины | **только вектор** | provenance обязателен |
| количество объектов семейства | **детерминированно**, если группировка стабильна | иначе → gate |
| значение размера | **вектор + самопроверка масштабом** | ошибка 0.01–0.52 % против стандартного масштаба |
| читается ли надпись | **вектор** (per-span readable + glyph hash) | Vision не нужен: 0.000 → 0.456…0.588 без модели |
| «это новый элемент или другой кроп?» | **детерминированно по странице** | 4 из 16 событий ss_table_graphic доказуемо артефакт кропа; 0 ложных на 7 тихих парах |
| «правильно ли описание передаёт чертёж» | **Vision verify**, по гейту | измеряется в ветке VV |
| «что означает этот незнакомый символ» | **Vision** | вектор не знает семантики |
| сборка нескольких evidence в одну инженерную фразу | **text LLM** | на L4, после гейтов |
| выбор пары блоков | **детерминированный shortlist + проверка** | coarse descriptor: recall 0.70, rank-1 19/20 |

## 1 → N и N → 1

Блок П может быть детализирован в несколько блоков РД. Архитектура это выдерживает, потому что
единица сопоставления — **объект и семейство**, а не блок:

```
   П-блок  ──┬─► object group A ─────────────► РД-блок 1  (object group A')
             ├─► object group B ─────────────► РД-блок 2  (object group B')
             └─► object group C ─┬──────────► РД-блок 3  (object group C'1)
                                 └──────────► РД-блок 4  (object group C'2)
```

Сопоставление ведётся по:
1. coarse descriptor блока → shortlist кандидатов;
2. пересечение **обозначений** (ВК/ОСПД/QF/ЩМкв…) — счётчики префиксов дали 0 ложных
   утверждений на 7 «тихих» парах и точный `Wh 0→4, QD 0→4, QF 0→4, ЩМкв 0→4` на паре с
   реальным изменением;
3. пересечение семейств и их кардинальностей;
4. геометрическая проверка выравнивания уже внутри отобранной пары.

Если группа объектов П находит соответствия в двух блоках РД, это фиксируется как
`split(1→N)`, а не как «удалено» + «добавлено». Именно поэтому кардинальность семейства обязана
быть отдельным полем: `2 обобщённые ветви → 4 явные` — это одно изменение, а не 6.
