# Общий `vector_path_graph` для СОВ и кабельных лотков

## Граница общего слоя

Общий слой работает только с геометрией и не знает, что такое СКУД или лоток:

1. разворачивает `page.get_drawings()` в отрезки с координатами, цветом, толщиной и
   ссылкой на исходный path;
2. фильтрует заливки, штриховки и мелкий CAD-шум;
3. объединяет близкие концы с масштабируемым допуском;
4. соединяет T-узел, если конец одного сегмента лежит внутри другого;
5. не соединяет простое пересечение X без конца/точки;
6. строит связные компоненты;
7. привязывает семантические якоря к компонентам.

Реализация: `backend/app/pipeline/stages/block_grounding/vector_path_graph.py`.

## Адаптер СОВ / `terminal_wiring`

Якорь — клеммный овал CAD. На пилоте детерминированно найдено:

- 222 CAD-полуовала объединены в 111 физических клемм;
- 88/111 клемм имеют локальную текстовую подпись;
- 107/111 клемм привязаны к родительскому компоненту;
- из 1057 чёрных отрезков после удаления внутренней геометрии приборов осталось 577;
- построено 17 внешних клеммных сетей;
- 5 сетей связывают разные компоненты: 3 подтверждённые пары и 2 многоклеммные
  сети, оставленные на проверке.

Семантические шаги `terminal → label` и `terminal → parent component` реализованы.
Родитель определяется сначала внешней оболочкой прибора, затем — ближайшей позиционной
подписью для простых символов без собственного quad-корпуса. Каждая уверенная связная
компонента превращается в ребро/сеть:

```text
STR-1AP-M.DOOR1 → КСПВПнг(А)-HF → УК-2П.3
```

Дополнительные правила:

- junction-dot подтверждает соединение пересекающихся проводов; без точки crossing
  не объединяется;
- линии целиком внутри корпуса не участвуют во внешней кабельной топологии;
- сеть ровно из двух клемм разных приборов получает `confirmed_pair`;
- сеть из трёх и более клемм получает `multi_terminal_review` и не разворачивается
  в попарные рёбра.

## Адаптер лотков / `tray_axonometry`

Якорь — текстовая выноска. На пилоте:

- 10 выносок распознаны;
- из них выходит 16 leader-линий (у двух групп гильз по четыре указателя);
- 16/16 целей связаны с цветной геометрией;
- синий path соответствует СБ, красный — СПЗ, пурпурный — гильзам.

Следующий шаг:

1. кластеризовать яркие paths по цвету и пространственной связности;
2. назначить каждому кластеру ID физического сегмента;
3. привязать выноску к кластеру через уже найденный leader target;
4. соединить верхний и нижний сегменты через пурпурную группу гильз;
5. сформировать рёбра `segment → sleeve_transition → segment`.

Пока связность сегментов имеет `visual_unverified`, но соответствие
`выноска → цветная геометрия` уже `present` с link rate 1.0.

## Разные адаптеры, один backbone

| Общий примитив | СОВ | Лотки |
| --- | --- | --- |
| Отрезок path | провод | грань/ось сегмента |
| Связная компонента | электрическая сеть | физический участок трассы |
| Текстовый якорь | подпись клеммы/компонента | выноска типоразмера |
| Графический якорь | клеммный овал, junction-dot | leader endpoint, цвет |
| Результат | `component.terminal → net → component.terminal` | `tray → sleeve → tray` |

Таким образом, общим должен быть только `vector_path_graph`; правила узлов и рёбер
остаются в `terminal_wiring` и `tray_axonometry`.

## Гейты готовности

СОВ уже имеет режим `confirmed_connections_only`. В нём выдаются только пары, для
которых path, родитель и подпись подтверждены. Перевод в полный граф возможен после:

- ≥90% внешних клемм имеют подпись и родительский компонент;
- каждая выдаваемая связь подтверждена одной внешней path-компонентой;
- crossing без junction-dot не создаёт ребро;
- кабельная марка привязана к сети либо честно `not_extracted`;
- многоклеммные сети разделены по проводникам или подтверждены как общая шина.

Лотки можно переводить из `inventory_only` после:

- callout link rate = 1.0 на корпусе;
- каждая выноска назначена одному физическому цветовому кластеру;
- переходы через гильзы подтверждены соприкосновением paths;
- неоднозначные слияния остаются `visual_unverified`, а не достраиваются по порядку.
