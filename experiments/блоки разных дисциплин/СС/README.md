# СС — детерминированный профиль графического слоя

СС нельзя обрабатывать одним геометрическим алгоритмом: три блока корпуса имеют три
разные грамматики. Реализован диспетчер `low_voltage_scheme` с отдельными подпрофилями.

## Результат

| Блок | Подпрофиль | Что извлечено | Готовность |
| --- | --- | --- | --- |
| `6W3K-9C4Y-VPY` | `aps_structural` | ПО → АЛС → этаж → 240 адресных точек | граф-иерархия готов |
| `4KGV-FMLW-7V9` | `tray_axonometry` | 8 лотков + 2 группы гильз | точный инвентарь, топология не подтверждена |
| `79PP-NE7C-VDH` | `terminal_wiring` | 111 клемм, 5 межкомпонентных сетей | 3 пары подтверждены, 2 сложные сети на проверке |

Все три типа классифицируются автоматически, без OCR и LLM.

## Визуальные эталоны структурной схемы СОВ

- `Структурная схема СОВ — К3-К6 — 6F7E-TCVU-KYW.pdf` — основной большой эталон,
  четыре корпуса; векторный crop по исходному полигону;
- `Структурная схема СОВ — К1-К2 — 6X4P-4EGH-VJ9.pdf` — второй точный эталон,
  два корпуса; векторный crop по прямоугольнику блока;
- `Аналог — Структурная схема СКУД — 9AJM-YHWM-CV9.pdf` — проверка общей
  геометрической грамматики на другом оформлении; не смешивать с прямым корпусом СОВ.

Все три PDF собраны из исходных страниц без растеризации: сохранены текстовый слой,
цветные paths и `page.get_drawings()`. Для блоков типа `polygon` к содержимому PDF
применён исходный clipping path, пересчитанный из `polygon_points` result.json.

## Фиксация Вектографа АПС на корпусе

Профиль проверен не только на пилоте, а на всех найденных локальных SS-блоках:

- 43/43 графа построены и прошли свой гейт;
- 16/16 `aps_structural` — полноценная этажная иерархия;
- 27/27 `aps_fragment` — адресный инвентарь/АЛС для планов, узлов и продолжений без
  собственной этажной оси;
- всего обработано 9628 адресных точек;
- слова ограничиваются `coords_norm`/полигоном блока, соседняя графика страницы в граф
  не попадает.

Поддержаны обе формы адресов:

- `9A2.144`, `10SC1.53...56`, `2SPM2.1..21`;
- `1BTH1.165(107)`: позиционный номер `165` и логический адрес `107` сохраняются
  раздельно; для непрерывности используется логический адрес.

## Алгоритм АПС — аналог Вектографа

1. Адрес является якорем узла. Поддерживаются `9A2.144`, `9BTM2.163`,
   `10SC1.53...56` и другие семейства.
2. Сам адрес задаёт шлейф:
   - `9A2.*` и `9BTM2.*` → `АЛС9.2`;
   - `9A1.*` и `9BTM1.*` → `АЛС9.1`;
   - `10A1.*` и `10SC1.*` → `АЛС10.1`.
3. Этаж определяется ближайшим Y-рядом. На пилоте найдены 26–30 этажи и кровля;
   привязано 240/240 адресных точек.
4. Тип устройства берётся по геометрии рядом с адресом (`МДУ-1С`, `АМ-4`, `ИЗ`,
   `ШУН/В`, `РМ-1С`): привязано 240/240.
5. Помещение определяется X-зоной заголовка `пом. №…`, дополнительные атрибуты —
   ближайшими подписями `ПД/ДУ/Вж/2ДППК/Д/BGB`.
6. Диапазоны `...` раскрываются в адресные слоты. Получено 305 слотов.
7. Результат — иерархия `ПО №7 → АЛС → этаж → устройство`, bbox каждого устройства,
   честные счётчики, warnings и гейт качества.

Если в блоке нет собственной этажной оси, он автоматически становится
`aps_fragment`: адреса и АЛС остаются точными, но этаж не придумывается.

Физический порядок прохождения красного шлейфа пока имеет состояние
`visual_unverified`: иерархия точна, но последовательность провода не выдумывается.

## Что найдено в исходной схеме АПС

- `АЛС9.1` → 26 этаж, 38 адресных точек;
- `АЛС9.2` → 27–30 этажи, 148 адресных точек;
- `АЛС10.1` → кровля, 54 адресные точки;
- адрес `9A2.181` подписан дважды — сохранён как `needs_review`;
- в видимом фрагменте `АЛС9.1` отсутствуют номера 181–196. Это не объявляется
  ошибкой: возможна граница листа, нужна кросс-листовая проверка.

## Лотки

Текстовый слой даёт точный инвентарь тип/система/размер/длина и параметры гильз.
Общий vector-path слой уже нашёл 10 выносок и 16 leader-линий; 16/16 целей привязаны
к правильной цветной геометрии (синий СБ, красный СПЗ, пурпурные гильзы). Осталось
кластеризовать цветные paths в физические сегменты и соединить верх/низ через гильзы.
До этого результат имеет режим `inventory_only`, а не ложный полный граф.

## Клеммная схема СОВ

CAD хранит каждую видимую клеммную окружность двумя полуовалами. Адаптер сначала
объединяет 222 полуформы в 111 физических клемм, затем назначает подпись и родительский
прибор. Внутренняя геометрия корпусов удаляется из внешнего кабельного графа: осталось
577 внешних отрезков из 1057 исходных.

На пилоте построено 17 клеммных сетей, из них 5 связывают разные компоненты:

- 3 сети имеют ровно две подписанные клеммы и выдаются как `confirmed_pair`;
- 2 сети содержат по четыре клеммы и сохраняются как `multi_terminal_review` без
  выдуманного попарного соединения;
- у всех 14 концов межкомпонентных сетей определены и прибор, и подпись клеммы;
- кабельная марка пока не назначается автоматически.

Гейт `confirmed_connections_only` разрешает использовать только три подтверждённые
пары. Полнота топологии остаётся `false`. Следующий слой — привязка кабельных выносок
к сетям и разделение двух многоклеммных групп.

Подробный контракт общего слоя и двух адаптеров — `VECTOR_PATH_GRAPH.md`.

## Воспроизведение

```bash
python "experiments/блоки разных дисциплин/СС/run_low_voltage.py"
python "experiments/блоки разных дисциплин/СС/benchmark_aps_corpus.py"
```

Результаты находятся в `low_voltage_out/`. Полный JSON включается флагом
`--include-json`. Реализация —
`backend/app/pipeline/stages/block_grounding/low_voltage_geometry.py`, регрессия —
`tests/test_low_voltage_geometry.py`. Сводка полного локального корпуса —
`low_voltage_out/aps_corpus_summary.json`.
