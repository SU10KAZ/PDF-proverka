Исследовательский пилот классического AuditManager

Назначение: проверить гипотезу, что управляемый поиск внутри полного комплекта,
доступ к деталям графики и явные расчёты возвращают пропущенные полезные находки.
Изменений производственного конвейера здесь нет. Разработка ведётся на main
согласно актуальному AGENTS.md; прежняя ветка A/B используется только как архив.

Постоянные данные:
/home/coder/auditmanager/corpus-audits/20261106_classic_investigation

sources/ — замороженные MD, PDF, blocks.json всех шести дисциплин; хеши совпадают
с исходным манифестом A/B. GRAPHIC заново растрируется из того же PDF; это не
исторические PNG. Текст PDF не извлекается. TEXT читается только из MD.
evaluation/ — отдельный архив 47 контрольных записей и 717 итоговых строк A/B.
717 строк не являются 717 подтверждёнными дефектами. Каталог evaluation не
передаётся моделям; нет доступа к файлам, MCP, сети или произвольным командам
через инструменты исследователя. Источники открывает контроллер по block_id.
runs/ — запросы, ответы, результаты инструментов, изображения, кандидаты,
отклонённые по структуре записи, операции, метрики и попытки транспорта.

Транспорт: подписочные Codex CLI gpt-6-astra и Claude CLI claude-sonnet-5-5,
medium. OpenRouter выключен. При временной ошибке — тот же запрос через 10 с;
ошибки авторизации/модели/исчерпания квоты не маскируются повтором.
Лимит каждого прохода: 24 шага, 6 действий/шаг, 600 с/запрос, 4 часа между
запросами (текущий запрос может завершиться позже). Один и тот же промпт и
набор инструментов. Это равные предельные бюджеты, не равные затраты токенов.
Значение cost_usd от подписочного runner не доказывает долларовую стоимость.

Запуск после подготовки:
python experiments/classic_investigator/investigate.py run --discipline ITP --provider codex
python experiments/classic_investigator/investigate.py run --discipline ITP --provider sonnet
Аналогично EOM. Повторный запуск существующего каталога запрещён: сохранять
старый результат и явно готовить новый эксперимент, а не затирать историю.
Остановка: создать STOP_REQUESTED.json в постоянной папке. Она проверяется
между запросами и перед повторными попытками, не прерывает текущий CLI-вызов.

Границы текущего этапа:
- Доступен один предоставленный документ проекта со всеми его блоками;
  смежные шифры ещё не добавлены. Это не полный обход всех файлов объекта.
- Находки имеют статус candidate/question, не автоматически verified.
- Проверка source_ids доказывает только доступность источника, не истинность
  тезиса и не полноту прочтения. Расчёт подтверждает арифметику, но не выбор
  операндов/единиц/режима. Выполненность операций пока самоотчёт модели,
  дополненный журналом реальных действий.
- Все промежуточные кандидаты сохраняются; отбрасывание по структуре также
  записывается. Семантическое объединение с классикой ещё не выполняется.
- Исходные сырые A/B-логи в /tmp утрачены; сохранённый архив итоговых строк
  нельзя выдавать за полное восстановление исходных прогонов.
- Известные проекты — DEV-known. Независимый запуск без подсказок истории
  не превращает их в новые слепые контрольные проекты.
- Свежего прогона исправленного классического варианта C здесь ещё нет.
  Сравнение с архивом A/B описательное, не доказательство причинного эффекта.

watch.py наблюдает уже запущенные четыре прохода, обновляет Статус_пилота.html
и очередь проверки каждые 30 секунд. Он автоматически восстанавливает только
сбой claude_json_not_found. Новых проектов/моделей сам не запускает.

Реестр потерь и изменения формулировок:
accounting.py сохраняет все различные предложения из промежуточных ответов,
включая отвергнутые по структуре, и связывает их с итогами и перепроверкой.
Одинаковый ID с другой формулировкой не считается доказанным сохранением смысла.
Отсутствие в итоге не считается техническим опровержением. Решения первичной
проверки имеют ссылки и SHA256 исходных изображений/MD; изменение свидетельства
останавливает применение решения. Обновляемый отчёт: Проверка_пилота.html.

Обязательные вычислимые операции:
run_operations.py исполняет прежний проверенный сканер candidateC на всех шести
замороженных MD. Источник md_operations.py — прежняя экспериментальная ветка;
правила не подстроены под новые ответы. Сканер не вызывает модели и не меняет
production. Сохраняет каждую выполненную операцию и случаи not_checked.
19 расхождений скоростей ИТП объединяются в один вопрос о методике с19 атомами,
а не объявляются19 дефектами. Пустое количество ВК — вопрос, не ноль/недопоставка.
Нулевой результат для остальных дисциплин означает узкую область сканера,
а не отсутствие дефектов или полный охват расчётов.

python experiments/classic_investigator/run_operations.py --work /home/coder/auditmanager/corpus-audits/20261106_classic_investigation

Свежий контроль классического метода:
prepare_classic.py копирует исходную подготовку тех же шести версий без прежних
замечаний/обратной связи. Растрируются только IMAGE-блоки; размеры изображений
возвращаются к исходным размерам кропов. Байтовая идентичность утраченным PNG
не заявляется. check_classic.py проверяет все хеши, исходные MD/PDF, состав
графических блоков и действующие контракты контекста и кропов. --normalize
разрешён только до появления результатов аудита. Подготовка не запускает модели.

В main перенесены два ранее проверенных исправления, без выпуска портала:
5788bdf7 — реальные TEXT-ссылки сохраняются структурным проверяющим (29 тестов);
b4679094 — расчёт размера требует явных единиц длины (8 тестов).
Детерминированные вопросы нового сканера пока остаются экспериментальными.
Контроль должен запускаться с явно замороженной таблицей моделей Codex-only;
обычные настройки по умолчанию содержат Claude и использоваться не должны.

classic_control.py запускает новый контроль classic_fixed_codex_only:
графика Astra + 6-sol, судья 6.1-sol; текст 6.1-sol; свод 6-sol; проверка
отсутствия 6.1-sol. Все вызовы medium, подписочный Codex, инструменты отключены.
Таблица моделей, исходники и код замораживаются командой freeze перед run.
Каждая попытка сохраняет запрос, изображения по хешам, ответ и расход.
Временные ошибки повторяются через 10 секунд. Незапланированные модели и
подпроцессы запрещены; STOP_REQUESTED.json останавливает новые вызовы.
Сохраняются отдельные версии замечаний после свода и после проверки.
Это контроль с двумя исправлениями классического метода, не исторический A/B
и не полный продуктовый аудит норм/оптимизаций. Завершение требует оценки качества.
