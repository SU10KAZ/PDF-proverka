# Контролируемые контрфакты на реальных подготовленных блоках

Дополнение к `BRIEF.md`. Читать вместе с ним.

## Зачем

Размеченных вручную трудных пар будет 20–30 — этого достаточно, чтобы поймать режимы отказа,
но НЕ достаточно, чтобы измерить recall локальных изменений, false-positive rate и порог
чувствительности: доверительные интервалы на n=25 бесполезны.

Контрфакт даёт **точную ground truth без разметки**: мы берём РЕАЛЬНЫЙ подготовленный
графический блок и детерминированно портим одну вещь, зная в точности, что именно изменилось.
Тогда:

- **recall** = поймал ли компаратор ровно то, что мы подменили;
- **false positive rate** = что ещё он «нашёл» кроме подмены;
- **порог чувствительности** = при каком размере подмены он перестаёт её видеть.

Оба источника обязательны и не заменяют друг друга:

| источник | что даёт | чего не даёт |
|---|---|---|
| реальные трудные пары (`mine`, `pd`) | внешняя валидность: так ломается реальный CAD | точной ground truth, статистики |
| контрфакты | точная ground truth, большие n, кривые чувствительности | внешней валидности: мы портим так, как придумали сами |

**В отчёте эти два источника ВСЕГДА разделены.** Ни одно итоговое утверждение не опирается
только на контрфакты. Число из контрфакта помечается `[CF]`, из реальной пары — `[REAL]`.

## Класс A. Перезапись представления — графика ТА ЖЕ, упаковка другая (§4, §11)

Ожидаемый вердикт всегда: **NO_GRAPHIC_CHANGE**. Любая находка здесь — ложная.

Применяется к геометрии, извлечённой из реального блока (это честная симуляция того, что
делает другой CAD-экспортёр — подтверждено реальным случаем OBJ‑10: тот же маркер 30
сегментов в v001 и 11 в v002):

| id | перезапись | что проверяет |
|---|---|---|
| `A1_path_split` | каждый path разбивается на отдельные односегментные пути | «один path П → 12 отдельных lines РД» |
| `A2_path_merge` | соседние сегменты одного пути сливаются в полилинию | обратное к A1 |
| `A3_curve_resample` | каждая кривая пересэмплируется другой плотностью хорд (24 → 5 и 5 → 24) | «circle как circle» ↔ «circle как 4 Bezier» |
| `A4_circle_to_bezier` | окружность заменяется на 4 кубические кривые и наоборот | ровно случай из §4 брифа |
| `A5_order_shuffle` | порядок операций рисования переставляется (детерминированный seed) | зависимость от порядка |
| `A6_round` | координаты округляются до 0.01 / 0.1 / 0.25 / 0.5 pt | устойчивость к округлению CAD (P9: 0.24 pt рвал символ на 3 мотива) |
| `A7_reexport` | страница прогоняется через `gs -sDEVICE=pdfwrite` и `pdftocairo -pdf` | настоящая перезапись PDF (измерено: cairo меняет 89 590 → 86 332 сегмента при том же изображении) |
| `A8_lineweight` | толщина/цвет обводки меняются в пределах одного стиля | стиль не должен создавать объектов |

## Класс B. Изменение целого блока — НЕ изменение проекта (§13 A)

Ожидаемый вердикт: **NO_GRAPHIC_CHANGE** (или `BLOCK_TRANSFORMED`, но не изменение объектов).

| id | перезапись | что проверяет |
|---|---|---|
| `B1_translate` | весь блок сдвинут на δ (0.5 %, 2 %, 10 % диагонали) | «блок сдвинулся» |
| `B2_scale` | весь блок отмасштабирован (0.95 / 1.05 / 1.2) | «блок отмасштабирован» |
| `B3_crop_jitter` | bbox блока дрожит на 0.25 / 0.5 / 2 / 5 / 10 % | кроп-дрожание (v0.1 разваливался на 0.5 %) |
| `B4_aspect` | bbox меняет пропорцию на 5 / 14 % | анизотропия нормировки |
| `B5_rotate_page` | страница помечается /Rotate 90 / 270 | путаница систем координат |

## Класс C. Настоящее изменение ОДНОГО объекта (§5, §10, §12, §13 B)

Ожидаемый вердикт: **GRAPHIC_CHANGE**, и — что важнее — ledger обязан указать **ровно тот
объект**, который мы тронули, и не более 1–2 лишних.

Объект берётся из object layer самого блока (реальный сгруппированный объект, не выдуманный).

| id | подмена | ожидаемая запись ledger |
|---|---|---|
| `C1_remove_object` | удалить все примитивы одного объекта | `REMOVED_OBJECT` |
| `C2_add_object` | продублировать объект в свободное место блока | `ADDED_OBJECT` |
| `C3_move_object` | сдвинуть один объект на δ (0.25 / 0.5 / 1 / 2 / 5 % диагонали блока) | `MOVED_OBJECT` |
| `C4_swap_objects` | поменять местами два одинаковых по счёту объекта | **счётчики не меняются** — §12 |
| `C5_swap_unlike` | поменять местами два РАЗНЫХ объекта | конфигурация изменилась при том же числе примитивов |
| `C6_reshape_object` | изменить форму объекта, сохранив число примитивов | §12: counts равны, графика другая |
| `C7_split_object` | разорвать один объект на две части | boundary churn (§5) |
| `C8_merge_objects` | соединить два соседних объекта линией | boundary churn |
| `C9_add_branch` | добавить одну ветвь к линейной сети | «добавлены два ответвления» (§24) |
| `C10_remove_opening` | удалить проём в стене (разрыв в линейном контуре закрыть) | «удалён проём» (§24) |

**Кривая чувствительности:** C1/C2/C3 прогоняются на блоках трёх размеров плотности
(разреженный < 500 сегментов, средний 500–5 000, плотный > 5 000) и с объектами трёх
размеров (доля площади блока < 0.1 %, 0.1–1 %, > 1 %). Нужна таблица «при какой доле
блока изменение перестаёт быть видимым» — это прямой ответ на §10.

## Класс D. Негативные контроли: текст и таблицы (§16, §17)

Ожидаемый вердикт: **NO_GRAPHIC_CHANGE** во всех случаях. Это обязательная защита от дублей
с уже существующим текстовым pipeline. Любое срабатывание здесь — прямой провал.

| id | подмена | почему это НЕ графика |
|---|---|---|
| `D1_text_edit` | изменить содержимое текстовых строк, геометрию не трогать | текстовый pipeline |
| `D2_text_move` | сдвинуть подпись, не трогая объект | подпись — не объект |
| `D3_label_rename` | `QF1 → QF2` во всех вхождениях | §1 брифа прямо: это НЕ graphic change |
| `D4_table_values` | изменить числа в ячейках таблицы, сетку не трогать | табличный pipeline |
| `D5_table_row_text` | заменить текст целой строки таблицы | табличный pipeline |
| `D6_dim_value_only` | изменить только ЧИСЛО размера (1500 → 1600), размерную линию не трогать | §17: TEXT CHANGE ONLY |
| `D7_dim_geometry` | перебить размерную цепочку (1500 → 300 + 1000 + 200), числа согласовать | §17: **это GRAPHIC CHANGE**, ожидается срабатывание |
| `D8_font_swap` | заменить шрифт при той же строке | не графика |
| `D9_text_to_curves` | текст переведён в кривые (реальный случай в корпусе) | контурам букв нельзя становиться объектами |

`D7` — единственный в классе D, где ожидается GRAPHIC_CHANGE. Он специально стоит рядом с
`D6`, чтобы поймать систему, которая «видит» размерную цепочку только через число.

`D9` критичен: в корпусе есть реальные листы, где весь текст выведен кривыми
(`fmc_eom_text_as_paths`: 0 текстовых спанов, 92 135 команд `c`). Если контуры букв
становятся графическими объектами — object layer выдаст сотни ложных изменений на любой
правке текста.

## Правила исполнения

1. Контрфакт применяется к геометрии РЕАЛЬНОГО подготовленного блока, прочитанного
   через `probes/v03_foundation.py`. Синтетических блоков «с нуля» не бывает.
2. Каждый контрфакт детерминирован: фиксированный seed, записанный в артефакт.
3. Каждый контрфакт сохраняет **точный манифест** того, что тронуто: id объекта, его bbox,
   список изменённых примитивов, δ. Без манифеста измерение recall невозможно.
4. Каждый класс прогоняется минимум на **15 разных реальных блоках из ≥5 дисциплин**,
   иначе число не публикуется.
5. Визуальная проверка: для минимум 3 контрфактов каждого класса отрендерить «до» и «после»
   и посмотреть глазами, что подмена сделала то, что задумано. Контрфакт, который на
   картинке выглядит не так, как описан, — брак, и его нельзя использовать.
6. Результат — `artifacts/cf_manifest.json` (что подменили) и `artifacts/cf_results.json`
   (что нашёл компаратор), плюс матрица recall / FP по классам.
