# CNS · правила детерминированной таксономии подготовленного графического блока

Единица — реальный блок `block_type == "image"` из `result.json`, прочитанный
**только** через `probes/v03_foundation.py`. Синтетических bbox нет.
Код правил: `probes/cns_rules.py` (`classify_v1` — замороженная версия, `classify` — v2).
Признаки: `probes/cns_features.py` → `artifacts/cns_features.jsonl` (43 261 строка, 0 ошибок).

## 1. Из чего считаются признаки

Всё — из `extract_block()` (сегменты в display-точках PDF, уже без «невидимой краски»,
`/Rotate` учтён), плюс рамка блока `clip_display`.

| признак | как считается |
|---|---|
| `n_seg`, `n_text`, `n_images`, `n_curves` | из `BlockExtract` (краска / печатные строки / растровые вставки / кривые Безье) |
| `share_axis` | доля сегментов, у которых \|dx\|≤0.35 pt или \|dy\|≤0.35 pt |
| `n_rule_h` / `n_rule_v` | горизонтальные (вертикальные) сегменты кластеризуются по постоянной координате с допуском 1 pt; кластер считается «линейкой», если объединённая длина его интервалов ≥ 0.5 ширины (высоты) блока |
| `len_share_on_rulings` | доля суммарной длины краски, лежащей на этих линейках (±1 pt) |
| `rule_h_span` / `rule_v_span` | размах линеек по перпендикулярной оси в долях блока |
| `text_area_share` | Σ площадей bbox текстовых строк / площадь блока |
| `ink_density` | суммарная длина краски / площадь блока (pt⁻¹) |
| `raster_coverage` | доля блока, покрытая самой большой растровой вставкой |
| `seg_per_text` | `n_seg / max(1, n_text)` |
| `page_text_lines` | число текстовых строк на **всей** странице PDF (`cns_curvetext.py`) |
| `geom_sha` | sha1 отсортированного множества всех сегментов, нормированных изотропно (деление на длинную сторону блока, сдвиг к началу clip), округление 3 знака |

## 2. Правила v2 (первое совпадение выигрывает)

| # | класс | условие |
|---|---|---|
| R1 | `empty` | `n_seg==0 и n_text==0 и n_images==0` |
| R2 | `stamp` | `category_code == "stamp"` (метка upstream) |
| R3 | `raster` | `raster_only`, либо `raster_coverage ≥ 0.50 и n_seg ≤ 200` |
| R4 | `curved_text` | `n_text==0 и n_curves ≥ 20 и page_text_lines ≤ 5` |
| R6 | `vector_raster_mix` | `raster_coverage ≥ 0.15` |
| R7 | `table` | `len_share_on_rulings ≥ 0.55 и text_area_share ≥ 0.09 и n_text ≥ 8 и share_axis ≥ 0.85` |
| R8 | `legend_notes` | `n_text ≥ 5 и seg_per_text ≤ 6 и text_area_share ≥ 0.08 и ink_density ≤ 0.030 и len_share_on_rulings < 0.50` |
| R9 | `drawing` | всё остальное с вектор-слоем |

Правила детерминированы: одинаковый вход → одинаковый класс, случайности нет.

Три набора, размеченные глазами по рендеру `v03_foundation.render_block`
(контакт-листы `artifacts/cns_renders/*.png`, метки — `cns_eye_labels_{R,H,T}.json`):

| набор | что это | n | v1 (заморожена) | v2 |
|---|---|---|---|---|
| DEV `R` | случайная выборка со стратификацией по дисциплинам, seed 424242 — **на ней подбирались пороги** | 64 | 0.984 | 0.984 |
| HOLDOUT `H` | свежая случайная выборка, seed 990011, пороги уже заморожены | 39 | **0.949** | **0.949** |
| TARGET `T` | стратификация по *предсказанному* классу — точность (precision) редких классов | 30 | 0.733 | **0.967** |

Итого просмотрено глазами **133 блока**. Числа: `artifacts/cns_rule_accuracy.json`.

## 4. Что было опровергнуто на T и что изменено в v2

1. **Геометрический запасной детектор штампа (R5 в v1) — precision 0/4.**
   Он срабатывал на широких разлинованных **таблицах** (экспликация помещений,
   ведомость деталей), а не на пропущенных штампах. Удалён: штамп берётся только
   из `category_code`. Потери recall нет — в корпусе R5 после удаления не сработал бы
   ни на одном блоке, у которого `category_code` пуст и который глазами оказался штампом
   (в 103 случайных блоках DEV+HOLDOUT все 40 штампов имели `category_code=="stamp"`,
   пропущенных штампов 0).
2. **«Текст выведен кривыми» (`n_text==0 и n_curves≥20`) — precision 1/4.**
   Три из четырёх блоков — обычные чертежи узлов, где текста нет вовсе, а кривые —
   это дуги крюков и лотков. Разделяет их страничный признак: у настоящего
   «контурного» блока на ВСЕЙ странице PDF было 2 текстовые строки, у ложных — 44/95/95.
   В v2 добавлено `page_text_lines ≤ 5`: по корпусу класс сжимается
   **411 → 33 блока** (1.0 % → 0.076 %).
3. **`share_axis` в правиле таблицы снижен 0.90 → 0.85**, иначе таблица условных
   обозначений с парой наклонных выносок уходила в `drawing`.

## 5. Где правила заведомо не держат (известные конфузии)

- `vector_raster_mix` — определение чисто механическое («в блоке есть растр ≥15 %»).
  Глазами такой блок иногда читается как чертёж с растровой штриховкой
  (R53, H14 — 2 ошибки из 103 случайных). Это спор об определении, а не сбой измерения.
- `legend_notes` ловит «текстово-доминантный блок» (легенда, примечания, экспликация,
  текстовая часть техлиста). Если рядом с легендой в том же блоке лежит фрагмент плана
  (H35: 3 625 сегментов), правило отдаёт `drawing`.
- Класс присваивается блоку целиком. Лист, где в одном блоке и схемы, и таблицы, и
  примечания (H04), получает один ярлык — сегментации внутри блока здесь нет.
