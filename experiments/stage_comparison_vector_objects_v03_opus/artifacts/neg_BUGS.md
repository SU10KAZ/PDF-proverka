# Дефекты, найденные зондом `neg` в общих модулях трека

Зафиксировано, но **не исправлено молча** — от этих модулей зависят соседние зонды.

## BUG‑1. `v03_objects._dash_runs` падает на сегменте нулевой длины

```
File "probes/v03_objects.py", line 331, in _dash_runs
    ux, uy = dx / L, dy / L
ZeroDivisionError: float division by zero
```

`_dash_runs` делит на `s["len"]` без защиты; второе такое же деление — строка 350.

**Когда стреляет.** Не при чтении реального блока: `v03_foundation.extract_block`
явно отбрасывает вырожденные сегменты (`if length <= 1e-6: return`, строка 649),
поэтому корпусные экстракты защищены. Стреляет на ЛЮБОМ преобразованном экстракте,
где сегмент может схлопнуться, — а `v03_counterfactual._mk_seg` (строка 94) такой
защиты не имеет: `len` считается как есть, нулевая длина проходит.

**Наблюдалось.** 14 из 52 применений контрфакта `NR3_row_delete_shift`
(`neg_n2_table.json → skips`, причина `CMP float division by zero`); каждое —
потерянный инстанс измерения. Воспроизведение:

```python
pb = grp_common.prepared_block("13АВ-РД-АР1.2-К5", "v004",
                               "blk_ede531d29f3d48bc98ae16f81ef82652")
ex  = grp_common.extract(pb)
ex2, _ = neg_tablecf.apply(ex, "NR3_row_delete_shift", "k", shift=True)
v03_objects.build_objects(ex2)     # ZeroDivisionError
```

**Кого затрагивает.** Прогон зонда `cf` этого не поймал (`cf_run.log`: 0 ошибок,
`n_errors = 0`) — значит числа `cf` НЕ затронуты. Затронут любой будущий зонд,
который двигает один конец сегмента (перекомпоновка, растяжение, привязка).

**Правка (не внесена):** `L = s["len"]` → `if L <= 1e-12: continue` перед делением
в обоих местах, и та же проверка в `_mk_seg`.

## BUG‑2. `neg_dim.DEFAULTS["run_min_S"] = 6.0` завышен вдвое (мой собственный)

Порог «размерная линия длинная» стоял на `6·S` без замера. У 12 из 25 носителей
контрфакта D7 размерная линия короче `6·S`, и канал цепочек не мог сработать по
построению — первый прогон `neg_n4_dims.json` дал `n_retiled` fire = 0.200 именно
поэтому, а не потому, что канал плох. Свип (`neg_n4b_dimsweep.json`) показывает:
при `run_min_S ≤ 3.0` recall на D7 = 1.000 при неизменных 0.000 ложных на D6.

В отчёт идут числа свипа. `neg_n4_dims.json` сохранён как есть и помечен устаревшим
по этому пункту; его числа по каналу краски (D6 0.000 / D7 0.000 при production-пороге)
дефектом не затронуты и остаются в силе.
