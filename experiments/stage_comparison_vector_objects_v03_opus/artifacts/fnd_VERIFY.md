# Состязательная проверка зонда `fnd` (модуль основания VECTOR 0.3)

Оппонент. Ничего не строил и не правил: `probes/v03_foundation.py` **не изменён**.
Вся проверка сделана независимым кодом (`probes/vfy_*.py`), который **не импортирует**
`v03_foundation` нигде, кроме двух мест, где предметом измерения является сам модуль
(`vfy_f4_render.py`, `vfy_repro_gate.py`).

**Главный результат: основание держит координаты и рвётся на геометрии.** Формула
`coords_px → clip`, `/Rotate` и `derotation_matrix` воспроизводятся до 1e-4 pt. Но
`extract_block()` молча выбрасывает **все чисто горизонтальные и вертикальные пути**
(45 % путей страницы) из-за `fitz.Rect.intersects()` на вырожденном прямоугольнике.
Медианный блок теряет **35.6 % суммарной длины штриха**; 28.6 % блоков — больше половины;
3.4 % блоков модуль объявляет пустыми, когда геометрия есть.
Ни одна метрика `fnd` этого увидеть не могла: все они измеряют **точность** (легли ли
сегменты на краску), ни одна — **полноту** (объяснена ли краска сегментами).

## NEW-1. Дефект гейта путей — минимальное воспроизведение

`probes/v03_foundation.py`, `extract_block()`:

```python
for path_index, dwg in enumerate(drawings):
    r = dwg.get("rect")
    if r is not None and not fitz.Rect(r).intersects(read_rect):   # <-- ЗДЕСЬ
        paths_outside_clip += 1
        invisible_by_rule["outside_clip"] = ...
        continue
```

и то же самое в `ink_verdict()`:

```python
if clip_page is not None and not rr.intersects(clip_page):
    return "outside_clip"
```

PyMuPDF 1.27.2:

```python
def intersects(self, x):
    rect2 = Rect(x)
    return (1 and not self.is_empty and not self.is_infinite
              and not rect2.is_empty and not rect2.is_infinite
              and self.x0 < rect2.x1 and rect2.x0 < self.x1
              and self.y0 < rect2.y1 and rect2.y0 < self.y1)
```

`Rect.is_empty` истинно при `x0 >= x1` **или** `y0 >= y1`. У горизонтальной линии
`rect = (10, 50, 200, 50)` — высота 0 — `is_empty == True`.

```python
>>> fitz.Rect(0,0,300,300).intersects(fitz.Rect(10,50,200,50))
False          # линия лежит ВНУТРИ клипа
```

Именно это и печатает `python probes/vfy_repro_gate.py`:

```
rect of a horizontal line : Rect(10.0, 50.0, 200.0, 50.0) is_empty = True
clip.intersects(line rect): False   <- v03_foundation gates on this
truth: the line is inside the clip
```

### Предлагаемый патч (текстом, файл я не трогал)

```python
def _overlaps(r: fitz.Rect, box: fitz.Rect, eps: float = 1e-6) -> bool:
    """intersects(), но без ложного False на вырожденных (line) прямоугольниках."""
    return (r.x0 <= box.x1 + eps and box.x0 <= r.x1 + eps
            and r.y0 <= box.y1 + eps and box.y0 <= r.y1 + eps)
```

и заменить обе проверки:

```python
-    if r is not None and not fitz.Rect(r).intersects(read_rect):
+    if r is not None and not _overlaps(fitz.Rect(r), read_rect):
```

```python
-        if clip_page is not None and not rr.intersects(clip_page):
+        if clip_page is not None and not _overlaps(rr, clip_page):
             return "outside_clip"
```

Побочный эффект: `paths_outside_clip` перестанет быть 90 % (в отчёте `fnd` —
6 479 656 из 7 198 165) и станет честной оценкой отсечения по площади; строка
«производительность: 90 % путей отбрасывается» из `Gaps` теряет силу примерно вдвое.

**Что после патча надо перемерить:** F5 целиком (пригодность, гистограмма сегментов),
F2 (доли считались от неполного знаменателя), любые числа `fnd`, где фигурирует

## Как измерялась полнота (метрика, которой у `fnd` не было)

## Прочие замечания к модулю (без числа, но воспроизводимо)

1. **`render_block(production_clip=True)` игнорирует переданный `frame`** — считает clip
   заново из `coords_px` (строки после `if frame is not None and production_clip:`).
   Это верно относительно прода (он тоже не клампит), но означает, что при
   `frame.clamped == True` пиксели и `frame.clip_display` описывают **разные** регионы.
   Сейчас безвредно: блоков вне страницы 0.
2. **`ink_verdict` пропускает пути без краски вовсе**: при `fill is None and color is None`
   ветка `zero_opacity` не срабатывает (`fo_zero or so_zero` ложно) и путь считается
   видимым. В корпусе `zero_opacity` не сработал ни разу, так что цена нулевая, но
   логика ветки не соответствует комментарию.
3. **`ink_verdict` пропускает «белая заливка + невидимая обводка»**: при `fill` белом и
   `stroke_opacity == 0` с тёмным `color` ни одно правило не срабатывает. Ошибка в
   безопасную сторону (лишний невидимый путь остаётся).
4. **`_DRAW_CACHE` не ограничен**: `get_drawings()` целой страницы (до 889 000 путей)
   держится до `clear_caches()`. При полнокорпусном проходе это единственный реальный
   риск по памяти.

## Gaps / not measured

* **Полнота — верхняя оценка.** Сегменты представляют только контур; внутренность
  заливок и штриховок засчитывается как «необъяснённая». Поэтому абсолютные
  `unexplained` завышены у обеих ветвей; сравнимы только их отношения.
* **F3″ (контроль с подменённым aspect) не перепроверялся** — это собственное
  самоопровержение `fnd`, оно работает против них, а не за.
* **rot90 в выборках мал** (25 блоков в F1, 6 в F7) — в корпусе всего 439 image-блоков
  на `/Rotate 90` и лишь 32 из них имеют сохранённый PNG.
* **Причина расхождения облачных кропов на rot270 не установлена**: это может быть и
  дефект облачного кропера, и устаревшие PNG от прежней версии `result.json`.
* **П↔РД не трогал** — как и `fnd`, все пары кросс-ревизионные.
* **Дефект гейта не «прокатан» по всем числам `fnd`**: я показал размер потери, но не
  пересчитал за них F5/F2 на исправленном экстракторе.
* **Память/время полнокорпусного прохода** не измерялись, только максимум сегментов
  на блок (817 732).
