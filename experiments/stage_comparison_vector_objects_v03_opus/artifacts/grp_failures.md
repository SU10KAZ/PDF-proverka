# G3 — каталог режимов отказа слоя объектов (с картинками)

16 случаев: 8 худших **реальных** кросс‑ревизионных пар по доле краски, оставшейся в
отношении 1:1, и 8 худших **контрфактов** класса A. Оверлеи: границы и краска объектов
поверх production‑идентичного кропа (цвет объекта выведен из его `object_id`; красная
рамка — объект, чья граница на другой стороне не сохранилась). Индекс —
`grp_overlay_index.json`, картинки — `grp_overlays/`.

Смотрел глазами один наблюдатель (этот зонд). Причины названы по картинке, а не выведены
из метрики.

## Что каталог говорит про приоритеты

1. **F1 лечится и вылечен в измерении.** Общий S (max от двух сторон) на 19 парах
   поднимает медиану 1:1 с 0.937 до 0.988, худшую пару — с 0.150 до 1.000; ухудшившихся
   пар нет (`grp_shared_scale.json`). Это единственная из восьми причин, для которой
   найдено полное исправление.
2. **F2/F3/F5 — одна и та же болезнь**: краска, у которой нет объектной семантики
   (штриховка, сетка, узор заливки), составляет большую часть сегментов плотного блока и
   не имеет устойчивого разбиения в принципе. Ни один из девяти параметров свипа G5 её не
   лечит: медиана churn держится в коридоре 0.901–0.946 при любых значениях. Вывод не
   «подобрать порог», а «эту краску нельзя пускать в объектный слой как объекты» — при этом
   generic background‑фильтр брифом запрещён, значит нужен явный, доказуемый детектор
   регулярного заполнения (не сделан, см. Gaps).
3. **F4 — переключатель, а не шум**: он даёт ровно те «±1 объект», которые ledger покажет
   как добавление/удаление. Его нельзя усреднить, его нужно распознавать (размерная
   цепочка — отдельный тип связи, а не член объекта).
4. **F7 обязан быть отдельным вердиктом** (`BLOCK_SCOPE_CHANGED`), иначе слой объектов
   выдаёт 214 «добавленных объектов» на пустом месте.
