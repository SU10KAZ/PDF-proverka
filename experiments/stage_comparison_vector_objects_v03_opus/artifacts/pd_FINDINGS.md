## Что это значит для трека

1. **Все выводы v0.2 о «кросс‑стадийности» так и остаются кросс‑ревизионными**, и v0.3 этого исправить
   не может: пар П↔РД в корпусе физически нет. Требование §21 (разбиение 1→N при переходе П→РД)
   на этих данных **не проверяемо**.
2. Прежде чем строить что‑либо «для сравнения стадий», нужен **вход**: либо PDF объекта 213
   (тогда есть один настоящий П‑том ТП и его РД‑альбомы), либо новая загрузка пары ПД+РД.
3. `stamp_data.stage` **нельзя** использовать как признак стадии ни в каком фильтре: на «П»
   точность 0.133, поле заполняется даже когда графы «Стадия» в штампе нет и когда блок вообще
   не штамп.
4. `sheet_name` как якорь сопоставления листов даёт **0 % точности** на типовых листах поставщика
   (10 совпадений имени → 0 совпадений чертежа). Сопоставление обязано опираться на геометрию.
5. `crop_url` = вектор‑PDF блока — рабочий второй источник геометрии там, где `document.pdf` нет
   (**3 041** блок объекта 213), но он гниёт: 28 версий из 96 уже отдают 404.

## Замечания к `probes/v03_foundation.py`

Багов не нашёл; модуль отработал на всех выборках 214/256/314. **Ограничение, не покрытое
контрактом**: модуль требует `02_work/document.pdf` и молча пропускает версии без него
(`iter_prepared_blocks` вернёт блоки, но `block_frame`/`render_block`/`extract_block` упадут либо
дадут пустоту, т.к. `_page_rects` вернёт `[]`, а `page_index >= n_pdf_pages > 0` отфильтрует всё).
Для 96 версий (8 796 image‑блоков, 14.4 % корпуса) единственный доступ — облачный вектор‑кроп;
это стоило бы добавить в модуль как второй источник (`probes/pd_cropfetch.py` — минимальная
реализация: `fetch` с `User-Agent`, иначе R2 отдаёт **403** на `urllib` при 200 на `curl`).
