# Правка основания: гейт путей выбрасывал 45 % геометрии

Внесена оркестратором после состязательной проверки (`fnd_VERIFY.md`, NEW‑1).
Затронут только `probes/v03_foundation.py`. Production не менялся.

## Дефект

`fitz.Rect.intersects()` в PyMuPDF 1.27.2 реализован так:

```python
return (not self.is_empty and not rect2.is_empty
        and self.x0 < rect2.x1 and rect2.x0 < self.x1
        and self.y0 < rect2.y1 and rect2.y0 < self.y1)
```

Два следствия, оба вредные:

1. **Вырожденный прямоугольник всегда даёт `False`.** У любого чисто горизонтального или
   вертикального однолинейного пути `rect` вырожден по построению (нулевая высота или
   ширина). Таких путей в корпусе **45.1 %** (400 803 из 889 016 на 25 случайных страницах).
2. **Строгое `<`** отбраковывает ещё и касание границы клипа.

`extract_block()` использовал это как гейт «путь вне блока» и молча выбрасывал такие пути,
относя их к `outside_clip`.

## Цена дефекта (два независимых измерения)

| величина | ревизия (`vfy_f6_gate.json`, n=500) | оркестратор (`fnd_gatefix_regression.json`, n=79) |
|---|---|---|
| восстановлено сегментов, медиана | 6.8 % | **6.1 %** |
| восстановлено длины штриха, медиана | 35.6 % | **33.7 %** |
| восстановлено длины, p90 | 83.3 % | **81.9 %** |
| блоков, где восстановлено >50 % длины | 28.6 % | **22.8 %** (18/79) |
| блоков, ложно объявленных пустыми | 3.4 % | 1.3 % (1/79) |

Числа сошлись на разных выборках и разном коде — дефект реален, масштаб подтверждён.

Расхождение «6 % сегментов, но 34 % длины» объясняется тем, что выбрасывались именно
**длинные прямые**: оси, рамки, стены, шины, размерные и выносные линии. То есть терялся
несущий каркас чертежа при сохранении мелочи.

## Почему этого не увидел автор модуля — методологический урок

Все метрики `fnd` измеряли **точность**: «легли ли извлечённые сегменты на краску растра».
У обоих вариантов она равна **1.000** — выброшенные пути точности не портят, они просто
отсутствуют.

Ни одна метрика не измеряла **полноту**: «объяснена ли видимая краска извлечёнными
сегментами». По ней разрыв стократный: необъяснённая краска **0.0033** у корректного
извлечения против **0.335** у модуля с дефектом.

**Правило для всего трека:** у любого извлечения и у любой группировки должны меряться обе
стороны. Метрика вида «то, что мы нашли, — верно» не способна обнаружить, что мы не нашли
половину.

## Правка

Добавлена `_rect_overlaps(a, b, eps=1e-9)` — замкнутое пересечение интервалов по обеим осям,
корректное для вырожденных прямоугольников; заменены все три вызова `.intersects()`
(`ink_verdict`, гейт путей в `extract_block`, гейт растровых вставок).

Отдельно исправлено `F1a′`: `render_block(target_px=0)` брал 800 px, тогда как production
использует `TARGET_LONG_SIDE_PX = 1500` (800 — это профиль `COMPACT`). Теперь по умолчанию
1500, и модуль совпадает с production без явной передачи параметров.

## Что это меняет в выводах `fnd`

- **F5 недействителен и подлежит перезамеру.** «7.0 % блоков без вектор-слоя» —
  артефакт дефекта; ревизия оценила истинную долю в **2.8 %**. Медиана сегментов на блок
  1 313 → **1 858**, доля блоков ≥10 000 сегментов 18.8 % → **28.6 %**, максимум
  475 828 → **817 732**.
- **Требование к сложности алгоритмов ужесточается**: не 18.8 %, а **28.6 %** блоков имеют
  ≥10 000 сегментов.
- F0, F1, F2, F4 не затронуты: они про координаты и рендер, а не про полноту чтения путей.
