### Разделяй замечания и оптимизации

`03_findings.json` — это ограничитель, а не источник основной массы OPT. Сначала, не опираясь на формулировки замечаний, составь кандидаты из спецификаций, повторяющихся проектных решений и графики. Только после этого сверь кандидаты с findings и убери конфликтующие.

Не создавай OPT, если `proposed` лишь повторяет требование уже существующего F/T-пункта: исправить размер, дописать ГОСТ, устранить расхождение, добавить отсутствующую норму или перевыпустить лист. Такой пункт уже является замечанием, а не оптимизацией. Он допустим только когда содержит отдельное проверяемое предложение по снижению стоимости, сроков монтажа, числа типоразмеров или стоимости эксплуатации.

## Направления оптимизации

### 1. ЗАМЕНА НА БОЛЕЕ ДЕШЁВЫЕ АНАЛОГИ
Проанализируй спецификации. Предложи аналоги с сопоставимыми характеристиками по более низкой цене. Укажи: исходную позицию, аналог, разницу в цене (%), обоснование эквивалентности.

### 2. УДЕШЕВЛЕНИЕ / УСКОРЕНИЕ МОНТАЖА
Найди позиции, где выбор материала усложняет монтаж. Предложи замены: более технологичные материалы, сборные соединения вместо сварки, быстромонтируемые крепежи. Указывай экономию в стоимости и человеко-часах.

### 3. УПРОЩЕНИЕ КОНСТРУКТИВА
Оцени компоновочные решения (обвязки, коллекторы, щиты, крепёж, проходки). Предложи упрощение конструкции, унификацию деталей, сокращение соединений или переход на заводские модули.

### 4. ОПТИМИЗАЦИЯ ЖИЗНЕННОГО ЦИКЛА
Решения дороже при строительстве, но с экономией на горизонте 10-25 лет: энергоэффективность, ремонтопригодность, увеличение межсервисных интервалов, снижение стоимости ЗИП.

## Правила анализа

- Все замены должны соответствовать действующим нормам (СП, ГОСТ, ТР ТС)
- НЕ предлагать замены, снижающие надёжность или пожарную безопасность
- При сомнениях — `"status": "требует проверки"`
- Приоритет: сначала крупные позиции с максимальным эффектом
- **Согласованность с замечаниями аудита:** если `03_findings.json` содержит замечание о несоответствии позиции нормам — НЕ предлагай для неё дешёвый аналог. Вместо этого можешь отметить что позиция требует замены по нормативным причинам (status: "обязательное исправление")
- **Вендор-лист обязателен:** при замене оборудования предлагай ТОЛЬКО производителей из вендор-листа. Если текущий производитель уже есть в вендор-листе — можно предложить другого из того же списка. Если текущего нет в списке — это само по себе замечание (status: "обязательное исправление")
- **Количество позиций определяется ТОЛЬКО по факту анализа** — столько, сколько реально найдено. Может быть 3, может 30. НЕ подгоняй под круглое число
- **Распределение по типам** — сколько получилось в каждой категории, а не равномерно
- **Процент экономии (savings_pct)** — только если можешь обосновать расчётом (разница цен, сокращение трудозатрат). Если не можешь посчитать — ставь `0` и поясни в `proposed`
- **estimated_savings_pct** — средневзвешенная оценка по крупным позициям, НЕ выдумывай круглое число. Если нет данных для расчёта — ставь `0`
- **spec_items** — указывай конкретные позиции из спецификации/ведомости, к которым относится оптимизация. Формат: `"Поз. N — Наименование"`. Если позиция касается группы — перечисли все
- **savings_basis** — честно указывай источник оценки экономии: `"расчёт"` только если есть конкретные числа (цены, объёмы), `"экспертная оценка"` если по опыту аналогичных проектов, `"не определено"` если нет данных
- **page и sheet** — `page` = номер страницы PDF, `sheet` = номер листа из штампа. Они НЕ совпадают. Используй данные из MD-файла (метки `**Лист:**` и номера страниц)
- **Если в задании есть блок “Автопрескан оптимизаций из MD”** — сначала проверь все кандидаты из него. Это не готовые выводы, а навигация по крупным позициям спецификаций и повторяющимся семействам, которые часто пропускаются при беглом чтении MD. Подтверждай только те кандидаты, где реально видишь позицию в MD и можешь привязать `spec_items`, `page`, `sheet`.
- **Не занижай cheaper_analog:** отсутствие точного прайс-листа НЕ означает, что экономическую оптимизацию нужно пропустить. Если по бренду/материалу/объёму видно, что позиция премиальная, импортная, индивидуальная или избыточно дорогая, сформируй предложение с `savings_pct: 0` и `savings_basis: "экспертная оценка"` или `"не определено"`. В `proposed` напиши, что требуется запрос КП/ТКП или рыночная проверка.
- **Не заменяй экономические предложения нормативными исправлениями:** если 03_findings содержит нарушение по позиции, дешёвый аналог для неё нельзя давать, но это не отменяет соседние независимые позиции из спецификации. Не схлопывай 5 разных кандидатов автопрескана в 1 общий OPT.
- **Баланс источников:** если MD содержит полноценную спецификацию, не менее половины итоговых OPT должны быть независимы от `03_findings.json` и найдены непосредственно в спецификации/ведомости/графике. Пунктов со статусом `"обязательное исправление"` должно быть не более 25% списка; они не заменяют экономические предложения.
- **Баланс эффекта:** при наличии подходящих позиций проверь минимум три независимых зоны: закупочные аналоги, унификация номенклатуры и ускорение/укрупнение монтажа. Не заполняй весь список редакционными исправлениями или одной категорией.
- **Премиальные триггеры:** натуральный камень, мрамор, PVD/цветная нержавеющая сталь, индивидуальные фасадные/интерьерные изделия, импортная сантехника/фурнитура/свет, HILTI, Dyson, Gessi, Salvatori, Archskin, декоративные штукатурки, мелкоформатная плитка на больших площадях, большое количество крепежа/кронштейнов/лотков/светильников — это обязательные зоны проверки на cheaper_analog, унификацию или faster_install.
- **Контроль полноты:** для документа с большой спецификацией 3-5 OPT-пунктов обычно недостаточно. Если автопрескан дал 10+ кандидатов без blockers, итог должен покрывать большую часть подтверждённых кандидатов, а не только top-3. Перед записью `optimization.json` проверь, не остались ли без анализа крупные позиции из автопрескана.
- **Blockers не повод сокращать ответ:** если кандидат автопрескана связан с замечанием аудита, не выкидывай его автоматически. Для такой позиции нельзя давать безусловный дешёвый аналог, но можно оформить `обязательное исправление`, `требует проверки`, `faster_install`, `simpler_design` или `lifecycle`, если MD подтверждает экономический/монтажный смысл.
- **Порог полноты для Codex:** если автопрескан дал 10+ кандидатов, а в `optimization.json` получается меньше 8 пунктов, перед записью обязательно вернись к списку и добавь все подтверждённые крупные позиции. Короткий список допустим только когда в `proposed`/`risks` каждого оставшегося пункта ясно видно, почему остальные крупные кандидаты не применимы.
- **Разные источники экономии — разные OPT:** отдельные крупные позиции спецификации, разные бренды/материалы и разные повторяющиеся семейства должны быть отдельными item, даже если общий тип оптимизации похож. Не объединяй Gessi/Salvatori/SunSong/HILTI/Archskin/крепёж/свет/штукатурку в один общий пункт.

## Дисциплинарные линзы для спецификаций

Используй эти линзы как чек-лист, особенно для Codex exec:

- **ЭОМ:** кабели, лотки, щиты, автоматы, УЗО/ВДТ, счётчики, светильники, трубы/гофра, АКБ/ИБП. Ищи крупные длины, повторяющиеся типы щитов, избыточные номиналы, разнородные серии устройств.
- **СС/АПС/СОУЭ/АК:** кабели, извещатели, оповещатели, ИВЭП/БП, АКБ, шкафы, контроллеры, проходки и крепёж. Проверяй запас аккумуляторов, унификацию шкафов и кабельных трасс.
- **ОВ/ВК/ПТ:** трубы, клапаны, краны, фильтры, насосы, воздуховоды, радиаторы/конвекторы, изоляция, компенсаторы, гильзы, фитинги. Ищи повторяющиеся типоразмеры, дорогие бренды, толщины изоляции, сварные/резьбовые узлы, готовые модульные узлы.
- **АР/ГП/AI/TX:** фасад/НВФ, камень, плитка, краски, штукатурки, двери, люки, мебель, дорожные знаки, покрытия, борта/бордюры, крепёж. Ищи премиальные материалы там, где нет эксплуатационного обоснования, мелкоформатные решения, дубли и разнотипность.
- **КЖ/КМ:** бетон, арматура, каркасы, закладные, анкеры, металлопрофили, сварные узлы, крепления, фасадные подсистемы. Ищи унификацию марок/длин/узлов, перевод ручной сборки в заводские элементы, снижение монтажных операций без потери несущей способности.

### Проверенные дисциплинарные направления

- **АР:** отдельно проверь материал и плотность перегородок/утеплителей, технологию стяжек и штукатурок, гидроизоляцию, повторяющиеся марки дверей/проёмов/ограждений, премиальные отделочные материалы и заводские модульные узлы.
- **КЖ:** отдельно проверь избыточные F/W при сохранении класса бетона, нахлёсты против муфт, заводские каркасы/сетки, число типов колонн и гнутых стержней, типизацию отверстий/закладных и технологичность бетонирования густоармированных зон. Не выдавай исправление ведомости за оптимизацию производства.
- **ОВ:** отдельно проверь аналоги массового оборудования, толщины изоляции по диаметрам, число типоразмеров воздуховодов/труб/приборов, заводскую готовность коллекторных и обвязочных узлов, крепёжные системы, ЧРП и рекуперацию. Не ограничивайся исправлением маркировок и EI.

## Порядок работы

1. Прочитай MD-файл целиком — тип объекта, ТЭП, нагрузки, оборудование
2. Проанализируй спецификации и составь независимый список экономических/монтажных кандидатов
3. Прочитай `01_blocks_analysis.json` и добавь подтверждённые графикой варианты компоновки/унификации
4. Сверься с вендор-листом выше — допустимые производители для замен
5. Только теперь прочитай `03_findings.json`: используй его как фильтр конфликтов, не как готовый список OPT
6. Проверь баланс источников и типов эффекта
7. Сформируй оптимизационный лист и запиши результат

```json
    "total_items": 0,
    "by_type": {

      "simpler_design": 0,
      "lifecycle": 0
    },

    {
      "id": "OPT-001",
      "section": "",
      "page": 12,

      "norm": ""

  ]

```

**Типы значений:** `total_items`, `by_type.*`, `estimated_savings_pct`, `savings_pct`, `page` — числа (number). `spec_items` — массив строк. Остальное — строки. Пустое поле: `""` для строк, `0` для чисел, `[]` для массивов.

### Поля

| Поле | Тип | Описание |
|------|-----|----------|
| `id` | string | `OPT-001`, `OPT-002`... |
| `section` | string | Откуда позиция: `"Спецификация лист 16"` |
| `page` | number/array | Номер страницы PDF (или массив `[12, 13]`). Для привязки к чертежам |
| `sheet` | string | Номер листа из штампа: `"Лист 7"`. НЕ путать с page! |
| `spec_items` | array | Конкретные позиции спецификации: `["Поз. 5 — Кабель ВВГнг(А)-FRLS 5x10"]`. Пустой массив `[]` если нет привязки |
| `source_block_ids` | array | block_id изображений-источников из графического контекста (если был). ТОЛЬКО сюда: в текстах `current`/`proposed`/`risks` внутренние block_id и метки IMG-NN упоминать ЗАПРЕЩЕНО — их читают сторонние эксперты. `[]` если привязки нет |
| `current` | string | Что есть сейчас (макс 200 символов) |
| `proposed` | string | Что предлагается (макс 200 символов) |
| `type` | string | `cheaper_analog` / `faster_install` / `simpler_design` / `lifecycle` |
| `savings_pct` | number | Экономия % (0-100). Если не числовая — `0` |
| `savings_basis` | string | Обоснование: `"расчёт"` (есть конкретные цены/объёмы), `"экспертная оценка"` (опыт аналогичных проектов), `"не определено"` (нет данных для оценки) |
| `timeline_impact` | string | `"без изменений"`, `"+2 дня"`, `"-3 дня"` |
| `risks` | string | Описание рисков. Нет рисков → `"минимальные"` |
| `status` | string | `"предложение"` / `"требует проверки"` / `"обязательное исправление"` |
| `norm` | string | Нормативная ссылка или `""` |

### Запреты

- НЕ создавай вложенные объекты — только плоские строки
- НЕ переименовывай поля
- НЕ добавляй поля, которых нет в схеме
- НЕ используй `null` — используй `""` или `0`
- НЕ создавай MD-отчёт — только `optimization.json`
