# Зависимости КОНВЕЙЕРА на воркере (этап реального VPS-пилота).
#
# Почему отдельный файл, а не дополнение requirements-worker.txt.
# requirements-worker.txt описывает САМ АГЕНТ (httpx + psutil) — он ставится
# даже туда, где реального аудита не будет никогда, и остаётся честно
# коротким. Но с момента, когда воркер начал выполнять `audit_pipeline_v1`,
# дочерний процесс `backend.app.pipeline.remote_audit_runner` запускается ТЕМ
# ЖЕ интерпретатором (если не задан AUDIT_WORKER_PIPELINE_PYTHON) и падает на
# импорте pydantic/fastapi/dotenv, а на этапе crop_blocks — на fitz.
#
# Список выведён из фактического импорт-графа кода конвейера, а версии
# ПРИБИТЫ по тому, что стоит на центре (/opt/py312, python 3.12.13): снимок
# моделей и профиля дисциплины едет в пакете задания, а вот версии библиотек
# не едут ничем — расхождение здесь даёт «работает на центре, падает на
# воркере» без единого сообщения о причине.
#
# Установка (после requirements-worker.txt, в тот же venv):
#   <venv>/bin/pip install -r requirements-worker-pipeline.txt
