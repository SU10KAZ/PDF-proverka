> ## ⭐⭐⭐ ВТОРОЙ УРОК: «ДАННЫЕ ПЕРЕДАНЫ В СМЕЖНЫЙ РАЗДЕЛ» — ТОЛЬКО НАЧАЛО ПРОВЕРКИ
>
> Общие указания СДС действительно передают магистральное оборудование, шкафы и резервное питание в ЛВС. Это не позволяет автоматически отклонить замечание.
>
> `F-014` показал правильный порядок:
>
> 1. открыть связанный комплект ЛВС той же версии;
> 2. найти сам расчёт, схемы шкафов и спецификацию;
> 3. сопоставить **нагрузку → шкаф → модель ИБП → батареи → время автономии**;
> 4. проверить, что расчёт выполнен именно для оборудования, выданного в РД.
>
> В ЛВС расчёт существует, но выполнен для `SKAT-UPS 3000/6000`, тогда как схемы и спецификация предусматривают `Ippon Innova RT II 10000` — 4 шт. и батарейные модули — 2 шт. Шкаф `ШК.ЛВС.0.2` с сервером `ETI/SER XIP` в расчёте не показан. Поэтому исходная фраза «расчёт отсутствует» неточна, но риск неподтверждённой автономии реален. Инженер принял `F-014` как есть с требованием выдать актуальный расчёт.

> ## ⭐⭐⭐ ЧЕТВЁРТЫЙ УРОК: ИТОГ НА ПОСЛЕДНЕЙ СЕКЦИИ МОЖЕТ БЫТЬ ОБЩИМ ИТОГОМ ВСЕХ СЕКЦИЙ
>
> `F-007` и `F-008` возникли потому, что аудит пересчитал только строки секции 5. Проверка всех экспликаций дала:
>
> - квартиры: `487,5 + 244,6 + 250,3 + 436,9 + 476,0 = 1895,3 м²`;
> - МОП: `84,8 + 57,2 + 57,1 + 71,8 + 99,9 = 370,8 м²`.

> **Правило:** перед замечанием к итогу последней таблицы проверить одноимённые таблицы предыдущих секций и выполнить сквозной расчёт.

### Невидимый слой PDF-страницы 18

На странице 18 находится скрытый текстовый слой кеглем `0.0`, дублирующий значительную часть документа. Он создаёт фантомные вхождения марок, итогов и обозначений.

```python
def dec(s):
    return "".join(chr(ord(c)+581) if 0x01C0 <= ord(c) <= 0x0260 else c for c in s)

def visible(page, minsize=0.5):
    out = []
    for block in page.get_text("dict")["blocks"]:
        for line in block.get("lines", []):
            for span in line["spans"]:
                if span["size"] >= minsize:
                    out.append(span["text"])
    return dec("\n".join(out))
```

**Правило:** OCR и поиск используются для навигации. Любое визуальное утверждение о марке, точке, номере или таблице подтверждается видимым текстом и растром нужной страницы.

### Иерархия доказательств

1. **Растр конкретного листа** — для надписей, точек, таблиц, штампов и графики.
2. **Векторный видимый текст** через фильтр — для точного поиска и цитирования.
3. **Спецификация и связанная схема той же версии** — для марки, артикула и состава.
4. **Связанный комплект** — только после проверки шифра, даты и версии.
5. **Официальная карточка нормы/производителя** — для статуса документа или идентичности изделия.
6. **OCR `document.md`** — только указатель, не самостоятельное доказательство.
7. **Статистика прошлых решений** — контекст, но не доказательство.

## 2. Процедура совместного разбора

По каждому пункту:

1. **Объяснить простыми словами**, что именно считает ошибкой аудит.
2. **Проверить привязку**: PDF-страница, номер листа, штамп, видимый текст и растр.
3. **Проверить все связанные данные той же версии**: общие указания, схема, спецификация, другие секции.
4. **Если решение делегировано**, открыть смежный комплект и проверить не только наличие ссылки, но и фактическое решение. Обязательно сравнить даты версий.
5. **Перепроверить самого себя**: сформулировать сильнейшее возражение против собственного вывода и проверить его проектными данными.
6. **Проверить нормативную ссылку отдельно**: статус, дату введения, область применения и конкретный пункт.
7. **Дать предварительный вердикт**, но окончательное решение принимает инженер.
8. После решения инженера **записать его и автоматически перейти к следующему согласованному пункту**.

### Что запрашивать у инженера

Если данных нет в доступном комплекте, просить конкретно:

- номер PDF-страницы и номер листа;
- схему шкафа или фрагмент плана;
- страницу спецификации с позицией;
- страницу расчёта;
- связанный лист другого раздела с шифром и датой;
- паспорт/артикул изделия, если спор идёт о тождестве модели.

Нельзя принимать или отклонять пункт со словами «вероятно предусмотрено в другом разделе» без открытия этого раздела.

## 7. Рабочие приёмы по фактической отдаче

### Приём 1. Лист 1 читать в трёх слоях

### Приём 2. Проверять изделие по цепочке

```text
текст общих указаний → схема → спецификация → артикул → официальный каталог
```

Если код изделия совпадает и состав функций тот же, разница сокращений не является самостоятельной ошибкой.

### Приём 3. Для итогов строить общую таблицу секций

Не ограничиваться листом, к которому адресовано замечание. Выписать одноимённые итоги всех секций, сложить и только затем оценивать последнюю строку.

### Приём 4. Для смежника проверять четыре документа

```text
ссылка в СДС → схема смежника → спецификация смежника → расчёт смежника
```

По питанию добавить пятое звено: **таблица распределения нагрузок по шкафам/ИБП**.

### Приём 5. Сравнивать даты штампов

Связанный комплект с более поздней датой может подтверждать архитектуру системы, но не доказывает, что решение или дублирующее замечание существовало в проверяемой версии.

### Приём 6. Разделять три оси

- **Факт:** действительно ли запись/число/обозначение есть.
- **Ценность:** заслуживает ли это отдельного замечания с учётом риска.
- **Причина решения:** доказана ли она данными именно этого проекта.

Реальный факт может быть отклонён как малозначимый (`F-009`, `F-012`, `F-018`). Верное решение может иметь слабую причину (`F-015`).

## 11. Ловушки метода

1. **Предварительная методичка может ошибаться.** В СДС она неверно выделила кандидатами `F-006`, `F-007`, `F-008`, `F-011`, `F-012` и неверно предлагала отклонить всю нормативную группу.

3. **Скрытый слой страницы 18 создаёт фантомы.** Применять фильтр размера шрифта и проверять растр.
4. **Название без артикула недостаточно.** Для `F-006` решающим стал код 62740121.
5. **Одна таблица не объясняет общий итог.** Для `F-007/F-008` понадобились все пять секций.
6. **Ссылка на смежника не доказывает выполненное решение.** Для `F-014` пришлось открыть расчёт, схемы и спецификацию ЛВС.
7. **Расчёт может быть арифметически верным, но относиться к другой комплектации.** Это главный технический урок `F-014`.
8. **Более поздний комплект нельзя считать same-version.** СКД 07.26 — только связанный контекст для СДС 03.26.
9. **Правильное отклонение может иметь неправильную причину.** Исправлять доказательство, не меняя решение автоматически.
10. **Решение «принято как есть» не стирает установленную оговорку.** Сохранять её в колонке 12.
11. **Не открывать бэкап с нестандартным расширением напрямую через `openpyxl`.** Перед диффом открыть через файловый объект либо временно дать имя `.xlsx`.
