Шкала масштаба (change_scope):
- «Нет изменений содержания» — в переходе нет технических изменений по представленным данным;
- «Только оформление» — служебные реквизиты, расположение или пустые листы без изменения технического решения;
- «Локальные изменения» — ограниченный состав позиций или узлов;
- «Существенные изменения» — заметные изменения состава работ, оборудования или технических решений
  в одной или нескольких системах;
- «Широкая переработка» — изменена структура решений либо несколько связанных систем и видов работ;
- «Не установлено» — по переданному тексту оценить нельзя (объясни в assessment_basis).
Значимость последствий (significance) оценивается отдельно: «Низкая», «Средняя», «Высокая»,
«Не установлена» при недостатке данных; «Нет новых технических изменений» — если технических
изменений нет. Число листов само по себе не определяет значимость. Не вычисляй процент изменения.
content_status: technical — есть технические изменения; formatting_only — только оформление;
no_content_changes — явное отсутствие изменений содержания; unknown — установить нельзя.

По каждому переходу:
1. Укажи, есть ли технические изменения, только оформление или явное отсутствие.
2. Выдели изменённые системы и связанные изменения: объект, было, стало.
3. Оцени масштаб и отдельно значимость, с коротким предметным основанием.
4. Опиши последствия для закупки, кабелей/материалов, монтажа,
   подключений и размещения при выполнении работ по предыдущей выдаче.
5. Найди прямые условия документации (explicit_conditions) и отдельно неизвестность.
6. Выдели наиболее важные факты (обычно 2–8 на переход, у большого перехода больше); не придумывай
   их для перехода без технических изменений. Числа, марки, сечения, номиналы, длины и единицы
   переписывай дословно, как в источнике.
7. Для каждого факта укажи строки источника (evidence: md_from, md_to). Лист и страницы PDF
   программа возьмёт из заголовков сводки по этим строкам.
8. Отметь кандидатов в серьёзные изменения (serious_candidate = true) и связанные позиции
   (related_objects: точные обозначения — марки шкафов, линий, аппаратов) для проверки через
   несколько версий.

Не смешивай режимы «Пожар», «нормальный», «авария на вводе» и т. п.
Не смешивай установленную и расчётную мощности.
Перенос между листами не объявляй исключением из проекта.
Расхождение схемы и спецификации фиксируй как противоречие (contradictions).
Изменение схемы само по себе не доказывает замену ранее закупленного аппарата.
Не утверждай запрет работ, аварийность, фактические переделки или затраты
только из-за появления следующей версии.

Если назначена только часть перехода (в списке переходов указано «часть k из n»), опиши то, что
есть в этой части, и поставь analysis_complete = false: остальные части анализируются отдельно

input_problems и не помечай такие блоки обработанными.
