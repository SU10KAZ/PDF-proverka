# Stage gate rules — completeness lens prompt block

**Назначение:** запретить ложные missing-findings, когда нечего сравнивать,
потому что текущий PDF — это не та стадия документации (ПД vs РД vs КМД).

## Правила

Перед тем как сгенерировать missing finding, определи стадию документа:

- **ПД (П / project_documentation)** — проектная документация по ПП РФ 87
  (тома 1-12). Шифр содержит «П» (не «РД», не «КМД»). В штампе стадия «П».
- **РД (Р / working_documentation)** — рабочая документация, конкретная
  марка (АР-К3, ЭМ-К3, …). Шифр содержит «РД» или «Р». В штампе стадия «Р».
- **КМД (detailing)** — деталировочные чертежи металлоконструкций. В штампе
  «КМД».
- **mixed** — документ совмещает ПД и РД (используй downgrade-логику ниже).
- **unknown** — стадия не определена ни в шифре, ни в штампе.

## Запреты

Запрещено генерировать missing finding на:

- «Отсутствует пояснительная записка» — в РД-марке. ПЗ — атрибут тома ПД.
- «Отсутствует ТЭП» — в РД-марке. ТЭП живёт в томе ПЗ (раздел 1).
- «Отсутствует общий электробаланс» — в РД ЭМ-К3. Может быть в томе ЭОМ-ПД.
- «Отсутствует расчёт КЗ / нагрузок» — в РД-марке без проверки наличия
  ссылки «по данным ПД». Если ссылка есть → drop.
- «Отсутствует ПЗ / общие данные / ТЭП» — при `stage = unknown` ставь
  severity **ПРОВЕРИТЬ_ПО_СМЕЖНЫМ** с пометкой «стадия документа не
  определена; возможно, атрибут тома ПД».

## Downgrade-логика

Если item помечен как «only for project_documentation» и:

- `stage = working_documentation` → finding **drop** (не упоминай).
- `stage = mixed` → severity **ПРОВЕРИТЬ_ПО_СМЕЖНЫМ** + явная пометка
  «возможно, атрибут тома ПД».
- `stage = unknown` → severity **ПРОВЕРИТЬ_ПО_СМЕЖНЫМ** + пометка
  «стадия не определена».

Если item помечен как «only for working_documentation» и:

- `stage = project_documentation` → finding **drop** (атрибут РД-марки).
- `stage = specification_only` (через document_type) → finding **drop**.

## Применимость

Этот блок применяется ВСЕГДА, независимо от document_type и discipline.
