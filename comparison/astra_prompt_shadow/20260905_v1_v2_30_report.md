# Astra prompt shadow A/B — 30 expert-linked blocks

Date: 2026-09-05  
Implementation commit: `16b5eeb1`  
Model: `codex/gpt-6-astra`  
Reasoning effort: `low`

## Method

- 30 same-version blocks: 15 containing at least one expert-accepted finding and
  15 containing only expert-rejected findings.
- 19 documents across AR, KJ, EOM, OV, and TX.
- 22 known accepted and 75 known rejected block/finding references.
- v1 and v2 ran concurrently for each block with the same image and reconstructed
  production context.
- Expert labels were joined only after generation and were not included in either
  model prompt.
- v1 is the unchanged production prompt. v2 is a disabled-by-default shadow profile.

## The three v2 additions

1. `AAFN-QEFV-LPW`, OV: node numbering `Узел 1` versus `Узел 3` for the
   DN 50–125 compensator scheme. This is an exact match to expert-accepted F-030.
   Astra returned `contradiction`, `sufficient`, confidence 0.97. The current gate
   can publish it.
2. `7K3Q-L6N3-LHP`, EOM: current transformers 120/5 A versus calculated current
   142.10 A. This is the same defect as expert-accepted F-022. Astra returned
   `context_gap`, `needs_retrieval`, confidence 0.90, so the current gate will defer it.
3. `9XNP-4JXR-KRU`, KJ: truncated stirrup marks `10-Х-...` prevent an unambiguous
   link to the schedule. This is the same defect as expert-accepted F-030. Astra
   returned `context_gap`, `needs_retrieval`, confidence 0.88, so the current gate
   will defer it.

v2 removed no v1 finding and reproduced no known rejected finding.

Both variants also found an arithmetic mismatch in `4ALF-RXML-WRA`: two anchors at
0.15 kg each have a displayed total of 1.8 kg instead of 0.30 kg. The exact values
are present in the supplied page text, but this issue is outside the block's joined
expert labels. It is kept as unreviewed and does not affect the comparison.

## Why Astra still misses most accepted findings

The v1 prompt encourages early completion with “most blocks are correct” and “the
checklist need not be exhausted.” Astra follows those constraints literally. v2
removes that early-exit framing and requires three passes, which recovered three
known defects without increasing known rejected matches.

The remaining misses are not explained by reasoning effort alone. They cluster in
checks that the generic three-pass protocol does not operationalize:

- EOM: uniqueness of QF labels, binding outgoing-line codes, `Ip` versus CT rating,
  short-circuit current versus breaker curve, and fire-resistant cable class;
- KJ/AR: exhaustive mark-to-schedule reconciliation across several details and
  schedules;
- TX/AR: cross-title, floor, explication, and repeated-sheet aggregation.

Several expert-accepted findings aggregate evidence across distant blocks. A single
block prompt can receive document retrieval snippets, but it has no deterministic
entity join that guarantees the required counterpart is selected. Generic wording
therefore cannot reliably trigger the comparison.

There is also a detector/gate contract mismatch: two useful v2 discoveries are
correct candidates according to expert review, yet their `context_gap` status makes
them non-publishable under the current evidence gate. Candidate recall and visible
publication recall must be measured separately.

## Decision

Do not switch the production prompt to v2 yet. The candidate-level gain is real but
small-sample, and the current gate turns two of the three gains into deferred items.
The next shadow should add bounded discipline-specific comparison recipes and targeted
retrieval for the missing counterpart, while keeping no forced minimum finding count.
After that, repeat the paired test on at least 50 blocks and review every new candidate
before enabling the profile in production.
