# Замена OpenRouter-ноги этапа «Блоки» — Этап 0: анализ истории

Дата: 2026-10-11 · Скрипт: `backend/scripts/research_openrouter_leg_history.py` ·
Сводка: `phase0_summary.json` · Вызовов моделей: 0

## Вопрос

С 23.09.2026 этап «[01] Блоки» работает без OpenRouter-ноги (`openai/gpt-5.4`, low,
temperature 0.2): в проде остались Astra + Sol + судья Sol с gap-search. Инженер
заметил, что эта нога находила замечания, которых не находили другие. Нужно понять,
что именно теряется и за счёт чего GPT это находила, — чтобы подобрать замену на
подписке Codex или Claude.

## Данные и метод

- Сырые ответы каждой ноги по каждому блоку:
  `…/runs/<run>/_stage01_findings_only_runs/<stamp>/block_*.json`. Прогонов с
  GPT-ногой — 435 (15.07–12.09.2026).
- Экспертные вердикты: `04_review/expert_review.json` (654 версии). Сшивка с
  замечаниями проверена по тексту через `knowledge_base/decisions_log.json`:
  15 200 совпадений, 40 расхождений (исключены).
- Для каждой версии взят прогон, который реально смотрел эксперт. Прогон Этапа 01
  найден по `run_id` в детекциях: поздние прогоны часто переиспользуют блоки из
  раннего. В анализ попали **309 версий**, где эксперт смотрел прогон с GPT-ногой.
- «Только GPT» означает: все детекции замечания пришли от `gpt_openrouter`,
  текстовый этап его не нашёл, и Codex-ноги на всех его блоках отработали без
  ошибок.

Целевое множество для замены — **126 принятых находок «только GPT»** на блоках, где
Codex-ноги отработали. Шумовое множество — 1 392 отклонённых.

### 2. Вклад GPT падал по мере усиления стороны Codex

| Codex-сторона рядом с GPT | Версий | Уник. принятых GPT на версию | Доля в принятых блоковых | Отклонённых на 1 принятое |

Состав объектов в периодах разный, а строгость экспертов по объектам — тоже.
Честное сравнение даёт только объект 256, который есть в обоих поздних периодах:
доля GPT — 10,0 % при `codex/gpt-5.4` + Sol и 9,5 % при Astra + Sol.

**Оценка потери для нынешнего прода: ~5–10 % принятых блоковых замечаний,
0,1–0,4 на документ. Цена у оригинала — 10–25 отклонённых на каждое принятое.**

### 3. Что именно ловила только GPT

Все 126 целевых находок прочитаны. Почти все — **сверки внутри одного листа**:
- марка на схеме ↔ спецификация или ведомость (ГС-5 Ø28/Ø25, «Ск-674» нет в
  спецификации, ПМ-8: 2∟50×5 против 2∟100×8);
- одно обозначение у разных объектов (QF, номера линий, rs4.ВТ.3, машино-места);
- количество на плане ↔ ведомость (отверстия, агрегаты А1–А3 при 2 шт., контакторы);
- размерные цепочки и отметки, противоречащие сами себе (сечение 1-1, приямок 1000 мм);
- не назначена перемычка над проёмом, отверстие не согласуется с болтом.

Это тот же класс, на котором промахивалась Astra в A/B от 05.09
(`comparison/astra_prompt_shadow/20260905_v1_v2_30_report.md`): исчерпывающая
сверка марок со спецификацией.

По дисциплинам: AR 41, EOM 27, KJ 16, SS 13, ITP 12. В OV и VK уникальные находки
GPT на 98 % отклонены (4 из 231 и 4 из 226 приняты). По категориям: «Проверить по
смежным» (5 из 212) и «Рекомендательное» (4 из 204) — практически чистый шум.

### 4. Дело не в модели, а в способе вызова

Одни и те же блоки, тот же промпт и контекст, то же усилие low:

| Нога | Находок на блок | Блоков с находками | Токенов рассуждения | Входных токенов |
|---|---:|---:|---:|---:|
| `gpt-5.4` через OpenRouter | **0,74** | **47,7 %** | **535** | 9 421 |
| `gpt-5.4` через Codex exec | 0,40 | 28,0 % | 280 | 18 291 |
| Sol через Codex exec | 0,34 | 27,7 % | 199 | 21 651 |
| Astra через Codex exec | 0,31 | 26,7 % | **39** | 23 274 |

**Одна и та же модель `gpt-5.4`** через Codex рассуждает вдвое меньше и находит вдвое
меньше. Codex exec добавляет ~9 тыс. токенов инструкций агента-программиста. Astra
на low почти не рассуждает: 39 токенов на блок. При этом GPT через OpenRouter нашла
114 принятых находок, которых не нашла `codex/gpt-5.4` с теми же весами.

Вывод: уникальность давали **«чистый» вызов и глубина рассуждения**, а не особые
веса GPT-5.4.

### 5. Ценные находки во многом случайны

Сравнение сырого ответа GPT с её же ответами на тех же блоках в повторных прогонах
(ответы из платного кэша исключены):

| Тип уникальной находки GPT | Пар прогонов | GPT нашла снова | Codex нашла |
|---|---:|---:|---:|
| Принятая экспертом | 19 | 21–26 % | 5–11 % |
| Отклонённая | 171 | 44–49 % | 4–10 % |

Свои принятые находки GPT повторяет лишь в каждом четвёртом прогоне, а шум —
в каждом втором. Выборка мала, а сопоставление лексическое (`SequenceMatcher`,
пороги 0,35/0,5), поэтому это предварительная оценка. Её надо перепроверить судьёй
в Этапе 2.

## Выводы для следующих этапов

1. **Главная гипотеза:** вернуть «чистый» вызов и глубину рассуждения, а не модель
   GPT-5.4. Отсюда кандидаты:
   - Claude через `claude_json_runner` (`--system-prompt` без агентской обёртки);
   - Codex-ноги с усилием medium вместо low;
   - промпт с протоколом исчерпывающей сверки внутри листа (класс из п. 3).
2. **K1 `codex/gpt-5.4` на low не имеет смысла:** история уже показала 0,40 находки на
   блок против 0,74 у OpenRouter. Проверять его есть смысл только с усилием
   medium/high — как проверку «компенсирует ли усилие обёртку».
3. **Критерий успеха пересмотрен.** Требовать возврата ≥ 50 % утраченного
   нечестно, если оригинал сам повторяет свои находки в ~25 % прогонов. Новый
   критерий: доля возвращённого не ниже воспроизводимости самой GPT; не больше ~10
   отклонённых на одно принятое. Каждый кандидат прогоняется дважды, чтобы оценить
   разброс.
4. **Дешевле, чем полная нога.** Если запускать дополнительный проход только для
   AR/EOM/KJ/SS/ITP/AI/PT и отсекать категории «Проверить по смежным» и
   «Рекомендательное», ценность почти не теряется, а квота и шум заметно падают.
5. Бесплатной проверки «вернулись ли находки сами» нет: ни одну версию с GPT-прогоном
   не переаудировали в режиме Astra + Sol. Реальную потерю на текущем проде
   покажет только реплей (Этап 2).

## Ограничения

- F-id в разных прогонах перенумеровываются (`docs/stable_finding_id.md`). Сшивка
  проверена по тексту там, где есть запись в базе знаний (15 200 из 22 466); для
  остальных — только по F-id.
- Gap-search судьи видел находки GPT. Без GPT он мог найти часть из них сам —
  это проверит реплей.
- Строгость экспертов различается по объектам. Межпериодные сравнения корректны
  только внутри одного объекта.
