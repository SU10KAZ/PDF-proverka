# Замена OpenRouter-ноги этапа «Блоки» — Этапы 1–3: реплей прода и кандидатов

Дата: 2026-10-11 · Скрипт: `backend/scripts/run_stage01_leg_replacement_replay.py` ·
Метрики: `phase123_metrics.json` · Анализ истории: `phase0_report.md`

## Вопрос

Этап 0 показал, что OpenRouter-нога (`openai/gpt-5.4`) находила уникальные принятые
замечания — в основном сверки внутри листа. Здесь проверено:
1. сколько из этого нынешний прод (Astra + Sol + судья Sol с gap-search) уже находит сам;
2. какая нога на подписке Codex или Claude возвращает остальное и какой ценой.

## Метод

- **Эталонный набор: 181 блок из 89 документов.**
  - B_T — 121 блок, на которых лежат 120 принятых экспертом находок «только GPT»;
  - B_R — 40 блоков только с отклонёнными находками GPT (контроль шума);
  - B_Q — 20 блоков без замечаний вообще.
- **Реплей — боевой код** `run_findings_only_for_project` на копии версии. Окружение
  снято с работающей службы (`/proc/<pid>/environ`): OpenRouter и платные API
  выключены. Каталог данных изолирован; кропы взяты из `.evicted/` — это ровно те
  картинки, которые видела GPT. Код Этапа 01 в репозитории совпадает с боевым
  релизом `ui-real-381fdc96`. Проверено, что `projects_v2` и боевая статистика
  расхода не изменились.
- **Кандидаты — одна дополнительная нога** через боевой одиночный путь
  `call_codex_for_block`: тот же системный промпт, контекст блока, картинка и схема
  ответа. Для Claude в процессе исследования подменён только транспорт
  (`run_codex_json_messages` → `run_claude_json_messages`: base64-картинка,
  `--system-prompt` без агентской обёртки). Шлюз OpenRouter не задействован.
- **Сопоставление** — слепой судья Sonnet 5.5: тот же ли дефект (элемент +
  противоречие). Один вызов на (прогон, блок); вердиктов эксперта и источника
  находки судья не видит. Выборочная ручная проверка пар — совпадения настоящие.
- Прод и Opus medium прогнаны дважды, чтобы видеть случайный разброс.

**Кандидат K1 изменён.** `codex/gpt-5.4` (веса утраченной ноги) Codex с аккаунтом
ChatGPT больше не принимает: HTTP 400 «The 'gpt-5.4' model is not supported when
using Codex with a ChatGPT account». Вопрос «компенсирует ли усилие обёртку Codex»
проверен на Sol с усилием medium (K1′).

## Результаты

### 1. Нынешний прод уже находит около половины «утраченного»

| Прогон | Целевые из 120 | Отклонённые GPT из 64 | Находок на блок B_T / B_Q |
|---|---:|---:|---:|
| Прод, проход 1 | 58 | 17 | 2,2 / 0,55 |
| Прод, проход 2 | 66 | 15 | 2,2 / 0,25 |
| Прод, оба прохода | 76 | 19 | — |

Нынешний код (контекст блоков, поиск по документу, gap-search судьи) заметно
сильнее июльско-сентябрьского. **Реальная потеря при одном проходе — L = 62.**
Второй проход тех же ног добавляет ещё 18: большая доля «уникальности» — это
случайный разброс выборки, как и предсказывал Этап 0.

Цены — эквивалент API по прайсу `usage_service.py`, с учётом кэша промпта, измерены

У Opus low в эксперименте кэш доходил до 99 %: он шёл сразу после Opus medium на
тех же блоках. Это артефакт эксперимента, поэтому его цена пересчитана при кэше
~20 %.

### 3. Где возвращает Opus

Возвращённое распределено так: АР 10, СС 5, ИТП 5, ЭОМ 4, КЖ 4, ВК 1; ОВ и ПТ — 0.
КЖ — до 60 % объёма прода, но в нём лишь 4 из 29 возвращённых. Если включать Opus
только для **АР/АИ/ЭОМ/СС/ИТП**, возврат составит 27–39 % вместо 34–47 %.

### 4. Нагрузка на подписку Claude

С августа прод обрабатывает в медиане ~2 150 блоков в неделю (в пиковую неделю W39 —
6 900), из них ~960 в АР/АИ/ЭОМ/СС/ИТП. Недельный лимит подписки — около $2 120 в
эквиваленте API (калибровка 11.10, `usage_service.py`).

| Режим Opus medium | Медианная неделя | Пиковая неделя |
|---|---:|---:|
| Все блоки | ~9 % лимита | ~29 % |
| Только АР/АИ/ЭОМ/СС/ИТП | ~4 % | ~7,5 % |

### 5. Шум новых находок (предварительно, до калибровки по эксперту)

Слепой судья Sonnet смотрел картинку блока и находку, которой нет ни у прода, ни в
экспертной разметке:

| Новые находки | Всего | Дефект подтверждён | Опровергнут | Без контекста не понять | «Эксперт принял бы» |
|---|---:|---:|---:|---:|---:|
| Opus | 58 | 24 | 2 | 32 | 26 |
| K4 | 40 | 10 | 4 | 26 | 10 |
| Второй проход прода | 37 | 11 | 4 | 22 | 10 |

Судья-модель заведомо мягче экспертов: по истории эксперты принимают 15–20 %
замечаний. Поэтому решающая цифра — слепая выборка из 40 находок (20 Opus, 10 K4,
10 второй проход прода). Она отправлена инженеру: `engineer_review/review.html`,
ключ — `engineer_review/key.json`. Файлы не в git, так как содержат чертежи
заказчиков.

## Выводы

1. **Уникальность GPT-ноги на две трети воспроизводится без неё.** Нынешний прод
   находит 48–55 % её принятых уникальных находок за проход, 63 % за два.
2. **Лучшая замена — Claude Opus 5.5 с усилием medium** через `claude_json_runner`
   («чистый» вызов, base64-картинка). Это единственный кандидат, который проходит
   критерий из Этапа 0 «не хуже воспроизводимости самой GPT (~25 %)». Возврат —
   34–47 % утраченного; среди размеченных — 2,5 принятых на 1 отклонённое (у GPT было
   1 к 10).
3. **Sonnet 5.5 и усилие low у Opus заметно хуже.** Sonnet дешевле Opus лишь
   примерно вдвое, а возвращает втрое меньше. Повышенное усилие у Codex-модели
   с прод-промптом (Sol medium) почти ничего не даёт: агентская обёртка Codex сильнее
   усилия.
4. **Промпт сверок (`astra_shadow_v3`) реально помогает**, и это лучший вариант без
   квоты Claude: K4 возвращает 23 % при минимальном шуме (+16/+3) и одном дешёвом
   вызове Codex. В связке Opus + K4 возврат — 53 %.

## Рекомендация (предварительная, до разметки выборки)

- **Основной вариант:** третья нога этапа «Блоки» — Opus 5.5 medium через
  `claude_json_runner`, только для АР/АИ/ЭОМ/СС/ИТП. Около 4 % недельного лимита
  Claude в обычную неделю, ~7,5 % в пиковую.
- **Резерв без квоты Claude:** Astra с `astra_shadow_v3` (K4). На случай, когда квота
  Claude занята, — либо всегда вдобавок к Opus.
- **Решение по шуму — после вашей выборки.** Если доля «принял бы» среди новых
  находок Opus окажется ниже ~15 %, нужно сначала ужесточить фильтрацию (например,
  отсекать категории «Проверить по смежным» и «Рекомендательное», как показал Этап 0).

## Что потребуется для встраивания (отдельной задачей)

- `call_claude_for_block` на `run_claude_json_messages` (по образцу
  `call_codex_for_block`, `gemma_findings_only.py:1897`);
- новый режим в `ensemble_mode.py` (три ноги без OpenRouter);
- судья на три ноги: `dual_review.py` сейчас сравнивает ровно две;
- маршрутизация по дисциплинам; `detector_summary`, квитанция и
  `audit_routing/registry.py`;
- тесты `tests/test_stage01_openrouter_off.py`;
- учёт расхода Claude-ноги в `manager._record_findings_only_usage`;
- поведение при исчерпании квоты Claude: нога не должна ронять этап при
  `STAGE01_ABORT_ON_LEG_FAILURE_ENABLED`.

## Ограничения

- 120 целевых находок и по 1–2 прохода на вариант — разброс между проходами
  заметный (Opus: 29 и 21). Порядок кандидатов устойчив, точные проценты — нет.
- «Размеченные» отклонённые — только те, что эксперт видел на этих блоках. Шум
  новых находок оценивается по выборке.
- Opus и K4 прогнаны отдельной ногой, без судьи между ногами. В проде судья
  разметит совпадения и может добавить gap-находки — это проверит встраивание.
- Июльско-августовские версии воспроизведены нынешним кодом контекста, а не тем,
  что был при их аудите. Для решения о проде это правильно, для истории — нет.
