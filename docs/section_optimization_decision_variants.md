# Варианты решения по кандидатам оптимизации раздела

## Вариант A — один экономический вердикт по кандидату (выбран)

Карточка показывает действие, область строк и проектов, объём по единицам,
расчёт эффекта и блокеры. Инженер выбирает одно из трёх решений:

- `economic_yes` — эффект рассчитан и технические гейты закрыты;
- `economic_no` — проверка завершена, решение невыгодно или небезопасно;
- `needs_data` — не хватает цены, количества, графики или технических данных.

Проверки по проектам остаются доказательствами и исключениями. Они не требуют
отдельного подтверждения каждой строки, если пакет принят целиком.

## Вариант B — решение по каждому проекту

Это прежний режим. Он точнее для разнородных целей, но превращает один кандидат
в десятки одинаковых кликов. Оставлен как ручная корректировка исключений.

## Вариант C — общий пакет по материалу или семейству

Несколько близких кандидатов объединяются в одну закупочную гипотезу. Вариант
подходит для следующего этапа, когда появится строгий профиль совместимости:
пожарное исполнение, IP, размеры, сечение, нагрузки и единицы измерения.
Пока такие сигналы не объединяются автоматически, чтобы не смешивать разные
технические ограничения.

На актуальном снимке EOM экономический статус кандидатов по умолчанию
`needs_data`: заявленные проценты экономии не считаются подтверждённым эффектом
без сопоставимых цен и текущих объёмов.
