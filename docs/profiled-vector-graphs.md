# Профильные векторные графы блоков

## Что считается эталоном

Эталон — это предметная грамматика конкретного `profile_id`: допустимые типы
контейнеров, узлов, сетей, рёбер и правила доказательности связи. Данные выбранного
эталонного блока никогда не копируются в новый граф.

Для проверяемого блока механизм:

1. находит по точному `block_id` исходные поля Chandra `Тип`, `Краткое описание`
   и `Описание`;
2. вырезает текст и CAD-геометрию строго по полигону блока в исходном PDF;
3. классификатор выбирает `profile_id` по описанию Chandra и точному векторному
   тексту полигона — тем самым выбирается грамматика;
4. профильный построитель создаёт новый граф только из геометрии текущего блока;
5. гейт качества решает, можно ли подавать граф в модель;
6. реестр находит контрольный эталон того же профиля в корпусе;
7. единый пакет сохраняется и без повторной интерпретации используется ChatGPT и TXT-режимом UI.

Поле Chandra `Текст на чертеже`, список `Сущности` и секции `[ENRICHED ...]`
не участвуют даже в классификации. Значения, размеры, марки, узлы и рёбра графа
берутся исключительно из векторного слоя PDF. Если исходного описания Chandra нет,
классификатор использует векторный текст блока и только тогда — контекст листа.

## Канонический артефакт

Стадия `block_context` создаёт по одному файлу
`block_vector_graphs/<block_id>.json`. В нём находятся:

- `discipline`, `profile_id`, происхождение `classification` и выбранный `reference`;
- исходный предметный `graph`;
- `gate`, `validation` и `readiness`;
- полное русскоязычное `markdown`-описание;
- точный `user_text`, который затем получает модель.

`block_context_summary.json` содержит краткий индекс этих файлов. Анализ блоков и
API кнопки TXT сначала читают сохранённый пакет. Поэтому показываемый текст и
фактический контекст модели совпадают.

## Выбор контрольного блока

При точном совпадении `(дисциплина, profile_id)` реестр предпочитает блок с
доступным текстовым слоем, нулём пропущенных фактов семантического аудита и
максимальным числом проверенных фактов. Далее используются разнообразный корпус,
готовый `.structure.json` и, последним резервом, встроенная грамматика профиля.

## Как добавить новый тип

Нужно добавить профиль в соответствующий доменный модуль: классификатор,
построитель, гейт и русский Markdown-рендер. После появления блока в разнообразном
корпусе реестр начинает выбирать его автоматически; менять API, ChatGPT-стадию и UI
для нового типа не требуется.
