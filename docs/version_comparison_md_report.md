# «Отчёт PDF» по MD-сводке изменений версий

Короткий аналитический PDF для руководителя и стройки по готовой «Сводке изменений (MD)»
раздела «Сравнение версий»: насколько изменилась каждая выдача, что это значит для закупки и
монтажа по предыдущей версии, какие изменения серьёзны и где есть неоднозначность.
Пакет — `backend/app/services/version_comparison_ai/md_report/`, промпты —
`backend/app/services/version_comparison_ai/prompts/md_report_*.md`, окно портала —
`frontend/static/js/version-comparison-md-report.js`. Задание-источник — пакет
`experiments/CLAUDE_EM2_MD_TO_PDF.zip` (17.10.2026).

## Как пользоваться

«Сравнение версий» → проект → кнопка **«Отчёт PDF»** в шапке проекта. Источник — текущая
«Сводка изменений (MD)» серии (те же байты, что при скачивании сводки) или загруженный MD-файл.
Галочка согласия на передачу текста исполнителю обязательна. В окне видны ход (анализ N из M,
проверка N из M, обращения и токены), причина ошибки или неполноты, кнопки «Отменить»,
«Продолжить», «Пересобрать PDF» и **«Скачать PDF»** — только у проверенного полного отчёта.
Включение — тот же переключатель ИИ раздела (`ai_settings.json`, `enabled`).

## Путь обработки

| Этап | Что делает | Где |
|---|---|---|
| A. Приём | точная копия (только чтение), размер, SHA-256; не UTF-8 и файл без переходов — отказ | `runner.create` |
| B. Разбор | переходы `## N. шифр: A → B`, листы `###` со страницами PDF A/B, пункты, явные «изменений содержания нет», неописанные места; разрывы цепочки и повторы пар — в `issues`, пары не достраиваются | `parse.py` |
| C. Нарезка | блоки без потерь: переход целиком; большой — по листам, большой лист — по пунктам (заголовок листа — контекстом); покрытие строк 1…N проверяется программно; строка длиннее предела — явный отказ | `plan.py` |
| D. Аналитик | группа блоков → факты «было → стало» со строками MD, масштаб и значимость раздельно, условия выдачи, противоречия | промпт `md_report_analyst.md` |
| E. Проверяющий | вердикт по КАЖДОМУ утверждению (supported / qualified / contradictory / insufficient / rejected), сведение частей перехода, связанные места из других переходов (поиск программой по обозначениям) | `md_report_verifier.md` |
| F. Составитель | короткий текст по report_v1 только из проверенного; программа подставляет подписи A/B, даты, лист и страницы PDF, проверенные оценки | `md_report_composer.md`, `stages.assemble` |
| G. PDF | reportlab, A4 книжная, DejaVu Sans встроен, шапка таблицы повторяется; проверка PyMuPDF: текст в полях, все переходы, числа серьёзных изменений, нет служебной разметки и идентификаторов | `pdf.py` |

Планировщик (промпт 9.2 задания) не вызывает модель: структура, группы и покрытие строятся и
проверяются программой (`plan.py`) — это и есть «программная проверка плана», модель её не заменяет.

## Исполнитель

`codex exec` через `executor.CodexExecDescriber` (тот же, что у ИИ-описаний): эфемерная сессия
на обращение, `--sandbox read-only`, без пользовательского конфига, строгий структурный вывод
(`--output-schema`). Независимые группы идут параллельно (`parallel`, по умолчанию 4) — у сессий
нет общего состояния. Модель по умолчанию — **Sol 6.1 = `gpt-6.1-sol`** (кэш моделей Codex,
`display_name` «GPT-6.1-Sol», окно 500 000 токенов), усилие `high`; CLI — свой `codex_bin` или
закреплённый CLI способа «Изменения в листе» (Sol отдаётся сервером только клиенту 0.162).
Подмены модели нет. Квота/вход → пауза `paused_quota`/`paused_auth`; отказ проверки, ответ не по
схеме, тайм-аут — повтор (`retries`, по умолчанию 1) с перечнем замечаний программы.

Настройки — секция `md_report` в `ai_settings.json` или окружение: `model`/`VC_MR_MODEL`,
`effort`/`VC_MR_EFFORT`, `codex_bin`/`VC_MR_CODEX_BIN`, `parallel`/`VC_MR_PARALLEL`,
`block_chars`/`VC_MR_BLOCK_CHARS` (70 000), `verify_full_chars`/`VC_MR_VERIFY_FULL_CHARS` (150 000),
`call_timeout_s`/`VC_MR_CALL_TIMEOUT_S` (2400), `retries`/`VC_MR_RETRIES` (1). Жёсткий предел
блока — половина окна контекста модели при 2 символах на токен.

## Хранилище и повторяемость

`objects/<object_id>/md_reports/<report_id>/`: `source/` (вход), `manifest.json`, `plan.json`,
`prompts/` (тексты правил, шаблонов и схем на момент создания), `calls/<этап>/<единица>/attempt-N/`
(`prompt.md`, сырой ответ, события CLI с `thread_id`, `call.json` с моделью, CLI, расходом,
причиной ошибки), `results/` (проверенные результаты с ключом совместимости), `report.json`,
`checks.json` (ошибки контракта, согласованность, непроверенные числа, вердикты), `report.pdf`,
`pdf_check.json`, `pdf_preview/`.

Продолжение повторяет только недостающие единицы: результат берётся, если совпал ключ (SHA-256
входа и блоков, версии и отпечатки промптов и схем, модель, усилие). Смена промптов после
создания отчёта — отказ продолжения («создайте новый отчёт»). Повторное нажатие с тем же файлом
во время обработки возвращает идущий отчёт. «Пересобрать PDF» — без обращений к модели.

## Состояния

`queued` → `running` (этапы `prepare`, `analysis`, `verify`, `compose`, `pdf`) → `done`;
`incomplete` — часть групп/единиц без годного ответа (PDF не формируется, перечислены
переходы); `failed` — отчёт или PDF не прошли проверку, причина в `reason`;
`cancelled`, `interrupted` (перезапуск сервера), `paused_quota`, `paused_auth`.

## Проверки программы

- аналитик: те же `run_id`/`group_id`, ровно назначенные переходы, обработаны все блоки,
  ссылки только на назначенные строки, явное «без изменений» не превращено в изменения;
- проверяющий: вердикт по каждому утверждению, итог по каждому переходу единицы, ссылки только
  на показанные строки; кандидаты в серьёзные не опираются на отклонённые утверждения;
- составитель: ровно все переходы, ≤ 5 серьёзных изменений с проверенными `claim_ids` и
  источником, каждое число текста есть в процитированных строках или проверенных формулировках,
  объём ≤ 1000 слов (иначе повтор, затем предупреждение в `checks.json`); оценки масштаба и
  значимости берутся проверенные;
- отчёт: контракт report_v1 (образец `03_EXPECTED_REPORT.json` проходит тот же валидатор),
  порядок и подписи переходов как в источнике, распределение переходов считает программа.

Тесты — `tests/test_version_comparison_md_report.py` (подменный исполнитель, другой шифр и число
переходов).

## Контрольный запуск 18.10.2026 (стенд, вход ЭМ2)

Вход — `Сводка_изменений_133_23-ГК-ЭМ2.md` из пакета задания (796 160 байт, 3 138 строк,
SHA-256 `2e65cca4…e6ba`), загружен через API портала на изолированном стенде (код этого выпуска,
свой каталог данных). Разбор: 11 переходов, 370 листов, 1 855 пунктов; нарезка — 15 блоков
(V5→V6, V6→V7, V7→V8 — по две части), 9 групп аналитика, 6 единиц проверки, покрытие строк полное.

- Отчёт 1 (`mr2026101811164593de`): 16 обращений к `gpt-6.1-sol` high (CLI 0.162.0-alpha.17.2),
  все с первой попытки, ~23 мин, вход 1,04 млн токенов, выход 0,24 млн; 265 утверждений —
  182 supported, 63 qualified, 20 contradictory. В PDF нашлись служебный идентификатор «T10» и
  повтор подписи перехода в строках — добавлены проверка составителя и подстраховка сборки.
- Отчёт 2 (`mr202610181144153f4d`, после правки промпта составителя): 15 результатов аналитика и
  проверяющего взяты из отчёта 1 по ключам совместимости, 1 новое обращение составителя. Проверки
  отчёта и PDF пройдены: 3 страницы A4, 11 переходов (7 технических / 3 без изменений содержания /
  1 только оформление — распределение считает программа), 5 серьёзных изменений, числа сверены
  с источником.
