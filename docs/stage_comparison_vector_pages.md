# Векторная отрисовка листов в просмотрщике «Связь блоков»

**Статус:** с 20.08.2026 вектор — ЕДИНСТВЕННЫЙ режим. Растровый просмотр,
тумблер «⬡ Вектор / ▦ Растр», per-лист фолбэк на растр по `@error` и ключ
`localStorage.sc_vector_pages` удалены из интерфейса. Endpoint `page-image`
остаётся живым, но фронтенд его не зовёт. Всё, что ниже сказано про
переключение и откат на растр, описывает снятое поведение.

## Зачем

Лист формата 2384×3370 pt отдавался растром шириной 1400 px — это **0,42 пикселя
на пункт**. На зуме 400 % браузер растягивал и без того грубый растр вчетверо,
и чертёж превращался в кашу: размеры, марки и примечания не читались.

Теперь страница отдаётся как SVG, и браузер растеризует её под нужное
разрешение на любом масштабе.

## Замеры на боевых листах (13АВ-РД-АР0.1-ПА)

| | растр 1400 px | SVG |
|---|---|---|
| плотный лист 7 (3696 векторных операций) | 510 КБ | 3,6 МБ сырых / **748 КБ по проводу** |
| весь документ V2 (19 листов) | 4,2 МБ | 5,7 МБ gzip |
| генерация всех 19 листов | ~2,3 с | **0,41 с** |
| перерисовка при ширине 16000 px | — | **51–98 мс**, куча JS 3 МБ |
| читаемость на 400 % | нечитаемо | резко |

Вектор оказался ещё и дешевле в вычислении: `get_svg_image` быстрее
`get_pixmap`.

## Почему SVG, а не альтернативы

* **Растр повышенного разрешения** — 4200 px даёт 1,9 МБ на лист и всего
  1,25 px/pt, то есть за пределами ~300 % опять мылит. Дороже и хуже.
* **pdf.js** — пришлось бы вносить ~1 МБ библиотеки и переписывать рендер
  страницы. SVG даёт тот же результат без этого.

## Ключевые свойства

* **`viewBox` = `page.rect`** (проверено: `0 0 2383.92 3370.32` против
  `Rect(0, 0, 2383.92, 3370.32)`). Системы координат block-оверлеев, change
  groups и atomic regions остаются прежними — геометрию править не нужно.
* **`text_as_path=True`** превращает шрифты в контуры. Внешних ссылок в файле
  нет (`@font-face` — 0, внешних `xlink` — 0), поэтому CAD-гарнитуры
  ISOCPEUR/GOST больше не зависят от того, стоят ли они у клиента.
* **Встроенные растры переносятся в ИСХОДНОМ разрешении.** По одному листу в
  каждом документе — полностраничный скан 7015×4961 (V2 стр. 14, V3 стр. 13);
  векторной резкости там взять неоткуда, но SVG отдаёт оригинал целиком
  (0,5 МБ gzip) вместо нынешней копии 1400 px, то есть на зуме появляется
  настоящая детализация. Остальные растры — QR 198×198 и логотипы, доли
  процента листа.

## Кэш

`comparison/sessions/<sid>/pairs/<pid>/pages/<side>/page_NNNN.svg.gz` —
**хранится сжатым**. Несжатый кэш занимал 53 МБ на пару, сжатый — 9,9 МБ.
Заодно снято повторное сжатие на каждый запрос: готовые байты уходят как есть.

Endpoint отдаёт предсжатое тело с `Content-Encoding: gzip`, если клиент это
принимает (заголовок заодно удерживает `GZipMiddleware` от повторного сжатия),
и распаковывает на лету, если нет. Запись атомарная через `.tmp` + `replace`.

## API и UI

```
GET .../sessions/{sid}/pairs/{pid}/page-svg?side=left|right&page=N
```

Растровый `page-image` остаётся и никуда не девается.

Тумблер **«⬡ Вектор / ▦ Растр»** — в панели инструментов левой панели рядом с
зумом; выбор сохраняется в `localStorage.sc_vector_pages`. Если вектор для
листа не отдался, `@error` уводит **этот лист** на растр, остальные продолжают
рисоваться вектором; ручное переключение сбрасывает накопленные сбои.
