# Отчёт: production-каталог эталонов и путь векторных графов в пайплайн

## 1. reference_catalog — встроенный production-каталог эталонов

Расположение: `backend/app/pipeline/stages/block_context/reference_catalog/` (часть pipeline-stage, самодостаточен, runtime НЕ читает `experiments/`).

**Состав и объём (manifest.json, версия `2026.07.13-1`, schema_version=1):**
- Всего **1133 записи, 105 профилей, 9 дисциплин**; `source_digest_sha256` фиксирует хэш исходного корпуса; флаг `runtime_dependency_on_experiments: false`.
- По дисциплинам (файл / записей / профилей / structure_examples): АР `disciplines/AR.json` 247/21/247; ВК `VK.json` 168/11/168; ГП `GP.json` 47/13/47; КЖ `KJ.json` 110/6/110; КМ `KM.json` 71/7/71; ОВ `HVAC.json` 154/9/153; СС `SS.json` 144/19/144; ТХ `TX.json` 35/7/35; ЭОМ `EOM.json` 157/12/157.
- `profiles/*.md` (AR/EOM/GP/HVAC/KJ/KM/SS/TX/VK.md) — человекочитаемые «грамматики» профилей (напр. EOM.md — «Двенадцать логических грамматик ЭОМ»: однолинейка, схема щита, план силовых сетей и т.д.).

**Формат записи дисциплины** (пример `disciplines/EOM.json`): `block_id`, `discipline`, `profile_id` (напр. `cable_route_plan`), `subtype`, `title`, `description` (русское), `source_page`, `source_layer_state` (`text_available`/…), `quality` = кортеж `[complete, covered_facts, evidence]`, `covered_facts`, `structure_signature` = `{node_types: Counter, counts: {nodes_total, containers_total, networks_total, edges_total, *_total из validation}}`. Т.е. в production попал **не сам граф эталона, а компактная сигнатура** его структуры.

**rules.json** (`rules_version: 2026.07.13-1`):
- `selection` — правила ранжирования эталонов: scope `[discipline, profile_id]`, `exclude_current_block: true`, `prefer_complete_candidates: true`, веса `semantic 0.35 / subtype 0.40 / structure 0.15 / quality 0.10`, `quality_weights {complete 0.5, covered_facts 0.3, evidence 0.2}`, пороги confidence `high≥0.55 / medium≥0.35`, `strongest_match_min 0.08`, `top_alternatives 3`.
- `classification` — первичный источник классификации `chandra_description`, fallback `strict_pdf_vector_region`.
- `text_scope` — строгий полигон/прямоугольник, `outside_margin 0.0` (клип текста без внешнего запаса; читается в `singleline_graph_geometry.py:113-122 _catalog_clip_margin`).
- `generic_subtypes` + `semantic_stop_words` — списки для нейтрализации «пустых» подтипов и стоп-слов при токенизации описаний.

**loader.py** — три `lru_cache(1)`-функции с жёсткой валидацией: `load_catalog_manifest()` (loader.py:26), `load_reference_rules()` (:38), `load_reference_records()` (:46, сверяет число записей по manifest per-discipline и total, дисциплину и наличие block_id/profile_id в каждой записи); `catalog_runtime_info()` (:78) — компактная сводка (`catalog_version`, `records_total`, `profiles_total`, `rules_version`, `runtime_source: "pipeline_stage_embedded_catalog"`) — записывается в артефакты стадии.

**build_catalog.py** — ручной одноразовый компилятор (`--source <experiments/блоки разных дисциплин> --target . --catalog-version`). На дисциплину берёт ровно один `*_DIVERSE_CORPUS.json` + один `*_SEMANTIC_COVERAGE.json` (build_catalog.py:134-137), качество `_record_score` (:70) из coverage (missed/covered/evidence), сигнатуру `_signature` (:82) из `*/*_out/*.structure.json`, склеивает `*_PROFILES.md` в `profiles/*.md`, вырезая исследовательские команды `python experiments/...` (:207-212), пишет manifest с sha256 источника.

**Потребители каталога** (rg по pipeline):
- `block_grounding/block_profile_registry.py:18-23` — главный: `select_reference()` (:238) выбирает ближайший эталон (semantic TF-IDF-косинус `_semantic_similarities` :202, `_subtype_similarity` :189, `_structure_similarity` :171, quality) → блок `reference{block_id, match_score, selection_confidence, alternatives, explanation}` внутри каждого пакета; `make_package()` (:375) кладёт `reference_catalog: catalog_runtime_info()` в каждый пакет графа.
- `block_grounding/block_source_router.py:43` — `load_reference_rules` (правила классификации/клипа).
- `block_grounding/singleline_graph_geometry.py:116` — `text_scope.outside_margin`.
- `block_context/builder.py:22,194` и `runner.py:42` — сводка каталога в `block_context_summary.json` (валидатор `contract.py:178-182` требует `runtime_source == pipeline_stage_embedded_catalog` и `records_total > 0`, иначе summary невалиден).
- `prepare/prepare_service.py:526` — версия каталога в сообщении подготовки.

## 2. Скрипты галереи и массовой сборки

**`backend/scripts/build_vector_graph_gallery.py`** (817 строк) — строит ревью-витрину «ВЕКТОГРАФ — <дисциплина>» как 9 псевдо-документов v2 в `projects_v2/objects/214_Alia_ASTERUS/disciplines/POS/documents/ВЕКТОГРАФ — <ДИСЦ>/versions/v001/`. Вход: **напрямую experiments** (`CORPUS_ROOT = experiments/блоки разных дисциплин`, :29): одностраничные PDF-вырезки, манифесты `*.json`, сохранённые графы `*_out/*.structure.json` (+`.structure.md`). Ключевое:
- `discover_blocks()` (:258) — PDF→block_id (`extract_block_id` :112), матч сохранённого графа `choose_graph` (:166); если графа нет — `build_standalone_package()` (:181) прогоняет PDF через **штатный** `resolve_block_package` во временном v2-дереве (граф генерируется CTX-кодом, origin `generated_ctx`).
- `create_graph_package()` (:390) — пишет штатный пакет в `03_analysis/latest/block_vector_graphs/<id>.json`; большой граф выносится хардлинком/файлом в sidecar `_graphs/*.graph.json`, в пакете `graph: null` + `graph_artifact` (читается назад `load_prepared_package`, block_profile_registry.py:456-468).

Страницы = профили (`assign_profile_groups` :309, русские подписи из `PROFILE_LABELS`). Запуск: `--execute`, `--disciplines`, dry-run по умолчанию.

**`backend/scripts/build_all_profiled_block_graphs.py`** (244 строки) — массовая сборка графов для ВСЕХ активных версий projects_v2. `discover()` (:58) обходит `projects_v2/objects/*/disciplines/*/documents/*/versions/v*`, требует `document_graph.json` + индекс кропов (`_blocks_index` :41: `blocks_stage02_100|blocks_gemma_100|blocks`, включая старые runs и legacy_output) + PDF в `02_work/`; фильтр — только объекты с `legacy_path` внутри `projects/`. `_worker` (:120) вызывает `build_block_context()` (та самая прод-стадия) per-версия в `ProcessPoolExecutor` (`--workers 4`); канонический выход всегда `03_analysis/latest/block_vector_graphs/` + summary. Отчёт → `comparison/profiled_block_graphs_bulk/latest.json` (`_write_report` :189), инкрементально каждые 5 версий.

**`backend/scripts/localize_profiled_block_graphs.py`** (114 строк) — пересборка ТОЛЬКО русских Markdown в готовых артефактах `block_vector_graphs/*.json` (rglob по `--root projects_v2`): `_renderer()` (:17) маппит `source_kind`→рендерер (`render_graph_etalon_markdown`, `render_electrical_markdown`, `render_gp_markdown`, `render_ar_markdown`, `render_structural_markdown`, `render_tx_markdown`, `render_hvac_markdown`, `render_water_markdown`, `render_remaining_markdown`/`render_alia_scheme_markdown`), `localize_file()` (:67) заменяет `markdown` и соответствующий фрагмент `user_text` (`_replace_prompt_markdown` :53 — по маркеру `\n\n## Задача:\n`). ## 3. ПУТЬ ГРАФА В ПРОД: от block_grounding до промпта Stage 02 и фронта

**Стадия `block_context` («Векторные графы блоков»)** — полноценная детерминированная стадия пайплайна (0 моделей/сети), запускается под compat-именем gemma: `manager.py:1860-1871 _run_gemma_enrichment_stage` → `run_block_context_stage` (block_context/runner.py:13) → `build_block_context` (block_context/builder.py:48). Идёт после кропов (`_ensure_stage02_crops`), до анализа блоков; статус зеркалится в лог и как `block_context`, и как `gemma_enrichment` (runner.py:48-50, manager.py:2754).

Цепочка построения per-блок:
1. `builder.py:93-99` → `asyncio.to_thread(resolve_block_package, ..., prefer_prepared=False)`.
2. **`block_source_router.resolve_block_package`** (block_source_router.py:669) — каскад профилей с гейтами качества (первый прошедший выигрывает): (1) однолинейка ЭОМ `build_singleline_graph`+`evaluate_vectograf_gate` → `structured_singleline` (:800-819); (2) `electrical_geometry` → `structured_electrical` (:824-852); (3) `general_plan_geometry` → `structured_general_plan` (:854-877); (4) `architecture_geometry` → `structured_architecture` (:879-919); (5) `structural_geometry` КЖ и КМ → `structured_structure` (:921-972); (6) `technology_geometry` → `structured_technology` (:974-998); (7) `water_geometry` → `structured_water` (:1000-1034, ВК раньше ОВ намеренно); (8) `hvac_geometry` → `structured_hvac` (:1036-1068); (9) СС: `low_voltage_geometry` (:1070-1129), затем `alia_scheme_geometry` (:1135-1163) и `alia_remaining_geometry` (:1165-1207) → `structured_alia_scheme`; (10) fallback `raw_vector` — сырой полигон-клип вектор-текста (:1209-1216, порог `_MIN_VECTOR_CHARS=40` :46); (11) `image_only`, если текста нет (:1131-1133). Каждая ветка вызывает `make_package` (block_profile_registry.py:375) → пакет `{schema_version:6, source_kind, discipline, profile_id, classification (+profile_routing при per-block A/B-флаге `STAGE01_PER_BLOCK_PROFILE_ROUTING_ENABLED`, только АИ), reference (эталон из каталога), gate, readiness, validation, graph, markdown, user_text}`. `user_text` = `# Блок {id} | страница PDF {n}` + структурированный Markdown графа + секция `## Задача:` (`_TASK` :103); для `structured_architecture` дополнительно вшивается «Полный точный текст полигона из PDF» (:785-796).
3. `builder.py:135-146` пишет пакет в `_output/block_vector_graphs/<block_id>.json` (атомарно), чистит устаревшие (:171-177), собирает `block_context_summary.json` (`BLOCK_CONTEXT_SUMMARY_FILENAME`) со счётчиками `source_counts`, `profile_counts`, `reference_selection_counts`, `reference_confidence_counts` и `reference_catalog` (:181-198).

**Stage 02 (block_analysis / gemma_findings_only.py):**
- Гейт входа: `validate_block_context_summary` обязателен (gemma_findings_only.py:1701-1705).
- Per-блок: заново `resolve_block_package(..., prefer_prepared=False)` (:1970-1981; намеренно не читает prepared, чтобы подхватывать смену профилей) → `routed_context = (package.user_text, source_kind)`; classification даёт `retrieval_query_text` для `retrieve_document_context` (:1982-2013).
- `build_effective_block_context` (:886) — итоговый промпт: `user_text` роутера (граф-Markdown) **заменяет** базовый `build_block_user_text` (:683, enrichment-JSON+page_text); поверх добавляются контекст листа `_page_context_data_section` + соседние блоки `build_page_neighbors_section` (при `STAGE01_PAGE_CONTEXT_ENABLED`, :911-921) + per-discipline анти-FP оговорка `_absence_caveat_section`; затем `document_type` и retrieval-контекст (:987-999). Легаси-флаги `SINGLELINE_RICH_PROMPT_ENABLED`/`MIRROR_OCR_ENABLED` работают только когда роутер не сработал (`not _router_applied`, :953-985).
- **Что реально уходит в LLM** (`call_gpt_for_block`, :1024): OpenAI-style messages — system prompt + user-контент из ДВУХ частей: `{"type":"text","text": user_text}` (Markdown графа/сырой вектор-текст + контекст листа/соседей) и `{"type":"image_url", ... png base64}` (:1114-1123). Т.е. **картинка PNG + текст, где граф уже отрендерен в русский Markdown; JSON графа в LLM не подаётся**. Тот же текст идёт в кэш-ключ (`stage02_paid_cache.compute_cache_key`, :1073) и во вторую/третью ноги ансамбля `call_codex_for_block` (:1237, :2034-2045). Сырой JSON графа используют детерминированные проверки (`protection_table_check.py:65-68` читает `package.markdown|user_text`; :490 — geometry) и observer'ы. `dual_review.py` (судья) граф напрямую не читает.
- Fallback-иерархия источника видна в `contract.py:20-49`: `structured_* > raw_vector > image_only`; `NO_VECTOR_TEXT_SOURCE_KINDS` → UI-признак `vector_text_available` (`decorate_blocks_vector_state`, contract.py:69).

**Фронт:** endpoint `GET /api/tiles/{project_id}/blocks/llm-text/{block_id}` (backend/app/api/routers/blocks.py:655) вызывает тот же `resolve_block_package` (:809-839) и возвращает: реальные `system_prompt`/`user_text` Stage 02, `stage02_prompt_mode` (=source_kind), `vector_text` (+`vector_usable`), `structured_graph` (разбор формул), `singleline_graph` (+bbox фидеров, пересчитанные в координаты блока :859-877), `singleline_graph_markdown`, полный `block_graph_package`, `profiled_graph` (JSON графа) и `profiled_graph_display` — русскую компактную проекцию (`package_display`, profiled_graph_localization.py:438; словари `PROFILE_LABELS`/`SOURCE_LABELS`/`ru_*` :11-434), `text_groups` (оверлей областей), `vector_text_available`/`vector_graph_message`. Frontend `frontend/static/js/app.js:8262-8363` — панель «Граф схемы» в окне «txt» блока грузит этот endpoint.

## 4. Что перенесено из experiments в reference_catalog, а что осталось

**Перенесено (компиляцией build_catalog.py, версия 2026.07.13-1):**
- 1133 компактные записи-эталона (описание, профиль, подтип, качество из семантических аудитов `*_SEMANTIC_COVERAGE.json`, компактные **сигнатуры** графов из `*_out/*.structure.json`) → `disciplines/*.json`;
- профильные документы `*_PROFILES.md` (для СС — склейка ALIA_SCHEME + ALIA_REMAINING + STRUCTURAL) → `profiles/*.md`, с вычищенными исследовательскими командами;
- правила отбора/классификации/клипа → `rules.json`; контроль полноты + sha256 источника → `manifest.json`.

**Осталось ТОЛЬКО в experiments** (`experiments/блоки разных дисциплин/`, ~2 ГБ, 3700 файлов, помечено `DELETE_CANDIDATE.md` «не удалять автоматически»):
- исходные одностраничные PDF-вырезки (АР 247, ВК 171, ГП 47, КЖ 110, КМ 71, ОВ 160, СС 183, ТХ 35, ЭОМ 163 — в каталог попало подмножество из `*_DIVERSE_CORPUS.json`: напр. СС 183 PDF → 144 записи);
- **полные JSON-графы** `*_out/*.structure.json` (в каталоге лишь сигнатуры-счётчики) и их Markdown-рендеры `*.structure.md`;
- инвентари/аудиты (`*_ALL_BLOCKS_INVENTORY.json`, `*_SEMANTIC_COVERAGE.json/.md`, `DISCIPLINE_COVERAGE.*`) и скрипты (`audit_all_disciplines.py`, `run_vectograf.py`, `extract_*_diverse_corpus.py` и т.п.);
- статусная разбивка эталонов: 983 полных / 124 ограниченных / 26 кандидатов.

**Важная зависимость:** ревью-витрина `build_vector_graph_gallery.py` по-прежнему читает experiments напрямую (CORPUS_ROOT, hard-link графов в sidecar `_graphs/`), т.е. пересборка галереи требует наличия experiments; runtime-пайплайн (block_context/Stage 02) от experiments полностью отвязан — README каталога и loader.py это явно декларируют, а условия удаления experiments перечислены в `DELETE_CANDIDATE.md` (в т.ч. зелёный `tests/test_block_reference_catalog.py`).
