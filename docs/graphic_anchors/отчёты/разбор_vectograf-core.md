## 1. ИЗВЛЕЧЕНИЕ: слова с координатами, поиск страницы, ограничение области

**Два независимых источника текста:**
1. **Плоский текст блока** (`vector_text`) — это `pdfplumber_text` конкретного блока из `02_work/result.json`. Достаётся через `_result_blocks_vector_index()` G:2477 (LRU-кэш по `(путь, mtime)`, maxsize=8): для каждого блока возвращает `{"text": pdfplumber_text, "bbox_norm": coords_norm, "polygon_norm": polygon_points_norm}`. Этот текст парсит структуризатор (S) — формулы фидеров сохраняются в porядке строк pdfplumber.
2. **Слова с координатами** — PyMuPDF: `fitz.open(pdf_path)` → `pg.get_text("words")` в `build_singleline_graph()` G:1481–1490. Формат кортежа fitz используется полностью: `w[0..3]` = x0,y0,x1,y1 (пункты PDF, начало координат — левый верхний угол, Y растёт вниз), `w[4]` = текст, `w[5],w[6],w[7]` = block_no/line_no/word_no (используются в `_singleline_semantic_facts` G:1446–1451 для группировки слов в строки). Все допуски в коде — в пунктах PDF («px»), нормализация — делением на `pg.rect.width/height` (G:1519).

**Поиск нужной страницы PDF (needle-токены).** `page_index` из result.json НЕ совпадает с реальной страницей PDF (задокументированный баг нумерации, G:4). Поэтому `_find_page_index(doc, vector_text)` G:52 перебирает ВСЕ страницы `doc[i].get_text()` и считает попадания needle-токенов. Needles даёт `_distinct_tokens()` G:40: до 8 уникальных редких токенов по регулярке `К\d+\.\d+\.\S+|QF\d+\.\d+|\d{3}\.\d+А|\d{2,3}кВт` (коды цепей, QF-метки, точные токи, мощности). Страница принимается, только если `best_hits >= max(2, len(needles)//2)` — иначе `None` (fail-soft всего графа).

**Ограничение области блока (клип).** `get_text("words")` отдаёт слова со ВСЕЙ страницы, поэтому геометрия режется по области выделения блока (G:1497–1502, флаг `VECTOGRAF_BBOX_CLIP_ENABLED`, default ON, лениво читается в `_bbox_clip_enabled()` G:65):
- `_clip_words_to_polygon()` G:175 — предпочтительно, если у блока есть `polygon_points_norm`: точка-центр слова `((x0+x2)/2/page_w, (y0+y3)/2/page_h)` проверяется через `_point_in_polygon()` G:161 (ray casting even-odd). Точнее bbox: у L-образных блоков осевой прямоугольник захватывает чужой контент в «вырезах» (замер: −550 слов таблицы ТТ при сохранении всех 70 QF, G:178–179).
- `_clip_words_to_bbox()` G:125 — фолбэк по `coords_norm [x0,y0,x1,y1]`; margin по умолчанию из каталога (`_catalog_clip_margin()` G:113 → `reference_catalog.load_reference_rules()["text_scope"]["outside_margin"]`, обычно 0).
- **Оба клипа fail-closed**: битая область → пустой список слов, а не текст всей страницы (G:131–134, 181–183).

**Клип ТЕКСТА (не только геометрии).** При флаге `VECTOGRAF_POLYGON_TEXT_ONLY_ENABLED` (G:74, default ON) плоский текст тоже фильтруется: `_filter_text_lines_to_region(text, region_words, thr=0.6)` G:83 — строка pdfplumber остаётся, если ≥60% её токенов встречаются среди уже клипнутых слов (`Counter` по `w[4]`). **Критично: порядок строк pdfplumber СОХРАНЯЕТСЯ** — пересборка по Y рассыпает формулы фидеров (проверено: 52→0 фидеров, G:87–89). После фильтра фидеры ПЕРЕ-ПАРСЯТСЯ структуризатором из отфильтрованного текста; если результат <3 фидеров — откат на исходный (G:1509–1515). `page_full_text` (для текстовых экстракторов метаданных) = отфильтрованный текст блока, фолбэк — `pg.get_text()` всей страницы (G:1518).

### 2.2 Колоночная модель (главный приём)

**Шаг колонки** = `_median(соседних Δx отсортированных X QF)` (вычисляется в ~5 местах, напр. G:671, 1313, 1418, 1689). Полуширина колонки почти везде **доля шага**: 0.35 (fit-порог привязки), 0.42 (fallback-код, гребёнка освещения), 0.55 (учёт), 0.5 (light-map) — это и есть переносимая идея: допуски НЕ в пикселях, а в долях медианного шага якорей.

**`_bind_codes_columnwise(pq, pc)` G:645 — offset-corrected nearest column (ядро ядра).**
- Вход: `pq` — X-отсортированные якоря панели `[(qx,qy,qf_name)]`, `pc` — токены-коды `[(cx,cy,code)]`.
- Коды смещены от своей колонки на ~постоянную δ. Наивная медиана `δ₀ = median(cx − nearest_qf_x)` ломается, когда |δ| > полушага (лист РП5.1: δ≈+38 при шаге 62 → алиас δ−шаг сдвигал ВЕСЬ ряд на 1). Поэтому **перебор алиасов** `δ ∈ {δ₀−шаг, δ₀, δ₀+шаг}` с ограничением `|δ|<0.9·шаг` (G:675).
- Оценка кандидата `evaluate(d)` G:677: fit = число кодов, попавших в колонку с невязкой `<0.35·шаг`; вторичный критерий — «мин. ведущих пустых колонок» (физика: резервы в хвосте ряда, не в начале); при равных — min|δ| (G:685–689).
- Коллизии → **GEOMETRY_CONFLICT** (G:700–708): (а) код почти равноудалён от двух колонок (`d2−d1 < 10px`) — «код у границы колонки, требует проверки»; (б) 2 РАЗНЫХ кода в одну колонку — реальная коллизия. Оба — заметки в review, НЕ молчаливый выбор.
- **Обобщение:** полностью универсален — «ряд якорей + ряд подписей со сдвигом» есть в любой дисциплине (размерные цепочки АР, оси КЖ, стояки ВК).

**`_split_codes_by_y_rows(qy_med, panel_codes)` G:735** — Y-осведомлённость перед колоночной привязкой: PRIMARY = ряд кодов, ближайший вверх к ряду QF (все в пределах `base+160px` от минимальной дистанции), SECONDARY = верхние ряды (вторичные цепи «ад»/«ан», dy≈500–780) — идут отдельным слоем `secondary_circuits`, в привязке не участвуют. Универсальный приём «многоярусные подписи → связывать только свой ярус».

**Монотонная привязка (fallback + cross-check)** G:1640–1668: коды по порядку X раздаются QF слева направо, резерв пропускает код. Используется ТОЛЬКО если колоночная ненадёжна (`col_links < 60%` кодов, G:1650); при расхождении column↔monotonic на границе колонки — заметка «монотонная дала X; принята колоночная Y» (G:1665–1666). `bind_method` ∈ {column, monotonic_fallback, reserve, none} на каждой линии.

**`_fallback_bind_code(qn,qx,qy,consumer,words,params,qf_out,assigned)` G:1400** — дожим для колонки без кода, строго консервативный: (1) код-ключ структуризатора как ПОДСТРОКА подписи потребителя, длинные ключи раньше (`М4-1.10` до `М4-1.1`, иначе префикс украдёт совпадение, G:1410–1415); (2) единственный незанятый params-токен в тесной X-колонке (`half=0.42·spacing`, Y-окно −430..+20), чья ближайшая QF — именно эта (G:1417–1426). `len(found)==1` — иначе None.

### 2.3 Локальные экстракторы колонки

- **`_extract_consumer_geo(qx,qy,nx,words,formula_vals)` G:552 — «распарсить известное → ОСТАТОК = подпись»** (самый переносимый приём). Колонка `half=min((nx−qx)/2+3, 35)`, Y-окно `qy−345..qy−5` (расширено под 2–3-строчные хвосты подписей). Вычитаются: (а) всё «структурное» по `_CONSUMER_KNOWN_RE` G:538 (код/формула/кабель/автомат/трасса/управление/устройства/учёт/разделители); (б) ТОЧНЫЕ значения формулы линии (`fset` — Кс/cos/P/I и их int-варианты, чтобы убрать «1» от Кс=1, но не тронуть «43 кв.»). Остаток-кириллица → доминирующая X-подколонка (`Counter(round(x/5)*5)`, допуск ±16), сборка сверху вниз (`-w[1]`). Анти-мусор: чистая пунктуация выброшена; итог с <4 буквами → None («лучше честное отсутствие, чем мусор», G:592–599). Обобщение: known-RE — единственная дисциплино-зависимая часть.
- **`_extract_additional_devices(qx,qy,nx,words)` G:610** — доп-аппараты в ВЕРТИКАЛИ QF: колонка `half=min((nx−qx)/2, 31)`, зона `qy−120..qy−18`; якоря `_DEV_ANCHOR_RE = ^(УЗО|МК103|КМ$)` G:604; вокруг якоря Y-полоса ±22px, сбор без `_DEV_EXCLUDE_RE` G:605; нормализация «30 мА»→«30мА». Паттерн «якорь-устройство + Y-полоса сбора атрибутов» универсален.
- **`_pole_for_breaker(qx,qy,ba_xy,poles,dx=44)` G:237** — полюса ищутся на СТРОКЕ автомата (`|y−ba_y|<26`), а не просто ближайшие (иначе захват «2Р» от УЗО выше по колонке); фолбэк `_near(...,dx,−95,110)`. Приём «атрибут привязывается к Y-строке своего хозяина».
- **`_extract_lighting_runs(words, page_h, top_frac=0.30)` G:1359** — «гребёнка» кабель-прогонов освещения: якорь = токен `L=(\d+)м` в верхних 30% листа; `half = max(6, 0.42·median(X-гэпов якорей))`; замыкание `_above(cx,cy,pred)` G:1381 собирает выше якоря по своей колонке сечение (`\dх[\d.,]+$`), прокладку (`(?:Пг|П)\.\d`), марку (`ППГнг…`). Привязка к фидеру — снаружи по колонке QF (G:1685–1694), с guard-стоп-листом `_POWER_CONSUMER_RE` G:1354 (не вешать освещение на силовые потребители). Паттерн «якорь-с-единицей + вертикальный сбор атрибутов» — прямой кандидат для размеров/отметок АР/КЖ.
- **Дедуп дублей QF-меток** G:1556–1560: при повторе метки среди отходящих остаётся ВЕРХНЯЯ (min Y — ближе к ряду кодов), дубль в чужой колонке иначе «ворует» код соседа; счётчик повторов сохраняется ДО схлопывания (G:1621–1624) и уходит в review/validation.
- **Y-разрез отходящие/вводные** G:1544–1547: `y_split = y_min + 0.6·(y_max−y_min)` при разбросе >60px; нижний ряд = вводные QF.
- **Восстановление разорванного CAD-номинала** G:1575–1584: `C 16 А` → пара «число + „А“» на одной строке (`|Δy|<3`, `0<gap<18px`) → синтетический токен «16А»; голые числа НЕ добавляются (расчётные значения не должны стать номиналами).
- **`_singleline_semantic_facts(words,page_w,page_h)` G:1429** — полный координатный реестр подписей БЕЗ рёбер: слова группируются в строки по `(w[5],w[6])`, 8 типизированных паттернов (щит/аппарат/цепь/кабель/сечение/эл.параметр/высотная отметка/электроприёмник, G:1436–1445), каждый факт с нормализованным bbox и явными `evidence_state`/`topology_state` («не создаёт ребро без колоночной или CAD-привязки»). Страховка от потери непривязанного.

### 2.4 Полигон линии («минимальная траектория по данным»)

G:1795–1860: область фидера обводится не геометрической полосой, а по СЛОВАМ, чей текст совпадает со значениями графа (`_hits` G:1827: нормализация `_nrm`, равенство или вхождение при длине ≥4). Два bbox — текст-блок (`qx−2..tright`, Y `qy−330..qy−40`) и автомат-блок (`qx−22..min(qx+46,next_x−8)`, Y `−2..+45`) — соединяются «перешейком» X-перекрытия в одну **I-фигуру** из 12 вершин (G:1846–1857), без выпуклой оболочки (она срезала бы углы). Правая граница текста = координата СЛЕДУЮЩЕГО символа QF (`tright = next_x` при spacing<90, иначе `qx+58`, G:1787–1793) — потому что текст-колонка смещена вправо от символа (~+12px).

## 4. ВАЛИДАЦИЯ: физика и честность

**Физика (S:284–296, структуризатор):**
- Мощность: `|Pуст·Kc − Pрасч| ≤ max(0.01, 2%·Pрасч)` → `power_check`/`power_rate`.

Только active-линии; нестандартное сечение → пропуск проверки (без ложных).

**Честные счётчики (G:1992–2030):** occurrences vs unique раздельно (`codes_linked_occurrences/codes_total_occurrences` по PRIMARY-токенам, `…_unique` по кодам); `duplicate_param_codes` (дубль в ПД — «не исправлено молча»), `duplicate_bindings` (один код на 2 QF), `unbound_param_codes`, `duplicate_qf_labels` + `qf_occurrences_collapsed`, `missing_panel_warnings` (кластер ≥2 непривязанных 4-числовых кодов с общим суб-префиксом = панель без QF-колонок, G:2001–2014), `coverage_gap`. `confidence = codes_linked_unique/codes_total_unique`. `status = "needs_review"` при ЛЮБОЙ аномалии (G:2028–2030).

## 6. СТРУКТУРИЗАТОР (S): диалекты формул

`structure_singleline_text(vector_text, panel)` S:104. Якорь линии = расчётная строка, **два диалекта**:
1. **Объединённый** `PARAM_RE` S:36: `<код> : <Pуст>кВт - <Kc> - <cos> - <Pрасч>кВт- <I>А`; числа с точкой ИЛИ запятой (`[\d.,]+` — без запятой на ЭО-К3 парсились 3 из 37 строк). Физстрока ниже (i+1..i+3) `PHYS_RE` S:61: `<L>м - <ΔU>% - <кабель> - Iкз(1)=<x>кА`.
2. **Разнесённый (ЭО/ЭОМ)** `SEPARATE_PARAM_RE` S:50: семичлен без единиц `Ру - Кс - Рр - cosφ - Iр - L - ΔU` (порядок отличается!), признаётся якорем ТОЛЬКО при коде `SEPARATE_CODE_RE = ^\d*(?:В?РП)\d+(?:-\d+)+$` S:59 в ≤6 строках выше (защита от произвольных семичленных таблиц); кабель — вверх между кодом и потребителем по `CABLE_LINE_RE` (ППГ|ВВГ|NYM|КПС), L/ΔU уже в формуле.

Разворот от якоря (reading-order): трасса — вниз ≤2 строк `ROUTE_RE` S:70 (`^(Лоток|Пг\.|Каб\.|Пг |П\.|см\.)`); потребитель — вверх ≤7 строк, первый не-шумовой (`_is_noise` S:81 по `NOISE_PREFIX` S:73 + KA/ROUTE/SEPARATE_CODE); тип автомата `BA_RE` S:67 — вверх, два лимита i−6/i−9; номинал `KA_RE = (\d+)кА (\d+)А` S:68 — аналогично; **QF принимается ТОЛЬКО на дистанции ровно 2 строки** (S:219–227, иначе null — QF дрейфует по X-колонке, «жадный» захват запрещён). Секции шин — маркеры `SECTION_RE = ^L1,?\s*L2,?\s*L3$` S:71, `section_of()` S:138; сироты → «СШ-0». `_f()` S:97 — русская запятая→точка. Возврат None, если якорей <2 (S:133–134). Выход: `bus_sections[].feeders[]` + validation (см. §4).
