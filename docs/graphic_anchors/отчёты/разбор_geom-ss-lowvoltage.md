# Отчёт: дисциплинарные геометрии СС (слаботочка) и «Алия»-профили

Все четыре модуля — детерминированные построители графов из вектор-слоя PDF (PyMuPDF/fitz), без OCR/LLM, fail-soft (любой сбой → `None`). Общая опора: `_lines()` (строки текст-слоя с bbox/center), `page.get_drawings()` (CAD-пути), `build_segment_components`/`point_segment_distance` из `vector_path_graph.py`, русификация состояний через `profiled_graph_localization.py` (`ru_state`, `ru_subtype`, `ru_profile`, `ru_node_type`, `ru_network_type`).

## 1. low_voltage_geometry.py (1032 строки, PROFILE_ID = "low_voltage_scheme")

### (а) Подпрофили
Классификатор `classify_low_voltage_subtype()` (:91-113) — только по вектор-тексту:
- **aps_structural** — структурная схема АПС «ПО → АЛС → этаж → адресное устройство»: ≥10 адресных токенов + «АЛС» + ≥2 этажных маркера (:94-107);
- **aps_fragment** — те же адреса/АЛС, но 0-1 этажный маркер: план/узел/продолжение, этажную иерархию строить нельзя (:105-107, комментарий);
- **tray_axonometry** — ≥3 совпадений `_TRAY_RE`+`_SLEEVE_RE` (:108-109);
- **terminal_wiring** — ≥4 сигналов READER/RS-485/DOOR/EXIT/SENS или «Схема электрических подключений»+кабельная марка (:110-112).

Маппинг на UI/CTX-профили — `PROFILE_IDS_BY_SUBTYPE` (:24-29) + `profile_id_for_subtype()` (:32-34): `fire_alarm_loop_topology`, `cable_tray_axonometry`, `low_voltage_terminal_wiring`.

### (б) Якорные точки (regex)
- `_ADDRESS_RE` (:37-40) — главный якорь АПС: адрес вида `9A2.144`, `1BTH1.165(107)`, `2BTM3.12..15` с группами controller/family/loop/start/end/logical. Разобрано двойное кодирование: число после точки = позиционное обозначение, в скобках = логический адрес шлейфа (комментарий :287-291);
- `_DEVICE_TYPE_RE` (:41-45) — подписи типов (МДУ-1С, АМ-4, ИЗ, РМ-4, РМ-1С, 2ДППК, BGB, ШУН/В, СКУД…);
- `_ZONE_RE` (:46) — зоны Вж/Вкр/Пкр/ПД/ДУ/ВЕлш; `_AUX_RE` (:47) — атрибуты (Д, упр., лифтом…);
- `_ALS_RE` (:48) — метки шлейфов «АЛС N.M»;
- `_TRAY_RE` (:50-56) — «Лестничный/Листовой лоток СБ/СПЗ/СЛЗ [с перегородкой] 300х100, L=12,5 м»; `_SLEEVE_RE` (:57-61) — «Гильзы в перекрытии N шт. ∅50, L=200 мм»;
- `_COMPONENT_PATTERNS`/`_COMPONENT_SEARCH_NAMES` (:63-75) — конкретные марки СКУД/домофонии (STR-1AP-M, УК-2П, ИО 102-26, Кнопка выход, Электромагнитный замок…); `_CABLE_RE` (:76-80) — марки КСПВПнг(А)-HF, U/UTP Cat5e;
- корень ПО: `_extract_root()` (:253-264) — слово «ПО» + `№\d+` в радиусе dx<24, dy<28.

### (в) Геометрические приёмы
- **Y-ряды этажей**: `_extract_floors()` (:156-173) — слово «этаж» + число НАД ним (|dx|<14, 0<dy<32), «Кровля» отдельно; сортировка по Y. Устройство → ближайший этаж по |ΔY| (:293);
- **X внутри этажа для помещений**: `_extract_rooms()` (:176-199) — «пом.» + «№…» справа в одной строке (|ΔY|<5, 0<ΔX<100), затем устройство → ближайшее помещение того же этажа по |ΔX| (:294-295);
- **близость с весом Y**: `_nearest_label()` (:202-212) — метрика `|dx| + 1.5*|dy|` в окне dx<31/dy<28 для типа устройства; `_near_attributes()` (:227-236) — окно 34×48 для зон/атрибутов; `_device_bbox()` (:239-250) — bbox устройства = union соседних слов в том же окне;
- **семантическая привязка шлейфа** — не по геометрии, а по коду адреса: loop = `АЛС{controller}.{loop}` (:292);
- **continuity-check адресов**: `_build_aps_graph()` (:333-343) — разрывы диапазона (`scope_gaps`), но при смешанной адресации (логическая+прямая на одном АЛС) сравнение отключается — `address_continuity_state = "not_comparable_mixed_addressing"` (:340-359), иначе «сотни ложных дыр»;
- **клип блока**: в `build_low_voltage_graph()` (:860-877) переиспользуются `_clip_words_to_bbox/_clip_words_to_polygon` из `singleline_graph_geometry` — соседняя схема не протекает в граф;
- **лотки**: `_build_tray_graph()` (:428-498) — инвентарь по regex + сцепка «выноска→цветная геометрия» через `extract_callout_leaders` из `vector_path_graph` (:453-469), zip по порядку;
- **клеммники**: `_position_terminal_components()` (:510-556) — `page.search_for(имя)` + кластеризация прямоугольников с зазором ≤20 (`_bbox_gap` :501-507), zip кластеров с экземплярами по (y,x); топология через `build_terminal_wiring_topology` (:577-591);
- **поиск страницы**: `_find_page_index()` (:132-142) — голосование по «отличительным токенам» `_distinct_tokens()` (:116-129), порог ≥ половины.

### (г) Маркировка недостоверного
Самая богатая шкала из четырёх модулей:
- устройство: `status = "requires_review"` если нет типа или этажа (:324); `device_type_source` = nearby_label / address_family / **not_extracted** (:316-318);
- `validation.physical_loop_path_state = "visual_unverified"` — физическая трасса шлейфа НЕ прослежена, только семантика кодов (:421);
- лотки: `topology_state = "visual_unverified"` (:489), `geometry_state = "visual_unverified"` при непривязанных выносках (:466-469), status `inventory_only`/`not_extracted` (:497);
- клеммники: `topology_state = "partial_confirmed"/"not_extracted"` (:623), status `partial_topology`/`requires_path_tracing` (:628); многоклеммные сети остаются `multi_terminal_review`, НЕ разбиваются на пары (:602-605);
- warning про разрывы диапазона прямо запрещает считать их дефектом без кросс-листовой проверки (:396-400);
- гейт `evaluate_low_voltage_gate()` (:896-956): aps_structural — ≥10 точек, floor_rate ≥95%, type_rate ≥90%; aps_fragment — режим `address_inventory` без этажей; лотки ≥3 элементов; terminal — ≥1 confirmed_pair + parent/label rate ≥90%.

### (д) Незакоммиченный diff и слабые места
**Diff HEAD** добавляет ровно два элемента: `PROFILE_IDS_BY_SUBTYPE`+`profile_id_for_subtype()` (:24-34) и большую `normalize_low_voltage_graph()` (:632-835) — универсальную проекцию containers/nodes/networks/edges для окна CTX (специализированные поля остаются источником истины; `readiness.complete` только для aps_structural со status ok, :756-763).

Слабо покрыто (по warnings/fail-soft):
- физическая трасса шлейфа АПС — только `visual_unverified` (:421);
- связность лотков: «связность цветных сегментов требует трассировки vector paths; инвентарь точный» (:496), `connections: []` (:483);
- terminal_wiring: «кабельная марка ещё не назначена path-сетям» (:599-600), `required_next_layer: "cable-label binding + multi-terminal network disambiguation"` (:624);
- `_family_device_type()` (:215-224) сознательно НЕ выдумывает расшифровку производителя для семейства «A»;
- компоненты/кабели заданы жёсткими списками марок конкретного альбома (перенос на другой проект требует расширения словарей).

### (е) Отличия от эталона ЭОМ (singleline_graph_geometry.py)
- у ЭОМ единая грамматика (X-колонки отходящих линий + QF↔код), здесь — **три разные грамматики в одном модуле** с классификатором по вектор-тексту;
- новинка — **семантическая топология по коду адреса** (шлейф из `АЛС{c}.{l}` внутри адреса) вместо геометрической трассировки: рёбра `contains_loop/serves_floor/contains_device` не требуют線ний;
- новинка — **двухшкальный continuity-check** адресной ёмкости с отключением при смешанной адресации;
- новинка — деление structural/fragment по числу этажных маркеров (защита от построения ложной иерархии на фрагменте);
- новинка — режимные гейты (`mode`: hierarchy / address_inventory / inventory_only / confirmed_connections_only) вместо единого порога.

### (д) Слабые места
- многие минимумы `_GATE_RULES` захардкожены под конкретный объект ALIA (например ровно ≥7 шкафов и ≥9 сегментов для кольца ВОК :904, `ring_closed` = счётный признак :417, не трассировка);
- fallback-ярус классификатора (:111-138) держится на уникальных марках одного альбома — на другом объекте сработает только верхний ярус;
- СОУЭ: шкаф для радиала — просто ближайший (`nearest_row_geometry`), не по трассе;
- лифт/МГН: `connect(..., same_building=True)` при пустых кандидатах откатывается на все корпуса (:598) — потенциальная межкорпусная догадка;
- дефолтная ветка гейта: «для профиля не определён строгий критерий полноты» (:964).

### (е) Отличия от ЭОМ
- **контейнерная модель** containers/nodes/networks/edges с provenance-состояниями каждой связи (у ЭОМ — колонки и рёбра фидеров);
- **X-полосы корпусов + Y-этажи** как двумерная сетка размещения (ЭОМ одно-корпусной);
- **цвет линии как тип сети** + сверка с легендой + `legend_only` для непротрассированных;
- **полигональный клип через инъекцию в content-stream** (`_clip_copied_page`) — ЭОМ клипует только слова;
- `semantic_ledger` — полный координатный текст-реестр как отдельный слой доказательств;
- «декодирование корпуса из марки» с приоритетом над геометрией.

- **панель**: `physical_order` по Y (:494); монтаж/СКУД — чистый инвентарь + `_path_metrics()` (:68-74, счётчики сегментов по цветам, vivid_segments).

## Сквозные наблюдения для обобщения на все дисциплины
1. Общий словарь provenance-состояний фактически сложился: `present / semantic_confirmed / annotation_confirmed / *_geometry_grouped / requires_review / visual_unverified / not_extracted / inferred_*` — но он размазан по модулям и не формализован единой схемой (частично закрывает незакоммиченная `normalize_low_voltage_graph`).
2. Три независимых источника связей везде ранжированы одинаково: **код в марке > текстовая аннотация пары > цветной CAD-путь > геометрическая близость**; близость всегда получает пониженный provenance.
3. Незакрытые ниши для цели «размер→полочка→элемент»: `_build_install`/`_build_panel`/`_build_access` (alia_remaining) и tray_axonometry (low_voltage) хранят размеры/выноски как инвентарь без трассировки выносных линий — единственный задел это `extract_callout_leaders` (low_voltage_geometry.py:455-459).
