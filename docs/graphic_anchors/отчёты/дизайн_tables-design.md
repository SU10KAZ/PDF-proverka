### `table_structured` — универсальный табличный профиль (~250 блоков корпуса)

**ЯКОРЯ (текстовые):**
- заголовок таблицы: `^(СПЕЦИФИКАЦИЯ|ВЕДОМОСТЬ|ЭКСПЛИКАЦИЯ|КАБЕЛЬНЫЙ\s+ЖУРНАЛ|ТАБЛИЦА|СВОДНАЯ ВЕДОМОСТЬ|СТРОИТЕЛЬНОЕ ЗАДАНИЕ)` (регистронезависимо) — в Chandra-описании и/или в верхней полосе региона;
- строка продолжения ГОСТ 2.105: ряд из последовательных целых `1 2 3 … N` — маркер «таблица-продолжение, именованная шапка на предыдущем листе»;
- итоговые строки: `^(Итого|Всего|ИТОГО ПО|Общая)`;
- словари шапок подтипов (§2) + переиспользуемые контракты `vj.CODE_RE/MARK_RE/SECT_RE` (journal_table_geometry.py:27-31) и лексика единиц (`м|км|шт|компл|кг|м2|м²|м3`).

**ЯКОРЯ (графические, все эмпирически подтверждены):**
- **линейка строки** = склейка коллинеарных H-сегментов; **линейка колонки** = V-сегмент, покрывающий ≥15% высоты региона;
- **регион таблицы** = кластер линеек одного X-спана (после склейки), Y-разрыв > ~3 медианных высот строки = разрез;
- **рамка/шапка** = линии толстого класса (бимодальность 1.0–1.44 vs 0.24–0.48 pt);
- **объединённая ячейка (шапка)** = отсутствие V-линии в полосе ряда при наличии её ниже;
- **обёрнутая ячейка** = ряд без собственной линейки снизу / высота ×1.7 медианы;
- анти-якоря: рамка листа (спан ≈ ширина страницы), штамп (регион у правого нижнего угла), псевдосетка чертежа (>5% слов поперёк V-линий).

**ПРАВИЛА СВЯЗЫВАНИЯ (пошагово):**
1. Клип блока — существующие `_clip_words_to_polygon`/`_clip_words_to_bbox` (ярус A, singleline_graph_geometry.py:125/175, fail-closed).
2. Сегменты: расширенный `flatten_line_segments` с разворачиванием `"re"`/`"qu"` в 4 стороны (сейчас игнорируются — vector_path_graph.py:91) + перенос `width`.
3. Склейка коллинеарных → линейки; кластеризация Y линеек (tol 1.5 pt) → `ys`, X колоночных линий → `xs` (кластеризатор = обобщение `_cluster_rows` из spec_table_geometry.py:52).
4. Регионы: кластер по X-спану ± 6 pt, исключение рамки листа и штампа; ≥4 линеек.
5. Ячейки: `bisect` центра слова в `xs`/`ys`; сборка текста ячейки в порядке (y, x); слово поперёк линии → счётчик конфликта (не молчаливый выбор — принцип GEOMETRY_CONFLICT ярусa B).
6. Шапка: ряды выше первой «числовой» строки тела; многоуровневость — по V-протяжённости (п.3 якорей): родительская ячейка получает `children=[колонки под ней]`.
7. Типизация колонок по заголовку → `typed_columns` (словарь подтипа §2); неузнанная шапка → `generic_table`, колонки `col_1..N` с образцами значений.
8. Обёртка строк: ряд, у которого ключевая колонка (Поз./Номер) пуста, а соседние заполнены → присоединение к предыдущему ряду (перенос приёма `Y_NEAR_TOL` journal_table_geometry.py:80-90).
9. Продолжение таблицы: цифровая строка «1…N» без именованной шапки → `continuation=true`, шапка наследуется от предыдущего блока той же цепочки листов; state-перенос значений («текущая марка») — готовый механизм spec_table_geometry.py:74-89.
10. Непопавшие слова → `semantic_ledger` (гарантия полноты, hvac_geometry.py:253-261), не теряются.

**НОВЫЕ ПРИМИТИВЫ (в общую библиотеку, ярус A/B):**
- `merge_collinear_segments(segs, gap_tol=2.0)` — нужен и таблицам, и размерным цепочкам АР/КЖ;
- `detect_ruled_regions(H, V, page_rect)` c исключением рамки/штампа;
- `build_cell_grid(xs, ys)` + `assign_words_to_cells(words, grid)` с контролем пересечений;
- `detect_merged_header_cells(V, header_band)`;
- классификатор толщины линий (порог = впадина бимодального распределения `width`);
- `classify_table_kind(header_tokens, n_cols)` — реестр подтипов §2.

**FINDINGS (детерминированные, без LLM):**
- арифметика: «Итого/Всего» ≠ сумма числовой колонки; `Кол. × Масса ед.` ≠ масса всего [ГОСТ Р 21.101-2020, ГОСТ 21.501-2018 — формы; категория Экономическое];
- нумерация позиций: дырки/дубли в «Поз.» [Рекомендательное];
- пустые обязательные ячейки формы (нет ед. изм., нет кол-ва) [Рекомендательное];
- кросс-блочная пересортица (§3) [Экономическое/Критическое].

**ГЕЙТ `evaluate_table_gate`:** use=true если: тело ≥3×3; ≥90% слов блока в ячейках; ≤5% слов поперёк V-линий; регулярность высот строк (CV медианы < 1.5); шапка классифицирована ИЛИ generic с ≥60% непустых ячеек занятых строк. Провал → штатный дисциплинарный каскад без потерь.

**ПРИОРИТЕТ/ЭФФОРТ:** ценность высокая (250 блоков, сейчас идущих в чужие графические профили или мимо роутера; таблицы = концентрат проверяемых чисел), сложность средняя — ядро доказано пробами, ~600-800 строк нового кода. Делать первым.

## 3. Связь ТАБЛИЦА ↔ ЧЕРТЁЖ (кросс-блочные рёбра)

Роутер работает по-блочно, поэтому кросс-рёбра строит **отдельный проход после сборки пакетов**, новый модуль `backend/app/pipeline/stages/block_grounding/table_cross_reference.py`:
1. читает пакеты версии из `_output/block_vector_graphs/` (block_profile_registry.py:437 `artifact_path`);
2. индексирует «валюты связи»: `Поз. N` / `Д-N` / `М-N` / коды цепей `К1.1.x` / марки Стм/Пм / номера помещений — у чертёжных графов это уже existing узлы (`position` structural_geometry.py:15, `opening` architecture_geometry.py, `finish_mark`, фидеры Вектографа);
3. пишет в ОБА пакета `cross_block_edges: [{value, value_norm, from_block, from_cell:{row,col}, to_block, to_node_id, edge_state}]`, где `edge_state` ∈ {`exact_value_match`, `normalized_match` (canon_mark/canon_val из spec_table_geometry.py:30), `ambiguous_multi_target` (заметка, не выбор)};
4. непарные значения → `unmatched_positions`/`unmatched_marks` — готовые findings «позиция в спецификации не найдена на чертеже и наоборот».

Это прод-порт уже доказанной связки `crosssheet_valuejoin` (журнал↔схема↔спека).

## 5. Порядок работ (приоритет × эффорт)
