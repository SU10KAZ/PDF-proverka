# Отчёт: слой векторных путей (`get_drawings`) в PDF-proverka

## 1. Что уже умеет `vector_path_graph.py` (623 строки, доменно-независимый backbone)

**Файл:** `backend/app/pipeline/stages/block_grounding/vector_path_graph.py`

### Извлекаемые примитивы
- **Только отрезки `"l"`**: `flatten_line_segments()` (vector_path_graph.py:71–107) разворачивает drawings в нормализованные сегменты `{p1, p2, length, color, width, drawing_index, item_index}`. Item-типы `"re"`, `"qu"`, `"c"` при флэттене **игнорируются** (строка 91: `if item[0] != "l": continue`). Фильтры: `stroke_only` (drawings с fill отбрасываются, :82), `color_mode` = any/black/neutral/vivid, `min_length` (default 1.0 pt).
- **Цветовая классификация**: `_is_black` (:19, tolerance 0.03), `_is_neutral` (:23, max−min ≤ 0.06), `_is_vivid` (:27, chroma ≥ 0.2).
- **Клеммные овалы**: `detect_terminal_ellipses()` (:110–170) — единственное использование `"c"`-items: ищет drawings с kinds == `("c","c")` (полуовал), чёрный stroke без fill, rect 7–10 × 3–6 pt; спаривает верхний/нижний полуовал (общая X-ось ≤ 0.35 pt, касание ≤ 0.35 pt) → физическая клемма (`merged_halves` / `half_unpaired`). Узкоспециализировано под пилотный СОВ (окружности 8.5×8.5 pt из двух paths).
- **Корпуса приборов (quads)**: `detect_terminal_parent_regions()` (:187–234) — drawings с kinds == `("qu",)`, 40 ≤ w ≤ 50% страницы, 35 ≤ h ≤ 85%, содержащие ≥2 клемм (margin 0.7); вложенные кандидаты («внутренние таблицы клемм — тоже quads») отбрасываются; подпись = ближайший component_label на дистанции ≤ 30 pt.
- **Клип по блоку**: `_drawings_for_bbox()` (:53–56) фильтрует `page.get_drawings()` по пересечению `drawing["rect"]` с абсолютным bbox блока (из `bbox_norm`).

### Сборка графа
- `build_segment_components()` (:455–531): узлы = концы сегментов, дедуп через грид-раундинг с tolerance **0.6 pt** (:465); union-find; **T-соединение** — конец одного сегмента лежит на внутренности другого (`point_segment_distance` ≤ tolerance, проекция строго внутри, :493–506). **X-пересечение НЕ соединяется** (осознанное правило «электросхемы без junction-dot»). T-проход — **O(N²)** с комментарием «приемлемо для ~1k сегментов, но не для сырого CAD» (:491–492).
- `attach_anchors_to_components()` (:534–553): центр якоря → ближайший узел графа, `max_distance=6.0`.
- `build_terminal_wiring_topology()` (:277–452) — полный конвейер СОВ: drawings → клеммы → корпуса → чёрные внешние сегменты (`_external_segments` :263 выкидывает геометрию целиком внутри корпуса, margin 0.4) → компоненты (tol 0.6) → клемма как электрический стык объединяет все path-компоненты в радиусе **4.8 pt** от её центра (:346) → сети. Подпись клеммы: `_terminal_text_label` (:244–260, лексикон `_TERMINAL_LABEL_RE` :237 — «+/−/цифры/GND/DOOR/PE/COM/NC/NO/АЛС», окно |Δy| ≤ 7, |Δx| ≤ 75, score = gap + 1.5|Δy|). Родитель-fallback: ближайшая подпись ≤ **120 pt** (`nearest_label_inferred`, :312). Классы сетей: `confirmed_pair` (ровно 2 клеммы двух приборов) / `multi_terminal_review` / `internal_or_unbound` (:388–391); кабельная марка честно `cable_state="not_extracted"` (:414). Богатый блок validation-счётчиков (:427–451).
- `extract_callout_leaders()` (:582–623) — выноска→цветная геометрия: текст-блоки с **захардкоженными** префиксами («Лестничный лоток», «Листовой лоток», «Гильзы в перекрытии», :590); leader = нейтральный **диагональный** сегмент (min_length 5.0; ортогональные рамки/оси отброшены условием dx > 0.3 И dy > 0.3, :596–598); конец возле bbox текста (< 8.0 pt), второй конец → ближайший vivid-сегмент (`geometry_linked` при ≤ 7.0 pt), возвращает `target_color`.
- `terminal_network_diagnostics()` (:556–573) — метрики готовности без семантики.

## 2. Что из «строительных» якорей реально закодировано, а что отсутствует

| Механизм | Статус | Где |
|---|---|---|
| Засечки/стрелки размерных линий | **ОТСУТСТВУЕТ полностью**. Grep по arrow/tick/засечк — нулевой в геометрии. «Размеры» везде = regex по ТЕКСТУ (`architecture_geometry.py:80`, `structural_geometry.py:18`, `water_geometry.py:345,408`, `technology_geometry.py:13`) без привязки к размерной линии | — |
| Полочки выносок | **Частично**: только диагональный leader к цветной геометрии с захардкоженным списком текстов (vector_path_graph.py:590). Горизонтальная «полочка», полилиния-leader, стрелка/точка на конце — нет | `extract_callout_leaders` |
| Осевые марки (кружок с буквой/цифрой) | **Только по тексту**: `_plan_axes` (`alia_remaining_geometry.py:88–104`) группирует повторяющиеся токены-подписи по разбросу X/Y (вертикальная ось: ΔY > 35% страницы и ΔX < 8%); аналогично `structural_geometry.py:83`, `architecture_geometry.py:139`, `technology_geometry.py:48` пишут `graph["grid"]={"axes":…}`. **Кружок оси не детектируется**, линия оси (штрихпунктир) не находится | текст-слой |

Универсального парсера сетки таблиц из линий НЕТ | structural_access |
| Junction-dot (точка пайки) | **Декларирован в доке** (VECTOR_PATH_GRAPH.md:41), **в коде отсутствует** — просто X-crossing никогда не соединяется | — |
| Дуги/кривые `"c"` | Только счётчики-кандидаты: `hvac_geometry.py:575–585` и `water_geometry.py:429–433` (`_build_chart`: drawing с `"c"` в kinds или ≥3 items = «кривая характеристики», геометрия НЕ разворачивается), `electrical_geometry.py:274–276` (поля освещённости). Безье не флэттенится в полилинии | счёт, не геометрия |
| Прямоугольники `"re"` | Не используются как сегменты нигде; quads `("qu",)` — корпуса приборов (vector_path_graph.py:192) и рамки аппаратов (`alia_remaining_geometry.py:150–186`, 20–400 × 15–250 pt, подавление дублей позиционных обозначений) | частично |

## 3. `get_drawings` в experiments

- **~90% использований — только метрика**: corpus-скрипты (`extract_ar_diverse_corpus.py:100`, `build_kj_corpus.py:95`, `build_km_corpus.py:91`, `extract_eom_diverse_corpus.py:156`, `extract_gp_corpus.py:80`, `extract_hvac_diverse_corpus.py:271`, `extract_ss_diverse_corpus.py:100`, `extract_vk_diverse_corpus.py:236`, `build_tx_corpus.py:77`) пишут `len(page.get_drawings())` в манифест как индикатор «вектор жив».
- **`experiments/блоки разных дисциплин/ВК/build_vk_fire_piping_graph_v02.py`** — самое честное признание границы: `:103–105` считает `dr_lines`/`dr_rects` из items, но топология труб по paths **сознательно не разбирается** (`:10`: «рёбра строятся только по тексту»; `:890`: `"geometry_sources_NOT_used": ["page.get_drawings() трассировка труб/выносок (v0.3)"]`). Граф v0.2 строится из текстовых строк (`build_lines`), зонирования листа жёсткими координатами кропа (`zone_of`) и линейной регрессии Y→отметка (`linreg`, quality = доля остатков < 1 м).
- **ВАЖНОЕ уточнение по таблицам**: `experiments/vector_pipeline/journal_table_geometry.py` и `spec_table_geometry.py` решают таблицы **НЕ по линиям сетки, а по координатам СЛОВ**:
  - `journal_table_geometry.py`: колонка = медиана X слов, матчащих regex типа (`_median_x` :38); допуски `X_COL_TOL=55`, `Y_NEAR_TOL=22` (ловит обёрнутую ячейку «4х(1х70)+(1х50)» строкой выше/ниже кода), `Y_ROW_TOL=4` (:33–35); сборка продолжения марки «FRHF» из узкого бокса `_assemble_mark` (:43–57); потребитель = слова между колонкой кода и колонкой марки (:92–96).
  - `spec_table_geometry.py`: ряды = Y-кластеризация `_cluster_rows` (:52, ytol 4.0); текущая марка переносится между страницами как state (:74–89); анти-габаритный фильтр — кабель обязан иметь единицу «м/км» (:104–109); `canon_mark` срезает суффикс напряжения (:30).
  - Т.е. grid-line-парсер таблиц в experiments отсутствует; линии сетки в проде использованы единожды (floors, п.2).

## 4. Что достроить в слое для якорей «размер↔элемент», «выноска↔элемент», «ось↔элемент»

**Фундамент (расширение `flatten_line_segments`):**
1. **Разворачивать все item-типы**: `"re"`/`"qu"` → 4 отрезка (рамки таблиц, корпуса), `"c"` (кубический Безье p1..p4) → сэмплированная полилиния (дуги, кружки осей, скругления труб). Сейчас всё, кроме `"l"`, невидимо для графа.
2. **Перестать выбрасывать fill-paths**, ввести классификатор мелких заливок по площади bbox: заполненный треугольник ~1–3 pt² у конца длинной линии = **стрелка**; заполненный кружок Ø 0.8–2 pt на пересечении проводов = **junction-dot** (закрывает декларацию из VECTOR_PATH_GRAPH.md:41, которой нет в коде); крупные заливки = штриховки/зоны — в отдельный слой.
3. **Извлекать `dashes` и использовать `width`**: штрихпунктир = осевая/центровая линия, тонкие (width ≈ 0.13–0.3) = размерные/выносные, толстые = контуры элементов. `width` уже лежит в сегменте (vector_path_graph.py:103) мёртвым грузом.
4. **Пространственный индекс** (grid-hash bucket'ы) для T-junction-прохода: текущий O(N²) (:491) не переживёт сырой CAD-лист (десятки тысяч сегментов); комментарий в коде это прямо признаёт.

**Якорь «размер↔элемент»:** детектор размерной цепочки = длинная тонкая линия + на концах засечки (короткие 1.5–4 pt сегменты под ~45° к линии — после п.1 они появятся в графе) или fill-стрелки (п.2) + выносные линии перпендикулярно от концов + число-слово с центром у середины линии (у `md_mirror_reconcile.salient_values`/`_RE_UNIT_NUM` уже есть лексика значений). Привязка: значение → пара ног выносных линий → сегмент контура элемента через существующий `point_segment_distance`/`attach_anchors_to_components`.

**Якорь «выноска↔элемент»:** генерализовать `extract_callout_leaders`: (а) убрать захардкоженные префиксы текстов (:590) — принимать любой текст-блок, к bbox которого примыкает конец leader'а; (б) leader как полилиния «диагональ + горизонтальная полочка под текстом» (сейчас полочка отбрасывается фильтром диагональности :596–598); (в) на целевом конце допускать стрелку/точку (п.2) и привязку к ЛЮБОЙ компоненте сегментного графа, не только к vivid-цвету.

**Якорь «ось↔элемент»:** детектор осевого кружка = окружность из 2–4 `"c"`-items (обобщить `detect_terminal_ellipses` за пределы окна 7–10 pt) + ровно одно слово-токен (буква/цифра) внутри bbox; осевая линия = коллинеарный штрихпунктирный сегмент через центр (нужен п.3); сетка осей = пересечения → координатная адресация элементов «в осях 1-2/А-Б». Заменит чисто текстовую кластеризацию `_plan_axes` (alia_remaining_geometry.py:88), которая не знает, где физически проходит ось.

**Таблицы:** универсальный grid-детектор (длинные горизонтали+вертикали + рамки `"re"` → кластеризация в границы строк/колонок → слова в ячейки) — заменит попарные эвристики медианных колонок journal/spec и обобщит приём `_bind_floor_geometry` на все ведомости/спецификации всех дисциплин.

**Контекст остальных прочитанных файлов** (не drawings-слой, но смежные): `qwen_grounding.py` — растровый fallback Phase 2 для блоков БЕЗ вектор-слоя (тайлинг 2600 px / overlap 350 / cap 48 тайлов, доказано 0%→90%, флаг `BLOCK_VALUE_GROUNDING_QWEN_ENABLED`); `md_mirror_reconcile.py` — сверка MD↔вектор-текст по словам (нормализатор кир/лат-двойников, вердикты «вектор верен» для потери десятичной точки/HF→НФ, подсветка в промпт Этапа 01); `mirror_block_text.py` — инжект чистого block-scoped `pdfplumber_text` как приоритетного источника чисел в Stage 02 (флаг `MIRROR_OCR_ENABLED`, min 40 символов). Оба текстовых модуля не трогают `get_drawings`, но дают готовую лексику «значимых значений» для будущей привязки размеров.
