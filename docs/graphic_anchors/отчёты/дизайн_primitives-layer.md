### 1.1 `core.flatten_drawings` — расширенный flatten (разрыв №1)

```python
def flatten_drawings(page, *, bbox_norm=None, polygon_norm=None,
                     clip: str = "crop",           # "crop" | "bbox" | "polygon" | "none"
                     normalize_rotation: bool = True,
                     bezier_max_dev: float = 0.35, # pt, макс. отклонение хорды от кривой
                     min_length: float = 0.3) -> DrawingsLayer
```

Правила (все подтверждены пробами):
1. **Нормализация пространства ПЕРВОЙ**: при `page.rotation != 0` каждый item-пункт умножается на `page.rotation_matrix` (Ф7). Без этого слова и геометрия живут в разных системах — это причина нулевого матчинга на АР узле 019 в probe2.
2. **Клип по `page.rect` обязателен и fail-closed** (Ф6): drawing, чей rect (после поворота) не пересекает кроп, отбрасывается ДО разворота items. Принцип «fail-closed для областей» — тот же, что `_clip_words_to_bbox` (singleline_graph_geometry.py G:131–134).
3. `"re"`/`"qu"` → 4 `Stroke(kind="re_edge"/"qu_edge")`; `"c"` (Безье p1..p4) → адаптивная полилиния `Stroke(kind="c_flat")` с шагом по `bezier_max_dev` (де Кастельжо, 2–8 хорд достаточно при 0.35 pt).
4. **Fill-paths не выбрасываются** (сейчас — blanket-фильтр `stroke_only`, vector_path_graph.py:82): заливки с bbox-площадью < 60 pt² уходят в `fills` с классификацией `kind_hint` по (kinds, w×h, aspect): `lll` + 4–8×3–6 pt → `arrow_triangle`; `cccc` + Ø 2–3.5 → `junction_dot`; `re` + 4.5–6.5 квадрат → `square_marker` (Ф10). Крупные заливки — счётчик `large_fill_count`, геометрия не разворачивается (урок ГП: >120 тыс. hatch-путей, general_plan_geometry.py:155–158).
5. **Полилинии**: подряд идущие l-items одного drawing с совпадением конец→начало < 0.3 pt собираются в `Polyline` (проверено: АР узел 3727, КЖ балка 861 цепочек). Это носитель модели «размерный интервал одной полилинией» (Ф3) и leader'ов.
6. **Окружности**: полные (≥3 c-items, aspect 0.85–1.18) + **спаривание полу-дуг** `('c','c')` aspect 1.6–2.5 по правилу Ф5 — прямое обобщение `detect_terminal_ellipses` (vector_path_graph.py:110–170), у которого сейчас захардкожено окно 7–10×3–6 pt; параметризовать диапазон диаметров (СС клеммы 8.5, оси 25–34).
7. `width`/`dashes` извлекаются всегда; `width` — рабочий классификатор (Ф11: 0.24 = размерное/засечки, ≥0.6 = контуры), `dashes` — резерв на чужие САПР (Ф1: в нашем корпусе пуст).

## 2. Детектор РАЗМЕРА (`dimensions.py`) — разрыв №2

### <gp_dimension_chain> — размерные цепочки (потребители: АР 247 + КЖ 110 + КМ 71 + ТХ 35 + узлы ЭОМ/ОВ/ВК ≈ 500+ блоков)
- **ЯКОРЯ (текстовые):** `^\d{2,5}(?:\*\)?)?$` (голые числа, включая «250\*»), rotation-aware через `TextLine.dir` (Ф13 — без этого теряется до 53% чисел); существующие regex-словари `PATTERNS["dimension"]` (architecture_geometry.py:80, structural_geometry.py:18) остаются для текст-фактов.
- **ЯКОРЯ (графические):** засечка = `Stroke` 2–6.5 pt @ 35–55° (пик 4.07 pt @ 45.0°, w=0.24 — Ф2); носитель — размерная линия ЛИБО коллинеарный ряд засечек (одной длинной линии может не быть — на КЖ балке 0 длинных носителей при 952 засечках); полилиния «диагональ+колено» (Ф3); fill-стрелки `arrow_triangle` как альтернатива засечкам (АР узел ×22, Ф10).
- **ПРАВИЛА СВЯЗЫВАНИЯ:**
  1. `detect_ticks(layer)` → засечки; дедуп двойного штриха (два ряда Δ≈2.9 pt с одинаковым span, КЖ балка y=1482.7/1479.8 — считать одной засечкой, keep-nearest-to-line; аналог дедупа QF-меток G:1556).
  2. Кластеризация в цепочки: проекция середин засечек на ось H/V, ряд = |Δпоперёк| ≤ 1.2 pt, сосед по ходу ≤ 250 pt (порог в дальнейшем — доля медианного шага, принцип Вектографа §2.2).
  3. Каждому интервалу пары соседних засечек — число: окно `|Δвдоль| < gap/2+6`, `|Δпоперёк| ≤ 14 pt` (probe2/4, для вертикальных — повёрнутые TextLine). Один кандидат — связь; два — GEOMETRY_CONFLICT-нота (правило Вектографа G:700–708, не молчаливый выбор).
  4. Полилинийная модель (КЖ): 3-точечные `Polyline` «diag 30–60° + horiz» → интервал = длина колена, число над ним (Ф3, 56 пар на закладной).
  5. `scale_mm_per_pt` = медиана `value/gap` по виду; `paper_scale = round(scale/0.352778)` (Ф4: 17.64→1:50, 35.28→1:100).
  6. Выносные линии: перпендикулярный `Stroke` через конец засечки (расстояние ≤0.7 pt) → второй конец через `SpatialIndex.query_point` → ближайшая компонента контура (width ≥ 0.6) = `extension_target` (существующий приём `_attach`, hvac_geometry.py:198).
- **НОВЫЕ ПРИМИТИВЫ:** `detect_ticks`, `assemble_dim_chains`, `estimate_scale`, дедуп двойного штриха. Переиспользуется: кластеризация по gap (G:1139 → общий `cluster_by_gap`), допуски в долях шага, `_near`-окна.
- **FINDINGS:** (а) `DIM_SCALE_OUTLIER` — интервал с `value/gap`, отклоняющимся >5% от медианы вида = число не соответствует начерченному (ловит класс АИ2 «580+580 против 1155 мм», architecture_geometry.py:30–32); (б) `DIM_CHAIN_SUM_MISMATCH` — сумма интервалов цепочки ≠ параллельный габаритный размер (допуск 1 мм·n); (в) `AXIS_SPACING_MISMATCH` — размер между осевыми кружками ≠ межосевое расстояние×масштаб. Класс норм: ГОСТ 2.307-2011 (нанесение размеров), ГОСТ Р 21.101-2020 (оформление РД) — категория преимущественно Рекомендательное/Экономическое (пересортица объёмов).
- **ГЕЙТ:** использовать слой, если засечек ≥ 6, цепочек ≥ 2, `scale_consistency` (доля интервалов в ±5% от медианы) ≥ 0.8, привязано чисел ≥ 60% интервалов; иначе — только счётчики в semantic-реестр (принцип «слабый граф хуже честного нет графа», G:2463).
- **ПРИОРИТЕТ/ЭФФОРТ:** ценность MAX (единственный детектор, закрывающий главный разрыв таблицы geom-ar-kj-km-etc §«Размер→линия→элемент: нет ×5 дисциплин») × эффорт M — обе модели носителя эмпирически подтверждены.

### <gp_leader_shelf> — полочка/leader (КЖ позиции, состав пола/кровли АР, марки КМ)

- **ПРАВИЛА СВЯЗЫВАНИЯ:**
  1. Две модели носителя (обе нужны): (A) единая `Polyline` diag+shelf (probe3: 10–60 связок на КЖ), (B) раздельные `Stroke` (probe6).

  4. Гроздья: несколько полочек на общей вертикали/диагонали → `stack_group` (состав пола: одна нога, стопка строк слоёв).
  5. Anti-capture: полочка, уже опознанная как размерное колено (Ф3), исключается — сначала dimensions, потом leaders (числа «1750» над коленом — это размер, не выноска; probe3 это перепутал).
- **НОВЫЕ ПРИМИТИВЫ:** `detect_leaders`, `stack_groups`, приоритет dimensions>leaders. Переиспользуется: `_distance_to_bbox` (:576), паттерн «якорь + вертикальный сбор атрибутов» (G:1359).

## 4. Детектор ОСЕВОГО КРУЖКА и СЕТКИ ОСЕЙ (`axes.py`) — разрыв №4

### <gp_axis_grid> — оси и адресация «в осях 1-2/А-Б» (все дисциплины с планами)
- **ЯКОРЯ (текстовые):** токен внутри кружка `^([А-ЯA-Z]с?|\d{1,2}|\d{1,2}\.[А-ЯA-Z])$` — секционные форматы «4.Г» подтверждены (Ф5); текущая чисто текстовая кластеризация `_plan_axes` (alia_remaining_geometry.py:88–104) и `_axes` (hvac_geometry.py:219) остаются фолбэком.
- **ЯКОРЯ (графические):** `CircleAnchor` Ø 20–40 pt (эмпирика: 34.0 АР план, 25.4/25.6 КЖ), `source="paired_halves"` — ключевой случай (полные окружности с токеном на АР плане: 0, спаренные: 5/5 с токенами); осевая линия = коллинеарный ряд коротких сегментов от кружка внутрь поля (Ф1: штрихпунктир = отдельные сегменты, НЕ dashes).
- **ПРАВИЛА СВЯЗЫВАНИЯ:** кружок+токен (ровно 1 слово внутри bbox) → пеленг осевой линии: сегменты на луче от центра (|поперечное отклонение| ≤ 1 pt, зазоры ≤ 30 pt) → ось-прямая; пересечения H/V осей → сетка; адресация узла = интервал сетки, в который попадает центр (`_bind_nearest_axes`, hvac_geometry.py:237 — наконец-то для всех дисциплин, сейчас вызывается только в ЭОМ); расстояния между кружками сверяются с размерной цепочкой между ними (совместно с dimensions).
- **НОВЫЕ ПРИМИТИВЫ:** `detect_axis_bubbles` (обобщение спаривания полу-дуг из `detect_terminal_ellipses`), `trace_axis_line` (коллинеарный ряд), `build_axis_grid`.
- **FINDINGS:** `AXIS_SPACING_MISMATCH` (см. §2); `AXIS_TOKEN_DUPLICATE` (два кружка с одним токеном на одной оси-прямой — норм); дубль токена на РАЗНЫХ прямых — конфликт; адресация даёт всем findings человекочитаемую локализацию «в осях…» (усиливает block_captions).
- **ГЕЙТ:** ≥ 2 осей на направление и ≥ 80% кружков с единственным токеном; иначе фолбэк на текстовый `_plan_axes`.
- **ПРИОРИТЕТ/ЭФФОРТ:** ценность HIGH (адресация улучшает ВСЕ findings планов) × эффорт S (спаривание полу-дуг уже написано для СС, обобщить параметры).

## 5. Детектор СЕТКИ ТАБЛИЦ (`tables.py`) — разрыв №5

### <gp_table_grid> — ведомости/спецификации/характеристики (ОВ 160 + ВК 171 частично, штампы всех)

## 6. Детектор ОТМЕТКИ УРОВНЯ (`levels.py`) — разрыв №6

### <gp_level_mark> — высотные отметки (фасады/разрезы АР, КЖ, ГП-профили)
- **ЯКОРЯ (текстовые):** `^[+-]?\d{1,2}[.,]\d{3}\*?$` (уже есть в PATTERNS всех модулей как «elevation», но без геометрии).
- **ЯКОРЯ (графические):** «галочка» = ≥ 2 сегмента 4–7 pt @ 40–50° со ВСТРЕЧНЫМ наклоном и общей вершиной ≤ 1 pt + горизонтальная полочка 15–60 pt; окно ±30×±15 pt от bbox числа (Ф8: подтверждено на 5/5 отметках АР фасада — сегменты 5–6 pt @ 43–47°, полочки 21/42 pt).
- **ПРАВИЛА СВЯЗЫВАНИЯ:** число → флажок → вершина галочки = физическая точка отметки → горизонтальная линия уровня через вершину (`SpatialIndex`) → компонента контура = элемент, к которому относится отметка.
- **FINDINGS:** `LEVEL_INCONSISTENT` — одна физическая линия уровня с разными числами на разных видах; разность соседних отметок ≠ размеру между ними × масштаб (совместно с §2); класс: ГОСТ 21.501 (АР-чертежи), Эксплуатационное/Рекомендательное.
- **ГЕЙТ:** ≥ 60% чисел-отметок нашли флажок; иначе отметки остаются текст-фактами (как сейчас).
- **ПРИОРИТЕТ/ЭФФОРТ:** ценность MED × эффорт S (сигнатура узкая и стабильная).
