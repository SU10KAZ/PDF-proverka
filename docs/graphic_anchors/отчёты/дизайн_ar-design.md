## 1. Новые примитивы общей библиотеки (ярус B), нужные АР

Предлагаемый новый модуль `backend/app/pipeline/stages/block_grounding/dimension_geometry.py` + правки существующих. Все допуски — в pt и долях медианного шага (принцип Вектографа).

- **P1 `detect_dimension_bindings(words, segments)`** — привязка числа к размерной линии тремя режимами: `break` (коллинеарные сегменты по обе стороны текста, ось на середине bbox ±2.5, зазор <12), `beside` (линия под/сбоку в 0.5–7 pt), для повёрнутого текста — транспонировано. Тонкость линии width ≤ 0.3 — префильтр. Эмпирика: 86/70%.
- **P2 `build_dimension_chains(bindings, ticks)`** — коллинеарный кластер линий (ось ±0.7, слияние разрывов ≤12 pt), засечки на кластере (midpoint ±1.5, дедуп 0.8), **сплит цепочки по разрыву > 3× медианного интервала засечек** (без сплита суммы ломаются: 23/24 mismatch на 6QT6 в probe5), число↔интервал (|центр−середина|<gap/2+8). Выход: `scale_mm_pt`, `chain.members`, `chain.sum`, общие X засечек между ярусами цепочек (подробная↔габаритная связываются выносными: совпадение координат засечек ±1 pt).
- **P3 `extract_leaders_generic`** — генерализация `extract_callout_leaders` (`vector_path_graph.py:582–623`): (а) убрать хардкод префиксов текста (:590); (б) полочка = H-сегмент под строкой (y1..y1+6, X-перекрытие ≥50%); (в) leader = сегмент любого наклона с концом на конце полочки ±2 pt; (г) целевой конец → ближайший узел/компонента (`point_segment_distance`, есть).
- **P4 `detect_axis_bubbles`** — оба представления кружка (см. §0 п.6: all-`"c"` drawing 6–30 pt ИЛИ кольцо коротких `"l"` на общем радиусе 4–16 от центра токена, ≥8 сегментов) + одиночный токен `[А-ЯA-Z]|\d{1,2}` внутри. Ось = луч от кружка внутрь чертежа (коллинеарные длинные сегменты через центр). Заменяет ложные текстовые оси («1000» в 7DU7) детектора `_axes` (`hvac_geometry.py:219`).
- **P5 `detect_elevation_markers`** — отметка `[+\-]N,NNN` + полочка (100% случаев) + флажок-треугольник (≥2 диагонали 2–9 pt в окне x±14/y−6..+10); Y полочки = физический уровень; кластеризация полочек по Y ±2 pt = «уровень здания» (связывает 80 отметок фасада в этажи).
- **P6 `build_table_grid`** — длинные H (≥100 pt) + V-линии → Y-банды строк / X-банды колонок → слова в ячейки → записи. Подтверждено: ведомость дверей 8/8; колонки площадей отделки. Универсален (просился и для КЖ/спецификаций — см. vector-paths-drawings.md §4).
- **P7 `extract_list_stack`** — этажерка: строки с общим левым X ±3 pt, опц. маркер «-»/№, Y-шаг ≤ 2.2 высоты строки → упорядоченный список; из строки — толщина (`толщин\w*\s+(\d+)\s*мм|(\d+)\s*мм`), класс материала (B12.5, М150/М200, П35).
- **P8 `room_area_pairs` (сейчас) / `room_polygon` (Phase 2)** — верт. пара «подпись/номер помещения ↔ площадь N,NN» (X-пересечение, зазор <2.2h); полигон комнаты из замкнутых контуров — дорого, отложить (сначала пары; полигон только для сверки площадей).
- **P9 `estimate_sheet_scale`** — побочный продукт P2: median мм/pt листа → физическая длина ЛЮБОГО сегмента → нормопроверки геометрии без текста (ширина марша, проход, высота ограждения).
- **Фундамент слоя**: развернуть `"re"`/`"qu"` в 4 сегмента и перестать выкидывать fill-paths в `flatten_line_segments` (`vector_path_graph.py:71–107`, строка 91 и фильтр :82) — флажки отметок и квадратики узлов живут именно там; `width` уже извлекается (:103) и обязан стать префильтром P1.

Точки врезки: `architecture_geometry.py:132–139` (`_plan`) и `:140–155` (`_view_graph`) — добавить вызовы P1–P8 по профилю; членство узлов в видах `_assign_nodes_to_views` (`hvac_geometry.py:473`) заменить на bbox-членство при наличии рамки вида (P6-сеткой).
