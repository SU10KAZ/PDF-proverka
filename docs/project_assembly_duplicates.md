# Одинаковые листы в сборке группы

С 22.11.2026. Флаг `PROJECT_ASSEMBLY_DEDUP_ENABLED=1` (по умолчанию выключен;
нужен ещё `PROJECT_ASSEMBLIES_ENABLED=1`).

## Зачем

Группа документов на доске пар склеивает несколько проектов стороны в сборку
(`docs/stage_comparison_document_groups.md`). Один и тот же лист часто вложен
в каждый проект: альбом технических решений в ЭМ каждого корпуса, приложения
к сертификатам, инструкции производителя, повторно загруженный документ. Копии
раздувают сборку и каждую стадию сравнения после неё.

Объект Stories, версия сравнения cv002, правая сторона группы ЭОМ: 19 проектов,
900 страниц, найдено 342 копии (38 %). Три проекта ЭМ-01 / ЭМ-02 / ЭО-01:
266 страниц → 177 после согласования (поиск 26 с, склейка 1 с).

## Что считается дублем

Решение инженера (22.11.2026):

- дубль — лист **того же формата**, у которого совпадают и графика, и текст
  на поле листа;
- **не учитываются**: штамп (основная надпись — шифр, номер листа, таблица
  изменений, подписи, даты), плашка «В ПРОИЗВОДСТВО РАБОТ» (организация, ГИП,
  дата) и QR-код;
- **любое другое отличие, даже мелкое**, оставляет лист в сборке. Пример:
  ГП3.2 лист 5 и ГП3.2.1 лист 4 совпадают по тексту, но на плане ГП3.2 стоит
  отметка изменения «1.2» и иначе нарисован контур — это самостоятельные листы.

Удаляются копии только после согласования инженером.

## Как ищется (`backend/app/services/project_assemblies/duplicates.py`)

Детерминированно, без OCR и моделей. Распознавание (Markdown) не годится: одна
и та же страница распознаётся по-разному; побайтное сравнение PDF тоже — у
копий разные QR и даты.

1. **Отпечаток страницы**: формат (`page.rect`), текстовый слой PDF вне грубых
   служебных зон, dHash 256 бит рендера 30 dpi со служебными зонами,
   закрашенными белым.
2. **Кандидаты**: тот же формат + тот же текст + dHash не дальше 24 бит.
   Оригинал — первое вхождение листа в порядке склейки; каждая копия — пара
   с ним (повтор внутри одного проекта — тоже пара).
3. **Строгая проверка**: точные служебные зоны обеих страниц, рендер до
   100 dpi (длинная сторона ≤ 4000 px), вне зон не должно отличаться **ни
   одного пикселя** (порог яркости 48) и ни одного слова текстового слоя.
   Допуска по площади нет намеренно: 1–2 % площади занимает и QR, и облако
   реальной правки.

Служебные зоны:

- штамп — блок `stamp` распознавания из `blocks.json` (+6 pt);
- отметка выпуска — текст «В ПРОИЗВОДСТВО РАБОТ» (ищется и за обрезом листа:
  на вкладыше A6 плашка вылезает за край), тонкие полосы рамки цвета
  (0.11, 0.53, 0.75) рядом с ним;
- QR — чёрная фигура из ≥ 40 элементов, квадрат 30–180 pt, на белой квадратной
  подложке (или без подложки рядом с текстом отметки); подложка закрывает
  чертёж и входит в зону.

Координаты текста и графики PyMuPDF отдаёт в неповёрнутой системе страницы,
рендер и `blocks.json` — в повёрнутой; все зоны пересчитываются через
`page.rotation_matrix` (листы ГП повёрнуты на 270°).

## Жизненный цикл версии сборки

```
«Собрать» → QUEUED → SCANNING (поиск, ~0,1 с/стр.) ─┬─ пар нет или все решены ранее → RUNNING → READY
                                                     └─ REVIEW (ждёт инженера) → «Удалить N и собрать» → RUNNING → READY
```

- `pending/<v>.duplicates.json` — найденные пары; `pending/<v>.review.json` —
  решение; после сборки `versions/<v>/duplicates.json` (пары с решениями).
- Решения запоминаются по паре страниц (sha PDF + страница, без порядка) в
  `assemblies/duplicate_decisions.json` области версии сравнения: пересборка
  группы (новый проект, другой порядок) не спрашивает о них повторно.
- Сборка без копий: `assembly_origin.json` — `removed_pages[]` с
  `duplicate_of` (страница оригинала в сборке); `page_start`/`page_end`
  проектов по оставшимся страницам (`null`, если все листы проекта — копии),
  `removed_pages` у проекта. В манифесте `dedup` (pairs / removed_pages /
  kept_pairs), `totals.page_count` — после удаления, `source_page_count` — до.
- Без флага сборка байт в байт прежняя: нет `dedup`, нет `removed_pages`.
- Воркер сборки: `run_version` = поиск + склейка, лимит 45 минут.

## API (`/api/stage-comparison/objects/{object_id}/document-groups/{group_id}`)

| Метод | Путь | Что делает |
|------|------|------------|
| GET | `/duplicates?side=right` | пары версии стороны (`proposed=remove` для нерешённых) |
| POST | `/duplicates` `{side, keep_pair_ids}` | REVIEW → собрать без копий; READY → запомнить решения и пересобрать сторону |
| GET | `/duplicates/page?side&source_index&page&width` | лист проекта картинкой (JPEG, ETag = sha PDF) |

Статусы стороны группы: `SCANNING` входит в «собирается», `REVIEW` — не
ошибка и не «Пересобрать»; `duplicates` в виде стороны — прогресс поиска,
число пар или итог.

## Портал

`frontend/static/js/stage-comparison-duplicates.js` (чистые функции) + состояние
в `app.js` + окно в `index.html`. В строке группы: статус «Ищем одинаковые
листы» с плашкой прогресса, затем «Проверьте одинаковые листы» с кнопкой
«Проверить дубли». Окно: список пар слева, «Остаётся в сборке» и «Копия»
рядом, пунктир — исключённые зоны; ← → листать, пробел — «Вернуть», клик по
листу — крупно в новой вкладке. После сборки плашка «Удалено дублей: N»
открывает окно с принятыми решениями («Сохранить и пересобрать»).
Если поиск прошёл и копий нет, сборка идёт без окна, а в строке стоит плашка
«Дублей не найдено · проверено N стр.» (с 23.11.2026; раньше «искали и не
нашли» не отличалось от «не искали»).

## Чего механизм не делает

- Не находит копии, отличающиеся отрисовкой (другой экспорт того же листа:
  в ЭМ-04 буква «а» в одном слове отрисована иначе — лист остаётся).
- Не исключает QR-картинки растром и другие системы отметок выпуска — такие
  листы останутся как самостоятельные (консервативно).
- Не снимает лимиты сборки (`MAX_SOURCES = 32`, `MAX_PAGES = 2000`): группа
  КР2 Stories из 107 проектов по-прежнему не собирается.
