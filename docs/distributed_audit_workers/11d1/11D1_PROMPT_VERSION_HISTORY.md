## 2. Ответы на вопросы §15

**1. Менялся ли шаблон? — Да, +52/−2.** По секции severity изменение **ровно
одно**: добавлены критерии «ПРОВЕРИТЬ ПО СМЕЖНЫМ» (06-20). Перечень пяти значений
(строка 108) и правило «ONLY one of the 5 values» (строка 145) **идентичны марту**.
Правила поиска замечаний (шаги 1-7, включая MANDATORY-проверки арифметики,
кросс-сверки, spec↔[IMAGE]) дословно не менялись. Направление дрейфа —
**строже/богаче**, а не мягче.

**2. Менялся ли профиль ЭОМ? — Нет.** Побайтовое сравнение
`3fb30eb3:disciplines/EM/*` с `537c08a5:prompts/disciplines/EOM/*`: `role.md`,
`checklist.md`, `finding_categories.md`, `norms_reference.md`, `triage_table.md`,
`project_params.md`, `drawing_types.md` — **все совпадают**. Изменился только
`config.json` (`"code": "EM"` → `"EOM"`) и путь папки.

**3. Новые фильтры очистки? — Функция не менялась, изменилась область
применения.** `_CLI_PATTERNS` и тело `_clean_template_for_api` побайтово
идентичны марту. Но **в марте на боевом пути они не применялись вовсе**:
исторический прогон шёл веткой B (`prepare_text_analysis_task` без очистки),
очистка существовала только для OpenRouter. В 11D боевой промпт впервые строится
через `build_text_analysis_messages` — то есть очистка применяется к Claude
впервые, плюс появился второй слой `provider_transport`.

**4. Absence guard.** Появился 2026-07-04 и **сразу default OFF**; ни один коммит
не переводил дефолт в `True`; в `.env` центра переменной нет. Значит его не было
**ни в марте** (кода не существовало), **ни в 11D**. Гипотезу
`11D_HISTORICAL_COMPARISON.json` «страж отсутствия выключен → потеряли КРИТ»
можно **закрывать**: он был выключен в обоих сравниваемых прогонах.

**5. md_prescan.** Модуль создан 2026-07-11, в марте не существовал. Секция
добавляется всегда, без флага. Для документа 133-23-ГК-ЭС `scan_md_file` даёт
**0 кандидатов** (все правила пре-скана доменно чужие — ОВиК/ВК), секция пуста.
Гипотезу «11 РЕКОМЕНДАТЕЛЬНЫХ — эхо пре-скана» проверено детерминированно и
**опровергнуто**.

## 3. Вывод

**Дрейф промпта был, и он направлен в сторону ужесточения/обогащения входа.** Ни
одно изменение шаблона или профиля между 2026-03-27 и `537c08a5` не ослабляет
требования к КРИТИЧЕСКИМ замечаниям:

* `+ {DISCIPLINE_ROLE}` — усиление (в марте роль ЭОМ в промпт вообще не
  подставлялась, и при этом три КРИТИЧЕСКИХ нашлись);
* `+` критерии «ПРОВЕРИТЬ ПО СМЕЖНЫМ» — сужение одной **некритической**
  категории; согласуется с «ПРОВЕРИТЬ ПО СМЕЖНЫМ: 1 → 0»;
* `+` шаг 8 и HARD RULE «…inflate severity» — в 11D блоков нет, секция работает
  вхолостую, но текст остаётся в промпте (**гипотеза**: может работать как общий
  тормоз на повышение severity; прогоном не проверено);
* `+` секция пре-скана — для этого документа пуста;
* профиль дисциплины — нулевой дрейф.

**Важный факт против простых объяснений:** мартовский шаблон был вдвое короче,
**без роли дисциплины, без критериев severity, без стража отсутствия и без
пре-скана** — и дал три КРИТИЧЕСКИХ. То есть КРИТИЧЕСКИЕ 2026-03-26 получены
не благодаря правилам промпта: правил там не было.

**Следствие для сравнения «11D vs история»:** оно смешивает три независимых
изменения — транспорт (11D), четыре месяца правок шаблона и смену модели на два
поколения. Чистое сравнение потребовало бы прогона текущей ветки B/C на том же
документе, то есть реального вызова модели, который 11D.1 запрещает.
