## C. «Не указан тип системы заземления TN-S / TN-C-S / TT / IT»

**Исходных данных в MD НЕТ** (грепано: `TN-S`, `TN-C`, `система заземления` — 0).
Тоже находка класса «отсутствие».

* правила дисциплины по теме: `role.md:12` прямо называет «TN-C-S, TN-S»;
  `_registry.json` держит `TN-C-S`/`TN-S` в `text_keywords` дисциплины ЭОМ;
* **пробел, общий для ОБОИХ путей:** `prompts/disciplines/EOM/project_params.md`
  содержит поле `grounding_system` (TN-C-S / TN-S / TT) — то есть единственное
  место профиля, где тип системы заземления назван обязательным параметром. Этот
  файл подставляется плейсхолдером `{DISCIPLINE_PROJECT_PARAMS}`, которого в
  шаблоне `text_analysis_task.md` **нет**. Значит он не доходит ни до ветки B, ни
  до provider — и не доходил в марте. Это **не** регресс 11D;
* правила отсутствия: не было ни в одном прогоне;
* обрезка/перестановка: **нет**;
* post-processing: **нет**.

| прогон | severity темы C |
|---|---|
| 2026-03-17 | **Эксплуатационное** («Не указана система заземления (TN-C-S / TN-S / IT)») |
| 2026-03-26 | **КРИТИЧЕСКОЕ** |
| 2026-08-09 (11D) | **тема отсутствует** |

Тема C — единственная, которая в новом прогоне пропала совсем. Входные условия
для неё в provider-пути присутствовали в том же объёме, что и в legacy: сам
факт отсутствия виден из вложенного целиком MD, а `role.md` называет обе системы
поимённо. Детерминированной причины пропажи не найдено.

Что могло на неё влиять (**гипотезы, прогоном не проверены**):

1. `INPUT_DATA_NOTE` предписывает не считать `[IMAGE]`-описания MD визуальным
   доказательством, а `TRANSPORT_CONTRACT` в редакции 11D заканчивал промпт
   фразой «do not report that a file is missing» — общая интонация «чего у тебя
   нет» на позиции максимальной рецентности могла подавлять именно
   absence-класс. На 11D.1 фраза уточнена: ограничение касается доступа к
   инструментам, а не предмета аудита.
2. Обеднение `project_params` в новом результате (3 ключа против 8): в
   историческом ответе `grounding_type` был отдельным параметром, и тема C
   выглядит его продолжением. В новом ответе такого параметра нет.
3. Смена модели `claude-opus-4-6` → `claude-opus-5`.
4. Обычная вариативность: прогон 2026-03-17 дал по этой теме
   «Эксплуатационное», а не «КРИТИЧЕСКОЕ» — тема нестабильна даже по severity.

## Вывод §12

Ни для одной из трёх тем **входные условия не ухудшились**: исходный текст
доставлен целиком, правила дисциплины и нормативный контекст доставлены не хуже
(по норм-базе — лучше), правила отсутствия отсутствовали одинаково, обрезки и
перестановки материала нет, детерминированного изменения severity нет.

Единственная доказанная потеря входа — определения шкалы severity (см.
`11D1_SEVERITY_TRACE.md` §5), и она **не специфична для этих тем**: касается
всех замечаний всех дисциплин. Исправлена на 11D.1 переносом определений в
промпт, без возврата личного контекста и без упоминания ОСУП, TN-S и ПУЭ 7.35.
