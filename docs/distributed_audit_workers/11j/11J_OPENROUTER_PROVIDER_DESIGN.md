# 11J — OpenRouter как провайдер воркера: устройство

## 1. Что переиспользовано, а не написано заново

Задание (§4) требует не переписывать существующий путь. Переиспользовано три
вещи, и каждая по своей причине.

**Форма запроса** взята у боевого центрального пути
(`gemma_findings_only.call_gpt_for_block`) дословно: тот же URL
(`https://openrouter.ai/api/v1/chat/completions`), те же заголовки
(`Authorization: Bearer`, `HTTP-Referer`, `X-Title`), тот же `messages` с
`{"type": "image_url", "image_url": {"url": "data:image/png;base64,…"}}`, тот
же разбор `usage` и `finish_reason`. Второй диалект запроса к тому же сервису
означал бы, что нога на воркере и нога на центре дают несравнимые ответы — то
есть ровно то, ради чего затевался план маршрутизации.

**Контракт результата** — общий `ProviderInferenceResult`. Ни одна строка
сводящего кода этапа 01 (`combine_detector_results`, провенанс, счётчики) об
OpenRouter не знает и знать не должна.

**Гейты вызова** — общий `ProviderAdapter._inference_gate`: политика,
разрешение на инференс, подтверждение вызывающего. Своей копии `if` в адаптере
нет.

## 2. Что пришлось написать заново и почему

Инварианты слоя (I-P1…I-P8) описывают **подпроцесс**: окружение с нуля, свой
HOME, пустой `cwd`, убийство группы по таймауту, промпт через stdin, argv из
констант. У провайдера без подпроцесса ни одного из этих объектов не
существует. Делать вид, что инварианты соблюдаются, было бы хуже, чем честно
назвать другие, — поэтому у HTTP-провайдера свой набор:

| | Утверждение | Чем обеспечено |
|---|---|---|
| I-H1 | Ключ живёт ровно один вызов | не сохраняется ни на адаптере, ни в модуле; ссылка снимается в `finally` |
| I-H2 | Ключ не приходит извне | ни из задания, ни из привязки, ни из окружения — только из локального файла |
| I-H3 | Окружение не влияет на маршрут запроса | `httpx.Client(trust_env=False)` |
| I-H4 | Адрес шлюза — константа либо явная настройка администратора | неофициальный адрес только при объявленном режиме заглушек |
| I-H5 | Ни промпт, ни вложение не попадают на диск | картинка уходит байтами в теле, временного файла нет |
| I-H6 | Ответ проходит редактор секретов до возврата | `redaction.redact` на всех ветках |

I-H5 стоит отдельного слова: у Codex вложение **неизбежно** пишется файлом
(`codex exec -i <FILE>` — единственный официальный способ), и адаптер тратит
заметный код на то, чтобы каталог вложений был свежим, узким по правам, сверен
по sha256 и удалён в `finally`. У HTTP-провайдера этой поверхности нет вовсе.

## 3. Ответы на абстрактные методы, у которых нет CLI

`ProviderAdapter` требует `version()`, `auth_status()`, `quota_status()`,
`minimal_probe()`, `supports_zero_inference_quota()`, `quota_source_name()`,
`quota_source_stability()`, `provider_env()`. Ни у одного нет CLI, который
можно спросить.

| Метод | Ответ | Обоснование |
|---|---|---|
| `executable_path()` | `None` | не «не нашли», а «нет» |
| `installed()` | доступен ли HTTP-клиент | у CLI установка — файл на диске; здесь ей соответствует наличие клиента. Вопрос один и тот же: «канал физически существует?» |
| `version()` | `httpx/<версия>` | `identity()` считает `version()==None` признаком `INSTALL_BROKEN`; возвращать `None` у здорового провайдера нельзя. Оператору нужно знать, каким кодом сделан вызов, — у HTTP-провайдера это клиентская библиотека |
| `auth_status()` | `logged_in`, если файл ключа на месте и права узкие | zero-inference по построению |
| `supports_zero_inference_quota()` | `False` | `GET /key` формально бесплатен, но это сетевой запрос с ключом каждые 15 минут ради числа, которым конвейер не пользуется |
| `quota_source_name()` | `unavailable` | из закрытого списка `quota.py` |
| `provider_env()` | `{}` | подпроцесса нет. Пустой словарь — утверждение: если кто-то однажды позовёт `run()`, запуск провалится громко, а не унаследует чужие переменные |

## 4. Код возврата

`validate_inference` требует `exit_code == 0` на успехе — это общее поле
контракта, и HTTP-статус в него класть нельзя: каждый успешный вызов
проваливал бы проверку результата. Семантика сохранена дословно («ноль =
получилось»), а сам статус попадает в `detail` тех веток, где он что-то
объясняет.

## 5. Классификация отказов (§23)

По СТАТУСУ, а не по тексту: текст ошибки платного шлюза меняется без
предупреждения, а 429 остаётся 429.

| Статус | Код | Почему так |
|---|---|---|
| 401, 403 | `auth_required` | |
| **402** | `rate_limited` | ключ действителен, денег нет. Отдельный случай: оператору нужно пополнить счёт, а не перевыпустить ключ. Именно 402 три дня подряд молча ронял GPT-ногу на центре |
| 429 | `rate_limited` | |
| 404 | `incompatible_cli` | шлюз отвечает 404 на неизвестную модель — это не «сервис недоступен» |
| 408, 504 | `timeout` | |
| 5xx | `provider_unavailable` | |
| 200 с полем `error` | по коду внутри | шлюз умеет возвращать «ошибка апстрима, но HTTP в порядке». Без этой ветки такой ответ прошёл бы как пустой успех, и этап получил бы ноль замечаний вместо отказа |
| `finish_reason=length` | `malformed_status` | усечённый ответ — не успех, даже если обрезанный JSON случайно разобрался |
| модель не та | `model_mismatch` | шлюз официально маршрутизирует между апстримами; суффиксы маршрутизации (`…:floor`) при сравнении снимаются, смена вендора — нет |

## 6. Нормализация расхода (§22)

Шлюз отдаёт `prompt_tokens` / `completion_tokens` / `cost`; конвейер читает
`input_tokens` / `output_tokens` / `total_cost_usd` по литеральному ключу. Без
приведения нога на воркере молча показывала бы ноль там, где та же нога на
центре показывает числа, — и расхождение выглядело бы как «блок дешевле».
Дополнительного сетевого запроса ради расхода нет: берётся то, что уже пришло в
ответе.

## 7. Идентификатор модели

`validate_model_id` стал провайдер-зависимым. Косая черта в `openai/gpt-5.4` —
часть НАЗВАНИЯ модели, а не путь; но у CLI-провайдеров идентификатор уходит в
argv, и закрытый набор символов там — сознательный рубеж. Послабление
ограничено HTTP-провайдерами, и формы, похожие на путь (`//`, ведущий или
завершающий слэш), отвергаются и у них.

Умолчание `accepted_reported_models` перестало приписывать HTTP-провайдеру
суффикс `[1m]`: это свойство CLI Claude, у шлюза оно не появится никогда, то
есть в списке допустимого лежала бы строка, которая не совпадёт ни с чем.

## 8. Режим `ambient_user` отвергается

`ambient_user` означает «CLI входит из личного каталога человека». У провайдера
без CLI входа нет, а раскладка при этом уехала бы в
`~/.openrouter/credentials.json` живого пользователя: воркер начал бы тратить
ключ, о котором его никто не просил и который оператор воркера не выдавал.
Режим отвергается, а не игнорируется; отказ виден в heartbeat отдельной
строкой `severity=error`, и агент при этом не падает.
