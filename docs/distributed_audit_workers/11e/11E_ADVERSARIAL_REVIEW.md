# 11E §24 — состязательный разбор ДО оплаченного вызова

Четыре независимых разбора, все — read-only, ноль обращений к модели.
Источником фактов служил не код, а **дамп реально отправленного stdin**,
снятый подделкой CLI, и отчёт, который написал сам конвейер.

---

## Разбор 1. SEMANTIC

**Что проверялось:** эквивалентность инженерного задания legacy ↔ provider;
правила дедупликации, объединения, источников и severity; скрытый контекст
`CLAUDE.md`; полнота блочных замечаний.

**Метод:** построчная классификация 177 непустых строк заменяемого CLI-промпта
против инструкций provider-промпта (`scripts/verify_11e_prompt_semantics.py`).

**Результат:**

| класс | строк |
|---|---|
| PRESERVED | 171 |
| TRANSPORT_ONLY | 6 |
| FORMAT_ONLY | 0 |
| ORDER_ONLY | 0 |
| CONTENT_REMOVED | **0** |
| CONTENT_CHANGED | **0** |
| UNKNOWN | 0 |

Шесть транспортных: `READ via Read tool` ×3 (текстовый артефакт, блочный
артефакт, MD), `WRITE via Write tool`, `Write JSON via Write tool — DO NOT
output to chat`, `After writing, output a brief summary of findings`.

**НАЙДЕН ДЕФЕКТ (подтверждён, исправлен).** Шаблон свода утверждает
«**Normative reference** — provided in system context», что неправда ни на
одной ветке. Добавленная справка о входе говорила обратное молча — и в промпте
оказались два соседних противоположных утверждения, причём ложное позже по
тексту, то есть с большей рецентностью. Модель, поверившая шаблону, имела ровно
один способ воспользоваться несуществующим справочником: выдумать пункт нормы.

*Исправление:* ложная строка названа и опровергнута явно, опровержение стоит
выше неё. Продовый шаблон не тронут. Коммит `b68629da`, тесты
`test_false_template_claim_is_refuted_not_merely_contradicted` и
`test_norms_reference_really_is_absent`.

**Отдельно названо, а не растворено в «транспортном».** Снятие строки про MD
формально транспортное (инструкция инструменту), но по существу меняет состав
доступных модели данных. Разница унаследована от давнего решения о ветке API и
в 11E не вводится; в промпте про неё сказано прямо. Зафиксировано в
`11E_PROMPT_SEMANTIC_DIFF.json` → `data_availability_delta`.

**Скрытый контекст:** см. `11E_HIDDEN_CONTEXT_REVIEW.md`. Определения severity
существуют ровно в одном месте платформы — корневом `CLAUDE.md`; перенесены
явно, одним импортом из модуля этапа 01.

## Разбор 2. SECURITY

**Что проверялось:** инструменты, cwd, изоляция авторизации, отсутствие доступа
к файловой системе проекта, канарейка, утечка промпта и клиентских данных.

**Свидетельства сняты с живого процесса (репетиция и боевой вызов):**

```
argv:  --safe-mode --strict-mcp-config --disable-slash-commands
       --no-session-persistence --setting-sources= --model=claude-opus-5
       --tools= --disallowed-tools=Bash,Read,Edit,Write,Glob,Grep,WebFetch,
       WebSearch,Task,NotebookEdit,TodoWrite,AskUserQuestion
       --permission-mode dontAsk --max-turns 1 --output-format json -p
cwd:   <попытка>/providers/claude/runtime
CWD_ENTRIES: (пусто)
env:   CLAUDE_CODE_DISABLE_NONESSENTIAL_TRAFFIC, CLAUDE_CONFIG_DIR,
       DISABLE_AUTOUPDATER, DISABLE_ERROR_REPORTING, DISABLE_TELEMETRY,
       HOME, LANG, LOGNAME, PATH, TMPDIR, USER  — 11 переменных
```

* переменных с именами вида `*TOKEN*/*SECRET*/*KEY*/*PASSWORD*/*CREDENTIAL*` —
  **0**; ни worker-token, ни адрес центра, ни execution-token в окружение
  подпроцесса не попадают;
* `TMPDIR` уведён внутрь попытки;
* `CLAUDE_CONFIG_DIR=/home/coder/.claude` — это **режим ambient_user** и иначе
  быть не может: подписка владельца машины живёт именно там. Гарантия против
  личного контекста даётся не сокрытием каталога, а флагами
  `--setting-sources=` / `--strict-mcp-config` / `--no-session-persistence` и
  нулём инструментов;
* проектный `CLAUDE.md` в артефакт релиза не попадает (denylist сборщика);
  пользовательский `~/.claude/CLAUDE.md` на .31 существует (226 байт) и
  определений severity не содержит;
* в инструкциях промпта: ни `.pdf`, ни `crop_url`, ни `/_output/`, ни `/home/`,
  ни `blocks_stage02`; абсолютных путей — 0;
* маркер канарейки найден ровно в одном файле — `metadata/provider_binding.json`,
  то есть в самом механизме проверки; больше нигде в дереве попытки;
* в отчёте о прогоне нет ни тела инструкций, ни формулировок входных замечаний,
  ни ответа модели — только отпечатки и счётчики.

**Дефектов не найдено.**

## Разбор 3. EXACTLY-ONCE

**Что проверялось:** разрешение, журнал вызовов, повторы, окно падения,
отсутствие фолбэка.

* разрешение выписывает ОПЕРАТОР отдельным запуском (`--issue-grant`); прогон
  только списывает. После списания `remaining = 0`, повторный поиск пригодного
  разрешения даёт `None` — проверено на всех четырёх прогонах;
* журнал попытки: `calls_started = 1`, `calls_completed = 1` в каждом прогоне;
  рабочих запусков CLI ровно один (`ARGV` с `-p`);
* повторный прогон в тот же каталог попытки отклоняется («затёр бы улики
  предыдущего») — проверено живым запуском;
* повтор завершённой попытки берёт результат из журнала и модель не зовёт
  (тест AE): артефакт восстанавливается без новой оплаты;
* состояние `indeterminate` (падение между вызовом и записью) автоповтора не
  вызывает — этап FAILED, решает оператор (тест AF);
* отказ моста возвращается кодом возврата, а не исключением, и ни одна ветка
  не ведёт к прежнему транспорту (тест AC: подставной `_run_cli` не вызывается
  ни разу).

**Дефектов не найдено.**

## Приложение: дефект, найденный ПОСЛЕ вызова

Разборы 1–4 сделаны до оплаченного вызова и его не предотвратили — вызов
завершился ошибкой CLI. При разборе неудачи вскрылся дефект, которого ни один
из четырёх разборов увидеть не мог, потому что он проявляется только на
провалившемся вызове: адаптер клал в `detail` константу «CLI завершился
ошибкой», а сам текст ответа нигде не сохранял — в журнал уезжал только
`raw_sha256`.

Цена: единственный оплаченный вызов этапа вернул ошибку в 99 байт, и разобрать
её оказалось нечем. Подбор строки по хэшу (известные сообщения CLI, шаблоны
`API Error: 4xx/5xx`, форма «usage limit reached|<epoch>» перебором по 300 000
значений) результата не дал.

Исправлено в `43d2437f`: `detail` несёт слова самого CLI (результат конверта →
stdout → stderr), с потолком в 400 символов; оба потока приходят в эту точку
уже пройдя `redaction.redact`. Тесты: текст доезжает, текст обрезается.
