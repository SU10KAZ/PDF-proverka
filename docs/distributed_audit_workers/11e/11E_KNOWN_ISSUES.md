# 11E — известные проблемы

## KI-1 (унаследована из 11D.2, НЕ чинилась) — `{DISCIPLINE_PROJECT_PARAMS}`

`prompts/disciplines/EOM/project_params.md` содержит `grounding_system`, но
плейсхолдера `{DISCIPLINE_PROJECT_PARAMS}` нет ни в ru-, ни в en-шаблоне этапа
`text_analysis` — параметры дисциплины до промпта не доходят ни по одному пути.

**Влияние на findings_merge:** шаблон свода `{DISCIPLINE_PROJECT_PARAMS}` вообще
не использует — из всех дисциплинарных плейсхолдеров в EN-шаблоне присутствует
только `{DISCIPLINE_ROLE}`. То есть свод затронут той же болезнью в более
широкой форме: он не получает ни чек-листа, ни таблицы триажа, ни параметров
проекта.

Дефект симметричный (одинаково задевает legacy и provider), задание прямо
запрещает его чинить в 11E. Зафиксировано и оставлено.

## KI-2 (найдена в 11E, НЕ чинилась) — ложное обещание про нормативную базу

Шаблон свода утверждает:

```
4. **Normative reference** — provided in system context.
```

Это неправда **ни на одной ветке**: `_read_norms_reference` в сборке свода не
вызывается, в EN-шаблоне нет `{DISCIPLINE_NORMS_FILE}`, справочник норм не
вкладывают ни ветка API, ни заменяемая CLI-ветка. Модель получает указание
опираться на источник, которого ей не дали.

Дефект пре-существующий и симметричный → по §15 он остаётся как есть.

**Что сделано вместо починки:** транспортная справка о входе называет ложную
строку и опровергает её явно, причём опровержение стоит ВЫШЕ неё. Продовый
шаблон не тронут ни на символ. Без этого в промпте оказались бы два соседних
противоположных утверждения, и ложное — позже по тексту, то есть с большей
рецентностью.

## KI-3 (найдена в 11E, ИСПРАВЛЕНА) — текст ошибки CLI терялся

**Симптом.** Единственный оплаченный вызов этапа завершился ошибкой:
`exit_code=1`, 0 токенов, `total_cost_usd=0`, модель не сообщена, ответ 99 байт,
длительность 32 с. Разобрать причину оказалось нечем.

**Корень.** `claude_adapter.structured_inference` при `not result.ok` клал в
`detail` КОНСТАНТУ «CLI завершился ошибкой», а сам текст ответа нигде не
сохранял: в журнал попытки уезжал только `raw_sha256`. Восстановить сообщение
постфактум невозможно — подбор строки по хэшу (известные сообщения CLI, шаблоны
`API Error: 4xx/5xx`, форма `usage limit reached|<epoch>` перебором по 300 000
значений) результата не дал.

**Цена.** Бюджет вызовов этапа равен одному и уже израсходован; §27 запрещает
повтор. Причина отказа осталась неустановленной — не из-за отсутствия
свидетельств, а из-за того, что свидетельство было выброшено на границе, где
деньги уже потрачены.

**Исправление (коммит `43d2437f`).** `detail` несёт слова самого CLI: результат
конверта → stdout → stderr, с потолком в 400 символов. Оба потока приходят в
эту точку уже пройдя `redaction.redact` в `run()`, поэтому учётные данные в них
не попадают; потолок держит поле диагностики от превращения в канал выгрузки
входа. Ветка codex намеренно не тронута: её путь 11E не проверял.

Тесты: `test_cli_failure_detail_carries_the_providers_own_message`,
`test_cli_failure_detail_is_bounded`.

## KI-4 (наблюдение, не чинится) — общая учётная запись Claude

`.31` и центральный VPS работают на ОДНОЙ учётной записи Claude (`max`).
Оператор знает об этом; §39 задания это фиксирует и запрещает утверждать, что
у воркера независимый пул квоты.

Для 11E это важно как **один из кандидатов на причину отказа**: во время
боевого вызова на той же подписке активно работала центральная сессия Claude
Code. Подтвердить или опровергнуть это нечем — ровно из-за KI-3.

Квотную архитектуру 11E не переделывает (§39: без подтверждённого дефекта — не
трогать).

## KI-5 (наблюдение) — причина отказа боевого вызова не установлена

Что известно достоверно:

| факт | значение |
|---|---|
| код возврата CLI | 1 |
| длительность | 32,3 с |
| `num_turns` из конверта | 1 |
| `total_cost_usd` из конверта | 0 |
| фактическая модель | не сообщена (`modelUsage` пуст) |
| токенов входа/выхода | 0 / 0 |
| размер ответа | 99 байт |
| `sha256` ответа | `d9758eb9e672f6182ebaa38bc90670da5510cf4b55c596534e6262e82212d122` |

Из этого следует: CLI запустился, принял stdin, отработал один ход и вернул
конверт `--output-format json` с признаком ошибки; биллинг конверт не показал.
32 секунды при нулевом расходе характерны для внутренних повторов CLI с
backoff перед сдачей.

Кандидаты, совместимые со ВСЕМИ сохранёнными свидетельствами:

1. исчерпание лимита подписки на учётной записи, общей с центром (KI-4);
2. временная перегрузка/лимит на стороне API (429/529).

Различить их сохранёнными свидетельствами нельзя. Именно эту слепоту закрывает
KI-3, поэтому следующая попытка ответит на вопрос сразу и без догадок.

Догадка в отчёт как вывод не выносится: §43 требует зафиксировать факты и
возможные причины, а не выбрать удобную.
