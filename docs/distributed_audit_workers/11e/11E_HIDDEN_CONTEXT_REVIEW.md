# 11E §14 — скрытый контекст: что legacy-свод получал неявно

Вопрос ставится ровно так, как его поставил урок 11D.1: заменяемая ветка шла
`claude -p` из корня репозитория, без `--setting-sources=`, и проектная память
CLI попадала в контекст модели. `ProviderAdapter` этот слой подавляет намеренно
и правильно — но вместе с личным контекстом может уйти инженерная инструкция,
которой больше нигде нет.

## 1. Что искали

Не «упоминается ли где-то слово», а **расшифровку** значений шкалы `severity` —
то, без чего шкала не имеет смысла. Поисковые иглы: `нельзя строить`,
`cannot be built`.

Поиск выполнен программно (`scripts/verify_11e_prompt_semantics.py`, раздел
`hidden_context`), ноль обращений к модели.

## 2. Результат

| источник | найдено |
|---|---|
| `prompts/` (все шаблоны конвейера и профили дисциплин) | **нет** |
| `disciplines/` | **нет** |
| корневой `CLAUDE.md` | **да** |
| `backend/app/pipeline/stages/text_analysis/provider_transport.py` | да (константа, перенесённая на 11D.1) |

Вывод 11D.1 подтверждается и для свода: единственная копия определений живёт в
корневом `CLAUDE.md`.

## 3. Почему для свода это важнее, чем для этапа 01

`text_analysis` severity **выбирает**. Свод его **меняет**, и это записано в
самом шаблоне этапа:

* `**Severity elevation**` — поднять уровень, если чертёж подтвердил текстовое
  замечание конкретной уликой;
* `**Severity reduction**` — понизить или убрать, если чертёж опроверг;
* правило подтверждения перечисляет переходы поимённо
  («РЕКОМЕНДАТЕЛЬНОЕ → ЭКСПЛУАТАЦИОННОЕ, ЭКСПЛУАТАЦИОННОЕ → ЭКОНОМИЧЕСКОЕ,
  КРИТИЧЕСКОЕ оставить как есть»);
* объединение сводит замечания разных уровней в одно.

Выполнять шкальные переходы, не зная, что значат концы шкалы, — это и есть та
самая слепота, которую 11D.1 обнаружил постфактум. Здесь она закрыта ДО вызова.

## 4. Что перенесено

Ровно одна вещь и явным текстом: константа `SEVERITY_SEMANTICS`. Она
**импортируется** из модуля этапа 01, а не копируется:

```python
from backend.app.pipeline.stages.text_analysis.provider_transport import (
    SEVERITY_SEMANTICS, ...
)
```

Тест `test_s_severity_semantics_shared_with_stage01` проверяет тождество
объектов (`is`), а не совпадение строк: два экземпляра одних и тех же
формулировок разошлись бы на первой же правке, и два этапа начали бы мерить
severity по-разному.

Место вставки — прямо перед `### Finding Fields`, то есть вплотную к перечню
значений шкалы. Якорь пишется в карту сборки промпта: если шаблон переименуют,
отчёт покажет `end_of_instructions`, а не промолчит о том, что блок уехал в
хвост.

## 5. Что НЕ переносилось

* персональные инструкции пользователя;
* инструкции агентов, хуки, MCP, skills, slash-команды;
* правила репозитория, не относящиеся к своду;
* формулировки, привязанные к конкретному документу (тест
  `test_s_severity_semantics_is_not_tuned_to_one_document` запрещает упоминание
  «ОСУП», «TN-S», «7.35», «133-23» в тексте константы).

## 6. Прочие каналы неявного контекста

| канал | статус в provider-режиме |
|---|---|
| проектный `CLAUDE.md` | недостижим: в артефакт релиза не попадает (denylist), cwd — пустой каталог попытки |
| пользовательский `~/.claude/CLAUDE.md` на .31 | существует (226 байт), определений severity НЕ содержит; подавлен `--setting-sources=` |
| память проекта / сессии | `--no-session-persistence` |
| MCP-серверы | `--strict-mcp-config`, `--mcp-config` не передаётся |
| хуки, slash-команды | `--disable-slash-commands`, `--safe-mode` |
| описания инструментов | инструментов ноль (`--tools=` + поимённый `--disallowed-tools`) |
| cwd как контекст | пустой каталог внутри попытки (проверено `CWD_ENTRIES` в живом процессе) |

## 7. Второй найденный случай: ложное обещание шаблона

Разбор вскрыл ещё одну зависимость от «того, чего нет». Шаблон свода
утверждает:

```
4. **Normative reference** — provided in system context.
```

Это неправда **ни на одной ветке**: в EN-шаблоне есть только
`{DISCIPLINE_ROLE}`, справочник норм не вкладывают ни ветка API, ни
заменяемая CLI-ветка (`_read_norms_reference` в сборке свода не вызывается).
Дефект пре-существующий и симметричный — по §15 он фиксируется как **KI-2** и
здесь не чинится.

Но добавленная справка о входе стояла рядом и говорила обратное МОЛЧА, из-за
чего в промпте оказались два соседних противоположных утверждения об одном и
том же, причём ложное — позже по тексту, то есть с большей рецентностью. Свод,
поверивший, что справочник «где-то в системном контексте», имеет ровно один
способ им воспользоваться: выдумать пункт.

Исправлено транспортно: ложная строка названа и опровергнута явно, а
опровержение стоит ВЫШЕ неё. Продовый шаблон не тронут ни на символ.
