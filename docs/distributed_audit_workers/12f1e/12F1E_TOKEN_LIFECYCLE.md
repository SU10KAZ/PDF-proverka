# Token lifecycle

There are two independent credentials:

1. The identity-reenrollment authorization token has prefix `ren_`, 32 random
   URL-safe bytes, default TTL 300 seconds, exact-pair scope and single-use
   status. Center stores only SHA-256.
2. The new runtime Worker token is generated by the existing `auth.generate_token`
   function only after every authorization and conflict check. Center inserts
   only its SHA-256 into `worker_tokens`; the first completion response returns
   the raw value.

The historical runtime token is never read, imported, copied, compared or sent.
The Worker replaces its local token file atomically with mode 0600 only after a
new credential is received. If the committed response was lost, an exact retry
returns no raw token and mints none. Recovery uses existing ADMIN-only token
rotation with a fresh idempotency key and preserves the Worker ID.
