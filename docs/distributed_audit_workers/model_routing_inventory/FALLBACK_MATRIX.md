## CRITICAL CONFIGURATION RISK

### 1. «Full Codex» частично уходит на Claude — и это не сбой, а код

Три места:

* **Верификатор (фикс) / страж отсутствия** — `claude -p --model claude-sonnet-5`,
  жёстко, `absence_guard.py:201-218`. Пользователь выбрал Codex и получает Claude.
* **05 Оптимизация** — нога `claude-opus-5` всегда. Это заявлено в подсказке пресета,
  но не видно в таблице.
* **Верификатор** и **F OPT Fix** — не уходят никуда, там нет модели.

Итог: **«Full Codex» никогда не был «всё на Codex».** Формулировка ожиданий по
названию пресета приведёт к неверному контракту для воркера.

### 2. `stage_models.json` грузится без валидации

`config.py:349-362` принимает любую строку, лишь бы ключ был известен.
Валидация есть только на входе API (`validate_stage_model_choice`) и в виде
диагностики `config_errors` в ответе `GET /api/audit/model/stages`. Файл,
отредактированный руками или приехавший из другой сборки, даст:
`block_batch` → тихая подмена на `openai/gpt-5.4`; остальные этапы →
попадание в OpenRouter-ветку с несуществующим id (см. комментарий в `config.py:466-470`).

### 3. Пресет — глобальное состояние, а не свойство задания

Смена пресета во время работы очереди меняет модели этапов, которые ещё не стартовали
в **уже запущенных** проектах: `get_stage_model()` читается в момент вызова стадии.
Снапшота в задании нет.

### 4. Одна нога 01 может выпасть без остановки — если выключить страховку

`combine_detector_results: ok = bool(ok_models)` — блок успешен при одной живой ноге.
Единственная защита — `STAGE01_ABORT_ON_LEG_FAILURE_ENABLED` (в `.env` `true`,
но дефолт в коде — `false`). На машине без этой строки в `.env` аудит завершится
«успешно» с молча урезанным recall. Исторический прецедент задокументирован
в самом коде (`config.py:489-510`): 19/22/29.07.2026, GPT-нога падала на 37/59/85 % блоков.
