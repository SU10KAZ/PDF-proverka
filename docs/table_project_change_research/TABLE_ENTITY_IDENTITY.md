# Entity identity в TABLE-route

Статус: исследовательское предложение. Изменения V3 и общего schema не предлагаются к выполнению в этой задаче. Основание: [S1–S9 и контракты V3](TABLE_PROJECT_CHANGE_RESEARCH.md).

## Четыре разных идентичности

| Уровень | Что идентифицирует | Может ли измениться при том же инженерном предмете |
|---|---|---|
| `TableKey` | Компонент таблицы в определённой DocumentVersion | Да: версия, структура, локальное вхождение |
| `row_key` / content fingerprint | Конкретное содержание строки в компоненте | Да: изменение любой ячейки меняет content fingerprint |
| Инженерный слот / entity | Установка П1 в определённой системе/корпусе; линия L1; помещение; расчётная группа | Сохраняется при доказанной замене модели или изменении свойств; alias марки требует доказательства |
| Изделие / вариант исполнения | Модель, артикул, материал, исполнение выбранного оборудования | Меняется при replacement; одно изделие может применяться во многих entity |

Следствие: модель нельзя одновременно требовать неизменной для сопоставления инженерного слота и искать её изменение как replacement. При этом для безымянной строки закупочной спецификации модель/артикул может быть частью identity **номенклатурной группы**: переход между моделями без связи слотов тогда неоднозначен.

## Область identity

Предлагаемая смысловая конструкция: область объекта/корпуса/раздела + тип инженерного предмета + явный идентификатор или группа + роль/назначение + необходимые различители. Это не формула хеша и не новый schema.

Межверсионная связь хранится отдельно от идентификаторов конкретных состояний. Для двух версий должны быть зафиксированы сравниваемый комплект, стадия/редакция и соответствие областей. Число `v001` само по себе не определяет, что две записи относятся к одному проекту или последовательным редакциям.

| Поле | Identity-роль | Роль параметра / ограничения |
|---|---|---|
| Марка установки `П1`, `Н1`, `ВРУ1` | Сильный локальный якорь после проверки уникальности и области | Может быть переименована. Одинаковая П1 в разных корпусах — разные слоты |
| «Марка» изделия, кабеля, материала | Идентификатор продукта/номенклатуры, иногда группы поставки | Выбранная марка является изменяемым состоянием слота. Значение колонки «Марка» определяют шапка и предмет |
| Тип | Функциональный класс помогает различению | Конкретный тип/типоразмер исполнения — изменяемое свойство. Переход класса может означать смену решения, а не утрату identity |
| Модель/артикул | Сильный идентификатор изделия; допустим в ключе однородной группы, когда речь именно о номенклатуре | Состояние инженерного слота; изменение модели не должно разрушать match этого слота |
| Позиция | Якорь, если это устойчивая позиция оборудования/ведомости и подтверждён scope | `№ п/п`, номер строки, номер колонки, номер листа — представление. Простое совпадение числа недостаточно |
| Система | Ограничивает область и membership | Переподключение entity к другой системе — изменение; нельзя потерять объект при изменении одного поля scope. Нужна независимая связь и сохранённые old/new membership |
| Назначение/функция | Якорь для функционального слота при уникальности в области | Назначение само может измениться; общее «вентилятор» не различает экземпляры. Без другого якоря смена назначения ведёт к REVIEW |
| Корпус, зона, этаж, помещение | Различают одинаковые марки/номера, ограничивают действие записи | Размещение может измениться. При изменении нужны независимые якоря, иначе REVIEW; не использовать изменяемый адрес как абсолютный запрет match |
| Серийный/заводской номер | Сильная identity физического экземпляра при достоверном чтении | Другой серийный номер не доказывает замену в том же слоте без связи с проектным назначением |
| Начало/конец линии | Контекст различения кабеля при неуникальной маркировке | Связи могут изменяться. Если единственные якоря изменились, не выдумывать continuity |
| Изготовитель | Уточнение выбранного продукта | Не identity экземпляра; изменение изготовителя без модели не всегда replacement |
| Мощность, расход, напор, масса, габариты | Не самостоятельные якоря слота | Сравниваемые свойства; совпадение помогает проверить совместимость, но не доказывает identity |
| Количество | Не identity экземпляра/функциональной группы | Состояние группы, с единицей, базой учёта и областью |
| Режим, сценарий, рабочая точка | Identity сравниваемого **наблюдения**, не оборудования | Изменение выбранного режима — отдельный возможный смысл; разные режимы одной версии не before/after |

Название колонки недостаточно для присвоения роли. В S7 колонка «Тип, марка…» содержит стандарт; в S2 «Маркировка кабеля» и «Марка» различны; в S4 `№` имеет дубли. Семантическая роль V3 `model` не устраняет эти неоднозначности.

## Профили предметов

| Семейство | Предмет | Возможная identity | Что не входит в обязательную неизменную identity |
|---|---|---|---|
| Спецификация с марками | Инженерный слот/комплект | Объект + система/группа + марка/устойчивая позиция + функция | Модель, количество, параметры выбранного изделия |
| Спецификация без марок | Номенклатурная группа | Область поставки + наименование класса + модель/артикул + исполнение + единица учёта | Количество. Замена модели потребует дополнительной связи между группами |
| Паспорта оборудования | Установка, её секция или вариант | Явная табличная марка установки + идентификатор секции/варианта + функция | Размер, масса, серия как единственный ключ. Заголовок паспорта вне TABLE не подменяет отсутствующую табличную связь |
| Кабельный журнал | Линия/цепь; при явном учёте — группа параллельных кабелей | Область + уникальная маркировка линии; при дублях — оконечные устройства/цепь/функция | Марка изделия, сечение, длина. В S2 одного MP-BIAL недостаточно |
| Воздухообмен | Помещение/зона и направление обмена | Корпус/этаж/зона + достоверный номер помещения + направление + режим | Площадь, объём, кратность, расход; общая система не делает все помещения одним entity |
| Расчётная таблица | Расчётный объект/группа нагрузки | Область питания/расчёта + явная группа + сценарий | Исходные величины, коэффициенты, результаты. Тип квартиры в S5 — группа расчёта, не единица оборудования |
| Таблица параметров | Система/зона/установка и её наблюдения | Явный предмет + параметрический раздел + режим/база значения | Каждая отдельная строка «напор/расход/масса» не создаёт новый entity |

Вертикальная таблица и широкая строка могут описывать один entity. Обратное также возможно: широкая строка содержит несколько сущностей («основной» и «резервный», приточная и вытяжная система). Границу entity определяет смысл ячеек, не физическая строка.

## Условия межверсионного сопоставления

1. **Явный уникальный якорь.** Сравнить марку/позицию внутри установленной области, проверить дубли и несовместимые назначения. Совпадение без проверки области — кандидат.
2. **Составной якорь.** При отсутствии уникальной марки использовать независимые табличные признаки функции, места и членства. Для PROVEN нужен единственный обоснованный counterpart; одна высокая похожесть строки этого не заменяет.
3. **Переименование.** Допускать только при независимом доказательстве continuity: явная old/new марка в таблице либо уникальная неизменная комбинация других якорей в полностью сопоставимом scope. Перестановка одинаковых экземпляров сохраняет только групповую identity, не индивидуальную.
4. **Дубли.** Полностью неразличимые одинаковые записи нельзя индивидуально match по порядку. Сохранить кратность multiset и сравнивать группу, если доказаны её однородность и область. Иначе REVIEW.
5. **Один → много / много → один.** Требуется явная комплектность или количественная эквивалентность в обеих версиях. Связь и базу «на комплект/всего» сохранить; не представлять как набор произвольных one-to-one match.
6. **Изменились все якоря.** Ни модельная похожесть, ни близость строк не доказывают замену. Сохранить альтернативы: replacement, removed+added, restructuring; REVIEW без сильного event.

Нет предлагаемого числового порога fuzzy matching: эта задача не является tuning. Для каждого будущего match нужны доказательства и причины исключения альтернатив, а не только confidence score.

## Примеры различения

- `П1, корпус А, A → B`: если П1 — подтверждённая марка установки в обеих таблицах, модель может измениться при той же entity.
- `модель A, 4 шт.` в двух корпусах: совпадение модели не объединяет области.
- S3: PatAIR-C/120 с разной массой в одной версии — два наблюдения; их принадлежность одному слоту не доказана.
- S4: повтор `2.2` не позволяет выбрать помещение по номеру; сохраняется конфликт/неоднозначность источника.
- «П1–П4, 4 шт.» ↔ четыре строки П1…П4: эквивалентность возможна только при подтверждённом смысле диапазона и одинаковой комплектности; промежуточные имена не генерируются из произвольного дефиса.

Все identity-основания должны ссылаться на TABLE-ячейки/шапки/группы. Внешний текст или графика не разрешают неоднозначность TABLE-route в рамках этого исследования.
