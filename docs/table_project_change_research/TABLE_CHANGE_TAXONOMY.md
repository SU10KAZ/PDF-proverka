# Таксономия крупных TABLE-изменений

Статус: предложение для обсуждения, 2026-09-13. Общий enum ProjectChange не изменяется. Существующие имена ниже сопоставлены со снимком TEXT-контракта; дополнительные названия — аналитические категории, не требование добавить enum. Источники S1–S9: [реестр исследования](TABLE_PROJECT_CHANGE_RESEARCH.md).

Единица события — инженерное решение в установленной области сравнения. Его размер определяется общим предметом и доказанной связью изменений. Число изменённых ячеек не является критерием крупности или значимости. Замена одного ответственного агрегата может быть крупнее сотни исправлений массы крепежа; оценку значимости нельзя выводить только из размера diff.

## Основные события

| Категория | Что означает одно событие | Минимальные TABLE-доказательства | Что входит в evidence | Когда REVIEW |
|---|---|---|---|---|
| `EQUIPMENT_REPLACED` | В том же инженерном слоте выбрано другое изделие/модель | Однозначная межверсионная связь слота; явные old/new модели; одинаковые роль и смысл колонок; исключены вариант/каталог и переименование | Модель, изготовитель, мощность, расход, напор, масса, размеры, подтверждённые компоненты новой комплектации | Модель отсутствует; поменялись только характеристики; новый тип несовместим с прежней функцией; одновременно исчезла identity; модель похожа только по строке |
| `EQUIPMENT_ADDED` / `EQUIPMENT_REMOVED` | Появился/исчез экземпляр либо вся учитываемая группа | Наличие на одной стороне и доказанное отсутствие в сопоставимой полной области другой стороны; либо явное табличное указание включения/исключения с областью и редакцией | Состояние существующей стороны, полнота отсутствующей, перечень проверенных таблиц, варианты сопоставления | Найдена/пропала строка, страница, таблица или фрагмент; комплект П ↔ РД разной подробности; не обследовано продолжение/перенос |
| `EQUIPMENT_COUNT_CHANGED` | Изменилось число одинаковых единиц одной доказанной группы | Установлена группа, обе величины, единица «шт.» либо иной доказанный счёт единиц, одинаковый охват и смысл количества | Количество, перечень включённых строк/экземпляров, основной/резервный состав при наличии | «Компл.» не раскрыт; в одной версии количество на систему, в другой суммарное; дубли; неизвестная принадлежность; ноль подменён пустотой |
| Изменение состава системы → `SYSTEM_CONFIGURATION_CHANGED` | У одной системы изменился состав функциональных членов/подсистем либо их отношения | Identity системы; old/new membership или явная табличная связь компонентов; полнота в границах заявленного вывода | Добавленные/удалённые роли, замены, количество, основной/резервный режим, старый и новый состав | Только сумма строк по разделу; количество таблиц; список компонентов стал подробнее без доказательства изменения комплекта |
| `CAPACITY_CHANGED` | Изменена производительность/расчётная нагрузка сущности в одном сопоставимом режиме | Те же сущность и сценарий; именованный показатель и единицы; old/new значения одного уровня: на единицу, рабочую группу или систему | Расход/тепловая нагрузка/мощность и связанные показатели, режим, источник агрегата, арифметика при допустимом выводе | «Номинальная» сопоставлена с «расчётной»; максимум с рабочей точкой; сумма резервных агрегатов принята за рабочую производительность; связь показателей не доказана |
| Изменение набора характеристик | Один предмет сохранился, изменены несколько его характеристик без доказанной замены/производительности | Identity предмета и сопоставимые свойства; обосновано, почему это один набор решения | Только изменённые характеристики плюс контекст их чтения | Нет общего предмета либо сгруппированы независимые решения. Снимок enum не имеет специального типа: обсуждается использование `OTHER_ENGINEERING_CHANGE` с явным смыслом, не подмена на replacement |

`EQUIPMENT_REPLACED` означает изменение выбора оборудования в документации. Таблица проектных версий сама по себе не доказывает физическую замену установленного оборудования на стройке.

## Специфические семейства

| Семейство | Предмет и крупное изменение | Ограничение классификации |
|---|---|---|
| Спецификации (S1/S7) | Выбор изделия, количество, комплектность; перегруппировка поставки | Материалы, метры кабеля, крепёж и оборудование не должны автоматически получать один equipment-тип. Изменение 35 → 40 м — количество материала/длина; соответствие общему типу ещё надо согласовать. |
| Ведомости/паспорта оборудования (S3) | Замена установки; изменение комплектации/характеристик установки | Вертикальная строка «Масса» — параметр, а не отдельное оборудование. Один паспорт может содержать несколько секций; один типоразмер встречается у нескольких установок. |
| Кабельные журналы (S2) | Для идентифицированной линии изменены марка изделия, жилы/сечение, параллельность, длина или оконечные связи | Это кабельное решение, не обязательно `EQUIPMENT_REPLACED`. Изменение конца при сохранённой identity линии — кандидат изменения конфигурации/соединения. Изменение длины не доказывает `ROUTING_CHANGED`: геометрический маршрут в этих колонках не указан. |
| Воздухообмен (S4) | Изменены приток/вытяжка помещения или зоны в одном режиме; изменена принадлежность обслуживающим системам | Помещение/зона не является вентилятором. Колонка систем может перечислять две разные системы. Требуемый расход помещения не равен паспортной производительности установки. |
| Расчётные таблицы (S5) | Изменена нагрузка расчётного объекта; пересмотрены исходные данные, коэффициенты или явный метод | Массовое изменение чисел не доказывает смену методики. Для метода нужна явно указанная в TABLE формула/методика с old/new; иначе фиксируется набор исходных/расчётных значений без причинного утверждения. |
| Параметры (S8/S9) | Изменён температурный график, напор, тепловая нагрузка; набор рабочих точек | Изменение рабочей точки в перечне не доказывает смену рабочего режима установки. Нужна отметка выбранного режима/точки. Таблица требований может описывать допустимый диапазон, а не фактическое состояние. |

Дополнительные типы из общего снимка (`SYSTEM_TYPE_CHANGED`, `SYSTEM_MODE_CHANGED`, `REQUIREMENT_CHANGED`, `ENGINEERING_SOLUTION_CHANGED`) пригодны только при прямом табличном свидетельстве соответствующего смысла. Без него остаётся более узкое параметрическое событие или REVIEW. Для кабеля, материала, помещения и расчётного объекта требуется корректный subject, см. [mapping](TABLE_TO_PROJECTCHANGE_MAPPING.md).

## Что не должно автоматически становиться ProjectChange

| Наблюдение | Проверка | Результат при достаточном доказательстве |
|---|---|---|
| Перестановка строк/колонок | Сохранились сопоставленные сущности, значения и роли колонок | Служебное изменение представления; 0 инженерных событий |
| Изменение порядковых номеров | Номер именно ordinal; независимая identity сохраняется | Служебная перенумерация; 0 событий. Изменённая инженерная марка требует отдельного анализа alias |
| Форматирование, десятичная запятая/точка, точная смена единицы | Однозначно сохраняются значение, размерность, смысл и точность исходной записи | Эквивалентное представление; 0 событий |
| Перенос таблицы/продолжения на другую страницу | Тот же набор сущностей/фактов при установленной области; сохранены дубли и роли | Изменение provenance; 0 событий |
| `SPECIFICATION_RESTRUCTURING` — аналитическая категория | Тот же смысловой состав и количества после доказанного преобразования групп/строк/колонок | Отдельная структурная запись; не новый enum ProjectChange и не состав системы |
| «Комплект, 1» раскрыт компонентами | Из таблиц доказана эквивалентная комплектность, нет двойного учёта | Детализация, 0 событий о добавлении. Без раскрытой старой комплектности — REVIEW, а не доказанное отсутствие изменений |
| Новые строки параметров в более подробной ведомости | Свойство раньше не было указано; изменения значения не доказаны | Дополнение данных; не old=null → новое инженерное значение |
| Добавлены требования в табличном ТЗ | Различить расширение представления и новое предписание в сопоставимом объёме | Может быть `REQUIREMENT_CHANGED`, если именно требование явно изменено; не всегда «детализация» |
| Повтор шапки/«ИТОГО» | Установлены роль и область агрегата | Не экземпляр и не независимое изменение оборудования |
| Противоречие двух ячеек одной версии | Сравниваются источники одного состояния | Конфликт источника, не выдуманное old → new |

Реструктурирование может сосуществовать с реальным изменением: перенос строк не скрывает изменение количества 2 → 3. Сначала сопоставляется содержание; служебный характер части diff не даёт права подавить весь diff.

## Условные сценарии с ожидаемой гранулярностью

Эти сценарии не являются результатами запуска. PROVEN здесь означает только выполнение перечисленных доказательных условий будущего решения.

| № | Условный TABLE-вход | Ожидаемый результат |
|---|---|---|
| T01 | Марка П1, та же функция/область: модель A → B; количество 1 → 1; изменены 20 характеристик | 1 `EQUIPMENT_REPLACED`; 20 характеристик и модель в фактах |
| T02 | Группа одинаковых установок G, модель A: 2 → 3 шт., вся группа явно учтена | 1 `EQUIPMENT_COUNT_CHANGED`; не три события по строкам |
| T03 | П1 и П2 отдельно идентифицированы, у каждой A → B | 2 замены. Допустима общая группа отображения, но единое инженерное решение не доказано |
| T04 | Одна поставочная группа из 20 одинаковых установок: A → B, 20 → 20; состав группы и единое назначение доказаны | 1 групповая замена с областью группы и количеством; не утверждать identity двадцати экземпляров |
| T05 | Та же группа: A → B и 2 → 3, общий переход состава явно не задан | 2 связанных события: замена и количество; свойства замены не создают дополнительные события. Если невозможно определить заменяемую подгруппу — REVIEW по замене |
| T06 | Система явно меняется с «1 рабочий + 1 резервный» на «2 рабочих + 1 резервный» | 1 `SYSTEM_CONFIGURATION_CHANGED`; количество и рабочая производительность — evidence, если их связь явно подтверждена |
| T07 | П1: расход/напор изменились, модель не указана в обеих версиях | 1 `CAPACITY_CHANGED` или изменение набора характеристик при доказанной identity и режиме; replacement не доказан |
| T08 | Все записи одинаковы, строка П1 уехала на следующую страницу | 0 инженерных событий; перенос provenance |
| T09 | П1 отсутствует справа, но следующая страница не получена | REVIEW для возможного удаления; запрет PROVEN removal |
| T10 | Впервые появилась подробная спецификация с десятью компонентами прежнего «комплекта» | REVIEW на эквивалентность, пока нет табличной расшифровки старой комплектности; не десять added |
| T11 | Линия L1: то же начало/конец, 3×2,5 → 3×4 мм², длина 40 → 45 м | 1 изменение кабельного решения с двумя фактами; физический перенос трассы не доказан |
| T12 | Группа нагрузки: изменился коэффициент, P/Q/S/I; явная табличная формула связывает их | 1 изменение расчётного решения/набора; выходы — зависимые факты. Без формулы причинную связь не утверждать |
| T13 | Перестроили спецификацию и одновременно количество той же группы 2 → 3 | 1 count event плюс отдельное структурное наблюдение |
| T14 | Единственная масса 871 → 845 кг, остальные данные не обеспечивают identity | REVIEW; ни replacement, ни «тот же агрегат» не доказаны |

Для всех сценариев действуют [правила collapse](PARAMETER_COLLAPSE_RULES.md) и [ограничения REVIEW](TABLE_TO_PROJECTCHANGE_MAPPING.md).
