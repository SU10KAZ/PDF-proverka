# UNIFIED ENGINEERING EVIDENCE V1 — единая модель доказательств, факты функции и переоценка lineage без ИИ

Исследование (Фазы 2–6 мастер-задачи «Architecture closure»). Модель не
вызывалась ни разу; выкатки, теневого режима, материализации и пуша нет, ни
один боевой модуль не изменён. Селектор, промпт и генератор кандидатов Function

213 задач и 1 461 кандидата. Артефакты пишутся только в
`comparison/ai_sheet_matcher/20260905_unified_evidence_v1/` (локально, вне git).

Продолжение после ворот Фазы 1 (`docs/function_assembly_membership_v1.md`):
сертифицированное покрытие 0 из 26. По условию мастер-задачи ноль не
останавливает работу, а задаёт вопрос — предел ли это **данных** или нашего
**представления**. Здесь все доказанные слои сведены в одну форму, из неё
синтезированы факты функций, построены профили доказательств для каждого
кандидата и переоценён lineage без единого обращения к модели.

## 1. Контракт `UnifiedFact`

Одна запись для всего, что показывают семь производителей:
`NATIVE_PDF_TEXT`, `MARKDOWN_OCR`, `TABLE`, `FUNCTION_REGION`,
`SCHEMATIC_TOPOLOGY`, `FUNCTION_TOPOLOGY_SUBGRAPH`, `FUNCTIONAL_ASSEMBLY`.

| Поле записи | Содержание |
|---|---|
| `fact_id`, `field`, `normalized_value` (+ `raw_value`) | закрытый словарь из 52 полей |
| `source_representation`, `producer` | чем нарисовано и какой модуль выпустил — две разные оси |
| `pair_id`, `document`, `side`, `physical_page`, `container` | контейнер: `TABLE_CELL` / `TABLE` / `REGION` / `ISLAND` / `ASSEMBLY` / `STAMP` |
| `declared_function_ids` | функция, которую **называет производитель** (паспорт) — заявлено, не доказано |
| `certified_function_scope_id`, `certified_function_ids`, `certified_assembly_id` | только через `CERTIFIED` сертификат принадлежности |
| `applicability` | `FUNCTION_LOCAL` / `ASSEMBLY_LOCAL` / `SHEET_SHARED` / `DOCUMENT_SHARED` / `UNKNOWN` — едет с фактом и никогда не расширяется |
| `claim_semantics` | `POSITIVE_PRESENCE` / `SUPPORT_ONLY`; фактов отсутствия в словаре нет |
| `provenance_grade` | `EXACT_GEOMETRY` / `DRAWN_RELATION` / `PAGE_ONLY` / `DERIVED` — перечисление, не число |
| `provenance_refs` | ссылки слоя-источника (label / node / edge / region / cell / passport / fragment) |

Правила стражей (`assert_fact_contract`): присутствие утверждается только с
точным провенансом (геометрия или нарисованное отношение); строка OCR имеет
страницу, но не прямоугольник, поэтому сама по себе только поддерживает и
**повышается** до присутствия, лишь когда нативный слой печатает ту же строку на
той же странице — с обеими ссылками; функция или сборка называются
сертифицированными только при наличии сертификата (страж сверяет пары);
`FUNCTION_LOCAL` требует названной функции; `ASSEMBLY_LOCAL` — названного
контейнера. Ключи сходства/ранга отвергаются стражем моста.

## 3. Факты функции (Фаза 3)

Каждый факт функции несёт **основание**: `CERTIFIED` (нарисован внутри
сертифицированной сборки — цепочка структурна от паспорта до туши), `DECLARED`
(так говорит паспорт; заявление производителя, никогда не повышается),
`SHEET_SHARED` (марка в заголовке/штампе: истинно о листе, молчит о функции),
`REFERENCED` (другой лист называет марку). Заявленное значение, которое нативный
слой печатает на той же странице, помечается `natively_corroborated`: **строка**
тогда присутствует положительно, а её принадлежность функции остаётся
заявлением паспорта.

## 5. Переоценка lineage без ИИ (Фаза 6)

Селектор не запускался, кандидаты не ранжировались и не удалялись. Вопрос:
улучшает ли новое доказательство правильного кандидата, не подавляя других
законных? «Новое» = общий факт, сертифицированный с обеих сторон, или
подтверждённый нативным слоем с обеих сторон (то, что построила эта линия
исследований; старые каналы — заявленные значения паспорта).

| | Задач |
|---|---:|
| Задач / кандидатов | 213 / 1 461 |
| С хотя бы одним поддержанным кандидатом (общий факт) | 168 |
| С общим **сертифицированным** фактом | **0** |
| С новым доказательством у какого-либо кандидата | 43 |
| Многокандидатных задач | 182 |
| из них с **идентичными** профилями у нескольких кандидатов | **168** |
| из них новое доказательство выделяет ровно одного кандидата | 11 |
| из них ровно один поддержанный кандидат (любыми фактами) | 18 |
| Несколько кандидатов делят вершину по числу общих фактов | 99 |
| Один кандидат ведёт только заявленными фактами | 20 |
| Явных противоречий (все — `board_mark` у MERGED: `ЯK1`↔`ЩAO5`, `BPY3`↔`BPY1`, `ЯK4`↔`ЩAO5`) | 3 задачи / 3 кандидата |

Идентичность: марка есть на обеих сторонах у 21 задачи; совпадает хотя бы у
одного кандидата — 13; явно расходится — 3.

Исследовательские эталоны (49, гипотезы, не истина): поддержан общим фактом —
18; поддержан новым доказательством — 12; имеет строго больше общих фактов,
чем любой другой кандидат, — 15; ничья — 2; новое доказательство говорит за
**не**-эталонного кандидата — 6.

Что стоит за «новым доказательством», измерено, а не предположено: общие
нативно подтверждённые факты — `floors` 109, `building`/`corpus`/`serviced_object`
по 46, `zone` 31 (на уровне кандидатов). `floors` наполняется боевой
регуляркой, ловящей отметки (`0.000`, `+4.500`, `6.000`) как этажи — это
значения **уровня листа**, повторяющиеся серией; `serviced_object`/`corpus`
приходят из штампа и различают **документы**, а не функции одной серии. Шесть
случаев «за не-эталонного кандидата» — прямое следствие: отметка, напечатанная
на многих листах серии, «поддерживает» любого соседа.

**Ответ на вопрос Фазы 6:** слой ни одного кандидата не удаляет; там, где он
выделяет одного, он делает это положительным фактом, которого нет у других, и
таких многокандидатных задач 11 из 182. Но выделяющие факты — уровня листа, а
168 из 182 многокандидатных задач остаются с идентичными профилями. Различающего
сигнала **уровня функции** между версиями на этом корпусе слой не даёт — не
потому, что не умеет его нести, а потому, что документы его не печатают там,
где его можно было бы приписать функции (Фаза 1, находки 1, 3, 4).

## 6. Предел данных или предел представления

Единая модель отвечает измерением: представление достаточно — семь
производителей ложатся в одну форму без потери провенанса, стражи держат
асимметрию, сертификаты сцепляют паспорт с тушью там, где тушь есть. Предел —
данные, и он трёхчастный:

1. **идентичность** функции слева печатается только в заголовке/штампе (0 из
   34 марок IOS1.1/LEFT привязаны к проводнику), справа — вдоль проводов у
   девяти;
2. **содержание** функции (строки фрагмента) живёт в OCR растровых таблиц:
   повышено нативным слоем 90 строк из 1 874;
3. **поля области действия** — уровня листа: напечатаны нативно в 90–95 %,
   приписаны функции — 0.

Поэтому `CERTIFIED_FUNCTION_FACTS_BOTH_SIDES` = 0 — это посчитанный ответ, а
не константа, и FUNCTION LINEAGE AUTO-MATCH на этом корпусе **ограничен данными**.
