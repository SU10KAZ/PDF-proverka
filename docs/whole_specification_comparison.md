# Сравнение полной спецификации между версиями

Дата: 18.10.2026. Статус: отдельный прототип; в интерфейс и production не подключён.

## Задача и принцип

При вставке листа или строки таблицы спецификация перераспределяется по страницам.
Сопоставление «лист A ↔ лист B» перестаёт соответствовать составу таблицы.
Единица нового сравнения — **полная спецификация в выбранной версии**.
Номер страницы используется для ссылки на доказательство, а не как ключ позиции.

В существующем `version_comparison/spec.py` уже есть сборка позиций через страницы,
но её вход строится из PDF. Текущая кнопка «Сводка изменений (MD)» использует
`version_comparison_ai/sheet_changes/series_summary.py` и собирает готовые
описания листов. Она не является источником полной спецификации.

Новый механизм получает подготовленный `_results.md` каждой версии. TEXT
авторитетен: ни повторного PDF-извлечения, ни OCR, ни исправления текста по растру.
Версии и полная область спецификации задаются явно. Нельзя передавать только
изменённые или успешно сопоставленные листы.

## Последовательность

1. Канонический парсер `common/results_md.py` читает все выбранные страницы/блоки
   каждой версии. Сохраняются SHA-256 исходного MD, абсолютные строки, страницы,
   `block_id` и исходные цитаты. Проверяются пропуски, дубликаты и неподдерживаемые
   типы блоков. Пустая или повреждённая область не означает пустую спецификацию.
2. Одна сессия Codex Luna получает **всю спецификацию одной версии**. Она
   возвращает позиции с разделом, родителем и девятью полями: позиция,
   наименование, марка, код, поставщик, единица, количество, масса, примечание.
   Позиция может ссылаться на несколько блоков/страниц. Повторы сохраняются.
3. Программа проверяет ответ: точный состав блоков, покрытие непустых строк,
   цитаты и значения полей. Неподтверждённое значение или потерянная строка
   делает сторону неполной. Содержательные примечания нельзя скрывать в ignored.
4. После сборки обеих полных сторон сравниваются реестры. Сначала взаимно
   погашаются одинаковые записи с сохранением кратности. Затем используются
   однозначные признаки внутри раздела/родителя: код, наименование с маркой,
   наименование. Спорные соответствия остаются отдельными группами для проверки.
   Близость количества, порядок строк и номер страницы не решают неоднозначность.
5. Изменение количества/марки/наименования и других содержательных полей
   записывается как «было → стало». Перенос между физическими страницами
   и перенумерация позиции отмечаются отдельно. Новые и исчезнувшие позиции
   имеют источники; при неполном входе остатки явно предварительные.
6. Записываются `report.json` и `report.md`. MD содержит сводку, изменения,
   неизменившиеся позиции, добавления/удаления, неоднозначности и ссылки
   на исходные строки обеих версий. JSON сохраняет полный реестр доказательств.

Полнота покрытия текста не доказывает безошибочность смысловой разметки модели.
Прототип не определяет автоматически границы нескольких спецификаций в одном
документе, их соответствие между версиями и правильность выбранной области.
Эти решения должны быть проверены перед подключением к действующему режиму.

## Исполнение и параллельность

Исполнитель — существующий `CodexExecDescriber`: `codex exec`, модель
**`gpt-6-luna`**, усилие `high`, авторизация Codex. Модель зафиксирована,
подмены и OpenRouter нет. CLI запускается в read-only sandbox, с отключёнными
инструментами, без пользовательского конфига, с JSON Schema.
Применение `codex exec` и структурированного вывода описано в
[официальной документации](https://developers.openai.com/codex/noninteractive/).

Предел — **50 одновременных сессий**, по умолчанию. Параллелятся целые
спецификации/версии; внутри одной спецификации страницы не разрезаются на
независимые задания. Для одной пары нужны две сессии, для 25 различных пар —
до 50. Фактический пик и число обращений записываются в отчёт.

Планировщик запускает следующую задачу при освобождении места. Автоматических
повторов нет. Ошибка квоты/входа останавливает выдачу новых задач и отменяет
незавершённые сессии; отчёт отмечает неполноту. Успешные ответы сохраняются и
при повторном явном запуске проходят проверку заново. Ключ кэша учитывает
вход, промпт, схему, модель, effort и CLI runtime.

## Локальный запуск

Вход — JSON manifest с одной или несколькими парами. Пути к MD считаются от
каталога manifest. Одна сторона сейчас соответствует одному подготовленному MD.

```json
{
  "schema": "whole-specification-input/v1",
  "pairs": [{
    "id": "spec-1",
    "title": "Спецификация оборудования",
    "old": {"path": "old_results.md", "label": "V11", "pages": [79, 80, 81]},
    "new": {"path": "new_results.md", "label": "V12", "pages": [81, 82, 83, 84]}
  }]
}
```

Можно вместо `pages` передать `block_ids`. Для MD, который целиком является
одной спецификацией, требуется явное `"all_blocks": true`. Номера страниц
физические, начиная с 1, и у старой и новой версии могут полностью различаться.

Подготовка пакетов без вызовов модели:

```bash
python scripts/compare_whole_specifications.py manifest.json output_directory
```

Запуск через Codex:

```bash
python scripts/compare_whole_specifications.py manifest.json output_directory \
  --run-codex --parallel 50 \
  --codex-bin /home/coder/auditmanager/shared/codex-cli/codex-0.162.0-alpha.17.2/codex
```

В `plan.json` фиксируются область, размер и пригодность каждого пакета.
В `calls/<hash>/` сохраняются `prompt.md`, `schema.json`, `source.json`, ответ,
проверенный реестр, метаданные вызова и события CLI. Реальные исходные документы
и артефакты прогонов не следует добавлять в git.

При превышении 140 000 символов полного пакета задача возвращается как неполная.
Механизм не обрезает хвост и не делит её по страницам. Автоматическое выделение
самостоятельных разделов большой спецификации — следующий этап разработки.
IMAGE/GRAPHIC требуют отдельного пути с изображениями; текстовое описание
графического блока не считается прочитанной таблицей.

## Проверки и пример

Модули: `specification_source.py`, `specification_compare.py`,
`specification_run.py` в `backend/app/services/version_comparison/`.
Тесты: `tests/test_whole_specification_{source,compare,run}.py`.

Синтетический вход: `tests/fixtures/whole_specification/manifest.json`.
Проверяются перенос всей спецификации на страницу, разрыв одной позиции,
изменение количества 120 → 125, перенумерация, добавление коробки и удаление
клеммы. Дополнительные тесты проверяют неоднозначные повторы, разные разделы,
нулевое количество, повреждённое доказательство, пропуски и остановку очереди.
Тест планировщика выполняет 52 подставные задачи с барьером на первых 50,
проверяя фактическую, а не только настроенную параллельность.

Проверка 18.10.2026: **65 тестов прошли**, включая существующие тесты
`test_version_comparison_spec.py` и `test_version_comparison_md_report.py`.
Две реальные сессии Luna обработали OLD и NEW из синтетического примера.
Обе дали по четыре позиции, все строки прошли проверку. Найдены ровно одно
изменение количества, одна добавленная и одна удалённая позиция; три переноса
и три перенумерации отделены от содержательных изменений.
[Готовый пример MD](examples/whole_specification_synthetic.md) пересобран из
сохранённых ответов с повторной локальной проверкой, без новых обращений.
Реальный нагрузочный прогон на 50 сессиях не проводился: для этой пары нужны две.

Это инженерные тесты на искусственных данных. Они не являются оценкой качества
на объекте 272 или доказательством исправления конкретной серии со скриншота.
Реальные прогоны ProjectChange должны использовать разрешённый DEV-корпус
объекта 272, stage_1 → stage_2, v002, через действующий access guard;
validation/final не использовать для доработки.

## Следующее решение о применении

Для действующего режима нужно определить, кто подтверждает полную область СО
в каждой версии, как объединяются части одного документа и где результат
появляется в серии. Предлагаемая точка подключения — отдельный раздел
«Спецификация целиком» в итоговом MD. Он должен формироваться из полных реестров
и не зависеть от успеха постраничного сопоставления. Статусы таблицы листов,
визуальные наложения и прежняя MD-сводка в этом прототипе не изменены.
