# Группы документов на доске пар (1 → N, N → 1, N ↔ M)

Один проект стадии П часто раскладывается в РД на несколько проектов
(например, по корпусам), и бывает наоборот: несколько проектов П сводятся в
один проект РД. Сравнивать такие документы попарно нельзя: листы остальных
проектов выглядели бы «удалёнными» в каждой паре. Поэтому документы одной
стороны группы склеиваются в сборку (`project_assemblies`). Сборка
прикрепляется к своей стадии и сравнивается с другой стороной как обычная пара
один к одному.

Допустимы все сочетания:
- **1 → N** — один слева, несколько справа (исходный вариант);
- **N → 1** — несколько слева, один справа (с 13.11.2026);
- **N ↔ M** — сборка против сборки.

## Что видит инженер

- Доска пар открывается уже после загрузки **одной** стороны. Напротив каждого
  документа стоит пустое место.
- В колонке «Управление парой» две кнопки:
  - «+ Слева» показывается, если в строке есть документ справа. Загрузка идёт в
    `stage_1` с привязкой к строке.
  - «+ Справа» показывается, если в строке есть документ слева. Загрузка идёт в
    `stage_2`.
- Один загруженный проект встаёт обычной парой. Два и больше на одной стороне
  образуют сборку этой стороны.
- Документ можно перетащить на «+ Слева» / «+ Справа» другой строки — он
  добавится к документам этой стороны строки.
- От документов одной стороны к документам другой идут пунктирные линии:
  - 1 → N — веер вправо;
  - N → 1 — зеркальный веер к правому документу;
  - N ↔ M — линии сходятся к середине и расходятся от неё.
- У группы есть статус сборок: «Собирается сборка…», «Нужна пересборка»,
  «Прикрепляем сборку…», «Сборка не удалась». Если склеена левая сторона,
  статус называет сторону: «Нужна пересборка слева».
- Подпись группы: «Сборка из N проектов · M листов» или «Слева сборка из … ·
  Справа сборка из …». Рядом кнопка «Пересобрать»: она пересобирает
  устаревшие или упавшие стороны.
- Участников склеенной стороны можно перетаскивать внутри своей стороны или
  двигать кнопками ↑/↓. Выбранный порядок сохраняется на сервере. После
  изменения порядка нажмите «Пересобрать»: до этого группа помечена «Нужна
  пересборка» и недоступна для нового анализа. Прежние результаты сохраняются.
- «×» у участника возвращает его в общий список:
  - сторона, на которой остался один документ, перестаёт быть сборкой (её
    сборка отцепляется);
  - если на обеих сторонах осталось по одному документу, группа распадается в
    обычную пару на месте строки.
- «Копировать сравнение» (независимое сравнение с тем же левым документом,
  `new_group: true`) существует только для правой стороны. Для строк со
  сборкой слева кнопка скрыта.
- Карта листов для пары со сборкой (на любой стороне) не строится: номера
  листов в сборке повторяются. Пара сразу идёт в режим смысловых блоков.

## Как устроено

- Реестр: `projects_v2/objects/<object>/comparison/document_groups.json`,
  схема `stage_document_groups/2`, сервис
  `backend/app/services/stage_comparison/document_groups.py`. Ключи — коды
  документов, а не пути PDF: сессия пересоздаётся при каждой загрузке, а код
  переживает новые версии.
- Группа — это строка доски. В ней есть стороны `left` и `right`
  (`members`, `manual_order`, `assembly_id`, `assembly_version_id`,
  `attached_version_id`) и якорь `anchor: {side, document_code}`.
  - Сторона с двумя документами и больше собирается: `left` → `stage_1`,
    `right` → `stage_2`. Независимое сравнение собирает правую сторону даже из
    одного документа.
  - **Якорь** — документ, вокруг которого возникла группа. Он держит позицию
    строки в раскладке пар и остаётся в ней, даже если его сторона стала
    сборкой (N ↔ M). Выбывший якорь заменяет первый участник той же стороны.
  - Документ стороны входит не больше чем в одну обычную группу. Повторное
    добавление переносит его из другой группы. Якорь другой группы перенести
    нельзя (`MEMBER_IS_GROUP_ANCHOR`).
  - Убрать последний документ стороны нельзя (`MEMBER_LAST`).
- Имена сборок: `"{документ другой стороны строки} · сборка из N"`.
  - Справа это по-прежнему `«ИОС2.1 · сборка из 9»`, поэтому у существующих
    групп имена и коды документов не изменились.
  - Слева — `«<правый код> · сборка из N»`.
- API (`/api/stage-comparison/objects/{id}/document-groups`):
  - `GET` — список групп. Каждая сторона отдаётся отдельно; поля верхнего
    уровня `members`, `assembly_*`, `page_count` описывают правую сторону
    (совместимость).
  - `POST` — `{side: "left"|"right" = "right", left_document_code |
    right_document_code, member_codes, group_id?, new_group?}`. Указывается
    документ **противоположной** стороны строки. Старый payload без `side`
    работает как раньше.
  - `DELETE …/{group_id}/members/{code}?side=right|left` — сторона обязательна
    по смыслу: один код может быть и в П, и в РД.
  - `PUT …/{group_id}/order` — `{side, member_codes}`, все участники стороны
    ровно один раз.
  - `POST …/{group_id}/rebuild[?side=]` — без `side` пересобираются стороны,
    которым это нужно.
  - Распад отдаёт `released: [{left_document_code, right_document_code,
    anchor_side}]`. Фронт ставит второй документ напротив якоря.
- Сборка запускается в фоне (`launch_version`). `GET` групп прикрепляет готовые
  версии обеих сторон и отцепляет прежние. Фронт опрашивает группы каждые 4 с,
  пока идёт сборка. После смены прикреплённой версии на любой стороне он
  обновляет сессию.
- Участники групп (кроме якорей) и сборки групп в раскладке пар не стоят: их
  место в строке занимает сама группа.
  - `save_document_pairing` не требует их ни в `left_order`, ни в
    `right_order`.
  - `suggest_document_pairing` их не видит.
  - Правило общее для бэкенда и фронта: `hidden_documents(stage, side)` на
    бэкенде, `scHiddenGroupPaths(side)` / `scBoardDocumentsLeft|Right` на
    фронте.
- Полнота состава пары (`composition_completeness`) наследуется от сборки
  справа, а если справа одиночный документ — от сборки слева.
- Анализ V3 читает происхождение листов (`assembly_origin.json`) для обеих
  сторон: «лист X проекта Y» работает и для левой сборки.
  - Mapper при переполнении делит NEW по проектам сборки, а OLD — пополам по
    страницам. Покрытие OLD×NEW от этого полное.
  - Резка OLD по проектам сборки — отдельная доработка (не сделана).
- Новая сессия тех же папок наследует раскладку пар последней сессии
  (`document_pairing.inherited_from`).
- Всё работает только при `PROJECT_ASSEMBLIES_ENABLED=1`. Без флага API
  отвечает 409 `ASSEMBLIES_DISABLED`, а «+» показывается только у строк, где
  на этой стороне пусто.
- Сборки создают только группы. Ручная вкладка «Сборки» и её API
  `/api/project-assemblies` удалены 30.09.2026. Сервис `project_assemblies`
  остался: на нём стоят группы и происхождение листов в V3.

## Схема 1 и откат

- Записи схемы 1 (`left_document_code` + правые `members` + плоские поля
  сборки) читаются как группа «1 → N» с якорем слева. Миграция не нужна.
- При записи каждая группа, у которой слева один документ, дублирует поля
  схемы 1. После отката на релиз до 13.11.2026 такие группы работают как
  прежде.
- Группа с несколькими документами слева в схеме 1 невыразима. Прежний релиз
  видит её с пустым `members` и не трогает. Её левая сборка остаётся
  прикреплённой к `stage_1` и появляется на доске свободным документом.
  Поэтому перед откатом такие группы стоит распустить (кнопкой «×»).

## Гочи

- SVG «веера» в шаблоне внутри `index.html`: `:viewBox` браузер приводит к
  нижнему регистру, и SVG перестаёт масштабироваться. Нужен объектный
  `v-bind="{viewBox: …}"`. SVG позиционируется абсолютно, иначе его высота по
  умолчанию (150 px) раздувает строку. Пути считает `scFanPaths(row)`.
- Выгрузки портала с августа 2026 пишут заголовки страниц как
  `## Page N — Sheet M — Название`. Общий разборщик `results_md` раньше их не
  видел, и сборка падала с «страницы MD не покрывают PDF». Исправлено
  отдельным коммитом, см. `PAGE_HEADER_RE`.
- Некоторые выгрузки пропускают в MD секции страниц без OCR-блоков.
  Сборщик допускает такие пропуски при полном `pages[]` в `blocks.json`,
  сохраняет все страницы PDF и создаёт пустые секции MD в сборке. Пропуск
  страницы с блоками, повторные заголовки, неверный порядок или расхождение
  страниц блоков между MD и JSON остаются ошибками. Исходный MD не меняется.
- Сканер стадии распознаёт раскладку `documents/<код>/versions/` только при
  `stage.json` с `storage_profile: comparison_stage_v1`. Без него каждый PDF
  (и `02_work/document.pdf`) идёт отдельным документом без кода.
