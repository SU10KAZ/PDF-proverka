# Группы «один слева → несколько справа» на доске пар

Один проект стадии П часто раскладывается в РД на несколько проектов
(например, по корпусам). Сравнивать его с каждым корпусом отдельной парой
нельзя: листы остальных корпусов выглядели бы «удалёнными» в каждой паре.
Поэтому правые проекты группы склеиваются в одну сборку
(`project_assemblies`), и она сравнивается с левым проектом как обычная пара
один к одному.

## Что видит инженер

- Доска пар открывается уже после загрузки **одной** стороны. Напротив каждого
  левого проекта справа стоит пустое место с кнопкой «+».
- «+» открывает загрузку справа (стадия заблокирована на `stage_2`) с
  привязкой к строке. Один загруженный проект встаёт обычной парой, два и
  больше образуют группу.
- Правый документ можно перетащить на «+» другой строки, и он добавится к её
  правым проектам.
- От левого документа к каждому элементу справа идут пунктирные линии.
  У группы есть статус сборки («Собирается сборка…», «Сборка из N проектов ·
  M листов», «Нужна пересборка», «Сборка не удалась») и кнопка «Пересобрать».
- По умолчанию проекты группы склеиваются в естественном порядке кодов.
  Участников можно перетаскивать внутри своей группы или перемещать кнопками ↑/↓.
  Выбранный порядок сохраняется на сервере; новые участники добавляются в конец.
  После изменения порядка нажмите «Пересобрать»: до этого группа помечена
  «Нужна пересборка» и недоступна для нового анализа. Прежние результаты сохраняются.
- Справа рядом расположены «+ Добавить в сборку» (дополняет текущую группу)
  и «+ Отдельное сравнение» (создаёт независимое сравнение с тем же исходным
  документом). Даже один правый проект сохраняет независимую группу.
  API: `new_group: true`; дополнение конкретной группы — через `group_id`.
  Пустой черновик хранится в браузере.
- «×» у участника возвращает его в общий список. Если в обычной группе остаётся один
  проект, группа распадается и он становится обычной парой.

## Как устроено

- Реестр: `projects_v2/objects/<object>/comparison/document_groups.json`,
  сервис `backend/app/services/stage_comparison/document_groups.py`. Ключи —
  коды документов, а не пути PDF: сессия пересоздаётся при каждой загрузке, а
  код переживает новые версии. Правый документ входит не более чем в одну
  группу.
- API: `GET/POST /api/stage-comparison/objects/{id}/document-groups`,
  `DELETE …/{group_id}/members/{code}`, `POST …/{group_id}/rebuild`,
  `PUT …/{group_id}/order` с `member_codes` (все участники ровно один раз).
- Сборка запускается в фоне (`launch_version`). `GET` групп прикрепляет готовую
  версию к `stage_2` и отцепляет прежнюю. Фронт опрашивает группы каждые 4 с,
  пока идёт сборка, и после прикрепления обновляет сессию.
- Участники групп и сборки групп в раскладке пар не стоят: их место в строке
  занимает сама группа. `save_document_pairing` не требует их в `right_order`,
  `suggest_document_pairing` их не видит. Правило общее для бэкенда и фронта
  (`hidden_right_documents` ↔ `scHiddenRightPaths`).
- Новая сессия тех же папок наследует раскладку пар последней сессии
  (`document_pairing.inherited_from`). Раньше после каждой загрузки раскладка
  пропадала.
- Всё работает только при `PROJECT_ASSEMBLIES_ENABLED=1`. Без флага API
  отвечает 409 `ASSEMBLIES_DISABLED`, а «+» показывается только у строк без
  правого документа.
- Сборки создают только группы. Ручная вкладка «Сборки» и её API
  `/api/project-assemblies` удалены 30.09.2026: вкладка дублировала группы, а
  на объекте 256 все шесть сборок были собраны группами. Сервис
  `project_assemblies` остался: на нём стоят группы и происхождение листов в V3.

## Гочи

- SVG «веера» в шаблоне внутри `index.html`: `:viewBox` браузер приводит к
  нижнему регистру, и SVG перестаёт масштабироваться. Нужен объектный
  `v-bind="{viewBox: …}"`. SVG позиционируется абсолютно, иначе его высота по
  умолчанию (150 px) раздувает строку.
- Выгрузки портала с августа 2026 пишут заголовки страниц как
  `## Page N — Sheet M — Название`. Общий разборщик `results_md` раньше их не
  видел, и сборка падала с «страницы MD не покрывают PDF». Исправлено
  отдельным коммитом, см. `PAGE_HEADER_RE`.

- Некоторые выгрузки пропускают в MD секции страниц без OCR-блоков.
  Сборщик допускает такие пропуски при полном `pages[]` в `blocks.json`,
  сохраняет все страницы PDF и создаёт пустые секции MD в сборке. Пропуск
  страницы с блоками, повторные заголовки, неверный порядок или расхождение
  страниц блоков между MD и JSON остаются ошибками. Исходный MD не меняется.
