# Изолированные вычисления сравнения версий

Изменение после зависания 15.10.2026: локальный сервер 8095 и IDE делили
`user-1001.slice` с `MemoryHigh=16G`, `MemoryMax=20G`. Шесть обработчиков
подняли память сравнения с 2,4 до 10 ГБ. При свободной памяти машины
возникли высокая задержка выделения памяти и заполнение swap.

Дополнительно `OPENCV_NUM_THREADS=1` не ограничивал OpenCV: проверка на
установленной 4.13.0 возвращала 12 потоков. Используется
`OPENCV_FOR_THREADS_NUM=1`, а в дочернем процессе также `cv2.setNumThreads(1)`.

## Устройство

- Веб-процесс управляет прогонами и отдаёт результаты. При
  `VERSION_COMPARISON_EXECUTOR=worker` профилирование PDF, сравнение листов и
  разбор спецификаций выполняются отдельной службой. Недоступность службы
  не включает запасной тяжёлый расчёт внутри веб-процесса.
- SQLite WAL хранит задания и результаты. Допустимы только операции
  `profile`, `sheet`, `spec`, `probe`; произвольные функции не сериализуются.
- Управляющий процесс запускает отдельный процесс для каждого задания.
  Одновременных процессов до 12, по одному вычислительному потоку на процесс.
  Завершение процесса освобождает его память; повреждение одного процесса
  не ломает пул остальных задач.
- Допуск учитывает резерв на лист, будущий рост уже запущенных задач,
  `MemAvailable`, все родительские `memory.high`/`memory.max` и показатели
  задержек памяти PSI. Превышение резерва или таймаута останавливает
  конкретный процесс. После аварии разрешён один повтор отдельно от других
  задач; следующая авария становится видимой ошибкой листа.
- Слишком большой лист получает явную ошибку бюджета. Разрешение рендера и
  алгоритм сравнения не изменяются. Разбиение крупных листов на фрагменты
  этой реализацией не вводится.
- При штатном рестарте службы незавершённые задания возвращаются в очередь.
  Linux `PR_SET_PDEATHSIG` и systemd `KillMode=control-group` не оставляют
  дочерние вычисления после гибели управляющего процесса.
- Веб-сервер восстанавливает только новые прогоны с явным `auto_resume=true`.
  Старые прогоны, отменённые задания, ошибки и другие конвейеры не запускаются.
  Готовые листы остаются в кэше. Идентичность владельца включает PID,
  время старта процесса и ID загрузки ОС.
- Это исключительно локальные детерминированные вычисления. Служба не
  запускает ИИ; сетевые подключения запрещены параметрами systemd.

## Установка для существующего локального сервера 8095

Установщик управляет **локальным сервером разработки**, который уже работал
из `/home/coder/projects/PDF-proverka`. Он не переключает production release,
не меняет `auditmanager-backend.service` и не обходит production source guard.
Для внедрения в публичный портал нужен обычный чистый опубликованный релиз
с этим кодом и отдельная настройка его окружения.

Из корня репозитория:

```bash
python3 scripts/server/install_comparison_worker.py --dry-run
sudo python3 scripts/server/install_comparison_worker.py --apply
```

Операция `--apply` требует root. Она создаёт системную службу
`auditmanager-comparison-worker.service` в `system.slice` с `User=coder`,
включает автозапуск и переключает локальный сервер 8095 на очередь.
`User=coder` системной службы не помещает её в группу пользовательской сессии.
Предыдущие конфигурации сохраняются в
`/home/coder/auditmanager/local-version-comparison-recovery/diagnostics/worker-install-*`.

| Ресурс | Вычислитель | Веб-сервер 8095 |
|---|---|---|
| Параллельность | до 12 отдельных процессов | обработка HTTP |
| CPU | без квоты; CPUWeight=25, Nice=5 | квота до 2 ядер |
| Память | резерв задач 18 GiB, предел службы 20 GiB | High=3 GiB, Max=4 GiB |
| Запас памяти всей машины | 6 GiB перед допуском новых задач | — |
| Swap | 0 | 0 |
| Таймаут одного задания | 900 секунд | — |

Существующие лимиты публичного портала и IDE не повышаются. Планировщик
учитывает их фактическую нагрузку через память всей машины. Максимумы служб
не являются предварительно выделенной памятью. Оценка затрат листа приблизительна;
конечная защита — предел отдельной службы и контроль RSS дочерних процессов.

Локальный вход `scripts.server.version_comparison_local:app` включает только
восстановление сравнения версий вместо прежнего `--lifespan off`; обычные
startup-процедуры других конвейеров не запускаются.

## Проверка и диагностика

```bash
systemctl status auditmanager-comparison-worker.service
systemctl --user status auditmanager-local-8095.service
journalctl -u auditmanager-comparison-worker.service
curl http://127.0.0.1:8095/login
```

Для авторизованного клиента `/api/version-comparison/worker-status` показывает
состояние очереди и ожидание памяти. Подробная телеметрия и журналы задач:
`/home/coder/auditmanager/local-version-comparison-recovery/worker-queue/`.
Файл `status.json` содержит актуальный бюджет, резервы и родительские лимиты.

Тесты: `tests/test_cpu_pool.py`, `tests/test_version_comparison_worker.py`,
`tests/test_version_comparison_worker_api.py`, `tests/test_version_comparison_api.py`.
Они проверяют реальный запуск процессов, ограничение потоков, отмену,
принудительное завершение, ограниченные повторы, таймаут, родительские лимиты,
полный API-путь на синтетических PDF и восстановление без пересчёта готовых листов.

Повторить проверку при пустой очереди:


Скрипт отказывается запускаться при активных заданиях; при задержке HTTP,
давлении на память или превышении 60 секунд отменяет только свои задания.

## Откат локальной установки

Остановить пользовательскую службу 8095 и системный вычислитель. Восстановить
`run-8095.sh` из выбранного `worker-install-*`; удалить созданный override
`20-isolated-worker.conf` (или восстановить его прежнюю копию). Выполнить
`systemctl --user daemon-reload`. Старый режим не запускать с шестью
обработчиками под прежним общим лимитом пользователя: причина зависания
вернётся. Данные и очередь при откате не удалять.
