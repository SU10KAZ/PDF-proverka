# Verifikator — обратная проверка отклонённых замечаний

> **Назначение.** Verifikator проверяет работу эксперта «в обратную сторону»: берёт
> замечания, которые эксперт **отклонил**, и находит те, где **эксперт сам мог ошибиться**
> (зря отклонил верное замечание). На выходе — короткий ранжированный список лидов на
> ручную перепроверку + Excel с выводом по каждому.
>
> Код: `experiments/evidence_agent_v2/` (независимый пакет, read-only на live-данные,
> сам аудит — 0 токенов подписки, только локальная qwen через ngrok; финальный арбитр — Claude).

---

## Главный принцип

Verifikator спорит **не с замечанием, а с ПРИЧИНОЙ отклонения**. Единственный вопрос:

> «Опровергает ли чертёж / норма / документ именно то, **чем эксперт обосновал отказ**?»

Два правила, без которых всё ломается:

1. **Reason-aware.** Оцениваем не «верно ли замечание», а «опровергнута ли КОНКРЕТНАЯ причина
   эксперта». Наивный сигнал «модель подтвердила замечание» даёт ~60% ложных (модель просто
   переподтверждает поверхностный факт, игнорируя обоснование эксперта).
2. **Консервативность.** По умолчанию верим эксперту. Если эксперт сослался на **общие
   указания / другой лист / спецификацию / экспертизу / разумное инженерное суждение** — и
   модель этого не видит — это **НЕ ошибка эксперта** (`cannot_tell`/`no`, не `yes`). Это был
   главный источник ложных срабатываний; калибровка промпта его убирает.

## Алгоритм (5 шагов)

```
ВХОД: отклонённые замечания (per-version expert_review — version-correct, без F-ID-дрейфа)

[1] СБОР
    Замечания со статусом «отклонено» + причина эксперта, по каждой версии отдельно.

[2] СОРТИРОВКА (офлайн, без нейросети — быстро, бесплатно, можно при занятом ngrok)
    ├─ есть графический блок?     → needs_vision (шаг 3)
    ├─ только текст?              → text_only (шаг 4)
    ├─ кросс-блок нашёл инфо?     → info_elsewhere (эксперт скорее прав)
    ├─ норма заменена/устарела?   → norm_superseded
    └─ finding по id не найден?   → version-drift (не аудируем)

[3] ПРОВЕРКА ПО ЧЕРТЕЖУ (локальная qwen, image-only)
    Рендерим блок из PDF в высоком разрешении (вектор → чётко, ~2200px) →
    модель видит ТОЛЬКО картинку (gemma-OCR НЕ подаём, чтоб не повторять её артефакты) →
    сама читает спорное значение → опровергает причину эксперта?

[4] ПРОВЕРКА ПО ТЕКСТУ (локальная qwen)
    Замечание + норма + причина эксперта → проверка логики и нормы (enforced JSON).

[5] ДВОЙНОЙ ФИЛЬТР
    ├─ (5a) Калибровка: убрать «модель не видит то, на что ссылается эксперт» (локально, 0₽)
    └─ (5b) Арбитр (Claude Sonnet, ПО ОДНОМУ): строгая консервативная перепроверка

ВЫХОД: ранжированный список «эксперт мог ошибиться» + Excel (с выводом арбитра)
```

## Модели и стоимость

| Где | Модель | Роль | Цена |
|-----|--------|------|------|
| Шаги 3–4, 5a | локальная `qwen/qwen3.6-35b-a3b` (LM Studio через ngrok) | массовая черновая работа | **0₽** |
| Шаг 5b | Claude **Sonnet** (`claude -p`, подписка) | консервативный арбитр | ~$40–45-экв на 262 |

Принцип: **дешёвая локальная модель кидает широкую сеть** (высокий recall, низкая точность),
**дорогой Sonnet отсеивает** (высокая точность, деферит к эксперту).

**Режим вызова Claude — ТОЛЬКО ПООДИНОЧКЕ.** Эксперименты: батч 1×10 совпал с поодиночке
5/10; одна сессия `--continue` — 6/10 (контекст копится → анкоринг, кэш растёт, НЕ экономит).
Каждый `claude -p` грузит системный контекст (~39K кэш) — это цена независимости вердиктов.

## Команды

```bash
# [2] Триаж всех отклонённых (офлайн)
python -m experiments.evidence_agent_v2.run_audit --phase triage

# [3] Графика high-res по всем (ночной sweep) — рендер из PDF + qwen image-only
bash experiments/evidence_agent_v2/run_sweep_highres_alia.sh

# [4] Текст по всем (цепочка ждёт окончания графики)
bash experiments/evidence_agent_v2/run_text_sweep_alia.sh

# [5a] Калибровка-фильтр кандидатов (локально)
python -m experiments.evidence_agent_v2.filter_candidates

# [5b] Финальный арбитр Sonnet (поодиночке, крэш-устойчиво)
python -m experiments.evidence_agent_v2.arbiter_pass --model sonnet

# Отчёты
python -m experiments.evidence_agent_v2.report_shortlist     # шорт-лист
python -m experiments.evidence_agent_v2.export_final_excel    # Excel
```

> ⚠️ Шаги 3–5 используют локальную qwen через ngrok. Перед запуском — `ngrok_guard.preflight`
> + кооперативный lock (нельзя гнать одновременно с другим потребителем модели).

## Ключевые уроки (что не работало и почему)

- **Наивный сигнал «модель подтвердила замечание» недостоверен** для обратного аудита (~60%
  ложных). Нужен reason-aware: оценивать причину эксперта, а не сам finding.
- **Прямой PDF в qwen нельзя** (провайдер не принимает). Текст-слой pdfplumber берёт числа, но
  НЕ CAD-надписи (классы/марки рисуются кривыми) → для них нужен high-res рендер картинки.
- **gemma-OCR на мелком кропе врёт** (напр. «В40» → «В4.0»), и модель повторяет артефакт. Фикс:
  рендер из PDF в высоком разрешении + image-only (OCR не подаём).
- **High-res в одиночку переобнаруживает** (видит один блок, не видит общих указаний эксперта).
  Фикс: калибровка «инфо в общих указаниях/др.листах/экспертиза → cannot_tell».
- **Claude нельзя гнать батчами/одной сессией** — вердикты плывут (анкоринг). Только поодиночке.

## Честные ограничения

- Кандидаты = **лиды на ручную перепроверку, НЕ вердикты.** Даже Sonnet не истина (бордерлайн ~1–2
  из топа).
- Спорное значение может быть в блоке, которого нет в evidence finding'а → `cannot_tell` (реальную
  ошибку можем пропустить — консервативно).
- Источник обязательно **per-version `expert_review.json`** (не `decisions_log` — в нём нет
  version_id → F-ID-дрейф между версиями V1/V2).
