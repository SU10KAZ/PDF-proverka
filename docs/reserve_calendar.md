# Календарь запаса

Вкладка «Календарь запаса» открывается в «График производства работ» по адресу
`/#/schedule?tab=reserve`. «Выполнено» остаётся существующим графиком и использует
прежние данные. Календарь хранит очередь экспертной проверки отдельно от фактов
выполнения; один пункт очереди соответствует объекту, тому (`project_id`), версии и
виду проверки `expert_review`.

## Источники и расчёт

- Инженеры берутся из реестра пользователей. Неактивные пользователи не получают
  новые назначения; их ранее назначенные активные задания остаются видимыми.
- Проекты и версии читаются через штатные резолверы хранилища. Готовность требует
  исходного PDF/Markdown и ненулевого списка замечаний или оптимизаций.
  Незавершённая ручная запись без документов остаётся подготовкой до явного
  связывания с точной версией. Название само по себе не связывает документы.
- Реальные решения эксперта и штамп завершения из существующего процесса
  синхронизируют состояние. Открытие карточки ничего не начинает. Действие
  «Взять в работу» на странице проекта и сохранение решений вне календаря
  поднимают начатую проверку перед ещё не начатыми. Факты графика «Выполнено»
  учитываются прежним механизмом однократной записи.
- Прогноз исходит из очереди, текущего общего плана инженера в «Выполнено» и
  доступных рабочих дней. Для недельного или месячного плана дневная доля
  сохраняется как точная дробь. Уже завершённые сегодня проверки уменьшают
  оставшуюся ёмкость дня. Без действующего плана либо заданной ставки дата
  остаётся неопределённой. Подготовка и все последующие даты помечены условными.
  Горизонт прогноза ограничен десятью годами.

По умолчанию рабочие дни — понедельник–пятница. Если платформа располагает
утверждённым календарём и индивидуальной доступностью, их можно передать через
`$AUDIT_APP_DATA_DIR/work_calendar.json` либо `AUDIT_WORK_CALENDAR_FILE`:

```json
{
  "holidays": ["YYYY-MM-DD"],
  "working_dates": ["YYYY-MM-DD"],
  "engineers": {
    "<staff-id>": {
      "direction": "<direction>",
      "daily_rate": 1.5,
      "unavailable": [{"from": "YYYY-MM-DD", "to": "YYYY-MM-DD"}]
    }
  }
}
```

Неуказанные направления показываются как «Без направления». Пример выше
описывает формат, а не рабочие ставки или праздничные дни.

## Хранение и доступ

При первом обращении автоматически создаётся аддитивная схема SQLite v1 в
`$AUDIT_APP_DATA_DIR/reserve_calendar.sqlite3` (путь можно переопределить
`AUDIT_RESERVE_DB`). Таблицы: `reserve_meta`, `reserve_tasks`,
`reserve_operations`. Отдельного изменения старых БД и backfill не требуется.
Операции и сверка с источником сериализуются транзакцией; каждый запрос записи
содержит UUID `operation_id` и ожидаемую `revision`. Повтор того же запроса
возвращает прежний результат без дубля, несовпадающая ревизия даёт 409.
Перенос и пакетное добавление атомарны; отмена проверяет, что созданные строки
или перенесённая очередь ещё не изменились. История операций содержит автора,
время и состояния до/после. Сервису нужна запись в каталог БД и lock-файл
рядом с ней; каталог должен быть доступен всем воркерам приложения.

`GET /api/schedule/reserve` читает очередь с обычным доступом к графику.
`POST /api/schedule/reserve/operations` использует право операций портала:
администратор или активный сотрудник с просмотром графика и отдельным правом
«Редактирование календаря и планов работ» в режиме accounts; сотрудники в режиме
env_users сохраняют прежние права. Остальные получают 403. Это право также
разрешает `PUT /api/schedule/plan`, управляется в настройках пользователя и
не открывает административные разделы. Отзыв просмотра графика снимает право
редактирования. Поддерживаются `add_preparation`, `assign`, `link`, `move`,
`delete`, `start`, `undo`.
Данные портала и сохранённый календарь остаются на сервере и читаются из другой
сессии. При недоступности источника запрос отвечает 503, не отменяя назначения.

Календарь не вызывает OpenRouter и не запускает обработку документов. Для
проверки применён отдельный стенд с копией действительных записей объекта 213;
записи рабочего портала им не менялись.

## Проверка на 2026-10-26

- На изолированном стенде проверены вкладка «Выполнено», реальный переход к
  версии, подсказка с полным именем и шифром, вставка нескольким инженерам,
  пропуск пустых строк, подсветка дублей, удержание черновика, перенос группы,
  отмена переноса и пакета, связь с точной версией и начало с карточки проекта.
- Две браузерные сессии подтвердили 409 при устаревшей ревизии и успешный
  повтор после обновления без потери текста. Очередь сохранилась после перезагрузки.
- Полный реестр из 1065 версий читается примерно за 5,8 секунды в локальном
  окружении. Постоянное обновление страницы происходит каждые 30 секунд, когда
  вкладка открыта. Для большой установки потребуется измерять нагрузку при
  числе одновременных пользователей выше проверенного.
- Оболочка текущего портала оставляет недостаточную ширину на телефоне; для
  компактного календаря понадобится отдельная адаптация общей навигации.

Снимки реального стенда: `deliverables/reserve_calendar_20261026/calendar.png`,
`preparation.png`, `completed.png`.

## Дневной лимит (29.10.2026)

Каждому инженеру установлен предел проектов на рабочий день: месячный общий
план из «Выполнено» делится на число его доступных рабочих дней в месяце
назначения, результат округляется вверх (42 / 22 → 2). Учитываются праздники,
рабочие выходные и индивидуальное отсутствие. Если план нового месяца ещё не
задан, последний предшествующий месячный план используется как месячная норма.
Будущий план не применяется задним числом. Явная дневная ставка в настройках
календаря имеет приоритет; при отсутствии месячных планов используется текущий
недельный план. Нулевая норма, отсутствие нормы и нерабочие дни не дают мест.

Добавление с портала распределяет проекты начиная с завтрашнего дня по свободным
местам, включая уже назначенные проекты из предыдущих пакетов. Подготовка без
даты не занимает дневные места; её перенос на дату проверяется на общих основаниях.
Ручной перенос, передача другому инженеру и отмена действия проверяются сервером
в одной транзакции. При превышении лимита отклоняется вся операция, включая
групповой перенос. Завершённые в этот день проверки по данным портала также
занимают дневную норму. Если свободных мест с заданной нормой нет в горизонте
десяти лет, добавление отклоняется с просьбой задать план.

Старые перегруженные дни не перераспределяются автоматически: их можно разгружать
или менять порядок внутри дня, но нельзя увеличивать нагрузку сверх лимита,
в том числе отменой переноса. В ячейке показано «занято / лимит», перегрузка
подсвечена. Параметр `view_start` у чтения календаря и ответа операции задаёт
28-дневный диапазон отображаемых лимитов; проверка операции всегда использует
фактическую дату назначения, независимо от открытого диапазона.
