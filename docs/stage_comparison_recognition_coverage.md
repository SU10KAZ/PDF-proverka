# Полнота распознавания в сравнении редакций

Как система отличает «этого в проекте больше нет» от «мы этого не прочитали».
Точка входа в код — `backend/app/services/stage_comparison/recognition_coverage.py`.

## Инвариант

```
ОТСУТСТВИЕ РАСПОЗНАННОГО ДОКАЗАТЕЛЬСТВА
НЕ ЯВЛЯЕТСЯ ДОКАЗАТЕЛЬСТВОМ ОТСУТСТВИЯ
```

Пропуск Markdown, ошибка распознавания, недочитанная таблица и неизвлечённый
фрагмент не имеют права сами по себе становиться «удалено», «добавлено»,
«изменено» и уж тем более «существенное изменение».

## Цена ошибки

Markdown правой редакции листа АР прочитал номера помещений с кириллической
«З» вместо цифры «3». В нативном текстовом слое того же PDF на том же листе
стояли правильные номера — с теми же названиями и площадями. Сравнение,
смотревшее только в Markdown, честно не нашло левых строк справа и
опубликовало четыре «удалено» плюс четыре «добавлено» как существенные
изменения проекта. Изменений проекта там не было ни одного.

## Что было вместо проверки

Три близких механизма, ни один из которых не отвечает на вопрос «сколько
текста листа удалось прочитать»:

| Механизм | Где | Что на самом деле меряет |
|---|---|---|
| `_structured_group_coverage` | `text_fact_producer.py` | число фрагментов встречной стороны, единственный порог — ноль; на CHANGED не действует вовсе |
| Гейт M7 | `unified_change_policy/rules.py` | покрытие ГРАФИЧЕСКОГО маршрута; для PARAMETER неприменим |
| `sheet_scope_policy` | одноимённый модуль | подтверждена ли ПАРА ЛИСТОВ |

## Сигналы

Полнота считается по независимым от Markdown сигналам — тот же Markdown,
сравнение которого проверяется, доказательством своей правильности быть не
может.

| | Сигнал | Откуда |
|---|---|---|
| A | подготовленный Markdown | `preparation.fragments[side][]` |
| B | нативный текстовый слой PDF | `preparation.recognition_index[side][page]` |
| C | привязка фрагмента к рамкам | `fragment.bboxes` — нашёлся ли фрагмент в слое |
| D | согласие чтения со слоем | `fragment.pdf_canonical_text` под теми же рамками |
| E | ожидаемые идентификаторы | номера помещений, площади, марки, отметки |
| F | диагностика извлечения | `preparation.extraction` |

Индекс страницы хранит не текст, а то, что нужно проверке: объём слоя (пригоден
ли он вообще) и множество значимых токенов. Полный текст листа удвоил бы
артефакт подготовки, ничего не добавив к ответу на вопрос «есть ли на той
стороне номер 315.1».

## Уровни и статусы

```
документ → страница → группа сравнения → область доказательства
```

`SUFFICIENT` / `PARTIAL` / `INSUFFICIENT` / `UNKNOWN`. Достаточность —
единственный статус, при котором расхождение имеет право стать содержательным
изменением. Из нескольких вердиктов побеждает худший: полнота — утверждение о
худшем месте, а не среднее.

**Страница.** Вердикт определяет доля СОГЛАСИВШИХСЯ с нативным слоем
фрагментов (`≥0.9` — достаточно, `≥0.6` — частично, ниже — недостаточно). Доля
НАЙДЕННЫХ измеряет привязку, а не чтение: заголовок или примечание может не
найтись в тексте PDF по причинам, к распознаванию отношения не имеющим, — она
только не даёт назвать лист прочитанным, когда проверить удалось совсем малую
его часть (`<0.35`). Ноль прочитанных фрагментов при живом текстовом слое —
`INSUFFICIENT` без обсуждения. Нет пригодного слоя (чертёж в кривых, скан) —
`UNKNOWN`: независимого сигнала нет, и делать вид, что он есть, нельзя.

**Область доказательства.** Решают прямые признаки, а не среднее по странице:

* *своя сторона* — значение, которого нет в нативном слое собственного листа,
  прочитано неверно;
* *встречная сторона* (только для «удалено»/«добавлено») — если значение лежит
  в тексте противоположного листа, разошлось распознавание, а не проект;
* если в значении нет ни чисел, ни обозначений, решает вердикт СОБСТВЕННЫХ
  фрагментов элемента: соседняя строка таблицы к этому расхождению отношения
  не имеет.

## Сравнение токенов

Нормализация снимает регистр, пробелы, разделитель дробной части и
типографские дефисы. Похожие по начертанию буквы и цифры НЕ сворачиваются
нигде: на различии «З» и «3» держится вся проверка.

Проверяемым считается токен длиной от трёх символов минимум с двумя цифрами:
номер «315.1», площадь «19.92», отметка «-1.800», марка «ei60». Единица «м2»
стоит в каждой строке экспликации и совпадением по ней доказывалось бы
присутствие любой строки на любом листе.

Ослабление «токен без разделителей» («21.50» ≡ «2150») включено ТОЛЬКО там, где
«нашлось» ведёт к осторожности — при проверке встречной стороны. При проверке
своей стороны сравнение строгое, иначе потерянная распознаванием запятая
прошла бы как совпадение.

## Что делает недоказанная полнота

Не прячет расхождение и не удаляет находку. Снимает ярлык «существенное»:
`outcome` становится `REVIEW_REQUIRED`, уверенность — `UNKNOWN`, а причины
доезжают до инженера через `provenance.review_requirement.reason_codes` и
переводятся на русский во фронтенде. Элемент остаётся видимым в Stage 7 и
подтверждается человеком, если он подтверждает.

Гейт впервые действует и на CHANGED: сравнивать два значения, одно из которых
прочитано неверно, — тот же вымысел, только в профиль.

## Место в конвейере

```
prepare_text_scope        → preparation.recognition_index (нативный слой)
build_text_differences…   → differences.recognition_coverage (вердикты)
produce_text_facts        → gate в _relation_assessment
```

Вердикт лежит ключом ВЕРХНЕГО уровня артефакта Stage 3: `stage3_content_signature`
покрывает элементы доказательств, а не оболочку, поэтому появление проверки не
объявляет протухшей ни одну сохранённую валидацию Stage 4.

## Замер на реальной паре

`scripts/stage_comparison_recognition_acceptance.py <pair.json>` прогоняет
настоящую текстовую ветку и сравнивает два прогона: с проверкой и с
объявленной достаточной полнотой.

Пара АР `13АВ-РД-АР0.1-ПА` (21 доказанная пара листов, 1437 расхождений
Stage 3, 1008 структурированных фактов):

| | существенных | на проверку |
|---|---|---|
| без проверки полноты | 612 | 396 |
| с проверкой полноты | 553 | 455 |

Переведено из «существенное» в «нужна проверка» — 59: удалено 26, уменьшено 19,
добавлено 6, заменено 5, увеличено 3. Двадцать семь из них — изменения, которых
прежняя проверка не касалась вовсе. У 34 значение не подтверждается текстовым
слоем своего же листа, у 12 — найдено на встречной стороне.

Отдельно на уровне доказательств Stage 3 нашлось 204 ложных отсутствия вида
«01.4 Лифтовой холл ПБЗ 21.24 м2»: строка объявлена добавленной справа, а её
номер и площадь стоят в текстовом слое левого листа. Это и есть корпус ложных
отсутствий — он не размечается руками и не объявляет истину там, где она не
доказана.
