# Вектограф (vectograf)

**Вектограф** — механизм построения графа однолинейной расчётной схемы (ВРУ/ГРЩ/РП)
**из вектор-слоя PDF по геометрии**, детерминированно, без нейросети и без OCR.

Имя-якорь для поиска: `Вектограф` / `vectograf`.
`grep -rn "Вектограф\|vectograf"` → все точки механизма.

## Что делает

Читает готовый текстовый слой PDF (тот, что заложил AutoCAD/Revit при экспорте — подписи
дословно точны, у каждого слова известны координаты X/Y) и **реконструирует топологию схемы**:
питание/вводы → секции шин/панели РПn → отходящие линии (автомат QF ↔ код цепи ↔ кабель ↔
потребитель), плюс расчёты панелей, проверку ТТ, примечания, иерархию, служебные элементы.

Результат — структура `singleline_graph` и её Markdown в формате эталона (8 разделов),
которые видны в txt-панели блока («🔌 Граф схемы / полная разметка»).

**Не нейросеть и не распознавание картинки.** Для сравнения: Qwen-OCR того же блока —
~15 минут и со смешанной точностью; Вектограф — секунды и дословно точно.

## Из чего состоит

| Часть | Файл | Роль |
|-------|------|------|
| Структуризатор | `backend/app/pipeline/stages/block_grounding/singleline_structurer.py` | Разбор строк-формул текста (`код : Pуст кВт - Kc - cosφ - Pрасч кВт - I А`) → параметры линий. Чистый текст, без PDF. |
| Геометрия (ядро) | `backend/app/pipeline/stages/block_grounding/singleline_graph_geometry.py` | Открывает PDF, берёт слова с координатами, собирает топологию: QF, привязка кода по колонке, аппарат/номинал/полюса, потребитель, вводы/АВР, валидация физикой, рендер Markdown. ⚠️ Зона параллельной работы Cursor — не редактировать без согласования. |
| Точка входа (API) | `backend/app/api/routers/blocks.py` (эндпоинт `/blocks/llm-text`, секции 6 и 7) | Собирает `structured_graph` и `singleline_graph`, отдаёт фронту. |

Публичные функции: `structure_singleline_text` (структуризатор), `build_singleline_graph`,
`render_graph_etalon_markdown`, `build_singleline_prompt`, `resolve_singleline_prompt` (геометрия).

## Как строит (кратко)

1. **Разбор формул** (структуризатор, ~1 мс): регулярками вытаскивает Pуст/Kc/cosφ/Pрасч/I и
   кабель (длина, потеря напряжения, марка/сечение, Iкз) для каждой цепи `К…`.
2. **Геометрия** (ядро): находит страницу в PDF по совпадению слов; берёт все слова с
   координатами; делит QF на отходящие (верх) и вводные (низ) по Y; для каждого QF по близости
   привязывает аппарат `ВА-…`, номинал, полюса `3Р`, метки резерв/ПС/АСУД; **код кабеля
   привязывает к QF по его вертикальной колонке** (запасной вариант — монотонный); имя
   потребителя = «остаток» текста в колонке.
3. **Валидация физикой**: пересчёт `P = √3·U·I·cosφ` — проценты «физика N%», счётчики
   актив/резерв/review/конфликты; непривязанный код → `requires_review`, а не выдумка.
4. **Рендер** в Markdown (8 разделов).

## Сколько времени

≈ **1,5 секунды** на блок (замер: ВРУ-К1.1, 69 линий). Почти всё — открытие 19 МБ PDF;
сам разбор + геометрия + рендер — миллисекунды. 0 токенов, офлайн.

## Ограничение

Работает **только если у PDF есть вектор-слой** (чертёж из CAD/BIM). Для **сканов** текстового
слоя нет — там нужна нейросеть (Qwen). Однолинейки проекта — векторные.
