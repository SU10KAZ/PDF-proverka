# Вектограф (vectograf)

**Вектограф** — механизм построения графа однолинейной расчётной схемы (ВРУ/ГРЩ/РП)
**из вектор-слоя PDF по геометрии**, детерминированно, без нейросети и без OCR.

Имя-якорь для поиска: `Вектограф` / `vectograf`.
`grep -rn "Вектограф\|vectograf"` → все точки механизма.

## Что делает

Читает готовый текстовый слой PDF (тот, что заложил AutoCAD/Revit при экспорте — подписи
дословно точны, у каждого слова известны координаты X/Y) и **реконструирует топологию схемы**:
питание/вводы → секции шин/панели РПn → отходящие линии (автомат QF ↔ код цепи ↔ кабель ↔
потребитель), плюс расчёты панелей, проверку ТТ, примечания, иерархию, служебные элементы.

Результат — структура `singleline_graph` и её Markdown в формате эталона (8 разделов),
которые видны в txt-панели блока («🔌 Граф схемы / полная разметка»).

**Не нейросеть и не распознавание картинки.** Для сравнения: Qwen-OCR того же блока —
~15 минут и со смешанной точностью; Вектограф — секунды и дословно точно.

## Из чего состоит

| Часть | Файл | Роль |
|-------|------|------|
| Структуризатор | `backend/app/pipeline/stages/block_grounding/singleline_structurer.py` | Разбор строк-формул текста (`код : Pуст кВт - Kc - cosφ - Pрасч кВт - I А`) → параметры линий. Чистый текст, без PDF. |
| Геометрия (ядро) | `backend/app/pipeline/stages/block_grounding/singleline_graph_geometry.py` | Открывает PDF, берёт слова с координатами, собирает топологию: QF, привязка кода по колонке, аппарат/номинал/полюса, потребитель, вводы/АВР, валидация физикой, рендер Markdown. |
| Точка входа (API) | `backend/app/api/routers/blocks.py` (эндпоинт `/blocks/llm-text`, секции 6 и 7) | Собирает `structured_graph` и `singleline_graph`, отдаёт фронту. |

Публичные функции: `structure_singleline_text` (структуризатор), `build_singleline_graph`,
`render_graph_etalon_markdown`, `build_singleline_prompt`, `resolve_singleline_prompt` (геометрия).

## Как строит (кратко)

1. **Разбор формул** (структуризатор, ~1 мс): регулярками вытаскивает Pуст/Kc/cosφ/Pрасч/I и
   кабель (длина, потеря напряжения, марка/сечение, Iкз) для каждой цепи `К…`.
2. **Геометрия** (ядро): находит страницу в PDF по совпадению слов; берёт все слова с
   координатами; делит QF на отходящие (верх) и вводные (низ) по Y; для каждого QF по близости
   привязывает аппарат `ВА-…`, номинал, полюса `3Р`, метки резерв/ПС/АСУД; **код кабеля
   привязывает к QF по его вертикальной колонке** (запасной вариант — монотонный); имя
   потребителя = «остаток» текста в колонке.
3. **Валидация физикой**: пересчёт `P = √3·U·I·cosφ` — проценты «физика N%», счётчики
   актив/резерв/review/конфликты; непривязанный код → `requires_review`, а не выдумка.
4. **Рендер** в Markdown (8 разделов).

## Сколько времени

≈ **1,5 секунды** на блок (замер: ВРУ-К1.1, 69 линий). Почти всё — открытие 19 МБ PDF;
сам разбор + геометрия + рендер — миллисекунды. 0 токенов, офлайн.

## Ограничение

Работает **только если у PDF есть вектор-слой** (чертёж из CAD/BIM). Для **сканов** текстового
слоя нет — там нужна нейросеть (Qwen). Однолинейки проекта — векторные.

## Полнота графа: что моделируется, что в roadmap (gap-анализ 2026-07-03)

Инвентаризация 15 боевых однолинеек (214/133) + 5 экспертных линз + верификация по данным.
Счёт «в графе / за бортом» — токены вектор-слоя, известные JSON-у графа.

**Покрыто хорошо:** фидеры QF↔код↔кабель↔потребитель, АВР (14/0), УЗО/дифф (11/1),
контакторы КМ/МК103 + флаги ПС/АСУД у линии (23 линии с control), вторичка ад/ан,
расчёты панелей, tt_check-таблица, примечания.

**Подтверждённые дыры (элементы есть на листах, связей в графе нет):**

| # | Упущенная связь | Листов | Ловит на аудите | Извлекаемость |
|---|---|---|---|---|
| 1 | фидер → **секция шин** (с.ш.1/с.ш.2) | 15 (PEN на всех; двухсекционные — ГРЩ, К1, К2, ЭМ1-ПА) | перекос секций, I категория на одной секции, резервирование | легко: X-координата фидера vs группы `L1,L2,L3`+`PEN` (на ГРЩ x=348 vs x=1289); структурер уже имеет bus_sections, геометрия теряет |
| 2 | линия/ввод → **TA-группа → Wh** (цепь учёта) | TA 11/15, Wh 13/15; на ГРЩ гребёнка TA+Wh над каждым фидером | фидер без учёта; Ктт (400/5) vs расчётный ток; tt_check без привязки к устройствам | средне: колоночная привязка по X (тот же приём, что код↔QF) |
| 3 | **вводы ГРЩ-номенклатуры** (`power.inputs=[]` на ГРЩ) | ГРЩ-листы | паспорт ввода, Iр.раб/авар | средне: обобщить паттерны (не только ВП1/ВП2) |
| 4 | **QS/ВР рубильник → панель/ввод** | 10/15 | панель без коммутационного аппарата | легко: X-зона панели, нижний ряд |
| 5 | **FU/ППН → ввод/цепь** | 2/15 (НС, К7) + ГРЩ | селективность вставок; FU вообще не моделируются (0 в графе) | легко там, где есть |
| 6 | пары **С1↔С2** (двухсекционные стояки, К*.xС1↔К*.xС2) | К1–К6 | несимметричное резервирование пары, разные номиналы | легко: суффикс кода |
| 7 | **семантика управления как рёбра**: ПС→КМ→линия («откл. при пожаре» 11/15), АСУД→МК103→освещение; связь с режимом «пожар» в panel_calculations | 10–11/15 | линия без обязательного отключения при пожаре; дымоудаление (ЩУ-ПД 4/15) без хар-ки МА | средне: сейчас есть атрибутами (control/additional_devices), поднять в edges |
| 8 | **УЗИП (ОП101/FV) → ввод** + его FU | 5/15 | ввод без УЗИП; УЗИП без защитного аппарата | легко |
| 9 | ввод → **HL/РН/МТ-72D** (индикация, реле напряжения, мультиметр) | HL 8/15, РН/KV 5/15, МТ-72D 6/15 | полнота паспорта ввода, АВР без контроля напряжения | легко |

**Правила-проверки (не рёбра):** жильность кабеля 4х/5х ↔ тип шинной системы приёмника
(PEN vs N+PE), точка разделения PEN — это генераторы findings поверх графа.

**Не подтверждено на выборке / межлистовое:** перекидной «1-0-2» (0/15), ГЗШ (лист МЗ),
КУП (квартирные щитки), SY-контакты (1/15) — низкий приоритет, часть уходит в кросс-листовые
связи (не однолинейка).

**Не добавлять (шум):** трейс каждой HL-лампы, легенды листа, дубли-теги.
