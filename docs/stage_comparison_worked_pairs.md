# Отметка «Отработано» у пары (с 18.11.2026)

В таблице результатов раздела «Сравнение стадий» (компонент
`project-comparison-catalog`) у каждой пары есть кнопка «Отработано».
Инженер нажимает её, когда закончил работу с парой. Портал переспрашивает,
и после подтверждения на месте кнопки остаётся «Отработано · ФИО», а время
отметки видно во всплывающей подсказке. Отметку видят все пользователи
портала, роль «только просмотр» кнопки не видит.

## Как устроено

- Хранение: `comparison/boards/<roots-hash>/worked_pairs.json` рядом с
  раскладкой доски (`board_state.worked_path`), схема
  `stage_comparison_worked_pairs/1`: `{pairs: [{left_pdf, right_pdf, by,
  by_id, at}]}`. Своя доска у каждой версии сравнения, значит и свои отметки.
- Отметка привязана к PDF обеих сторон. Новая версия документа или
  пересборка группы дают другую пару, и кнопка «Отработано» появляется
  снова. Первая отметка не перезаписывается.
- Подпись: `actor_label(request, prefer="name")` — ФИО сотрудника,
  связанного с аккаунтом, иначе логин; `by_id` — id сотрудника.
- API: `POST /api/stage-comparison/sessions/{session_id}/worked-pairs`
  `{left_pdf, right_pdf}`. Оба PDF должны быть документами сессии (400 иначе),
  неизвестная сессия — 404. Ответ — все отметки доски.
- Чтение: поле `document_pairing.worked_pairs` ответа сессии. Его каждый раз
  читают из файла заново; в раскладку (`state.json`) оно не попадает, поэтому
  автосохранение раскладки отметки не затирает.
- Снять отметку из интерфейса нельзя. При ошибке её убирают из
  `worked_pairs.json` вручную.
