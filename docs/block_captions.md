# Гуманизация ссылок на блоки в текстах замечаний (block_captions)

## Проблема

Merge-LLM вставляла внутренние block_id в видимые тексты замечаний:

> «…Текстовое замечание подтверждено блоками 6L97-3VTH-XTC и 3C6E-3QEP-D39.»

Сторонний эксперт (Excel-отчёт, База знаний, UI) не знает, что такое «блок»
и не может расшифровать ID. Замер на живых данных 16.07.2026: **4814 из 11841
замечаний (~41%)** содержали block ID в тексте (`description` — 4760,
`problem` — 122, `solution` — 55). Python-генератора фразы нет — её писала
сама модель на этапе `findings_merge` (доказано трассировкой audit_trail:
фраза отсутствует в 01/02/pre_merge и впервые появляется в raw-выводе merge).

## Решение — три слоя

### 1. Запрет в промптах (профилактика)

Разделы «Запрет внутренних идентификаторов в текстах» добавлены в:

- `prompts/pipeline/ru/findings_merge_task.md` (+ en-вариант)
- `prompts/pipeline/ru/text_analysis_task.md` (поле `finding` у T-NNN)
- `prompts/pipeline/ru/block_analysis_task.md` (поле `finding` у G-NNN)
- `SYSTEM_PROMPT_BASE` в `block_analysis/gemma_findings_only.py`
- промпт оптимизации `optimization/visual_context.py` (раньше он ПРЯМО ТРЕБОВАЛ
  вписывать block_id в видимые `current`/`risks`; block_id также убран из
  листинга вложений `IMG-NN: …`)

Правило: ID — только в структурные поля (`source_block_ids`,
`related_block_ids`, `evidence`, `highlight_regions`); в тексте — словами:
тип фрагмента + короткое название + лист.

### 2. Детерминированный гуманизатор (гарантия)

`backend/app/services/findings/block_captions.py`:

- `build_block_caption_map(output_dir)` — карта block_id → подпись.
  Источники: `01_blocks_analysis.json` (`label` + `page`; guard от битых
  label-JSON — огрызок ответа OCR парсится regex'ом по `content_summary`/
  `zone_name`), `document_graph.json` (text_blocks — первая содержательная
  строка текста ≥ 12 симв.; image_blocks — OCR), номер листа — всегда
  `get_page_sheet_no` (v1/v2). Название режется до 60 симв., предпочтительно
  по первому предложению.
- `humanize_findings_file(output_dir)` — пост-проход в `run_findings_merge`,
  **строго ПОСЛЕДНЯЯ post-merge операция** (после merge/dedup/highlights/
  coverage): группировка `merge_similar_findings` и якоря text-layer
  highlights работают по сырым текстам — подписи схлопнули бы паттерны
  разных блоков в один и сломали якоря:
  - заменяет известные ID в `problem/description/solution/risk/recommendation`
    и в `sub_findings[].problem` на `«Название» (лист N, стр. PDF M)`;
    при > 4 разных ID в одном поле — компактный рендер `(лист N, стр. PDF M)`
    без названий (иначе текст раздувается втрое);
  - слово «блок*» перед ID → «фрагмент*» с падежной поправкой («блоки» →
    «фрагменты»), англицизм `BLOCK <ID>` → «фрагмент»;
  - ID из **problem/description** переносятся в структуру (паритет с критиком,
    который сканировал только эти поля): image-блоки → `related_block_ids`,
    текст-блоки → `selected_text_block_ids` (в related они дали бы ложный
    `phantom_block`); ID из solution/risk НЕ переносятся (перенос
    блока-примера с другой страницы дал бы ложный `page_mismatch`);
  - неизвестные ID не трогаются (лучше сырой ID, чем неверная подпись);
    вырожденные подписи и подписи, чей рендер сам содержит ID-токен,
    не подставляются (иначе ID возвращается в текст и ломает идемпотентность);
  - множественные пробелы (псевдотаблицы) сохраняются; посторонний U+0000
    вычищается до маркерной замены;
  - запись атомарная (tmp + os.replace); идемпотентно, fail-soft.

Смежные адаптации (симметрия «сырой текст ↔ подпись»):

- `findings_service._normalize_problem_pattern` — подписи распознаются ДО
  правил кавычек/скобок и превращаются в различимые токены
  `_CAP_<имя>_<лист>_` (цифры транслитерируются) — иначе UI-группировка
  `group_similar_findings` схлопывала бы замечания разных блоков;
- `verdict_preservation.build_fingerprint` — `_strip_block_refs()`
  канонизирует обе редакции текста (сырые ID, подписи, «блок*»/«фрагмент*»
  → `_BLK_`), чтобы разметка эксперта переносилась через первый пере-аудит
  после включения гуманизации;
- оптимизации: item получил структурное поле `source_block_ids`
  (схема + промпт + ярус 0 в `get_optimization_block_map`); block_id в
  листинге `IMG-NN` остаётся для этого поля, но промпт запрещает его
  в видимых `current`/`proposed`/`risks` (regex-ярус по этим полям оставлен
  для legacy-данных).

Флаг: `FINDINGS_BLOCK_CAPTIONS_ENABLED` (default **ON**, kill-switch в .env).

### 3. Точечные Python-правки

- `optimization/context_builder.py` — title автопрескан-кандидата
  «Проверить альтернативу: <summary>» вместо «…для блока {block_id}».

## Что осталось сознательно

- `corrector_note` (`[phantom_block] block_id отсутствуют…`) — служебное поле
  внутренней ревизии, phantom-ID в карте подписей отсутствуют по определению.
- Заголовок замечания `sheet` может расходиться с листом в подписи (пример:
  заголовок «Лист 13», подпись «лист 11.03 (из 22)» для той же страницы) —
  это СУЩЕСТВУЮЩИЙ рассинхрон заголовков с картой штампов, подписи берут
  лист из штампа (source of truth). Пересинхронизация заголовков —
  отдельная задача качества данных.
- Старые данные (4814 замечаний в `projects_v2`) НЕ переписаны — backfill
  выполняется `scripts/backfill_block_captions.py` отдельным шагом
  (по умолчанию dry-run; `--apply` создаёт `.bak-captions` рядом с файлом),
  по команде.

## Тесты

`tests/test_block_captions.py` — 25 юнитов: карта подписей (текст-блоки,
приоритет label Stage 02, guard мусорных/generic label, ID-эхо в label,
хедж-хвосты, сокращения), замены (падежи вкл. «блоки»→«фрагменты», скобки,
BLOCK-англицизм, неизвестные/вырожденные ID, псевдотаблицы, U+0000,
compact-режим), идемпотентность, маршрутизация image/text → related/
selected_text, roundtrip файла, различимость подписей в
`_normalize_problem_pattern`, симметрия фингерпринта verdict_preservation.

Смоук на живых копиях: ТХ.ВТ V1 (59 замечаний с ID) — 86 замен, 0 оставшихся
сырых ID; АР1.1-К3 (146 замен) — compact-режим удержал F-019 в 1358 симв.
(без него было 3114). Дифф прошёл адверсариальную ревизию (3 линзы × 22
замечания, 19 подтверждено и исправлено, кроме двух сознательных пунктов выше).
