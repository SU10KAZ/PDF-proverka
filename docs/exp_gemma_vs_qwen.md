# Испытание: правильно ли gemma делает свою работу и поможет ли qwen

> **Вопрос.** gemma OCR — базовое обогащение графических блоков (читает чертежи → текст/сводка
> для Stage 01/02). Правильно ли она это делает? Поможет ли qwen high-res сделать лучше?
> Объект испытаний — «Алия (ASTERUS)», 31 080 блоков, 205 версий документов.

## Что и как тестировали

| Тест | Метод | Эталон |
|------|-------|--------|
| 1. Ландшафт | покрытие pdfplumber + типы блоков по всем 31 080 | — |
| 2. gemma vs эталон | recall числовых токенов (4000 блоков) | pdfplumber (вектор) |
| 3A. head-to-head | gemma vs qwen, одни блоки, 30 шт | pdfplumber |
| 3B. точность значений | qwen-транскрипция vs gemma-описание + ручная сверка | моё зрение по рендерам |
| (опора) известный кейс | В40 → gemma «В4.0» на мелком кропе, qwen high-res «В40» | вектор/зрение |

## Результаты

**Тест 1 — ландшафт.** gemma читает **99%** блоков. Векторный текст-слой (pdfplumber) есть у
**49%** блоков. Типы: image 57%, text 43%.

**Тест 2 — gemma vs эталон (числа, 4000 блоков).** gemma содержит ~**53%** чисел вектор-слоя.
Метрика смешана: gemma — режим **сводки**, не полной транскрипции (часть чисел опускает сознательно).

**Тест 3A/3В — head-to-head по размеру блока (эталон pdfplumber).** Главный вывод: **recall зависит
от плотности/размера блока.**

| Категория | n | ср.ширина | gemma recall | qwen single-render |
|-----------|---|-----------|--------------|--------------------|
| Обычные блоки | 100 | ~2000px | **89%** | 41% |
| Большие (планы/узлы) | 15 | ~8500px | 37% | 14% |
| **Большие однолинейные схемы** | 3+ | ~22000px | **6–11%** | **0%** |

- На **обычных** блоках gemma **отлично** ловит ключевые значения (89%); qwen single-render хуже
  (41%, частично из-за обрезки вывода по токенам).
- На **больших** блоках обе деградируют; **одиночный qwen-рендер рушится** (ужатие 8500→2200px).
- На **гигантских однолинейных схемах** (22000px+) одиночный рендер ужимается в ~11× → **текст
  физически нечитаем**: qwen **галлюцинирует** («1000,1000,1000…», степени 10) → **0%**; gemma тоже
  почти ничего (6–11%). А **pdfplumber-вектор имеет ВСЁ (100%, до 1224 чисел в одной схеме)**.

**Тест 3Б — точность на конкретных значениях.** qwen в режиме транскрипции даёт **дословные
значения** (разрез 4-4: «4-4», «+134,680» ✓); gemma описывает без самого значения.

**Известный кейс В40.** На мелком кропе gemma прочла «В40»→«**В4.0**» (×10); qwen на ТОЧЕЧНОМ
high-res кропе прочёл «В40» верно. Аудит на этом снял 122 ложных кандидата — артефакты gemma-OCR.

## Вердикт

**Правильно ли gemma делает свою работу?**
- ✅ **На обычных блоках — да, хорошо** (89% ключевых значений, отличная сводка на тексте/штампах).
- ⚠️ **Слабости:** глифовые misread'ы на мелком кропе (В40→В4.0) и **почти полный провал на больших
  однолинейных схемах** (6–11%) — блок огромен, мелкий кроп видит крохи.

**Поможет ли qwen сделать лучше?**
- ✅ **Да — но ТОЧЕЧНО, на маленьком высокоразрешённом кропе** конкретного значения (классы, марки,
  размерные цепи). Там qwen чинит глифовые ошибки gemma.
- ❌ **НЕТ на больших схемах через одиночный рендер** — ужатие убивает текст, qwen даёт **0%** и
  галлюцинирует. Тут нужен **тайлинг** (как GRSH) ИЛИ просто **pdfplumber-вектор** (он всё имеет).

## Рекомендация — у каждого инструмента своя зона

```
Обычные блоки, базовое чтение        → gemma (быстро, 99%, 89% значений)
Где есть векторный текст (49%, в т.ч. → pdfplumber напрямую (100%, бесплатно, OCR не нужен)
   практически ВСЕ однолинейные схемы)
Точная сверка ОДНОГО значения на CAD  → qwen high-res ТОЧЕЧНЫЙ кроп (чинит глифы gemma)
Большая схема без вектор-слоя          → qwen + ТАЙЛИНГ (одиночный рендер не годится)
```

Главный практический итог: **для больших однолинейных схем ни gemma, ни одиночный qwen не годятся —
там работает pdfplumber-вектор (он есть у 199/205 схем) или тайлинг.** qwen полезен как **точечный
high-res верификатор отдельных значений**, а не как замена gemma на крупных листах.

## Как довести чтение до ~100% на ВСЕХ типах блоков

Исследование показало: **100% даёт не один инструмент, а маршрутизация + устранение конкретного
ограничения каждого.** Доказанные рычаги:

**Тест тайлинга (главный рычаг для больших схем).** Гигантскую схему режем на читаемые тайлы
(~2600px с перекрытием), qwen читает каждый, значения объединяем:

| Метод | recall на больших однолинейных |
|-------|-------------------------------|
| gemma | 9% |
| qwen single-render | **0%** (текст ужат, галлюцинации) |
| **qwen + ТАЙЛИНГ** | **90%** (12 тайлов/схема, ~240с) |
| pdfplumber-вектор | 100% |

В тайлах qwen читает реальное содержимое: «ВРУ-К3.2», «QF5.1», «BA-300 1P», «10A», длины кабелей.
До 100% не хватает из-за границ тайлов — добирается **бóльшим перекрытием / меньшим тайлом** (дороже)
или объединением с pdfplumber.

**Рецепт ~100% (маршрутизация «лучший инструмент на блок»):**

```
Слой 1 — pdfplumber-вектор   → 100% там, где есть (49% блоков, в т.ч. ~ВСЕ схемы). БЕСПЛАТНО.
Слой 2 — нет вектор-слоя:
          • большой блок      → qwen + ТАЙЛИНГ (0%→90%, добор перекрытием)
          • маленький/значение → qwen high-res точечный кроп (89%+, чинит глифы)
Слой 3 — gemma                → всегда (описание/сводка, покрытие 99%)
Объединение слоёв (union)     → ~100% на всех типах
```

**Почему НЕ «один инструмент на 100%»:**
- gemma не выйдет на 100% на больших схемах — её мелкий кроп физически не видит весь огромный лист.
- qwen single-render не выйдет — ужатие убивает текст. Только **тайлинг** (дорого) или **вектор**.
- Самый дешёвый путь к 100% на схемах — **pdfplumber-вектор** (он уже есть у 199/205 схем), тайлинг
  qwen — для редких схем без текст-слоя.
