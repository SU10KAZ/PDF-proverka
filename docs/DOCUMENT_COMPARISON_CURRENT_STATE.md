# «Сравнение документации»: текущий минимальный контракт

Раздел очищен от прежней аналитической архитектуры и служит каркасом для
будущей реализации сравнения П → РД.

## Что работает

- загрузка папок `stage_1` и `stage_2`;
- версионное сохранение всех загруженных исходных файлов;
- рекурсивный список PDF каждой стадии;
- ручной выбор двух PDF и сохранение пары;
- двухпанельный просмотр PDF;
- переключение страниц, масштаб и синхронная прокрутка;
- векторная выдача страницы только через `GET .../page-svg`.

Кнопки «Обработать» и «Обработать выбранные» видимы, отключены и не имеют
обработчиков. Вкладка «Расхождения» показывает
«Сравнение ещё не выполнено», вкладка «Отчёт» — пустой каркас.

## Границы

Раздел не читает MD, HTML, JSON или `blocks.json` для анализа. Эти исходные
файлы физически сохраняются вместе с загрузкой и остаются доступными будущей
архитектуре, но текущий shell индексирует только PDF.

В разделе нет сопоставления листов или блоков, координат и overlays,
распознанного текста, аналитических jobs, LLM/Vision-вызовов, findings,
экспертных решений и отчётов. Старые runtime-сессии намеренно не читаются:
store принимает только данные с собственным типом и версией минимального
shell-контракта.

## Карта

```text
Сравнение документации
├── Загрузка stage_1
├── Загрузка stage_2
├── Версионное хранилище исходников
├── Список PDF
├── Выбор и сохранение пары PDF
├── Связь блоков              [двухпанельный page-svg viewer]
├── Обработать                [отключённая заглушка]
├── Обработать выбранные      [отключённая заглушка]
├── Расхождения               [пустой каркас]
└── Отчёт                     [пустой каркас]
```

Основные точки входа:

- `backend/app/api/routers/stage_comparison.py`;
- `backend/app/services/stage_comparison/stage_upload.py`;
- `backend/app/services/stage_comparison/stage_storage.py`;
- `backend/app/services/stage_comparison/scanner.py`;
- `backend/app/services/stage_comparison/store.py`;
- `frontend/index.html`;
- `frontend/static/js/app.js`.
