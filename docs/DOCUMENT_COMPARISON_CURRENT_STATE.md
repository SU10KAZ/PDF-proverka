# «Сравнение документации»: текущий контракт этапов 1–2

Раздел реализует сопоставление PDF-листов стадии П и стадии РД, а после
подтверждения связей — детерминированное исключение доказанно одинакового
текста. Остаток пока не считается расхождением: графика будет сравниваться
отдельным следующим этапом.

## Рабочий поток

```text
MD П ─┐
      ├→ SheetPassport
MD РД ─┘
          ↓
     простые правила
          ↓
   TOP-кандидаты
          ↓
 sheet_match_suggestions.json
          ↓
       человек
          ↓
     sheet_links.json
```

Карта листов строится по оглавлению актуального `ocr.html` (канонической копии
загруженного `_results.html`); краткая семантика из `document.md` используется
только как ограниченный fallback для повторяющихся заголовков. PDF читается
для page count и выдачи страницы через `page-info` / `page-preview` /
`page-tile`.

Автоматика сначала ищет однозначное совпадение `тип + корпус + этаж`,
`тип + корпус + кровля` или `тип + уровень` для подземной части. Затем
используется короткая шкала `корпус 4 / этаж 4 / уровень 3 / тип 2 / Sheet 1 /
порядок 1`. Противоречие корпуса, этажа или типа нельзя перекрыть одинаковым
номером Sheet либо порядком.

## Хранение

- `sheet_match_suggestions.json` — безопасно пересчитываемый автоматический
  результат с primary и не более чем тремя alternatives;
- `sheet_links.json` — принятое пользователем решение;
- `left_pages` и `right_pages` всегда массивы, uniqueness-гейтов нет;
- `unlinked_left_pages` хранит явное ручное решение оставить лист без связи;
- повторная обработка заменяет только suggestions и не изменяет links.

## Интерфейс

- «Обработать» строит предложения для выбранной PDF-пары;
- «Обработать выбранные» выполняет ту же операцию для отмеченных сохранённых
  пар;
- вкладка «Связь блоков» сохраняет прежнее имя, но показывает связь листов;
- доступны «Оставить», «Изменить», «+ Добавить лист РД» и «Удалить связь»;
- связанные правые страницы переключаются в двухпанельном тайловом viewer;
- карта листов показывает ровно 5 строк и прокручивается: высота списка
  считается из `--sc-sheet-map-row`, поэтому «пять» не разъезжается с вёрсткой,
  а активная строка при листании подкручивается внутри самого списка
  (`scRevealActiveSheetMapRow`, не `scrollIntoView` — тот утащил бы страницу);
- видны количества уверенных, требующих проверки, ручных и несопоставленных
  листов.

## Панель миниатюр листов

Кнопка «Миниатюры» открывает слева от просмотрщика полосу пар листов: в строке
мини-кроп П и мини-кроп РД, клик — переход обеих панелей. Панель нужна только
для ориентации — действий над страницами (поворот, печать, удаление) в ней нет.

- растр даёт `page-thumb` (PNG, ширина 64–400 px). Вектор здесь не годится:
  лист A1 после `text_as_path` весит ~6 МБ;
- цена в отрисовке содержимого, а не в размере растра — насыщенный лист A1
  рисуется ~120 мс при любой ширине, лёгкий титульный 3 мс. Поэтому готовые PNG
  лежат в памяти (512 штук ≈ 6 МБ) и отдаются с ETag и суточным Cache-Control,
  а `<img loading="lazy">` тянет только видимые кропы;
- строки полосы строятся из `scSheetMapRows`, чтобы связи не считались второй
  раз и не разъезжались с картой листов; пока карта не построена — из номеров
  страниц, чтобы панель работала сразу после открытия пары;
- активная пара подкручивается в видимую зону при листании
  (`scRevealActiveThumb`, крутится сам список, не страница);
- слева от каждой строки стоит номер пары.

### Перестановка листов

Ctrl/Shift + клик отмечает листы ОДНОЙ стороны (обычный клик остаётся переходом
к паре), перетаскивание переносит всю отметку. У края списка работает
автопрокрутка: `dragover` при неподвижном курсоре не приходит, поэтому список
крутится в своём кадре по последней известной точке.

Строка полосы — это пара, и её положение выводится из связей, а не хранится
отдельно, поэтому перестановка — это переназначение связей
(`scPlanThumbMove` → `scLinksFromThumbRows` → `scPersistLinks`), после которого
карта листов сверху пересобирается сама из тех же данных.

Два правила, которые нельзя терять:

- листы раскладываются по ближайшим СВОБОДНЫМ местам вниз от цели: перестановка
  не должна молча разрывать пару, которую инженер подтвердил раньше;
- явной связью становится только ИЗМЕНЁННАЯ строка, иначе разовая перестановка
  перекрасила бы всю карту в «Ручная» и стёрла уверенность автосопоставления на
  строках, которых никто не трогал. Лист, оставшийся без пары, попадает в
  `unlinked_left_pages` — без явной пометки автосопоставление вернуло бы ему
  прежний правый лист.

## Просмотрщик листов

Инлайновый SVG больше не используется основным интерфейсом: насыщенный A1 давал
около 6 МБ разметки и 30 000 DOM-узлов на страницу, а непрерывный режим держал
сразу несколько таких деревьев на каждой стороне. Теперь страница открывается
как полноформатный PNG-preview шириной 1400 px, а при увеличении поверх него
лениво подставляются только видимые PNG-тайлы 512×512. Уровни 1–64 пикселя на
PDF-point позволяют рассматривать локальный фрагмент при прежнем диапазоне
масштаба 0,1×–100×, не создавая гигантский растр всего A1.

Непрерывный режим использует preview шириной 1000 px и по-прежнему держит окно
не более чем ±2 страницы от текущей. Legacy `page-svg` оставлен серверным
fallback на время проверки нового рендера, но frontend его не запрашивает.

Обе панели ведёт ОДИН видовой порт в нормированных координатах листа
(`cx`/`cy` ∈ [0,1] — точка листа в центре панели, `zoom` = 1 — лист целиком).
Каждая панель переводит их в свои единицы, поэтому один и тот же участок
чертежа стоит в одном месте обеих панелей даже когда слева A4, а справа A1.
Флажок «Синхронный вид» разводит панели на независимые состояния; при
отвязке правая продолжает с текущего места, при возврате подхватывает левую.

Управление: `Ctrl`/`⌘` + колесо — масштаб вокруг курсора, колесо — прокрутка
листа, `Shift` + колесо — горизонтально, перетаскивание — сдвиг, двойной клик —
×2 (с `Alt` — ÷2); кнопки «Вписать» и «1:1».

В шапке каждой панели есть независимый поиск по встроенному текстовому слою
её PDF. Первое нажатие «Найти» открывает первую подходящую страницу, повторные
нажатия переходят по отдельным совпадениям по кругу. Запросы и результаты левой
и правой панели не смешиваются. Все слова найденной фразы выделяются жёлтыми
рамками непосредственно поверх листа; активное совпадение имеет усиленную
обводку. Кнопки `↑`/`↓` рядом с «Найти» циклически переходят между отдельными
совпадениями и выводят выбранный фрагмент в центр панели с читаемым масштабом.
Координаты нормированы относительно страницы, поэтому подсветка остаётся на
месте при pan/zoom и работает как в постраничном, так и в непрерывном режиме.
Для сканов без текстового слоя интерфейс явно показывает «Нет текста»; OCR
этим поиском не запускается.

## Этап 2: исключение одинакового текста

Кнопка «Сравнить текст» запускает отдельный слой после того, как инженер
сохранил связи в `sheet_links.json`. Он не пересчитывает и не меняет карту.

Структура и второй проход берутся из TEXT-блоков текущего `document.md`.
Страница разбивается на заголовки, небольшие абзацы, подписи, нумерованные
пункты, элементы списков и отдельные строки таблиц. Форматирующая канонизация
приводит регистр, `ё`, пробелы, тире, Markdown-разметку и очевидный десятичный
разделитель; цифры и инженерные термины не исправляются.

Серый слой первого прохода строится точнее: непосредственно из визуальных
строк встроенного текстового слоя двух PDF. Точные строки сопоставляются внутри
принятой связи, поэтому разная нарезка или опечатка распознавания в MD не
оставляет визуально одинаковый текст открытым. Проценты UI рассчитываются по
тому же PDF-слою. Если текстового слоя нет, используется структурированный
MD-результат. LLM для этого не вызывается.

Первый проход ищет точный canonical match только внутри каждой принятой связи,
включая many-to-many. Повторяющиеся фразы связываются только при совместимых
типе и относительном положении; неоднозначные повторы остаются нетронутыми.
Второй проход берёт остатки и ищет точное совпадение на других листах
противоположного документа. Короткие и часто повторяющиеся строки для этого
не используются.

Результат хранится в `text_comparison.json` версии 1:

- исходные минимальные `TextFragment` и устойчивые идентификаторы;
- `same_on_linked_sheet` и `found_on_other_sheet` с фактической страницей;
- остатки `remaining_for_comparison` в виде списков fragment id;
- метрики по фрагментам и символам для каждой связи;
- только рекомендательные `sheet_link_hints`;
- нормированные bbox overlay для обеих панелей.

В MD/HTML координат нет, поэтому bbox извлекаются из встроенного текстового
слоя PDF через PyMuPDF. PDF открывается только на чтение. Серые области — это
DOM-overlay в постраничном и непрерывном viewer, а не изменение PDF. Совпадение
на другом листе получает компактный маркер `↗` и tooltip. Подсказка меняет
`sheet_links.json` только после явного нажатия инженером «Добавить связь» или
«Заменить связь»; после изменения карты старый слой помечается устаревшим.

API:

- `POST .../pairs/{pair_id}/text-comparison` — построить/получить тот же
  детерминированный результат для неизменившихся входов;
- `GET .../pairs/{pair_id}/text-comparison` — получить сохранённый UI-слой.

В этом этапе нет LLM, Vision, повторного OCR, semantic similarity, embeddings
или сравнения векторной графики. Остаток не создаёт findings.

Инженерные решения, которые нельзя ломать:

- состояние вида НЕ реактивно, `transform` пишется прямо в DOM внутри
  `requestAnimationFrame`; набор тайлов обновляется только через 90 мс после
  паузы pan/zoom;
- preview всегда остаётся под тайлами, поэтому при движении либо смене уровня
  детализации на листе не появляются пустые области;
- серверный кэш preview и тайлов ключуется подписью `mtime+size` исходного PDF,
  ограничен 128 МБ и отдаёт ETag с суточным browser cache;
- разобранная MuPDF display list держится только для двух последних страниц:
  тяжёлый A1 разбирается один раз (~1 с в худшем текущем примере), после чего
  каждый его тайл рендерится примерно за 15–25 мс; одновременно исполняются не
  более двух raster-задач, чтобы непрерывный режим не устроил всплеск памяти;
- URL изображения содержит подпись версии PDF, поэтому браузер не показывает
  устаревший лист после замены файла;
- `will-change: transform` включается только на время сдвига и снимается через
  200 мс покоя либо перед зумом;
- legacy `page-svg` по-прежнему сжимается вне event loop и безопасно
  namespace-ит идентификаторы, пока существует как fallback.

## Границы clean-slate

Здесь нет PreparedDocument, старого sheet matcher/page alignment, affine/ORB,
image fingerprint, block/entities matching, change regions/groups,
semantic diff, Pipeline V2, LLM, Vision или embeddings. Раздел не создаёт
findings и не запускает внешние процессы либо модели.

Основные точки входа:

- `backend/app/services/stage_comparison/sheet_matching.py`;
- `backend/app/services/stage_comparison/store.py`;
- `backend/app/api/routers/stage_comparison.py`;
- `frontend/index.html`;
- `frontend/static/js/app.js`.
