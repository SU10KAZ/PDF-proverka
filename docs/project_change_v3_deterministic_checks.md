# ProjectChange V3 3.8.0 — детерминированные слои (Dedupe без потерь, проверки источника)

Версия 3.8.0 добавляет два слоя без вызовов модели. Каждый включается своим флагом, **все флаги по умолчанию выключены**:
- без флагов результат побайтно совпадает с 3.7.0;
- промпты, схемы и вызовы моделей не менялись.

Основание — сравнение трёх моделей на DEV5 (29.09):
- `corpus-audits/20260929_dev5_three_model_comparison/`;
- план `corpus-audits/20260929_projectchange_quality_plan/PLAN.md`.

## Флаги

| Флаг (`=1` включает) | Что делает |
|---|---|
| `PROJECT_COMPARISON_V3_DEDUPE_LOSSLESS` | Слияние Dedupe без потерь (см. ниже). |
| `PROJECT_COMPARISON_V3_ABSENCE_CHECK` | `ABSENCE_CONTRADICTED`: карточка утверждает «в OLD не было / не указано», а OLD это говорит. |
| `PROJECT_COMPARISON_V3_NUMERIC_CHECK` | `ELEVATION_UNCLEAR`: «0.000 = B» + отметка ≠ подписанной абсолютной, а карточка повторяет числа без оговорки. `TABLE_TOTAL_MISMATCH`: итог ≠ сумме строк при доказанном на той же таблице законе суммы. |
| `PROJECT_COMPARISON_V3_OPTION_CHECK` | `OPTION_NOT_REFLECTED`: оборудование, которое источник помечает «опция», подано как обязательное. |
| `PROJECT_COMPARISON_V3_DOCUMENTARY_FLAG` | `LEGEND_ONLY`: все доказательства карточки — строки легенды или перечни условных обозначений. |
| `PROJECT_COMPARISON_V3_TABLE_ROWS` | `UNCOVERED_TABLE_ROW`: изменённая строка таблицы водопотребления, которую не называет ни карточка, ни подсказка. |

## Dedupe без потерь (`dedupe.py`)

В 3.7.0 при `MERGE_DUPLICATES` все тексты брались у первой карточки в списке модели, остальные терялись. С флагом:
- **главная — самая полная** по обозначениям и числам (`salient_tokens`); при равенстве сохраняется порядок модели;
- `dedupe_members` хранит тексты всех слитых карточек;
- `dedupe_residual` перечисляет обозначения и числа членов, которых нет в главной;
- одинаковые параметры и доказательства сворачиваются;
- в результате появляется `dedupe_policy`: сколько главных сменено и у скольких членов есть остаток.

## Проверки источника (`source_checks.py`)

Проверки работают после реестра качества.

Что читают:
- только `page.json` пакета источников: нативный текст PDF, структурированный Markdown, таблицы;
- служебные строки распознавания (`**Description:**`, `**Summary:**`, …) исключены — это пересказ модели, а не текст документа.

Что делают с находками:
- карточки не меняются и не удаляются;
- находки пишутся в артефакт `project_change_v3_source_checks.json` (входит в манифест прогона) и в `result.source_checks`;
- в интерфейсе находки показываются как конфликты карточки (`conflicts[].source_check`);
- находки без карточки попадают в `run.source_check_findings_unassigned`;
- прогон с находками уходит в REVIEW.

Ключевые решения, проверенные на стенде:
- **Отсутствие.** Поиск по окну из двух строк, потому что PDF переносит фразу посреди предложения. Слово считается характерным, если встречается не более чем в 100 строках документа, а тройка слов — редкой, если каждое не более чем в 20 строках. Совпадения по одной цифре не принимаются.
- **Отметки.** Формулировка — «требует уточнения», а не «ошибка»: подпись может относиться к другой точке. На NEW29 DEV5 119,60 — это, вероятно, низ трубы Ø225, тогда как в OLD подпись означала ось.
- **Строки таблиц.** Строки сопоставляются по номеру и первому слову названия. Значения сравниваются как числа («0,28» = «0,280»). Строка считается покрытой, если карточка называет её по словам и значению или содержит два её новых числа.

## Консолидатор 1.1.0

- «к.1 / корп.4» попадают в реестр корпусов.
- Лимиты длины прозы подняты в полтора раза: все откаты 1.0.0 по длине были на верных слияниях.
- Префильтр **не менялся**. Потолок кластера 12 и рёбра внутри региона проверены на DEV5 и откатаны:
  - верных пар почти не добавили (Opus 5.5: 34 → 36 из 93);
  - смешение событий выросло 35 → 77 пар.
  
  Мера сходства сводит карточки по корпусу, а не по событию — отдельная задача.
