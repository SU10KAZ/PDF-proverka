# Алгоритм формирования «Граф схемы» для однолинейных расчётных схем (ВРУ/ГРЩ/РП)

Документ для разработчика/агента (Codex). Описывает метод, к которому мы пришли:
извлечение структурированного графа однолинейной расчётной схемы **детерминированно из
вектор-слоя PDF по геометрии**, без OCR/LLM. Состояние на 2026-06-30, прод (ветка `main`).

---

## 0. Главный вывод (читать первым)

**Подписи потребителей, параметры линий, автоматы, кабели, трассы, связи АСУД/ПС — это
CAD-текст в вектор-слое PDF** (повёрнут на 90°, но `fitz.get_text("words")` отдаёт его с
координатами). Opus при визуальном чтении читал ровно этот же текст. Значит граф строится
**из геометрии вектора**: мгновенно, бесплатно, без OCR-ошибок.

- Вектор-слой есть у **199/205** электросхем объекта → метод применим почти везде.
- **Qwen/OCR — только фолбэк для СКАНОВ** без вектор-слоя (см. §9).
- Сравнение на блоке 7HYD (ВРУ-К1.1): вектор = дословно как у Opus, ~миллисекунды;
  Qwen-тайлинг = ~15 мин/схему, качество ниже, ошибки OCR.

## 1. Вход / выход

**Вход:** `pdfplumber_text` блока (плоский вектор-текст из `result.json`) + сам `document.pdf`.

**Выход:** `singleline_graph` — JSON:
```jsonc
{
  "panel": "ВРУ-К1.1", "type": "single_line_calc_diagram",
  "source_page_index": 7,            // НАЙДЕННАЯ по контенту страница PDF (см. §3)
  "feeders_total": 68, "incomers": 2,
  "power": { /* вводная часть, §8 */ },
  "panels": [ { "id":"РП3","name":"РП3","feeder_count":43,"active":..,"reserve":..,
                "feeders": [ /* §7 */ ] } ],
  "validation": { "active":59,"reserve":5,"ambiguous":4,
                  "power_rate":1.0,"current_rate":1.0,         // физпроверка
                  "breaker_bound":"68/68","codes_total":59,"codes_linked":59 },
  "review": [ {"qf":"QF3.35","code":"K1.1.22","notes":["номинал 16А < тока 28.65А — проверить"]} ]
}
```

Точка входа: `build_singleline_graph(pdf_path, vector_text, *, panel_hint="ВРУ") -> dict|None`
в `backend/app/pipeline/stages/block_grounding/singleline_graph_geometry.py`.
`None`, если это не feeder-схема (`structure_singleline_text` дал < 3 линий) или нет геометрии.

## 2. Принцип «параметры из текста + топология из геометрии»

Два независимых надёжных источника, сшиваются по **коду цепи** `К<n>.<m>.<...>`:

1. **Параметры линии** — из плоского текста (`singleline_structurer`), верифицированы физикой.
2. **Топология** (какой QF / какая панель / автомат / резерв) — из геометрии колонок PDF.
3. **Подпись потребителя + устройства** — из геометрии колонки методом «остаток = подпись» (§7).

---

## 3. Поиск страницы по контенту (КРИТИЧНО — баг page_index)

`page_index` из `result.json` **≠** номер страницы в исходном PDF (Chandra нумерует иначе).
Пример: блок 7HYD имеет `page_index=8`, а реально лежит на **PDF-странице 7**.

`_find_page_index(doc, vector_text)`:
- берёт «редкие» токены вектора: `re.finditer(r"К\d+\.\d+\.\S+|QF\d+\.\d+|\d{3}\.\d+А|\d{2,3}кВт", vector_text)`;
- для каждой страницы PDF считает, сколько этих токенов встречается в её `get_text()`;
- выбирает страницу с максимумом совпадений.

**Любой рендер/геометрия по `page_index` возьмёт не тот лист.** Всё (геометрия + рендер
`region-image`, §10) идёт по найденной странице.

---

## 4. Параметры линий: `singleline_structurer.structure_singleline_text(vector_text)`

Якорит param-строки регуляркой вида
`<код> : <Pуст>кВт - <Kc> - <cosφ> - <Pрасч>кВт - <Iр>А` и парсит поля:
`circuit_code, P_inst_kw, Kc, cosphi, P_calc_kw, I_a, cable, length_m, voltage_drop_pct,
Ikz_ka, routing, phase, consumer(может быть пустым)`.

**Физпроверка** (даёт `validation.power_rate / current_rate`, на 7HYD = 100%):
- `P_calc ≈ P_inst × Kc`;
- `I ≈ P_calc / (√3 × 0.38 × cosφ)`.

Возвращает `bus_sections[].feeders[]`. В графе индексируется в `params = {circuit_code: feeder}`.
Физпроверка попутно ловит реальные замечания `In(автомата) < I(линии)`.

## 5. Геометрия колонок QF

Из `pg.get_text("words")` (раскладка `x0,y0,x1,y1,text,...`):

- **QF-колонки:** `re.fullmatch(r"QF\d+\.\d+", w)`.
- **Исходящие vs вводные по Y:** `y_split = ys[0] + (ys[-1]-ys[0])*0.6`;
  `qf_out` (Y ≤ split, отходящие линии), `qf_incomers` (Y > split, вводные автоматы панелей).
- **Коды цепей:** `coll(r"^К\d+\.\d+\.")` — **generic-префикс** (был хардкод `К1.1`, из-за
  чего схемы с префиксом `К1.2` (9VCW) не привязывались; `codes_linked` 0→52 после фикса).
- **Атрибуты автомата из колонки** через `_near(qx,qy,arr,dx,dymin,dymax)` (ближайший токен
  в полосе): `ВА-…` (тип), `\d+кА` (Icn), `\d+А` (In), `[123]Р` (полюса); резерв — слово
  «резерв» в колонке; управление — `ПС` / `АСУД` в полосе.

### 5.1 Монотонная привязка QF ↔ код (по панели)

Внутри панели (`панель = префикс QF`: QF3.x → РП3) и QF, и коды идут слева-направо.
Поэтому: отсортировать QF панели по X, коды панели по X, **спаривать по порядку**; резервная
ячейка **пропускает** код. Это устраняет коллизии, которые даёт nearest-neighbour в плотной
зоне (РП3 = 43 линии).

```
для каждой панели p:
  pq = QF панели, sorted by x
  pc = коды в X-диапазоне панели, sorted by x
  ci = 0
  для qx,qn в pq:
    если reserve(qn): assign[qn] = None
    elif ci < len(pc): assign[qn] = pc[ci]; ci += 1
    else: assign[qn] = None
```

`status`: `reserve` (резерв) / `active` (есть привязанный код+параметры) / `ambiguous`
(колонка без кода → `requires_review`).

## 6. `_PANEL` и сборка линии

`_PANEL = {"1":"РП1","2":"РП2","3":"РП3","4":"РП4 (АВР)","5":"РП5"}` (по префиксу QF).
Каждая линия — dict с `qf, panel, consumer, location, circuit_code, breaker_type/poles/icn/in,
P_inst_kw, Kc, cosphi, P_calc_kw, I_a, cable, length_m, voltage_drop_pct, Ikz_ka, routing,
control, status, review, bbox_page` (§10).

## 7. Подпись потребителя: «распарсить известное → ОСТАТОК = подпись»

Функция `_extract_consumer_geo(qx, qy, nx, words, formula_vals)`.

**Проблема:** в колонке текст «слоится» по под-X-линиям и переплетается по Y: подпись
потребителя, формула нагрузки, кабель, трасса, автомат, управление, устройства (УЗО/КМ/МК).
Якорь-по-словарю (искать «Освещение»/«Щит»…) **хрупок** — всегда найдётся неизвестный тип
(«Световое ограждение кровли»).

**Решение — классификация по исключению + вычитание ТОЧНЫХ значений формулы:**

1. Колонка = слова в `[qx-half, qx+half] × [qy-280, qy+30]`, где `half = min((nx-qx)/2+3, 35)`.
2. Убрать всё **распознанное** регуляркой `_CONSUMER_KNOWN_RE` (формула `К<code>`/`кВт`/`%`/
   десятичные/`cos`, кабель `ППГ`/`NхN`/`Iкз`/`кА`, автомат `ВА-`/`NР`, трасса `Лоток`/`Пг.`/
   `Каб.несущ`/`Nм`, управление `^АСУД`/`^ПС`/`откл`/`пожар`/`систем`/`к`, устройства
   `МК103`/`УЗО`/`-230В`/`2Р`/`NНО|НЗ`, учёт `TA\d`/`хТ`/`НАРТИС`/`Wh`, разделители).
   **Важно: голые ЦЕЛЫЕ числа НЕ исключаем** (счёт квартир «33», этаж «41», «1 кат.»),
   а десятичные — да (это Кс/cos).
3. Дополнительно вычесть **точные значения формулы** этой линии (`P_inst, Kc, cosphi,
   P_calc, I_a`, включая целые формы, напр. Кс=1 → токен «1») — чтобы убрать формулу,
   но сохранить числа подписи.
4. Из остатка взять под-X-линию подписи = мода X кириллических слов; собрать токены на
   ней (`±16px`), упорядочить по Y по убыванию (текст читается снизу-вверх).
5. Нет кириллицы → «Резерв», если в колонке есть «Резерв», иначе пусто.

**Приоритет:** geo-подпись > подпись из `structurer` > «Резерв (свободная ячейка)».
Валидировано: 7HYD РП3 8/8 дословно как у Opus; 9VCW «Световое ограждение кровли» —
поймано без словаря.

### 7.1 Известные баги, найденные на 9VCW (и решённые)
- P1 словарь якорей → решено исключением;
- P2 «Резерв» как ошибка → детект статуса;
- P4 дубли QF (вводной+отходящий) → разделение по Y (§5);
- P5 числа подписи срезались / P6 формула в подписи → **вычитание точных значений формулы**.

## 8. Вводная часть (питание): `_extract_power(words, page_text, qf_incomers)`

- **Подписи `Ввод N (РП…)`** — `re.finditer(r"Ввод\s*([12])\s*\(([^)]{3,80})\)", page_text)`
  → какой ввод какие РП питает (готовая топология питания, надёжнее линий — схема подписывает
  связи текстом).
- **Инвентарь устройств:** вводные автоматы `ВА-305`, разъединители `ВР-101-*`, `АВР-301`,
  счётчики `НАРТИС`, ТТ-коэффициенты `\d{3,4}/5А`.
- **Токи вводов** из таблицы: `(ВП[12]|ВП-АВР|РПn)\s+(Iраб)\s+(Iавар)`.
- **Вводные QF РП** (нижний ряд `qf_incomers`, `ВА-305 320А`).
- Сборка: `inputs[ВПn] = {vvod, feeds[РП…], incomer, switch, meter, i_rab, i_avar}`,
  `avr = {device:АВР-301, in_a:40, feeds:[РП4(АВР)]}`, `external_source`, `rp_incomers`.

## 9. Рендер графа в промпт Stage 02 (опц.)

`render_graph_for_prompt(graph) -> str` — компактный текст графа (питание + панели + линии +

## 10. bbox линии + визуальная проверка («области») — и фикс координат

Для визуальной проверки связи данных каждая линия несёт **bbox колонки** (что алгоритм
считает «одной линией»):

- `bbox_page` (page-normalized): **X = середины до соседних QF** (тайлинг без наложения,
  cap 38px/сторону — иначе боксы наезжают); **Y = от верха текста потребителя ВНИЗ до шины**
  (`qy+60`) — всё над автоматом и под ним.
- Endpoint `/blocks/llm-text` конвертирует `bbox_page → bbox` (координаты блока) через
  `coords_norm` блока из `result.json`.
- Фронт (тоггл «области») рисует полупрозрачные SVG-прямоугольники по `bbox` + подпись QF +
  tooltip «QF — потребитель», цвет по статусу.

### 10.1 КРИТИЧНО: рассинхрон координат картинки и геометрии
Картинка блока `/blocks/image` — это **кроп Chandra-страницы** (иная нормировка/поля), а
геометрия (`bbox`) — с **fitz-страницы**. Из-за разной нормировки SVG-области **сдвигались на
~колонку**. Фикс: endpoint **`/blocks/region-image`** рендерит базу **из той же fitz-страницы
(найденной по контенту, §3) и того же `coords_norm`**, что и bbox. В режиме «области» фронт
берёт эту базу (`blockImageSrc`) → области точно над колонками. Проверено наложением bbox на
оба рендера: fitz = совпадает, Chandra = сдвиг. **Полигоны бы не помогли — это сдвиг координат,
а не форма.**

## 12. Известные ограничения (last-mile)

- «ввод **1** кат.» → «ввод кат.» (Кс=1 неотличима от категории «1» — редкая неоднозначность).
- Хвосты подписи на 2-й X-линии «(потол.) (левый)», «(п.1.МОП.2…)» — пока не собираются
  (брать 2 ближайшие X-линии подписи).
- Дубли маркировки QF (вводной/отходящий, повтор QF2.3) — помечаются `review`, не дедуплицируются.
- bbox = axis-aligned прямоугольник; для наклонных колонок возможен полигон по форме фидера
  (текст-колонка сверху → провод → QF/автомат → шина снизу) — улучшение, не блокер.

## 13. Qwen как фолбэк для сканов (без вектор-слоя)

Только если у блока нет/беден вектор-слой. Тайлинг обязателен (one-shot на плотной схеме = 0%):
рендер региона блока → тайлы 1600px с перекрытием → per-tile Qwen-VL → merge. Рычаги качества:
поворот тайла на 90° (текст→горизонталь), чтение по одной колонке, OCR-модель
`infinity-parser2-flash`. Модель `qwen/qwen3.6-35b-a3b` через ngrok (см. `local_vision_provider.py`),
concurrency=1, холодная загрузка ~80с, ~60с/тайл. Для вектор-схем Qwen НЕ нужен.
