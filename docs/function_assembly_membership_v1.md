# FUNCTION ASSEMBLY MEMBERSHIP CERTIFICATE V1 — сертификат принадлежности FunctionScope ↔ FunctionalAssembly

Исследование (Фаза 1 мастер-задачи «Architecture closure»). Модель не вызывалась
ни разу; выкатки, теневого режима, материализации и пуша нет, ни один боевой
модуль не изменён. Слои `pdf_evidence_v1`, `pdf_evidence_v2`,
`function_topology_v1` и `function_representation_bridge_v1` взяты как
**замороженные эталоны**; генератор кандидатов Function Lineage не тронут.
Артефакты пишутся только в
`comparison/ai_sheet_matcher/20260905_function_assembly_membership_v1/`
(каталог `comparison/` в git не попадает — как и у предыдущих треков).

Продолжение после вердикта **B** трека FUNCTION REPRESENTATION BRIDGE V1
(`docs/function_representation_bridge_v1.md`), который оставил незакрытым
вопрос: 9 PROVEN привязок, 91 PARTIAL по каналу значений, 26 задач с фактами
сборки на обеих сторонах — но ни одного *сертификата* принадлежности, и оба
AUTO-тира на нуле.

## Принятый контракт

Наследуются без ослабления: асимметрия V1 (несертифицированная функция — это
функция, о которой слой ничего не говорит), «пересечение — не соединение» V2,
«подпись называет группу и не создаёт её» Topology V1, «лист — не контейнер»
и «значение обязано различать» моста.

Добавлен **сертификат**: утверждение об одной функции и одном нарисованном
контейнере, называющее структурное отношение, на котором оно стоит. Статусов
пять: `CERTIFIED`, `PARTIAL`, `AMBIGUOUS`, `CONTRADICTORY`, `UNKNOWN`.
Сертифицировать вправе ровно четыре канала, и каждый **составляет два уже
доказанных структурных отношения**, а не вводит третье:

| Канал | Что составлено | Отношение |
|---|---|---|
| `TOPOLOGY_OWNER_MARK_ON_MEMBERS` | марка паспорта привязана нарисованной подписью (V2) к **двум и более** членам одного острова и ни к одному вне его; при одном члене — только если остров не несёт ни одного другого обозначения (кабельные марки читаются продовым разборщиком и не считаются) | `IS_DRAWN_AS` |
| `CAPTION_NAMES_SCOPE_WITH_DOCUMENTED_VALUE` | линованная решётка с единственной ячейкой-заголовком, заголовок печатает марку функции (продовый извлекатель с обеих сторон), и внутри той же решётки напечатано документированное значение паспорта | `IS_DOCUMENTED_BY` |
| `MARK_INSIDE_ONE_CONTAINER_WITH_DOCUMENTED_VALUE` | марка напечатана внутри ровно одного несхемного контейнера страницы (ячейка/бокс/выноска V1) вместе с документированным значением | `IS_DOCUMENTED_BY` |
| `FRAGMENT_EVIDENCE_IN_ONE_CONTAINER` | сырые строки Markdown, которые детерминированный извлекатель приписал фрагменту функции, напечатаны внутри одного контейнера и ни в каком другом; порог по числу строк и их длине опубликован кривой | `HOLDS_SCOPE_EVIDENCE` |

Каналы поддержки (`MARK_BOUND_TO_ONE_MEMBER`, оба ограниченных канала моста)
никогда не сертифицируют. Отвергнуты поимённо: та же страница, ближайший
контейнер, самая похожая строка, кандидат с высшим рангом, **единственный
оставшийся кандидат**, расстояние до контейнера и «заголовок листа + один
доказанный щит» как доказательство. Страж `assert_no_similarity_evidence`
моста обходит все артефакты.

**Страница — область вопроса, а не доказательство.** Паспорт извлечён с одной
физической страницы, поэтому вопрос «какой нарисованный контейнер этой страницы
и есть эта функция» корректен, а ответ «он на той же странице» — нет. Страж
`assert_certified_container_lies_on_the_function_page` отказывает сертификату,
назвавшему контейнер с другой страницы.

**`CONTRADICTORY` намеренно узок**: только два положительных структурных
доказательства об одной функции, называющих контейнеры, которым чертёж дал
*разные* обозначения, либо контейнер, названный маркой функции и печатающий
единственное значение величины, которое паспорт утверждает как единственное и
другое. Пробел — никогда не противоречие; несколько скоупов на одном контейнере
— никогда не противоречие.

`systems` (мешок токенов описания листа) исключён из значений, несущих
идентичность: сертификат слияния v2.8 исключил его за отсутствие инженерного
смысла, а канал значений моста измеримо голосовал словами заголовка
(«Внутреннее», «электроснабжение»), напечатанными в боксе.

## Находки

* **1 — единственная структурная идентичность на этом корпусе — марка-владелец
  топологии, и она есть только справа.** У IOS1.1/LEFT 34 функции несут марку,
  напечатанную на листе, и **ни одна** не привязана ни к одному узлу
  (`MARK_BOUND_TO_NO_MEMBER` = 34): имя щита стоит в заголовке и штампе.
  Поэтому все 9 сертификатов — IOS1.1/RIGHT, а 213 скоупов lineage
  левосторонние по построению → 0 сертифицированных скоупов.
* **2 — правило владельца измерено на девяти PROVEN моста.** Пять привязок
  держатся на 10–63 связанных членах; четыре — все на стр. 25 IOS1.1/RIGHT
  «Однолинейная схема ВРУ-1 (конец)» — на **одном** члене с подписью
  `ВРУ1 АВР ППУ IP31` в острове без шины и без иного имени. Строгое «≥2»
  понижало их до PARTIAL; правило исключительного имени (остров не несёт ни
  одного другого обозначения; `HF5` из `ППГнг(А)-HF 5х185` отсеивается продовым
  `parse_cable`) возвращает их в CERTIFIED и не пропускает ни одной приманки.
* **3 — заголовок ячейки называет функции ДРУГИХ страниц.** Девять
  линованных блоков листа ГРЩ (`ВРУ1`…`ВРУ-НСТ`) называют марки, чьи паспорта
  лежат на стр. 24–30 обеих сторон, а числа из этих блоков (414,5 / 449,3 /
  717,3…) не документированы ни в одном из тех паспортов. Двенадцать PANEL на
  стр. 37 IOS1.1/LEFT озаглавлены «1»…«12». Итог канала заголовка: **0 из 313**
  на собственной странице функции. Это межлистовая **ссылка**, а не
  принадлежность — новый вид положительного факта, `cross_sheet_named_reference`
  Фазы 2.
* **4 — канал фрагмента даёт 0 в рабочей точке, и причина — растр.** 177 из
  313 фрагментов не имеют **ни одной** строки доказательств, напечатанной
  нативно на своей странице. На стр. 22–23 IOS1.1/RIGHT картинки занимают
  45–47 % листа, нативных слов 65 против 147 строк Markdown — таблицы
  нагрузок вставлены растром; на схемах ВРУ (стр. 25–29) таблица нагрузок тоже
  картинка: 31–45 ячеек Markdown, напечатано нативно 0–3. По корпусу **122
  страницы из 278** несут ≥5 табличных ячеек Markdown, ни одной из которых нет
  в нативном слое. V1 намерил обратный разрыв (19 223 нативные строки, которых
  нет в Markdown). Каналы **дополнительны, и ни один не надмножество другого**.
* **5 — кривая чувствительности лежит на плато.** При минимуме в одну
  найденную строку канал фрагмента сертифицирует 2–3 функции; при двух и более
  — 0 на всех четырёх длинах (4/6/8/12). Рабочая точка (8, 2) не выбрана под
  результат: одна найденная строка — совпадение, и контроль так и говорит.
* **6 — приманки: 0 ложных сертификатов, и одна ошибка учёта, названная
  вслух.** Каждая функция сертифицирована повторно против своей страницы с
  паспортом чужой функции (другая страница, другая марка) в трёх формах.
  `FULL_SWAP` и `MARK_SWAP` — 0 сертификатов. `EVIDENCE_SWAP` оставляет функции
  её собственную марку, и канал топологии, не читающий фрагментов, законно
  выдал 9; первый прогон посчитал их ложными, и это была ошибка приманки, а не
  канала — в артефакте это отдельное число.
* **7 — правило расстояния коснулось бы 119 несертифицированных функций** (285
  напечатанных строк паспорта лежат в двух кеглях от контейнера) и присвоило
  бы 0: оно отвергнуто, и отказ — число.
* **8 — одна сборка, много скоупов, подтверждено на паспортах.** Все 78
  многофункциональных страниц делят один заголовок листа: паспорт режет один
  щит по классам функций (`ЯК1` → METERING, LIGHTING, RISER_DISTRIBUTION,
  GROUNDING, ELECTRICAL_DISTRIBUTION). Три сертифицированные сборки несут по
  2, 3 и 4 функции; сборка не дробится ради `ONE_SCOPE`.

## Механизмы несертификации (наиболее конкретная причина)

| Механизм | Функций |
|---|---:|
| `NO_FRAGMENT_EVIDENCE_IS_LOCATED` — ни одна строка фрагмента не напечатана нативно | 93 |
| `NO_CONTAINER_ON_THE_SHEET` | 68 |
| `SCOPE_HAS_NO_PRINTED_MARK` (и никакой другой канал не дошёл дальше) | 49 |
| `LOCATED_EVIDENCE_LIES_OUTSIDE_EVERY_CONTAINER` | 38 |
| `MARK_LIES_OUTSIDE_EVERY_CONTAINER` (заголовок/штамп) | 22 |
| `SEVERAL_ISLANDS_CARRY_THE_MARK` | 4 |
| `TOO_FEW_LOCATED_SEGMENTS` / `EVIDENCE_SPANS_SEVERAL_CONTAINERS` | 2 / 1 |

Исходы всех четырёх каналов по каждой функции сохранены в
`channel_outcomes` — ни один ответ не потерян за «первой причиной».
