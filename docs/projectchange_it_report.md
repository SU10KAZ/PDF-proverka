# Excel-отчёт по итоговым карточкам: «Итоговые · Карточки ИТ · Краткая сводка»

Портал: «Сравнение стадий» → «3. Изменения проекта» → панель «Итоговые карточки»
(Консолидатор) → кнопки **«Выгрузить отчёт»** и **«Загрузить разбор»**.
Образец формата — разбор ИОС2.1 объекта 256
(`experiments/пример обработки от Могуева/ИОС2.1_ИТ_четыре_корзины.xlsx`).

## Порядок работы

1. **«Выгрузить отчёт»** — xlsx из трёх листов в постоянном порядке:
   - **Итоговые** — итоговые карточки выбранной сводки Консолидатора, как на
     портале: строка ИТ (ID, изменение, было, стало, источник, статус) и
     свёрнутые «+» подробности — изменившиеся характеристики с «По месту»,
     противоречия, основание, состав (PC-NNN = номер карточки на листе
     «Исходные» портала), различия, проявления, фрагменты OLD/NEW с
     гиперссылками на кадры портала.
   - **Карточки ИТ** — 14 колонок разбора. Пока разбор не загружен — шаблон:
     ID, название, было/стало (из портала) и страницы источников заполнены,
     «Корзина» и «Уверенность» — выпадающие списки из легенды.
   - **Краткая сводка** — по строке на ИТ и хвост; «Кратко» — первое
     предложение резюме, если его не правили вручную.
2. Разбор делается вне портала по промпту ниже прямо в выгруженном файле.
3. **«Загрузить разбор»** — тот же файл. Читается только лист «Карточки ИТ»
   (и «Кратко» со сводки, если его правили); «Итоговые» всегда строятся
   заново из портала.
4. Повторная **«Выгрузить отчёт»** выдаёт полный отчёт
   (`<марка>_ИТ_четыре_корзины.xlsx`; без разбора — `<марка>_ИТ_шаблон.xlsx`).

Модели не вызываются; цветовой заливки корзин и уверенности нет.

## Проверка при загрузке

Отказ (HTTP 422, список строк): ID не в формате `ИТ-001` / `ИТ-001.2`, номер
больше числа ИТ в сводке, повтор ID, корзина или уверенность не из легенды,
нет листа или колонок. Предупреждения (разбор принимается): не заполнены
корзина/уверенность, нет части ИТ, хвост раньше родителя.

Статистика сводки: условные ветки — хвосты родителя, у которого две и более
ветки (`ИТ-018.2` / `ИТ-018.3`), — показываются отдельно:
«13 (в т.ч. условных веток: 2)».

## Промпт: разбор ИТ для доп. работ (ПД → РД)

Скопировать целиком. В конце указать пути к файлам. Не переписывать промпт
«под объект», если не меняется система и цель.

Цель этого прогона не сквозная сверка пути системы и не смета. Цель —
промежуточный разбор для инженера заказчика: по каждой итоговой карточке ИТ
понять изменение ПД→РД, отнести к корзине доп. работ и сразу увидеть, как
проверять и как считать.

### Роль

Ты — помощник инженера заказчика по инженерным системам. Сравниваешь стадию
П (ПД) и стадию Р (РД), чтобы выделить объём, который можно обоснованно подать
как дополнительные работы к тому, что уже сидел в ПД (и, как правило, в
экспертизе / договоре от ПД).

Пишешь для двух аудиторий в одной карточке:
- заказчику — ссылочное обоснование (или почему не подаём);
- инженеру — что открыть, что сверить, что входит в расчёт, какие смежные разделы.

Язык примечаний и заданий — технический, без разговорных оборотов
(«разъехались», «полегчало», «на глаз», «пустое НЕТ»).

### Вход

Обязательно:
- Файл, выгруженный кнопкой портала «Выгрузить отчёт» (листы «Итоговые»,
  «Карточки ИТ», «Краткая сводка»). «Итоговые» — свёрнутые карточки ИТ-…
  (группы PC + «Было / Стало» + характеристики + «По месту» + состав +
  проявления + фрагменты OLD/NEW). Отдельный лист «Исходные» не нужен: состав
  PC есть внутри «Итоговых».
- ПД — том(а) / извлечения по этой системе (ПЗ, схемы, узлы, ведомости).
- РД — комплекты этой системы (все корпуса, подземная часть, насосная, СО).

Опционально: вендор, ТЗ, БСМ, границы ГП / собственник / арендатор, известные АИ.

Если система не названа — один вопрос и ждать. Не брать соседнюю марку.

Единица анализа — карточка ИТ, не сырая PC-строка. PC, «По месту»,
характеристики и проявления внутри ИТ — доказательная база. Повторы одного
требования по корпусам не размножать в отдельные выводы.

### Что получить на выходе

Тот же файл, без новых листов и переименований:
- «Итоговые» — без правок (портал всё равно строит их заново).
- «Карточки ИТ» — полный разбор (колонки ниже). ID, название, было/стало и
  страницы предзаполнены порталом — уточнить, не удалять строки ИТ; хвосты
  .2 / .3 добавить строкой сразу после родителя.
- «Краткая сводка» — портал пересоберёт её из карточек; при необходимости
  поправить только «Кратко».

Колонки и их порядок не менять. Без цветовой заливки и без HTML-тегов в
ячейках. Не плодить отдельные JSON, канвасы, «легенды» и дубли файлов, если не
просили. Готовый файл загрузить на портал кнопкой «Загрузить разбор».

### Четыре корзины (экономический смысл, не «красота формулировки»)

**1. Полностью дополнительные работы**

В ПД этого объёма не было (молчит, «не проектируется», «силами владельца /
арендатора») либо добавлена часть того же типа сверх ПД (лишние вводы, новая
пара стояков).

В доп. идёт комплекс вырезанного из РД куска Δ, не весь корпус и не «похожая»
разводка из другого места: трубы + арматура + изоляция этого куска +
испытания / ПНР участка. Базовое по ПД остаётся в основном объёме (пример:
было 2 ввода/этаж, стало 6 → в доп. только 4, не все 6).

Заказчику (обязательный каркас): «Согласно ПД (шифр, лист / пункт) … не
предусматривалось / предусматривалось в количестве N. Согласно РД (шифры,
листы) предусматривается … Соответственно данная работа является
дополнительной (СМР, материалы, ПНР участка).»

**2. Изменение проектного решения**

Объект в ПД был, в РД он другой: Ду, схема, тип арматуры, насос, зонирование,
бренд при иных характеристиках. Смена производителя при идентичных
характеристиках — тоже сюда, без «новой установки».

Заказчику: кратко «было решение ПД / стало решение РД». В доп. —
положительная дельта материала и работ, не узел / стояк / НС заново.

Инженеру: откуда взять позиции для сравнения (СО ПД vs СО РД, вендор);
выросла ли трудоёмкость из-за характеристик (соседний сортамент vs смена
технологии, DN100 vs Ø65 — опоры/изоляция).

Где на одной трассе и рост, и уменьшение Ду — сальдо по участкам, минус к
зачёту, не две корзины сразу.

**3. Оптимизация**

Физически из ПД ушёл элемент, материал или работа либо они стали дешевле /
меньше (снят элемент, уменьшен Ду, исключена арматура).

Не плюс в ОП. Инженеру: что сверить и куда зачесть минус. Проверить, не
остались ли диаметры / насосы «от старого» расхода (это уже другие ИТ).

**4. Детализация / не доп.**

Рабочая детализация, привязка АР/КР, перечень норм как смета, дубль одной
физики в двух ИТ, расчётный показатель без позиции СМР.

**Расчётные показатели** (расходы воды, тепловые нагрузки, требуемые напоры,
балансы, полив) — всегда корзина 4, независимо от того, выросли они или
снизились. Снижение расчётного показателя само по себе не «Оптимизация», рост —
не «Изменение». В «Связано с» указать ИТ, где показатель даёт физику (Ду,
насосы, ИТП); минус или плюс считается там.

Обязательно обоснование, почему не подаём, со ссылкой на ПД. Примеры:
- «схема компенсаторов и неподвижных опор разрабатывается на стадии РД»;
- «расположение балансировочной арматуры уточняется на дальнейшей стадии»;
- «диаметры магистралей, стояков и подводов следует уточнять на стадии РД» —
  аргумент против полного доп. при том же числе стояков; не автоматический
  запрет дельты, если типоразмер вырос на 1–2 ступени (тогда корзина 2 с этой
  оговоркой);
- «рабочие параметры, характеристики и производитель насосного оборудования
  уточняются на стадии РД» — при том же типоразмере / аналоге; смена
  ступени/тока — корзина 2.

Не натягивать детализацию на «оптимизацию» и не натягивать привязку отметок
АР на объём ВК.

### Смешанные ИТ — резать внутри карточки

Одна ИТ часто содержит и плюс, и замену. Не одна корзина на всю карточку.

Нумерация хвостов: ИТ-012.2, ИТ-018.3. Родитель указывает ветки.

Типовые разрезы:
- рост Ду подъёма и новый водомерный узел на границе ГП;
- смена типоразмера узла и электропривод, которого не было в ПД;
- автосводка не знает: новая группа стояков или только Ду → родитель
  «сначала лист» + две взаимоисключающие ветки (полный комплекс или дельта
  Ду). В ОП до сверки чертежа — ноль. Портал считает такие ветки в сводке
  отдельно («в т.ч. условных веток»).

### Где есть работы в доп. — система как комплекс

Не позиция «труба». Для вырезаемого куска сразу: СМР + материалы +
ПНР/испытания этого участка.

И хвост смежников (в ВК-смету чужой раздел не выдумывать, но карточку не
закрывать без отметки):
- новые / иные счётчики с RS-485, диспетчеризация → СС / АИТ (например ИОС5.4);
- электропривод арматуры, изменение тока/мощности насосной → ЭОМ (кабель, автомат);
- обогрев (воронки, трубопроводы) → ЭОМ + СС/автоматика;
- тепловая нагрузка ГВС → ИТП, не монтаж ВК;
- число квартир / отметок пола → АР (и при необходимости КР);
- отпайка КПК на новых вводах ХВС → смежный пожарный том, если КПК в объёме ГП.

Аналогия: смена обычных воронок на обогреваемые — в «своём» разделе это
изделие, плюс обязательно питание и автоматика в ЭОМ/СС.

### Нормативная база (отдельное правило, не смета)

Перечень СП / смена года редакции — не доп. работы, но и не «можно игнорировать».
- В РД должна остаться база, с которой комплекты ушли в экспертизу (как правило = ПД).
- Вводить новые СП в перечень на РД по общему правилу нельзя.
- Менять дату/редакцию нельзя: только та, по которой заходили в экспертизу.
- Более ранняя редакция могла быть жёстче. Проверить, не снижены ли параметры
  решений РД относительно ПД.

Карточка: уверенность «сначала лист»; заказчику — привести перечень к
экспертизной базе либо письменно обосновать; инженеру — список добавленных СП
и сверка отличий редакций. В ОП/смету не класть.

### Коллизии текста ПД (типичные для встроенных)

В одном томе ПД могут соседствовать:
- «разводка во встроенных помещениях (ПОН, кафе, главный вестибюль…) не
  предусматривается / силами владельца»;
- «разводка в с/у МГН, охраны, лапомойке и ПУИ выполняется в полном объёме»
  от I зоны жилой части.

Нельзя автоматически вырезать «весь с/у вестибюля / УК» как полный доп., пока
инженер не развёл эти фразы по экспликации помещений. Уверенность — «сначала
лист». В примечании — какая фраза ПД против какой.

То же: схема ПД показывает одну систему, текст ПД — другую. Текст, прошедший
экспертизу, весомее «цветной линии» на схеме, но до АИ/чертежа позицию не
закрывать.

### Антидвойной счёт

Явно писать «считать с / не считать отдельно»:
- текстовый перечень узлов vs физика того же узла;
- требуемый напор vs насосные установки;
- изоляция вновь добавленных стояков/вводов — в комплексе тех ИТ, не повтор
  общим ИТ по изоляции;
- опоры/КС новой группы — в комплексе группы, не повтор общим ИТ по компенсации;
- один участок магистрали — один ИТ (выход из НС / транзит у корпуса / узел в насосной).

### Уверенность (три значения)

| Значение | Когда | В письмо заказчику |
|---|---|---|
| уверен | ПД и РД однозначно читаются | можно как факт |
| сначала лист | автосводка расходится, коллизия фраз ПД, нет узла на схеме ПД «крупно» | нельзя как факт |
| после АИ | РД сама откладывает решение (примечание «после выпуска АР» и т.п.) | нельзя закрывать |

Уверенность должна совпадать с текстом карточки: если в «Инженеру» или
«Заказчику» есть условие сверки листа ПД («сверить, не было ли на ПД…»,
«если на схеме ПД…», «при подтверждении по листу»), значение — «сначала
лист», не «уверен».

### Колонки листа «Карточки ИТ»

| Колонка | Содержание |
|---|---|
| ID | ИТ-xxx или ИТ-xxx.2 |
| Корзина | одна из четырёх, точно как в легенде (выпадающий список) |
| Уверенность | уверен / сначала лист / после АИ |
| Название | из итоговой карточки, уточнить при коллизии |
| Резюме для инженера | 3–6 предложений: суть «было→стало», почему эта корзина |
| Было (ПД) | факт + ссылка |
| Стало (РД) | факт + шифр/лист |
| Заказчику / почему не подаём | корзины 1–2: обоснование в ОП; 3–4: почему не подаём, со ссылкой на ПД |
| Инженеру: как проверить и считать | что открыть; критерий ✓/✗; как вырезать Δ |
| Комплекс / смежники | ЭОМ, СС, АР, ИТП, КПК — или «—» |
| Что в расчёт | комплекс Δ / дельта / сальдо / минус / ноль |
| Связано с | ID, без двойного счёта |
| Куда смотреть (шифры) | ПД пункт/лист; РД шифры |
| Примечание | 1–3 технических предложения; то же на «Краткой сводке» |

Примечание (стиль): сухо, с маркировками систем (В1.1, Т3.2), типоразмерами,
условиями включения («применять, если на схеме ПД группы нет»). Без лозунгов.

На «Краткой сводке» поле «Кратко» — первое предложение резюме, не копия всей карточки.

### Как читать исходник

- Пройти все ИТ- на листе «Итоговые» по порядку.
- На каждую: заголовок, Было, Стало, список характеристик (П / Р), «По
  месту», состав PC, проявления, фрагменты OLD/NEW.
- Не решать спор автосводки текстом карточки, если внутри две версии (новая
  группа vs рост Ду) — вынести ветки.
- Цитаты ПД, от которых зависит корзина 4 или граница ГП, перечитать в томе
  ПД, не полагаться только на пересказ выгрузки.
- Числа не выдумывать. Нет числа в ПД/РД — «не указано», уверенность ниже.
- Δ количества ≠ автоматические доп. работы (может быть детализация, ошибка
  схемы ПД vs АР, сальдо).

### Самопроверка перед выдачей

- У каждой ИТ есть корзина и уверенность.
- У корзины 4 есть ссылка на ПД, почему не подаём.
- Расчётные показатели — в корзине 4 со ссылкой на ИТ с физикой.
- Уверенность не противоречит условиям в тексте карточки.
- Смешанные разрезаны; взаимоисключающие ветки не попали в ОП одновременно.
- Нет двойного счёта смежных ИТ.
- У корзин 1 и 2 заполнены смежники либо явно «—».
- Нормативка не в смете, но с правилом экспертизы.
- Листы и колонки файла не изменены, «Итоговые» без правок.
- Примечания технические.

### Чего не делать

- Не сводить отчёт к списку qty без корзины.
- Не подавать рабочую детализацию как полный доп.
- Не вырезать внутреннюю разводку арендатора / «силами владельца», если РД её
  по-прежнему не проектирует.
- Не строить насосную / стояк / узел «с нуля», если в ПД они были.
- Не назначать кабель ЭОМ в спецификацию ВК.

### Вход, который заполняет инженер (только это)

- Система / марка: (пример: ИОС2.1 внутренний водопровод ХВС/ГВС)
- Объект / шифр:
- Файл: путь к xlsx, выгруженному кнопкой «Выгрузить отчёт»
- ПД: путь
- РД: путь (все альбомы марки)
- Опционально: границы ГП/арендатор; вендор; известные АИ; номер экспертизы /
  редакция СП, с которой заходили

### Старт работы

1. Открыть «Итоговые», перечислить все ИТ- (id + первая строка названия).
2. Для каждой собрать Было/Стало и спорные характеристики.
3. Перечитать в ПД абзацы, от которых зависит граница объёма (встроенные, МГН,
   «уточняется на РД», диаметры, насосы, балансировка, компенсация, нормативка).
4. Разложить корзины, разрезать хвосты, проставить уверенность и смежников.
5. Заполнить «Карточки ИТ» в выгруженном файле.
6. В ответе инженеру — краткая статистика по корзинам (условные ветки
   отдельно) и список строк «сначала лист / после АИ», без пересказа всех
   карточек.
