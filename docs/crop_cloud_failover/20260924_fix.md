# Crop cloud availability failover — 2026-09-24

## Cause and exact execution path

Production at incident: `ui-real-0f322165`, backend PID 179562.
`PipelineManager._ensure_stage02_crops` → `_run_script_for_job` →
`process_runner.run_script` → `blocks.py crop` → `crop_blocks` →
`download_and_convert` → `_download_with_retry` → stdlib `urllib.request.urlopen`.
The foreground processes and a duplicate lookahead precrop of АОВ were all alive.
`py-spy dump` of АУТ/АУВ showed `socket.create_connection` inside this path.
Job logs showed successful `[PDF-CROP]` after each network timeout.

Old cost **per block**: three 30-second HTTP timeouts plus 0.5 + 1 second backoff
(91.5 seconds, approximately 92 with overhead). There is no SDK or storage-client
retry in this path. `run_script` does not retry the child; its optional process
timeout is not an HTTP retry. The crop stage does not automatically restart the
job. Precrop is a separate process, previously repeating the same costs.
Experimental `crop_blocks_to_dir` and standalone recrop callers retain their
existing retry policies; this patch targets production `crop_blocks`.

## Change

A verified local source permits fast failure of **crop-specific availability
errors** on the first HTTP attempt; the timeout remains 30 seconds, and unrelated
HTTP retry defaults are unchanged. A successful local fallback then opens a
circuit keyed by job ID, provider, and the resolved PDF/OCR identity (paths and
SHA256). Subsequent blocks use local PDF without an HTTP request. Failed local
fallback does not open it. A new job ID probes again.

The manager passes the same item job ID to foreground and precrop. State is in
`/tmp/auditmanager-crop-<uid>/<hashed-job>/`; an OS file lock covers checking the
state, cloud probe, local fallback, and atomic OPEN write. This serializes probes
across processes and threads; it is not a permanent installation setting.

Timeout/connection/DNS failures and HTTP 408/502/503/504 open the circuit only
after successful local crop. HTTP 403/404/410 retain individual local fallback
without opening a provider circuit. Corrupt content, invalid identity, certificate
errors, and other nonavailability failures remain visible errors.

PDF selection refuses an unrelated named document or ambiguous generic multi-PDF
source. A normalized PDF is compared by SHA256 to the OCR-declared original when
names differ. Declared `pdf_sha256`/`source_pdf_sha256` are checked when present.
PDF/OCR stat identity is checked during the job. Page dimensions and PDF are bound
to each block's OCR source, avoiding collisions between page 1 of different PDFs.
No rendering/geometry function was changed.

One `CLOUD_CROP_UNAVAILABLE` transition includes job ID, source identity, provider,
reason, `LOCAL_PDF`, and `OPEN`. Per-process/job counters appear in
`CROP_FAILOVER_SUMMARY`, the return receipt, and `index.json.crop_failover`.
These are invocation counters, not globally aggregated lifetime counters.
